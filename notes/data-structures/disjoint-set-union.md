# 并查集

> 最近修订：2026-08-17 06:53 +10:00（未审阅）

一开始有 $n$ 个互不相连的点，随后不断加入无向边。我们希望随时回答：

- 两个点现在是否已经连通；
- 把两个点所在的连通分量合并；
- 一个点所在的连通分量有多少个点；
- 当前还剩多少个连通分量。

每次查询都重新 DFS 或 BFS，需要 $O(n+m)$ 时间。若问题只有“合并集合”和“判断是否属于同一集合”，并不需要保存连通分量内部的路径结构。并查集（Disjoint Set Union，DSU）为每个集合选择一个代表元，只维护“每个元素属于哪个集合”，从而让合并和查询都接近常数时间。

并查集适合边只增加、不删除的动态连通性。它不能回答两点之间的具体路径，也不能直接处理删除边以后连通分量重新分裂的问题。

## 用代表元判断集合

最初每个点单独组成一个集合，可以让每个点都代表自己：

```text
{1} 的代表元是 1
{2} 的代表元是 2
...
{n} 的代表元是 n
```

若两个点最终找到同一个代表元，它们就在同一集合；代表元不同，它们就在不同集合。

可以用 `parent[u]` 保存节点 `u` 向上指向的父节点。代表元是整棵树的根，满足：

```text
parent[u] == u
```

初始化时每个点都是一棵只有根的树：

```cpp
for (int u = 1; u <= n; u++) {
    parent[u] = u;
}
```

这里的树只用于表达集合从属关系，不是原图中的边。加入图边 `(u,v)` 时，并查集不会把它原样保存为父子边；它只把两个集合的代表树连接起来。

## 查找代表元

若 `u` 不是根，就继续查找 `parent[u]` 的代表元：

```cpp
int find(int u) {
    if (parent[u] == u) {
        return u;
    }
    return find(parent[u]);
}
```

例如：

```text
4 -> 3 -> 1 -> 1
```

从 `4` 出发不断沿父节点向上，最终到达代表元 `1`，所以 `find(4) == 1`。

只要两个点的查找结果相同，它们就属于同一集合：

```cpp
bool same(int u, int v) {
    return find(u) == find(v);
}
```

## 合并两个集合

合并 `u` 与 `v` 所在的集合时，先分别找到代表元：

```cpp
u = find(u);
v = find(v);
```

若 `u == v`，两个点本来就在同一集合，不需要修改。否则让一棵代表树的根指向另一棵树的根：

```cpp
parent[v] = u;
```

必须连接两个**代表元**，不能直接写 `parent[v] = u` 而省略前面的 `find`。原始的 `u` 或 `v` 可能只是树中间的节点；随意修改中间节点会拆走它原来的整棵子树，破坏已有集合关系。

当合并确实发生时，连通分量数量减少一个。让 `merge` 返回 `bool` 可以同时表达“是否真正合并”：

```cpp
bool merge(int u, int v) {
    u = find(u);
    v = find(v);
    if (u == v) {
        return false;
    }
    parent[v] = u;
    components--;
    return true;
}
```

这个返回值在 Kruskal 算法中尤其有用：`merge(u,v)` 返回 `false` 说明两点原本已经连通，再加入这条边会形成环。

## 树链过长的问题

若每次合并都随意把一棵树接到另一棵树下面，可能形成很长的链：

```text
5 -> 4 -> 3 -> 2 -> 1
```

此时 `find(5)` 要经过 $O(n)$ 个节点，并查集就失去了效率。需要从两个方向限制树高：

1. 查找以后压缩经过的路径；
2. 合并时把较小的树接到较大的树下面。

## 路径压缩

递归查找代表元返回时，已经知道整条路径最终到达哪个根。可以顺手让沿途每个节点直接指向根：

```cpp
int find(int u) {
    if (parent[u] == u) {
        return u;
    }
    return parent[u] = find(parent[u]);
}
```

对链：

```text
5 -> 4 -> 3 -> 2 -> 1
```

执行一次 `find(5)` 后，经过的节点会变成：

```text
5 -> 1
4 -> 1
3 -> 1
2 -> 1
1 -> 1
```

这称为**路径压缩**。赋值表达式 `parent[u] = ...` 的结果仍是刚刚写入的代表元，所以可以直接返回。

压缩只改变集合内部的父节点形状，不改变任何节点所属的集合，也不改变代表元。

## 按大小合并

用 `component_size[u]` 记录以代表元 `u` 为根的集合大小。初始化时每个集合只有一个点：

```cpp
component_size[u] = 1;
```

合并两个不同代表元时，让较小集合的根指向较大集合的根：

```cpp
if (component_size[u] < component_size[v]) {
    swap(u, v);
}
parent[v] = u;
component_size[u] += component_size[v];
```

这样节点所在树的深度每增加一次，它所在集合的大小至少翻倍。一个集合最多从 $1$ 翻倍到 $n$，所以即使暂时不考虑路径压缩，树高也不会超过 $O(\log n)$。

`component_size` 只保证代表元位置的数值有效。非根节点保留的旧值不再表示当前集合大小，因此查询必须先找代表元：

```cpp
int size(int u) {
    return component_size[find(u)];
}
```

也可以按树高或秩合并；基础实现只保留按大小合并，因为它同时自然支持集合大小查询。

## 完整代码

下面的 `DSU` 封装父节点、集合大小和连通分量数量。内部 `vector` 分配 `n + 5` 个位置，点编号使用 `1..n`，位置 `0` 留空。

程序处理四类操作：

- `1 u v`：合并 `u` 与 `v` 所在集合；
- `2 u v`：同集合输出 `1`，否则输出 `0`；
- `3 u`：输出 `u` 所在集合的大小；
- `4`：输出当前集合数量。

```cpp
#include <bits/stdc++.h>
using namespace std;

struct DSU {
    int components;
    vector<int> parent;
    vector<int> component_size;

    DSU(int n) : components(n), parent(n + 5), component_size(n + 5, 1) {
        for (int u = 1; u <= n; u++) {
            parent[u] = u;
        }
    }

    int find(int u) {
        if (parent[u] == u) {
            return u;
        }
        return parent[u] = find(parent[u]);
    }

    bool merge(int u, int v) {
        u = find(u);
        v = find(v);
        if (u == v) {
            return false;
        }
        if (component_size[u] < component_size[v]) {
            swap(u, v);
        }
        parent[v] = u;
        component_size[u] += component_size[v];
        components--;
        return true;
    }

    bool same(int u, int v) {
        return find(u) == find(v);
    }

    int size(int u) {
        return component_size[find(u)];
    }

    int component_count() const {
        return components;
    }
};

int main() {
    int n, m;
    scanf("%d%d", &n, &m);

    DSU dsu(n);

    while (m--) {
        int op;
        scanf("%d", &op);

        if (op == 1) {
            int u, v;
            scanf("%d%d", &u, &v);
            dsu.merge(u, v);
        } else if (op == 2) {
            int u, v;
            scanf("%d%d", &u, &v);
            printf("%d\n", dsu.same(u, v));
        } else if (op == 3) {
            int u;
            scanf("%d", &u);
            printf("%d\n", dsu.size(u));
        } else {
            printf("%d\n", dsu.component_count());
        }
    }
    return 0;
}
```

输入：

```text
6 10
4
1 1 2
1 2 3
2 1 3
2 1 4
3 2
1 4 5
1 3 5
3 4
4
```

输出：

```text
6
1
0
3
5
2
```

最初有 $6$ 个单点集合。合并 `1,2,3` 后它们属于同一个大小为 $3$ 的集合；合并 `4,5`，再连接 `3,5` 后，`1..5` 属于同一个大小为 $5$ 的集合，只剩它与 `{6}` 两个集合。

## 复杂度

初始化需要 $O(n)$ 时间和 $O(n)$ 空间。

同时使用路径压缩和按大小合并时，连续执行任意次 `find` 与 `merge`，每次操作的**均摊**时间复杂度是 $O(\alpha(n))$。$\alpha$ 是反阿克曼函数，在任何实际竞赛数据范围内都不超过一个很小的常数，因此通常口头描述为“几乎是 $O(1)$”。

但它在理论上不是严格的最坏 $O(1)$。需要写复杂度时使用 $O(\alpha(n))$ 更准确；“均摊”表示少数操作可能较慢，但一长串操作的总成本很低。

## 适用边界

并查集最适合：

- 无向边不断加入时维护连通性；
- Kruskal 算法判断一条边是否连接两个不同连通分量；
- 把具有等价关系的对象逐步归并成集合；
- 只关心集合归属和大小，不关心集合内部路径。

基础并查集不适合：

- 删除边以后把一个集合拆开；
- 查询两点之间经过哪些边或距离是多少；
- 维护集合内部有方向的父子结构；
- 表示元素之间的距离、奇偶性或模关系。

在基础并查集之上，后续有两个彼此平行的常用扩展：

- [扩展域并查集](extended-domain-disjoint-set.md) 为每个对象建立多个表示不同状态的元素，用集合关系表达互斥类别；
- [带权并查集](weighted-disjoint-set.md) 在代表树的边上维护距离、奇偶性或模意义下的相对关系。

它们都是并查集的扩展，不是谁从属于谁。离线删除、可撤销状态和可持久化版本还会继续改变核心维护方式，本篇不提前加入这些内容。

## 常见错误

### 合并原始节点而不是代表元

`merge` 开头必须先执行两次 `find`。只有代表树的根能够安全地连接另一棵代表树。

### 同集合仍然减少数量

若两个代表元已经相同，合并没有发生，`components` 不能减少，集合大小也不能重复相加。

### 路径压缩漏掉赋值

`return find(parent[u]);` 能找到代表元，却没有压缩路径。必须把结果写回 `parent[u]`。

### 查询非根位置的旧大小

一个根接到其他根以后，它在 `component_size` 中的旧值不再代表完整集合。始终使用 `component_size[find(u)]`。

### 把并查集父边当成原图边

路径压缩会随时改变父节点。`parent[u]` 只用于快速找到集合代表元，不能用来恢复题目中的路径或边。

### 认为能够直接删边

合并会丢弃两个集合原来的边界信息。删除一条原图边以后，基础并查集无法判断集合是否应当分裂。

## 基础练习

1. 初始化 `1..6`，依次合并 `(1,2)`、`(3,4)`、`(2,3)`，画出一种可能的代表树。
2. 在一条较长父节点链上执行路径压缩，写出每个经过节点的新父节点。
3. 构造大小分别为 $3$ 和 $5$ 的集合，说明按大小合并应当让哪个根成为父节点。
4. 修改完整程序，让 `merge` 成功时输出 `1`、两点已经同集合时输出 `0`。
5. 用 $O(n)$ 的标签数组实现朴素集合合并，与 `DSU` 随机对拍 `same`、`size` 和集合数量。
6. 给定一组无向边，使用 `merge` 的返回值统计有多少条边连接了原本已经连通的两个点。

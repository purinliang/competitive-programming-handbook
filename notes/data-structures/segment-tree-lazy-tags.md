# 线段树：懒标记的组合顺序

> 最近修订：2026-08-13 03:03 +10:00（未审阅）

[线段树：基础](segment-tree.md#懒标记) 只使用一种区间加标记，两次修改可以直接累加。当同一道题同时支持加法、乘法或赋值时，只记录“有哪些操作”已经不够，还必须保存它们的组合顺序。

多个懒标记同时存在时，最容易错的不是代码长度，而是“新操作覆盖旧操作”还是“新操作叠加到旧操作”。

一个可靠的理解方式是：懒标记本质上是在节点区间里暂存一个还没有下传到儿子的函数。以后访问儿子时，把这个函数应用到儿子身上。

## 单个加法标记

区间加 `val` 可以看成函数：

```text
f(x) = x + val
```

如果一个节点先加 `a`，后加 `b`：

```text
(x + a) + b = x + (a + b)
```

所以多个加法标记可以直接累加。

```cpp
vector<ll> lazy(4 * n + 5);
```

加法标记的恒等元是 `0`：

```text
x + 0 = x
```

本篇只有一种加法操作时，`lazy[u]` 直接保存加法参数。清空状态写成 `0`；判断 `lazy[u] == 0` 是安全的，因为“增加 0”本来就是不产生任何效果的恒等操作。

## 单个乘法标记

区间乘 `val` 可以看成函数：

```text
f(x) = x * val
```

如果一个节点先乘 `a`，后乘 `b`：

```text
(x * a) * b = x * (a * b)
```

所以多个乘法标记可以直接相乘。

```cpp
vector<ll> lazy(4 * n + 5, 1);
```

这里 `lazy[u]` 直接保存乘法参数。

乘法标记的恒等元是 `1`：

```text
x * 1 = x
```

清空状态写成 `1`。判断 `lazy[u] == 1` 同样安全，因为“乘以 1”就是不产生效果的恒等操作。

## 加法和乘法同时存在

如果题目同时支持区间乘、区间加、区间和，常见做法是把懒标记维护成一次线性变换：

```text
f(x) = x * mul + add
```

初始状态是恒等变换：

```text
mul = 1
add = 0
f(x) = x
```

同时存在乘法和加法时，一次待处理操作本身需要 `mul` 和 `add` 两个参数。这里先保留数学推导，不规定具体存储类型；基础模板只处理一种修改。

对整个节点区间 `[l, r]` 应用标记时，区间和也要同步更新。

如果新操作是加 `val`：

```text
原来：f(x) = x * mul + add
现在：g(f(x)) = f(x) + val = x * mul + (add + val)
```

```cpp
tree[u] += val * (r - l + 1);
add += val;
```

如果新操作是乘 `val`：

```text
原来：f(x) = x * mul + add
现在：g(f(x)) = f(x) * val = x * (mul * val) + (add * val)
```

```cpp
tree[u] *= val;
mul *= val;
add *= val;
```

如果题目要求取模，上面的所有乘法和加法都要取模。

字符串多项式哈希里也会出现类似的乘加结构。合并左右儿子时，左半段哈希通常要乘上 `base` 的若干次幂，再加上右半段哈希：

```text
h = h_left * base^len_right + h_right
```

这不是懒标记意义下的区间乘加，但它提醒我们：线段树维护的“合并”可以是有顺序的乘加运算。字符串哈希的左右顺序不能交换。

## 赋值标记

区间赋值 `val` 可以看成函数：

```text
f(x) = val
```

它和加法、乘法不同：赋值会覆盖这个位置之前的值。也就是说，新来的赋值操作会覆盖旧的加法、乘法、赋值标记。

赋值标记不能只用一个 `ll` 表示。因为“赋值成 0”是合法操作，不能拿 `0` 表示没有标记。

常见写法是把“是否存在赋值标记”和“赋成什么值”绑成一个 `pair`：

```cpp
vector<pair<bool, ll>> lazy(4 * n + 5);
```

其中：

```text
lazy[u].first == false：没有赋值标记
lazy[u].first == true：存在赋值标记，值为 lazy[u].second
```

## 三种标记的统一形式

如果同时支持区间赋值、区间乘、区间加，可以把每个节点的懒标记理解成：

```text
f(x) = (has_assign ? assign_val : x) * mul + add
```

恒等标记是：

```text
has_assign = false
mul = 1
add = 0
```

此时三个操作的覆盖关系如下。

新操作是加 `val`：

```text
add = add + val
```

新操作是乘 `val`：

```text
mul = mul * val
add = add * val
```

新操作是赋值 `val`：

```text
has_assign = true
assign_val = val
mul = 1
add = 0
```

这说明赋值是覆盖型操作。一次新的赋值到来后，旧的加法和乘法都已经没有意义，因为所有旧值都会被直接替换。

## 下传顺序

`push` 时，父节点的标记必须按它实际代表的函数顺序下传给儿子。

对统一形式：

```text
f(x) = (has_assign ? assign_val : x) * mul + add
```

下传顺序应该是：

1. 如果有赋值标记，先把赋值下传。
2. 再下传乘法标记。
3. 最后下传加法标记。

这是因为：

```text
先赋值，再乘法，再加法
```

才等价于：

```text
x -> assign_val -> assign_val * mul -> assign_val * mul + add
```

如果没有赋值标记，就只是：

```text
x -> x * mul -> x * mul + add
```

## 常见错误

- 区间乘法后只更新 `mul`，忘记同步更新 `add`。
- 新的区间赋值到来后，没有清除旧的乘法和加法效果。
- 把 `lazy[u].second == 0` 当成没有赋值标记。
- 下传时先加后乘，导致结果变成 `(x + add) * mul`。
- 节点的 `tree[u]` 改了，但 `lazy[u]` 没有同步改，之后查询儿子会错。
- 懒标记下传给儿子后，没有把父节点标记恢复成恒等标记。
- 维护字符串哈希时把左右儿子合并顺序写反。

## 需要记住什么

1. 为什么可以把懒标记理解成一个暂未下传的函数？
2. 两次加法标记和两次乘法标记分别怎样合并？
3. 新乘一个数时，为什么 `mul` 和 `add` 都要同时改变？
4. 新的赋值操作为什么会清除此前累积的乘法和加法效果？
5. 当一个标记表示为 `f(x) = (has_assign ? assign_val : x) * mul + add` 时，下传为什么要按赋值、乘法、加法的顺序进行？

这是一篇扩展专题。只有在题目确实出现多种会互相影响的区间修改时，才需要掌握这套组合方法；学习基础线段树时不要求理解或记忆。

# Notes 写作与协作规范

本文件约束 `notes/` 下教程正文、知识目录、学习路线和长期图片资产的维护方式。仓库根目录 `AGENTS.md` 的通用约束仍然生效；发生冲突时，以更具体且不违反根规则的本文件为准。

## 正文唯一，导航分离

- 每个知识点只有一份正文，保存在所属模块目录中。
- 每篇文章只回答一个足够小的主要问题；不得因为若干概念经常一起教就把它们合并成篇。
- 标题可以使用稳定的课程或主题前缀，例如“入门：Hello World!”、“复合类型：struct”和“有序关联容器：map”；前缀同时出现在正文一级标题、模块目录和学习路线中。不要在知识点名称后追加“第一次提交”之类仅描述教学任务的副标题。
- 同一知识族出现多篇文章时，使用“知识族：单一主题”的标题建立层级，例如“图的遍历：深度优先搜索（DFS）”“树：有根树”“动态规划：线性 DP”“背包：0-1 背包”和“字符串：KMP 与前缀函数”。冒号后的部分仍必须是一个明确主题，不能借前缀重新合并互相独立的知识点。
- 二级标题使用简洁、稳定的名词性短语，使目录可以脱离正文独立阅读；“先……”“再……”“如何……”等口语化过渡留在段落中，不作为标题。
- 行内 Markdown 链接与相邻的中文正文之间各留一个空格；链接紧邻句号、逗号、括号等标点时不在标点内侧额外加空格。
- 知识点独立成篇的条件是：脱离父主题后，它仍有独立的学习目标、语义或模型、使用场景，并值得被下游单独引用。文章很短不是合并理由。
- 只为完成父主题而存在的语法或机制留在父文章中：`break` / `continue` 属于循环，比较器属于排序，迭代器由容器文章解释，函数的形参、实参和返回语法属于函数基础。
- 有依赖不等于应该合篇。例如比较运算产生布尔值，逻辑运算组合布尔值；两者前后依赖，但语义和操作集各自完整，因此分篇。
- `CATALOG.md` 是唯一的知识注册表，按模块列出核心教程与扩展专题。
- `LEARNING-PATH.md` 的阶段 1–6 是核心教程的大致教学顺序；文末另设“扩展阅读索引”，按模块和 ID 收录目录中的全部扩展专题，但这些索引项不属于主学习路线。
- 四位文章 ID 按模块编号，不表示学习顺序。大纲首次审核通过后保持稳定，不要为了调整路线而重命名正文。
- 直接配套某篇基础文章的深入或参考文章使用 `e1`、`e2` 等后缀并共享基础编号，例如 `0102e1`；它们不占用新的四位编号，也不进入核心学习路线。独立扩展专题仍在四位 ID 后标记 `*`。
- 正文文件名使用小写短横线语义名，不必重复文章 ID 或标题中的课程、模块前缀，例如“入门：Hello World!”保存为 `hello-world.md`。已有的 ID 前缀文件可以在正式修订或移动时逐步迁移，不为统一外观批量重命名。
- 计划中的知识点只登记路径，不创建空 Markdown 文件。

模块目录的每一行使用固定字段：

```text
ID | 知识点 | 状态 | 文件
```

允许值：

- 纯四位数字 ID 表示核心教程；ID 后的 `*` 表示独立扩展专题，例如 `0305*`；`e1`、`e2` 等后缀表示基础文章的直接配套扩展，例如 `0102e1`。
- 状态：`计划`、`待审阅`、`已审阅`。旧文章中的 `草稿`、`定稿` 只作为过渡状态保留；下一次发生实质修订时再迁移，不批量伪造历史。
- 正文尚未齐全时不在目录维护前置编号。全书完成到足以观察真实引用以后，再根据正文反向梳理依赖关系。

## 核心与扩展的边界

核心教程解释一个知识点最常用、最基础、足以独立解决标准问题的版本，并说明代码每个组成部分为什么存在。

例如：

- 树状数组正文解释 `lowbit`、节点覆盖区间、`add` 与 `prefix_sum` 的跳转及区间和。
- 线段树正文解释递归划分、`4n` 空间、`build/pull/push`、基础查询修改和一种基础懒标记。
- 普通图正文展示结构本身的 value 与边关系，不把内部 id 当成教学重点。

以下内容通常独立为扩展专题：

- 为少见功能精密改造基础结构，例如树状数组维护区间最值。
- 需要额外技巧但不改变基础结构理解的操作，例如线段树二分。
- 复杂标记组合、可持久化、动态开点、Segment Tree Beats 等高级变体。
- 左偏堆、复杂平衡树、高级字符串结构等低频或超出主路线收益范围的内容。

扩展专题只进入模块目录和路线文末的扩展阅读索引。核心教程可以在文末链接它，但不能把它作为主线必学内容。

标准库教程只负责容器或固定任务的接口、常用复杂度和比赛所需的最少安全规则，不在同一篇重新推导底层数据结构。不设“STL 算法大全”、“比较器”或“迭代器”这种泛化主线文章：比较器放在排序文章中，迭代器由各容器文章在首次使用时解释。迭代器失效不单独成篇，也不罗列完整标准表；相关教程只需展示遍历中用 `it = container.erase(it)` 删除的安全模式，并提醒 `vector` 扩容后旧迭代器、指针和引用不能继续使用。

抽象数据结构和标准库实现必须分篇：数组、链表、栈、队列、二叉堆和哈希表负责结构、操作与复杂度；`vector`、`stack`、`queue`、`priority_queue` 和无序关联容器负责比赛中的编码接口。不能因为比赛中通常直接调用标准库，就省略结构本身，也不能在概念文章中顺便教完容器接口。`vector`、`string` 和 `sort` 等最低限度工具可以先作为接口使用，学习复杂度后再从数据结构或算法视角重新理解；`stack`、`queue`、`priority_queue` 等名称直接对应抽象结构的工具，则先讲概念，再紧邻安排接口文章。

C++ 与 STL 的关键字、标准库标识符和成员函数始终保留代码中的英文拼写，例如 `struct`、`vector`、`pair` 和 `push_back`，不创造会替代正式名称的固定中文译名。中文正文负责解释语义，例如“使用 `struct` 声明结构体类型”“`vector` 是动态数组式的序列容器”；已经稳定的通用概念继续使用中文，例如结构体、引用、迭代器、结构化绑定和容器适配器。标题优先使用“中文分类：代码名”，例如“复合类型：struct”“序列容器：vector”。不得把 `vector` 固定译为“向量”，以免与数学和计算几何中的向量混淆。

算法与数学名称按中文竞赛圈的稳定通名处理。中文资料也普遍直接使用拉丁字母的人名算法保留原名，例如 `Kruskal`、`Bellman–Ford`、`Floyd–Warshall`、`Dijkstra`、`Hierholzer`、`Tarjan` 和 `Dinic`，不使用生硬音译；已经形成固定中文名称的概念使用中文，例如欧拉函数、莫比乌斯函数、欧拉路径、欧拉回路、欧拉图、哈密顿路径和哈密顿图。描述性名称使用中文，并在首次出现时给出通行缩写，例如深度优先搜索（DFS）和广度优先搜索（BFS）。

二进制二选一模型统一写作 `0-1`，使用短横线：`0-1 背包`、`0-1 BFS`。标题和正文不交替使用 `01`、`0/1` 等写法。

## 图论术语

- 中文术语以 [OI Wiki](https://oi-wiki.org/graph/concept/) 的竞赛用法为基准；英文竞赛术语以 USACO 收录的 [Competitive Programmer's Handbook](https://usaco.guide/CPH.pdf) 为基准。其他教材中的别名只在确有必要时放入引用块，不在正文中交替使用。
- 一般图的对象首次出现时写“顶点（vertex），简称点”，此后正文只使用竞赛中更常见的“点”；相应地使用“点集、点数、点权”等说法。进入树的语境后统一使用“节点”，例如根节点、父节点、子节点和叶节点；说明树与图的对应关系时，可以明确写“树的节点对应图中的点”。链表等由实体组成的数据结构也沿用“节点”。英文图论资料即使使用 node，中文的一般图正文仍写“点”。
- `path` 统一译为“路径”，指点不重复的边序列；`cycle` 统一译为“环”，指除首尾重合外不重复点的闭合结构；`self-loop` 或 `loop` 统一译为“自环”。
- `circuit` 统一译为“回路”，指边不重复、但允许重复经过点的闭合结构。基础概念正文不展开 `walk`、`trail` 与 `circuit` 的完整分类，只在自环、欧拉或哈密顿语境中解释真正需要的区别。
- 固定使用“欧拉路径（Eulerian path）”“欧拉回路（Eulerian circuit）”“哈密顿路径（Hamiltonian path）”“哈密顿回路（Hamiltonian circuit）”和“有向无环图（Directed Acyclic Graph，DAG）”。其他中英文名称只作为注释。
- 题面若自行定义 path、cycle 等词，以题面定义为准；教程应直接复述“是否允许重复顶点或边”，不要只依赖术语猜测限制。
- 教程正文、示例代码和图示中的点编号统一使用从 `1` 开始的连续整数 `1, 2, ..., n`，不使用字母充当点编号；YAML 中的图节点 `id` 与该编号保持一致。点权是附在点上的独立数值，不能代替点编号。
- 图的基础存储示例使用 `graph`、`from`、`to`、`weight` 等完整名称说明每个量的含义；进入可复制的竞赛代码后，统一使用常见缩写 `g`、`u`、`v`、`w`。布尔邻接矩阵命名为 `connected`，带权矩阵命名为 `weight`，不使用无法体现格子含义的二维 `graph`。
- 图的三种基础存储方式统一称为“边集、邻接矩阵、邻接表”。“邻接表”描述的是为每个点保存出边集合的抽象方法，不限定底层容器；`vector` 邻接表、前向星和链式前向星都是邻接表的实现。“邻接链表”只在底层确实使用链表时出现，不作为 adjacency list 的统一译名。
- 普通图算法的主线模板只使用 `vector` 实现邻接表。对应文章标题写作“图的存储：邻接表（vector 实现）”，正文在语境明确后可以简称“`vector` 邻接表”。无权邻接项保存 `int`；带权邻接项优先保存 `pair<int, int>`，固定按 `(to, weight)` 排列，并用 C++17 结构化绑定 `for (auto& [v, w] : g[u])` 访问。边集在需要整体扫描或排序全部边时独立成篇；邻接矩阵只在基础概念中说明，并由确实需要它的算法按题目语义具体实现。
- 前向星是将边集按起点分组后，用每个点的区间边界定位连续出边；常见排序构建为 $O(m\log m)$，计数分组也可达到 $O(n+m)$。它只用于解释存储关系，不列入主线模板。
- 欧拉图、网络流等高频访问配对反向边的算法改用链式前向星：两条记录连续存入全局边数组，以 `edge_id ^ 1` 互相定位，并可用 `head` 或当前边下标跳过已经无用的记录。对应文章标题写作“图的存储：邻接表（链式前向星实现）”。链式前向星在高中阶段独立成篇，作为邻接表的特殊数组实现教授，不列为第四种基础存图方法。哈密顿问题限制的是点而非边，不因此改用链式前向星。

树位于图论与数据结构的交界，模块归属不能只按“是否有根”或“是否称为节点”判断：

- 当题目给出一棵树，我们研究它的点边关系、路径、遍历、直径、重心、LCA 或分治时，归入图论；临时选根只是为无向树赋予父子层级。
- 当树形由我们为存储数据和支持操作而构造，并需要维护左右孩子、键值顺序、区间、平衡性等不变量时，归入数据结构，例如二叉搜索树、堆、线段树和平衡树。
- 普通二叉树兼有两种视角。本书把显式左右孩子、存储方式及前序、中序、后序遍历放在数据结构模块；把不依赖左右次序的树上遍历与性质放在图论模块。
- 树的基础概念先讲无根树，再讲指定根以后新增的层级关系。无根树的叶节点定义为度数不超过 `1` 的节点，以覆盖单节点树；有根树的叶节点定义为没有子节点的节点，因此只要根有子节点，它就不是叶节点。

## 文章信息块

文章没有永远不再修改的“终稿”。状态只描述当前版本是否经过用户完整审阅：

- `计划`：目录中已有节点，但尚无正文。
- `待审阅`：正文已经存在，但用户尚未完整审阅当前版本。
- `已审阅`：用户已经完整审阅当前版本；这不妨碍文章以后继续修订。

新文章必须在一级标题后用一行记录最近修订时间和审阅状态，使用 Australia/Sydney 当时的 UTC 偏移：

```markdown
# 树状数组：基础

> 最近修订：2026-08-13 14:30 +10:00（未审阅）
```

要求：

- 信息块括号中的审阅状态必须与 `CATALOG.md` 一致：`未审阅` 对应 `待审阅`，`已审阅` 对应 `已审阅`。核心或扩展属性只在目录 ID 上标记。
- 正文可以在真正有帮助时用自然语言链接前置阅读，但不维护编号化的强制前置清单。
- 新正文一律从 `待审阅` 开始，信息块写“未审阅”。只有用户明确表示已经完整审阅当前版本，才能把目录改为 `已审阅`，并把括号改为“已审阅”；局部批注、讨论某一节或 agent 自检不算完整审阅。
- 教学内容、代码、示例、标题或章节结构发生实质变化时，更新“最近修订”。若文章原为 `已审阅`，将目录改回 `待审阅`，并把括号改回“未审阅”。
- 纯格式化、拼写、链接或 LaTeX 兼容性修复不更新文章日期，也不改变审阅状态。
- 旧文章中的 `草稿`、`定稿` 和简短信息块不批量迁移。下一次实质修订该文时，再改用新状态并写入当次“最近修订”，不得猜测或倒推历史日期。
- 信息块固定写作 `> 最近修订：YYYY-MM-DD HH:MM +HH:MM（未审阅）` 或对应的负 UTC 偏移、已审阅状态。不记录初稿时间，也不单独记录审阅时间。
- 已有正文的二级标题视为稳定引用接口。重命名时检查并更新所有下游锚点链接。

## 正文内容检查清单

下面八项是写作时逐项判断的内容清单，不是固定目录。文章只保留真正有教学价值的部分，可以改标题、调整顺序或合并相邻内容；不适用的部分直接省略，禁止为了结构齐全制造空洞章节。

1. **问题背景**：为什么要引入这个知识点，它解决什么困难。算法文章通常从直接或暴力解法的时间、空间或实现问题出发；语言和工具文章只需说明真实用途，不必虚构“暴力解法”。
2. **前置知识**：只在读者确实需要复习或跳转时，用自然语言说明理解正文所需的背景；不为计划中的文章维护编号化依赖。
3. **逐步解构与图示**：从读者已经理解的做法出发，逐步增加真正需要的结构。先让读者看见为什么需要区分或保存一个东西，再给它准确、稳定的中文名称和英文代码名；不得开头集中倾倒变量、数组和函数定义。手算、流程图或 SVG 只在能显著帮助理解状态变化时使用。
4. **示例代码**：把已经讨论清楚的方法逐块翻译成 C++17，每块代码对应一个明确步骤。不得在代码中突然加入正文没有出现的优化、状态或抽象。
5. **完整代码**：当本文得到一个可以独立运行或提交的程序、算法或数据结构实现时，在正文内完整复制，不用模板文件、其他笔记或外部链接代替。若知识点本来只有局部语法或接口，则提供足以说明它的最小完整示例，不强行拼成大程序。
6. **基础练习**：只选择使用本文及其直接或传递前置就能完成的题目。若一个短小的语法或接口主题没有值得单列的练习，可以省略；不得用尚未学习的技巧凑题单。
7. **扩展阅读**：只登记自然延伸但不属于基础版本的未来工作。没有合适内容时省略。著名不等于适合现在学习；扩展阅读不是下一课。
8. **需要记住什么**：每篇核心知识正文在末尾用自检问题指出当前真正需要掌握的内容，并明确哪些细节只需理解或能够查阅，不要求背诵。问题必须能够只依靠本文及其前置回答，不提供参考答案，也不能用新的术语考查正文没有教过的内容；读者答不上来时应返回对应章节复习。配套扩展篇根据用途明确掌握边界：课程或考试会涉及的内容同样设置自检问题；纯背景与查阅内容则明确说明不要求任何读者理解或记忆，不设置变相的必答问题。路线说明等不承担知识教学的文档可以省略。

正文可以在“需要记住什么”之后用“下一篇”链接 `LEARNING-PATH.md` 中的直接后继，帮助读者沿主线继续学习。“下一篇”与“扩展阅读”必须分开：前者属于当前教程路线，后者属于可选的未来工作；入门阶段没有合适扩展时不写扩展阅读。

相邻主线文章有直接承接关系时可以使用双向导航：前一篇的“下一篇”链接到后一篇，后一篇在开头明确链接回前一篇。正文若提到“上一篇”或“上一章”，必须把名称写明并链接，不依赖读者当前的阅读顺序猜测目标；不要为了导航伪造知识依赖，也不必增加重复的“上一篇”二级标题。

算法和数据结构文章通常需要完整覆盖背景、推导、正确性直觉、复杂度、关键边界、分块代码、完整实现和基础练习。C++ 语法、STL 接口、路线导读和短参考应按主题自然展开：给读者当前需要的用途、最小示例、语义、常用复杂度与陷阱即可，不套用算法文章的外形。常见错误和可操作的调试方法应紧邻相关内容出现。

代码继续遵守仓库约定：竞赛风 C++17；需要标准库、命名空间、`long long` 别名或输入输出时，分别使用 `#include <bits/stdc++.h>`、`using namespace std;`、`typedef long long ll;` 和 `scanf` / `printf`。第一次接触完整程序时可以使用更直观的 `cin` / `cout`，避免同时引入格式控制符；这不改变后续竞赛代码的默认约定。最小示例不添加没有被正文动机引出的固定行。代码命名应与解释保持一致。

教程正文和可复制的竞赛模板使用竞赛圈常见的简洁转换写法，不使用冗长的 `static_cast`。题面上限保证长度能放进 `int` 时，直接写 `int n = strlen(s);` 或 `int n = s.size();`；需要在整数除法前进入浮点运算时优先写 `1.0 * sum / count`，确实要明确目标类型时使用 `(int)x`、`(double)x` 等常见写法。验证程序等仓库内部工具不受此展示风格约束。

容量上限常量使用 `MAXN`、`MAXM` 等 `MAX` 前缀名称，实际输入规模使用小写 `n`、`m`，不得用单独的 `N` 同时表示容量和实际长度。竞赛代码中的十进制整数量级可以写成 `1e5 + 5`、`2e5 + 5`；派生容量优先直接表达关系，例如无向边的两条记录可写为 `const int MAXM = 2 * MAXN`，线段树数组可写为 `tree[4 * MAXN]`。

基础文章优先给出一个最常见实现。不要为了覆盖所有题型把模板抽象成复杂框架；题目特有胶水、罕见维护信息和高级优化应进入扩展专题、模板验证入口或工作区。

可复用的数据结构模板在没有性能或内存上的明确反例时，优先用 `struct` 封装状态，并用构造函数或 `init(n)` 按实际规模分配内部 `vector`；不要仅因传统模板常用全局静态数组，就把容量上限和内部状态泄漏到全局。动态容量统一保留 `+5` 的边界余量：树状数组分配 `n + 5` 个元素并使用 `1..n`，线段树分配 `4 * n + 5` 个节点并让根节点编号为 `1`，动态树结构保留节点 `0` 表示空节点。第 `0` 格的空状态具有实际语义，末尾其余余量只为保持模板习惯一致，不代表算法需要访问。全局静态数组仍可用于一次性题解、尚未学习 `vector` 的基础文章、必须避免调用栈大对象或能够证明它更合适的特殊实现；正文要说明选择原因。

是否使用 `struct` 取决于状态和操作是否构成一个对象，而不是知识点属于数据结构还是数学：若多个操作共同读写一份持续状态并维护同一组不变量，使用 `struct` 绑定状态与方法，避免污染全局命名空间，例如树状数组、线段树、并查集、平衡树和字符串哈希对象；若计算只依赖本次参数且没有跨调用状态，使用普通自由函数，例如 `gcd`、`exgcd`、快速幂、单次 CRT / exCRT 和素性判断。数学对象本身拥有值与封闭运算规则时仍可使用 `struct`，例如 `ModInt`、矩阵和多项式。不要为了形式统一把一组无状态函数塞进空壳对象，也不要让有状态数据结构依赖一组共享全局数组。

下标从 `0` 还是从 `1` 开始由对象的语义决定，不追求全书机械统一：

- `string`、普通 `vector` 序列和 CRT 中“第几条同余式”之类没有外部编号意义的列表，默认使用容器自然的 `0..n-1`；
- 题目把点、节点、数组位置编号为 `1..n` 时，图、树和对应算法默认保留题目编号，容器分配 `n + 1` 个元素；
- 树状数组、线段树和平衡树等以 `1` 为根或天然使用 1-based 公式的数据结构继续从 `1` 开始，节点 `0` 可以稳定表示空节点；不要为了节省一个元素改用容易参与非法下标访问的 `-1`；
- 题面位置与内部表示不一致时，在输入或输出边界集中转换并立即注明，不让同一个算法内部交替使用两套编号。字符串题的题面区间可能从 `1` 开始，但 `std::string` 和 KMP、Z 函数、后缀数组等字符串算法默认保持 0-based；需要时读入后执行一次 `--l`、`--r`。

使用内置定长数组时，大型对象通常放在全局作用域，避免占用调用栈；这是一种实现选择，不是全书模板的默认封装方式。函数需要接收动态序列并修改元素时使用 `vector<T>&`，只读时使用 `const vector<T>&`。`array<T, N>` 适合编译期定长的小型值对象以及需要标准容器接口的场景，不作为大型全局数组或运行期规模数据结构的普遍替代品。

## 引用与复用

- 下游文章不重复讲解已经稳定成文的基础，只做一句必要提醒并链接到对应小节。
- 正文可以引用已经存在的核心教程或扩展专题；引用只表达实际需要，不建立一套尚需持续维护的目录级依赖图。
- 允许从任意节点开始起草；提交正文前检查实际引用是否足以让目标读者继续阅读。
- 若 `已审阅` 或旧 `定稿` 文章需要实质修改，先检查下游引用；完成修改后标为 `待审阅` 并更新修订时间，等待用户再次审阅。

## SVG 图示

- 教程只引用 SVG，不创建或引用 PNG。
- 新图的 YAML 源保存在 `tools/diagrams/sources/<module>/`。
- 长期引用的 SVG 保存在 `notes/assets/<module>/`，并与 YAML 使用相同 basename。
- 已存在于 `tools/diagrams/examples/` 的正式示例可以继续作为对应 SVG 的来源。
- YAML 只描述结构与语义，不保存坐标、字体、线宽或具体色值。
- 提交前验证 YAML、重新渲染 SVG，并检查图片链接与文字可读性。

## 逐篇协作状态机

默认一次只主动推进一篇教程：

1. 从学习路线或模块目录选择一个节点。
2. Agent 起草正文、必要 YAML/SVG，并同步目录状态。
3. 运行 `make notes-check` 和相关代码/图示检查。
4. 只提交该文章、直接资产和必要导航变化，提交信息为 `notes: 起草……`。
5. 用户补充细节或提出问题；Agent 先解释，再按要求修订并使用 `notes: 修订……` 提交。
6. 只有用户明确表示已经完整审阅当前版本，才把状态改为 `已审阅`，把信息块括号改为“已审阅”，并使用 `notes: 标记……已审阅` 提交；最近修订时间保持不变。
7. 审阅不是冻结。文章以后仍可修订；发生实质修改时重新标为 `待审阅`。
8. 下游文章可以引用已经存在且内容足够稳定的具体章节，不要求前置文章拥有不可变的终态。

不得把其他已暂存或未跟踪的 notes 改动混入当前文章提交。提交前使用精确路径检查和提交；不执行破坏性 Git 操作清理用户工作区。

## 大纲维护

- 新知识点先进入 `CATALOG.md`，确定类型、路径和模块 ID。
- 核心教程随后插入 `LEARNING-PATH.md` 阶段 1–6 的大致教学位置；扩展专题只加入文末的“扩展阅读索引”。
- 学习路线目标是从 C++ 基础到约 Codeforces 2100 的高频、通用知识，不按单题 rating 机械裁切。
- 学习路线中的“C++ 基础”只表示从 C++ 视角理解程序所需的语言与机器背景，不冒充完整的计算机组成、体系结构或编译原理课程。
- 学习阶段不是模块隔离墙。阶段 2“算法基础”交错安排基础算法、基础数据结构和必要的标准库接口；栈、队列、二叉堆等直接对应抽象结构的接口，尽量紧跟在概念文章之后。
- 难度阶段固定使用“初中基础、初中进阶、高中基础、高中进阶”，不使用“经典中级算法”等边界不清的自造层级。
- 主学习路线只到阶段 6“高中进阶”。不适合归入高中竞赛一等奖常见主干的内容一律标记为扩展；扩展阅读可能明显超过这一范围，不暗示统一难度或严格先后顺序。
- `LEARNING-PATH.md` 的扩展阅读索引必须覆盖 `CATALOG.md` 中每个带 `*` 或 `e` 后缀的节点，先按模块、再按 ID 排列，使单个路线文件也能索引整个知识库。
- 数学、图论、数据结构等分支可以处于同一阶段；路线只维护明显合理的先后，不在正文完成前假装拥有精确拓扑序。
- 修改目录后必须运行 `make notes-check`。

# Notes 写作与协作规范

本文件约束 `notes/` 下教程正文、知识目录、学习路线和长期图片资产的维护方式。仓库根目录 `AGENTS.md` 的通用约束仍然生效；发生冲突时，以更具体且不违反根规则的本文件为准。

## 正文唯一，导航分离

- 每个知识点只有一份正文，保存在所属模块目录中。
- 每篇文章只回答一个足够小的主要问题；不得因为若干概念经常一起教就把它们合并成篇。
- 同一家族使用“主题：具体对象”命名，例如“复合类型：struct”和“有序关联容器：map”，保留关联但不共用正文。
- 知识点独立成篇的条件是：脱离父主题后，它仍有独立的学习目标、语义或模型、使用场景，并值得被下游单独引用。文章很短不是合并理由。
- 只为完成父主题而存在的语法或机制留在父文章中：`break` / `continue` 属于循环，比较器属于排序，迭代器由容器文章解释，函数的形参、实参和返回语法属于函数基础。
- 有依赖不等于应该合篇。例如比较运算产生布尔值，逻辑运算组合布尔值；两者前后依赖，但语义和操作集各自完整，因此分篇。
- `CATALOG.md` 是唯一的知识注册表，按模块列出核心教程与扩展专题。
- `LEARNING-PATH.md` 是核心教程的分阶段拓扑顺序，不收录扩展专题。
- 四位文章 ID 按模块编号，不表示学习顺序。大纲首次审核通过后保持稳定，不要为了调整路线而重命名正文。
- 计划中的知识点只登记路径，不创建空 Markdown 文件。

模块目录的每一行使用固定字段：

```text
ID | 知识点 | 状态 | 直接前置 | 文件
```

允许值：

- 无星号 ID 表示核心教程，ID 后的 `*` 表示扩展专题，例如 `0305*`。
- 状态：`计划`、`草稿`、`已固化`。
- 直接前置只列不可跳过的直接依赖，不传递抄写所有祖先。
- 没有前置时写 `—`；多个前置使用英文逗号分隔 ID。

## 核心与扩展的边界

核心教程解释一个知识点最常用、最基础、足以独立解决标准问题的版本，并说明代码每个组成部分为什么存在。

例如：

- 树状数组正文解释 `lowbit`、节点覆盖区间、`add` 与 `prefix_sum` 的跳转及区间和。
- 线段树正文解释递归划分、`4n` 空间、`build/pull/push`、基础查询修改和一种基础懒标记。
- 普通图正文展示结构本身的 value 与边关系，不把内部 id 当成教学重点。

以下内容通常独立为扩展专题：

- 为少见功能精密改造基础结构，例如树状数组维护区间最值。
- 需要额外技巧但不改变基础结构理解的操作，例如线段树二分。
- 复杂标记组合、可持久化、动态开点、Segment Tree Beats 等高级变体。
- 左偏堆、复杂平衡树、高级字符串结构等低频或超出主路线收益范围的内容。

扩展专题只进入模块目录。核心教程可以在文末的“扩展阅读”中链接它，但不能把它作为主线必学内容或核心教程的直接前置。

STL 教程只负责容器或固定任务的接口、常用复杂度和比赛所需的最少安全规则，不在同一篇推导底层数据结构。不设“STL 算法大全”、“比较器”或“迭代器”这种泛化主线文章：比较器放在排序文章中，迭代器由各容器文章在首次使用时解释。迭代器失效不单独成篇，也不罗列完整标准表；相关教程只需展示遍历中用 `it = container.erase(it)` 删除的安全模式，并提醒 `vector` 扩容后旧迭代器、指针和引用不能继续使用。二叉堆、哈希表等底层原理另放数据结构模块，且不是使用对应 STL 容器的直接前置。

## 文章信息块

新文章和第一次正式修订的遗留草稿，必须在一级标题后加入可见信息块：

```markdown
# 树状数组

> 状态：草稿
> 直接前置：[0207 前缀和与差分](../algorithm-basics/0207-prefix-sums-and-difference.md)、[0133 表达式：位运算符](../cpp/0133-bitwise-operators.md)
```

要求：

- 信息块的状态与直接前置必须与 `CATALOG.md` 一致；核心或扩展属性只在目录 ID 上标记。
- 正文文件只使用 `草稿` 或 `已固化`；`计划` 只存在于目录。
- 遗留草稿第一次正式修订时，从 `CATALOG.md` 顶部的迁移清单移除并补齐信息块。
- 已固化文章的二级标题视为稳定引用接口。重命名时检查并更新所有下游锚点链接。

## 核心文章完成标准

核心教程的正文固定使用以下七个二级标题，并按此顺序书写：

1. `问题背景`
2. `前置知识`
3. `一步一步解构`
4. `示例代码`
5. `完整代码`
6. `基础练习`
7. `扩展阅读`

各部分承担的职责如下：

1. **问题背景**：先说明为什么需要这个知识点。算法文章通常从直接或暴力解法遇到的时间、空间或实现困难出发；语言、工具和数据结构文章则说明它解决什么表达或维护问题。写清适用范围，但不要用尚未解释的术语预告整套结论。
2. **前置知识**：只列理解本文不可跳过的直接前置，并链接到对应教程。它必须与文章信息块和 `CATALOG.md` 一致；没有前置时明确写“无”。本节可以提醒读者本文会把哪些暂未学习的固定语法当作代码骨架，但不能借此偷偷增加前置。
3. **一步一步解构**：从最直接的方法开始，逐步暴露困难、增加结构并通过手算、流程图或 SVG 图示展示状态如何变化。名称必须在读者已经看见“为什么需要区分或保存这个东西”之后才引入：先解释职责，再给出一个准确、稳定的中文名称和对应英文代码名；不得开头集中罗列变量、数组或函数定义，也不得用一段成品代码代替推导。这里同时说明不变量、正确性直觉、复杂度、边界和不适用范围。
4. **示例代码**：把第三部分最终得到的方法逐块翻译成 C++17。第三部分每得到一个可以独立描述的步骤，这里就给出与之对应的一小块代码，并逐句说明其来源；代码中的名称必须与图示和正文一致。不要在本节突然加入推导中没有出现的优化、状态或抽象。
5. **完整代码**：在本文内完整复制一份可直接编译、运行或提交的基础实现，不以模板文件、其他笔记或外部代码链接代替。即使前一节已经出现全部片段，也必须在这里重新给出组合后的完整代码，方便读者复制和核对。
6. **基础练习**：只选择使用本文内容及其直接或传递前置就能完成的题目。练习不得暗中要求扩展技巧或路线中尚未学习的知识；必要时注明每题具体练习本文哪一个基本动作。常见错误和可操作的调试方法也放在这里，或者紧邻会触发它们的代码块说明。
7. **扩展阅读**：只登记从本文自然延伸但不属于基础版本的未来工作，并简述它额外解决什么问题。著名不等于适合现在学习，高级或低收益变体默认不展开，也不得伪装成“学完本文后的下一步”。当前阶段真正的下一篇始终由 `LEARNING-PATH.md` 决定，正文只链接学习路线，不另外复制一套后继顺序。

非算法文章仍使用同一结构，但允许把“暴力解法”替换为尚未引入该语言机制或工具时的实际困难；没有必要为了凑图而制造复杂插图，简单执行流或对象关系已经足够。某部分内容很短时也保留标题并直说结论，不与相邻部分合并。

一篇核心教程达到可固化状态时，除了结构完整，还必须具备：最基础版本的正确性直觉、时间空间复杂度（不适用时明确说明）、关键边界、常见错误与可执行的调试办法。

代码继续遵守仓库约定：竞赛风 C++17；需要标准库、命名空间、`long long` 别名或输入输出时，分别使用 `#include <bits/stdc++.h>`、`using namespace std;`、`typedef long long ll;` 和 `scanf` / `printf`。最小示例不添加没有被正文动机引出的固定行。代码命名应与解释保持一致。

基础文章优先给出一个最常见实现。不要为了覆盖所有题型把模板抽象成复杂框架；题目特有胶水、罕见维护信息和高级优化应进入扩展专题、模板验证入口或工作区。

## 引用与复用

- 下游文章不重复讲解已经固化的基础，只做一句必要提醒并链接到对应小节。
- 文章只能把核心教程作为必需前置；扩展专题之间可以互相依赖。
- 允许从任意节点开始起草，但文章固化前原则上应先固化全部直接前置。例外必须由用户明确批准。
- 若已固化文章需要实质修改，先恢复为草稿，检查下游引用，再重新修订和固化。

## SVG 图示

- 教程只引用 SVG，不创建或引用 PNG。
- 新图的 YAML 源保存在 `tools/diagrams/sources/<module>/`。
- 长期引用的 SVG 保存在 `notes/assets/<module>/`，并与 YAML 使用相同 basename。
- 已存在于 `tools/diagrams/examples/` 的正式示例可以继续作为对应 SVG 的来源。
- YAML 只描述结构与语义，不保存坐标、字体、线宽或具体色值。
- 提交前验证 YAML、重新渲染 SVG，并检查图片链接与文字可读性。

## 逐篇协作状态机

默认一次只主动推进一篇教程：

1. 从审核后的知识 DAG 选择一个节点。
2. Agent 起草正文、必要 YAML/SVG，并同步目录状态。
3. 运行 `make notes-check` 和相关代码/图示检查。
4. 只提交该文章、直接资产和必要导航变化，提交信息为 `notes: 起草……`。
5. 用户补充细节或提出问题；Agent 先解释，再按要求修订并使用 `notes: 修订……` 提交。
6. 只有用户明确确认后，才把状态改为 `已固化` 并使用 `notes: 固化……` 提交。
7. 下游文章随后可以稳定引用该文章的具体章节。

不得把其他已暂存或未跟踪的 notes 改动混入当前文章提交。提交前使用精确路径检查和提交；不执行破坏性 Git 操作清理用户工作区。

## 大纲维护

- 新知识点先进入 `CATALOG.md`，确定类型、直接前置、路径和模块 ID。
- 核心教程随后插入 `LEARNING-PATH.md` 的合法拓扑位置；扩展专题不得加入。
- 学习路线目标是从 C++ 基础到约 Codeforces 2100 的高频、通用知识，不按单题 rating 机械裁切。
- 数学、图论、数据结构等互不依赖的分支可以处于同一阶段；表内顺序仍必须满足直接前置先出现。
- 修改目录后必须运行 `make notes-check`。

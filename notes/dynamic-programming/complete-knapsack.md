# 背包：完全背包

> 最近修订：2026-08-13 22:39 +10:00（未审阅）

[背包：0-1 背包](zero-one-knapsack.md) 中每件物品至多选择一次。现在给出 `n` 种物品，第 `i` 种物品的单件重量为 `weight[i]`、单件价值为 `value[i]`，每种物品都有任意多件，可以选择 `0,1,2,...` 件。要求总重量不超过 `capacity`，并让总价值最大。

这种模型称为完全背包（complete knapsack，英文资料也常称 unbounded knapsack）。状态定义可以沿用 0-1 背包，但允许重复选择会改变转移读取的是上一行还是当前行，最终使一维容量循环从倒序变成正序。

## 枚举每种物品的件数

仍使用上一章的样例，背包容量为 `10`：

| 物品种类 `i` | 单件重量 `weight[i]` | 单件价值 `value[i]` |
| ---: | ---: | ---: |
| `1` | `6` | `30` |
| `2` | `3` | `14` |
| `3` | `4` | `16` |
| `4` | `2` | `9` |

0-1 背包中每一行只有选或不选两个分支。完全背包需要为第 `i` 种物品枚举件数 `k`：

```text
k = 0, 1, 2, ..., floor(c / weight[i])
```

选择 `k` 件以后，占用 `k * weight[i]` 容量，贡献 `k * value[i]` 价值。若直接枚举件数，二维转移是：

$$
dp[i][c]
=\max_{0\le k\cdot weight[i]\le c}
\left(dp[i-1][c-k\cdot weight[i]]+k\cdot value[i]\right).
$$

容量为 `capacity` 时，一种物品最多枚举 $O(capacity/weight[i])$ 个件数。最坏重量为 `1`，每个状态都可能枚举 $O(capacity)$ 次，总时间达到 $O(n\cdot capacity^2)$。

这个转移答案正确，可以作为小规模朴素算法；但相邻容量之间重复枚举了大量相同件数组合。

## 状态定义

继续定义：

$$
dp[i][c]=\text{只使用前 }i\text{ 种物品、总重量不超过 }c\text{ 时的最大总价值}.
$$

- `i` 表示允许使用的物品种类是 `1..i`；
- `c` 表示总重量上限是 `0..capacity`；
- 每种允许的物品可以使用任意非负件。

不使用任何物品种类时，只能选择空集合：

$$
dp[0][c]=0.
$$

本篇仍然表示“总重量不超过 `c`”，所有状态都能通过空集合达到，所以初始值全部为 `0`。

## 不选择当前种类

若第 `i` 种物品一件也不选，方案只使用前 `i - 1` 种物品，候选值与 0-1 背包相同：

$$
dp[i-1][c].
$$

## 至少选择一件

若最优方案至少选择一件第 `i` 种物品，先从方案中取出其中一件：

- 被取出的一件占用 `weight[i]`，贡献 `value[i]`；
- 剩余方案的容量上限是 `c - weight[i]`；
- 剩余方案仍然可以使用第 `i` 种物品，因为原方案可能选择了不止一件。

因此剩余部分不是 `dp[i - 1][c - weight[i]]`，而是：

$$
dp[i][c-weight[i]].
$$

把取出的一件加回来，至少选择一件的最大候选为：

$$
dp[i][c-weight[i]]+value[i].
$$

这一步把“枚举一共取多少件”改成了“取出一件，剩余相同种类交给更小容量状态处理”，从而消除件数循环。

## 二维转移

当 `weight[i] > c` 时，当前种类一件也装不下：

$$
dp[i][c]=dp[i-1][c].
$$

当 `weight[i] <= c` 时：

$$
dp[i][c]=\max\left(dp[i-1][c],\ dp[i][c-weight[i]]+value[i]\right).
$$

代码为：

```cpp
vector<vector<ll>> dp(n + 5, vector<ll>(capacity + 5, 0));

for (int i = 1; i <= n; i++) {
    for (int c = 0; c <= capacity; c++) {
        dp[i][c] = dp[i - 1][c];
        if (weight[i] <= c) {
            dp[i][c] = max(dp[i][c],
                           dp[i][c - weight[i]] + value[i]);
        }
    }
}
```

当前状态读取同一行的更小容量 `c - weight[i]`，所以容量必须从小到大计算。由于 `weight[i] > 0`，依赖下标严格减小，不会形成自我循环。

## 与 0-1 转移比较

两个模型只有选择当前物品时的来源行不同：

| 模型 | 选择当前物品后的剩余状态 | 原因 |
| --- | --- | --- |
| 0-1 背包 | `dp[i-1][c-weight[i]]` | 当前物品不能再次使用 |
| 完全背包 | `dp[i][c-weight[i]]` | 当前种类仍可继续使用 |

这个行号差异不是记忆口诀，而是“剩余问题还能使用哪些物品”的直接结果。

0-1 背包把所有副本看成只有一件；完全背包在取出一件后仍然拥有无限副本。先确定选择次数限制，才能决定转移应该来自哪一行。

## 填表过程

对于样例中的第一种物品 `(weight=6, value=30)`：

```text
dp[1][0..5] = 0
dp[1][6..10] = 30
```

容量最多为 `10`，还放不下两件重量 `6` 的物品，所以第一行与 0-1 背包相同。

处理第四种物品 `(weight=2, value=9)` 时，同一行可以连续复用它。例如：

```text
dp[4][2]  可以由 dp[4][0] + 9 得到
dp[4][4]  可以由 dp[4][2] + 9 得到
dp[4][6]  可以由 dp[4][4] + 9 得到
...
```

最终容量 `10` 的最优方案是选择一件第一种物品和两件第四种物品：

```text
总重量：6 + 2 + 2 = 10
总价值：30 + 9 + 9 = 48
```

因此完全背包答案为 `48`，高于同一输入在 0-1 背包中的答案 `46`。

## 一维压缩

与 0-1 背包相同，第 `i` 行只需要上一行和当前行已经完成的较小容量，可以复用一个一维数组：

$$
dp[c]=\text{当前已处理种类中，总重量不超过 }c\text{ 的最大价值}.
$$

更新式仍然是：

```cpp
dp[c] = max(dp[c], dp[c - weight[i]] + value[i]);
```

处理第 `i` 种物品以前，`dp[c]` 保存上一行，对应一件也不选。选择当前种类时，需要让 `dp[c - weight[i]]` 已经包含当前行的结果，才能继续使用它。

## 容量正序

对每种物品，从刚好能装下一件的容量开始，向上递增：

```cpp
for (int c = weight[i]; c <= capacity; c++) {
    dp[c] = max(dp[c], dp[c - weight[i]] + value[i]);
}
```

因为 `c - weight[i] < c`，处理 `c` 时，更小位置已经在本轮更新，代表允许使用前 `i` 种物品的当前行状态。随后再加一件第 `i` 种物品，就能得到任意件数。

仍以一件重量 `3`、价值 `5` 的物品种类和容量 `6` 为例：

```text
c = 3：dp[3] = dp[0] + 5 = 5
c = 6：dp[6] = dp[3] + 5 = 10
```

第二次读取的 `dp[3]` 已经包含一件当前物品，因此 `dp[6]` 正确表示选择两件。

## 倒序会发生什么

若容量从大到小枚举，计算 `dp[c]` 时，更小位置 `dp[c - weight[i]]` 还没有在本轮更新，仍然只允许使用前 `i - 1` 种物品。当前物品最多只能加入一次，代码就退化成 0-1 背包。

因此：

```text
0-1 背包：读取上一行 -> 容量倒序
完全背包：读取当前行 -> 容量正序
```

循环方向是状态依赖关系的实现，不应脱离二维转移机械背诵。

## 一维不变量

开始处理第 `i` 种物品以前，`dp[c]` 表示只使用前 `i - 1` 种物品、容量上限为 `c` 的最大价值。

正序处理某个容量 `c` 时：

- 当前 `dp[c]` 尚未在本轮更新，仍然表示不选择第 `i` 种物品；
- 更小的 `dp[c - weight[i]]` 已经在本轮更新，表示可以使用前 `i` 种物品；
- 在后者基础上再加一件当前物品，仍然是合法的完全背包方案。

二者取最大以后，`dp[c]` 成为允许使用前 `i` 种物品的正确答案。完成整轮正序更新后，一维数组等价于二维表的第 `i` 行。

## 函数接口

计算只依赖本次输入的物品种类和容量，没有跨调用状态，使用普通函数：

```cpp
ll complete_knapsack(const vector<int>& weight,
                     const vector<ll>& value,
                     int n,
                     int capacity)
```

物品种类使用 `1..n`，位置 `0` 留空；容量使用 `0..capacity`，其中 `0` 是真实边界状态。

## 完整代码

输入格式：

```text
n capacity
n 行 weight[i] value[i]
```

保证每种物品重量为正、价值非负，`n * capacity <= 2 * 10^7`，最终答案能使用 64 位整数保存。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

ll complete_knapsack(const vector<int>& weight,
                     const vector<ll>& value,
                     int n,
                     int capacity) {
    vector<ll> dp(capacity + 5, 0);

    for (int i = 1; i <= n; i++) {
        for (int c = weight[i]; c <= capacity; c++) {
            dp[c] = max(dp[c], dp[c - weight[i]] + value[i]);
        }
    }
    return dp[capacity];
}

int main() {
    int n, capacity;
    scanf("%d%d", &n, &capacity);

    vector<int> weight(n + 5);
    vector<ll> value(n + 5);
    for (int i = 1; i <= n; i++) {
        scanf("%d%lld", &weight[i], &value[i]);
    }

    printf("%lld\n",
           complete_knapsack(weight, value, n, capacity));
    return 0;
}
```

输入：

```text
4 10
6 30
3 14
4 16
2 9
```

输出：

```text
48
```

## 复杂度

优化后的二维转移和一维实现都让每种物品扫描一次容量，时间复杂度为 $O(n\cdot capacity)$。一维 `dp` 使用 $O(capacity)$ 额外空间，输入数组使用 $O(n)$ 空间。

直接枚举每种物品件数的朴素转移最坏需要 $O(n\cdot capacity^2)$；从当前行更小容量转移消除了这层件数枚举。

与 0-1 背包相同，这仍然是依赖容量数值的伪多项式算法。容量极大时，不能只因为公式写成两个循环就认为可行。

## 零重量物品

本篇要求 `weight[i] > 0`。若某种物品重量为 `0` 且价值为正，又允许选择任意多件，背包总重量不会增加，价值却能无限增长，问题没有有限最大值。

即使零重量物品价值为 `0`，转移也会依赖 `dp[c]` 自身，破坏“读取严格更小容量”的计算顺序。竞赛题通常直接保证重量为正；若没有保证，必须先单独处理零重量情况。

## 常见错误

### 沿用 0-1 背包的倒序

倒序让较小容量保持上一行，当前种类最多只能使用一次。完全背包必须正序，让较小容量先吸收当前种类。

### 直接保留件数循环

枚举 `k` 的转移正确，但多出一层与容量有关的循环。取出一件当前物品后，剩余问题仍允许使用当前种类，可以压缩成同一行转移。

### 选择当前物品时读取上一行

`dp[i - 1][c - weight[i]]` 排除了再次使用第 `i` 种物品，只能表达 0-1 选择。完全背包应读取当前行 `dp[i][...]`。

### 把正序当成孤立口诀

循环方向取决于更新时应读取旧行还是新行。题目限制变化以后，应重新从状态定义推导，不能只根据“背包”两个字套模板。

### 允许正价值零重量物品

这种物品可以无限选择，答案没有上界。普通有限 DP 数组无法表示“正无穷”。

## 基础练习

1. 手动填写样例的二维表，找出 `dp[4][10] = 48` 的转移过程。
2. 只有一种重量 `3`、价值 `5` 的物品，分别用正序和倒序计算容量 `0..9`。
3. 实现枚举件数的 $O(n\cdot capacity^2)$ 转移，与正序一维代码随机对拍。
4. 修改问题为必须恰好使用完容量，重新设计不可达状态和答案判断。
5. 给定硬币面额，每种硬币无限，求凑出总额的方案数；思考状态值与 `max` 应怎样改变。
6. 比较同一输入在 0-1 背包和完全背包中的答案，构造二者答案严格不同的最小例子。

## 需要记住什么

1. 完全背包与 0-1 背包对每种物品的选择次数分别有什么限制？
2. 直接枚举第 `i` 种物品件数时，转移怎样写？
3. 至少选择一件当前物品后，剩余状态为什么仍在第 `i` 行？
4. 二维完全背包为什么必须从小到大计算容量？
5. 压成一维以后，`dp[c]` 与 `dp[c-weight[i]]` 在更新前分别代表哪一行？
6. 正序怎样让当前物品能够重复使用？
7. 倒序为什么会把完全背包变回 0-1 背包？
8. 为什么物品重量必须为正？
9. 从件数枚举优化到同一行转移后，时间复杂度怎样变化？

本篇只处理每种物品数量无限、总重量不超过容量、最大总价值的基础模型。具体数量受到上限时，需要在下一篇多重背包中重新处理选择次数。

# 区间 DP

> 最近修订：2026-08-17 00:42 +10:00（未审阅）

有 `n` 堆石子排成一行，第 `i` 堆有 `a[i]` 颗石子。每次只能合并相邻的两堆，
代价等于这两堆石子的总数。不断合并，直到所有石子成为一堆，怎样让总代价最小？

例如三堆石子数量是：

```text
1 2 3
```

先合并前两堆，总代价是：

```text
(1 + 2) + (3 + 3) = 9
```

先合并后两堆，总代价是：

```text
(2 + 3) + (1 + 5) = 11
```

局部选择会改变后续石堆的大小，不能只看眼前代价。这个问题的子问题天然由一段
连续区间描述，适合使用区间动态规划。

## 为什么子问题必须是区间

因为每次只允许合并相邻石堆，任意时刻的一堆石子都对应原序列中的一段连续区间。
例如原来的第 `l..r` 堆最终合并成一堆以后，不会夹入区间外的石子。

因此定义：

$$
f[l][r]=\text{把原来的第 }l\text{ 到第 }r\text{ 堆合并成一堆的最小代价}.
$$

当 `l=r` 时，区间中本来就只有一堆，不需要执行任何合并：

$$
f[i][i]=0.
$$

## 从最后一次合并寻找决策

要把 `[l,r]` 最终合并成一堆，最后一次操作以前一定恰好剩下相邻的两堆。设它们
分别由原区间：

```text
[l, k] 和 [k + 1, r]
```

合并而来，其中 `l<=k<r`。

确定最后的分割点 `k` 后，总代价由三部分组成：

1. 把 `[l,k]` 合并成一堆的最小代价 `f[l][k]`；
2. 把 `[k+1,r]` 合并成一堆的最小代价 `f[k+1][r]`；
3. 最后把两堆合并，代价是区间 `[l,r]` 的石子总数 $S(l,r)$。

枚举所有可能的 `k`，取最小值：

$$
f[l][r]
=\min_{l\leq k<r}
\left(f[l][k]+f[k+1][r]+S(l,r)\right).
$$

这里的 `k` 是决策。使用“最后一次合并”推导，可以保证任何完整方案都有唯一的
最后分割点，不会遗漏；固定 `k` 后，左右两侧又是相同形式的更短区间问题。

## 用前缀和计算区间总数

每个状态会反复查询 `[l,r]` 的石子总数。定义前缀和：

$$
prefix[i]=a[1]+a[2]+\cdots+a[i].
$$

则：

$$
S(l,r)=prefix[r]-prefix[l-1].
$$

这样每次区间求和只需要 $O(1)$ 时间，不会在三层动态规划循环里面再扫描一遍区间。

## 阶段、状态与决策

这份动态规划的三个要素分别是：

| 要素 | 含义 |
| --- | --- |
| 阶段 | 区间长度 `len` |
| 状态 | 当前区间 `[l,r]` |
| 决策 | 最后一次合并的分割点 `k` |

代码虽然把结果保存在 `f[l][r]` 中，但不代表 `l` 是阶段、`r` 是状态。真正决定
计算顺序的是区间长度：一个长区间依赖分割出来的两个更短区间，所以必须按照
`len=1,2,...,n` 从短到长推进。

对固定长度 `len`，左端点与右端点的关系是：

```cpp
int r = l + len - 1;
```

为了让 `r<=n`，左端点范围是：

```cpp
1 <= l <= n - len + 1
```

## 填表顺序

长度为 `1` 的区间已经由 `f[i][i]=0` 初始化。之后枚举长度、左端点与分割点：

```cpp
for (int len = 2; len <= n; len++) {
    for (int l = 1; l + len - 1 <= n; l++) {
        int r = l + len - 1;
        f[l][r] = INF;

        for (int k = l; k < r; k++) {
            f[l][r] = min(
                f[l][r],
                f[l][k] + f[k + 1][r] + range_sum(l, r)
            );
        }
    }
}
```

每个候选中的 `[l,k]` 与 `[k+1,r]` 都比 `[l,r]` 短，所以在当前状态以前已经
计算完成。

## 一个四堆石子的例子

设石子数量是：

```text
4 1 3 2
```

先得到长度为 `2` 的状态：

```text
f[1][2] = 5
f[2][3] = 4
f[3][4] = 5
```

计算 `f[1][3]` 时有两个最后分割点：

```text
k = 1: f[1][1] + f[2][3] + 8 = 0 + 4 + 8 = 12
k = 2: f[1][2] + f[3][3] + 8 = 5 + 0 + 8 = 13
```

因此 `f[1][3]=12`。只有所有长度为 `2` 和 `3` 的状态完成后，才计算最终的
`f[1][4]`。

## 正确性

按照区间长度归纳证明 `f[l][r]` 符合定义。

长度为 `1` 时，区间已经是一堆石子，不需要合并，`f[i][i]=0` 正确。

假设所有长度小于 `len` 的状态都已经正确。考虑任意长度为 `len` 的区间
`[l,r]`。它的任意完整合并方案在最后一次操作前，必然由某个分割点 `k` 分成
`[l,k]` 与 `[k+1,r]` 两堆。根据归纳假设，两侧分别采用 `f[l][k]` 与
`f[k+1][r]` 就能取得各自最小代价；最后一次合并必然再付出整个区间的石子总数。

算法枚举所有可能的 `k`，因此包含最优方案的最后分割点；每个候选又都能由左右
两个合法方案和最后一次合并构造出来。取最小值后，`f[l][r]` 正是该区间的最小
合并代价。

依次完成所有长度后，`f[1][n]` 就是把全部石子合并成一堆的最小代价。

## 完整代码

输入第一行是 `n`，第二行是 `n` 堆石子的数量。保证 `1<=n<=500`，答案能用
64 位整数保存。

```cpp
#include <bits/stdc++.h>

using namespace std;

typedef long long ll;

const ll INF = LLONG_MAX / 4;

int n;
vector<ll> a;
vector<ll> prefix;
vector<vector<ll>> f;

ll range_sum(int l, int r) {
    return prefix[r] - prefix[l - 1];
}

int main() {
    scanf("%d", &n);

    a.assign(n + 5, 0);
    prefix.assign(n + 5, 0);
    f.assign(n + 5, vector<ll>(n + 5, 0));

    for (int i = 1; i <= n; i++) {
        scanf("%lld", &a[i]);
        prefix[i] = prefix[i - 1] + a[i];
    }

    for (int len = 2; len <= n; len++) {
        for (int l = 1; l + len - 1 <= n; l++) {
            int r = l + len - 1;
            f[l][r] = INF;

            for (int k = l; k < r; k++) {
                ll candidate = f[l][k] + f[k + 1][r]
                    + range_sum(l, r);
                f[l][r] = min(f[l][r], candidate);
            }
        }
    }

    printf("%lld\n", f[1][n]);
    return 0;
}
```

输入：

```text
4
4 1 3 2
```

输出：

```text
20
```

## 复杂度

区间数量是 $O(n^2)$，每个区间枚举 $O(n)$ 个分割点，因此时间复杂度是
$O(n^3)$。状态表占用 $O(n^2)$ 空间，前缀和占用 $O(n)$ 空间。

前缀和把每次区间求和从 $O(n)$ 降为 $O(1)$；否则总时间会继续增加到
$O(n^4)$。

## 常见错误

### 按左端点递增直接计算

`f[l][r]` 的依赖关系由区间长度决定。只按 `l` 或 `r` 的自然顺序填表，可能读取
尚未完成的短区间。

### 把合并代价写成两侧状态之和

`f[l][k]+f[k+1][r]` 只完成了左右两侧内部的合并。最后还要把两堆合并一次，必须
加上 `range_sum(l,r)`。

### 枚举 `k<=r`

分割点左侧是 `[l,k]`，右侧是 `[k+1,r]`。必须满足 `k<r`，否则右侧为空区间。

### 把 `f[i][i]` 初始化为石子数量

状态保存的是合并代价，不是区间石子总数。单独一堆无需操作，代价是 `0`。

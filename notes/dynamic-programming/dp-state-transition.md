# 动态规划的状态与转移

> 最近修订：2026-08-16 21:43 +10:00（未审阅）

有一段共 $n$ 级的楼梯。每一步只能向上走 $1$ 级或 $2$ 级，问从地面走到第 $n$ 级一共有多少种不同走法。

例如 $n=4$ 时共有五种：

```text
1 + 1 + 1 + 1
1 + 1 + 2
1 + 2 + 1
2 + 1 + 1
2 + 2
```

这是一道很小的问题，却完整包含动态规划最重要的组成部分：阶段、状态、决策、状态
转移、初始状态、计算顺序和答案位置。本篇先从暴力递归出发，观察它为什么重复
计算，再把相同子问题合并起来。

## 暴力递归

若当前还剩 `remaining` 级，可以选择走 $1$ 级或 $2$ 级。两种选择之后的问题分别变成：

```text
还剩 remaining - 1 级
还剩 remaining - 2 级
```

因此可以直接递归：

```cpp
ll count_ways(int remaining) {
    if (remaining == 0) {
        return 1;
    }
    if (remaining < 0) {
        return 0;
    }
    return count_ways(remaining - 1) + count_ways(remaining - 2);
}
```

`remaining == 0` 表示恰好走到终点，当前完整选择构成一种走法，所以返回 `1`。`remaining < 0` 表示最后一步越过终点，不是合法走法，所以返回 `0`。

两类走法的第一步不同，不会重复；所有合法走法的第一步又必定是 $1$ 或 $2$，不会遗漏。因此可以直接相加两个递归结果。

这份代码答案正确，却会非常慢。

## 重复子问题

以 `count_ways(5)` 为例，递归首先产生：

```text
count_ways(5)
├── count_ways(4)
│   ├── count_ways(3)
│   └── count_ways(2)
└── count_ways(3)
    ├── count_ways(2)
    └── count_ways(1)
```

`count_ways(3)` 在不同分支中出现多次，`count_ways(2)` 又在更深处反复出现。无论前面通过什么走法来到“还剩 3 级”，后续合法选择和答案都完全相同；重新展开同一棵子树没有产生新信息。

每次调用最多继续产生两个递归调用，递归深度为 $O(n)$，所以一个简单时间上界是 $O(2^n)$。而 `remaining` 实际只可能是：

```text
0, 1, 2, ..., n
```

也就是说，指数级递归调用反复计算的不同有效子问题只有 $n+1$ 个。

动态规划的关键不是“使用数组”，而是发现许多不同选择历史会形成同一个后续问题，并让这个问题只计算一次。

## 阶段

许多动态规划会按照问题规模或处理位置逐步推进。这个从小到大、从前到后的进度称为
阶段（stage）。

爬楼梯的第 `i` 个阶段表示“已经到达第 `i` 级”。阶段依次为：

```text
0, 1, 2, ..., n
```

以后处理数组或字符串时，第 `i` 个阶段经常表示“已经处理前 `i` 个元素”，也就是
已经完成一个长度为 `i` 的前缀。阶段先回答“问题推进到哪里”，并给出计算的大致
方向。

阶段不一定足以描述当前处境。同一个阶段可能存在多种会影响下一步选择的情况，
这时还需要状态。

## 状态

状态（state）必须保存同一阶段中足以决定后续选择的信息。对于当前爬楼梯规则，
只要知道已经到达第几级，前面每一步具体怎样走都不会改变之后的合法选择。因此
每个阶段只有一种需要保留的情况，不需要额外的状态维度。

定义：

$$
dp[i]=\text{从地面恰好到达第 }i\text{ 级的走法数量}.
$$

这里：

- `i` 是阶段，表示已经到达的位置；
- 当前阶段没有额外状态；
- `dp[i]` 是这个阶段唯一状态的值，表示到达该位置的走法数量。

不同历史只要到达同一个 `i`，之后都面对相同的楼梯。我们不再分别保存每一条历史，只把它们的数量合并在 `dp[i]` 中。

若题目额外规定“不能连续两次走 $2$ 级”，同样到达第 `i` 级时，后续能否再走
$2$ 级还取决于上一步的长度。此时 `i` 仍是阶段，而“上一步走了 $1$ 级还是
$2$ 级”成为额外状态；可以用 `dp[i][last_step]` 区分它们，不能强行沿用一个
`dp[i]`。

竞赛讲解中经常把完整下标 `i` 或整个 `dp[i][state]` 统称为“状态”。这种简称没有
问题；本篇把阶段和阶段内状态拆开，是为了在多维动态规划中看清每一维分别表达
推进位置还是影响后续选择的信息。

## 状态转移

在一个阶段中采取的选择称为决策（decision）。要到达第 `i` 级，最后一次决策只有
两种可能：

1. 从第 `i - 1` 级走 $1$ 级；
2. 从第 `i - 2` 级走 $2$ 级。

第一类有 `dp[i - 1]` 种，第二类有 `dp[i - 2]` 种。两类最后一步不同，所以互不重复；所有走法的最后一步又只能是 $1$ 或 $2$，所以没有遗漏。

因此，对于 `i >= 2`：

$$
dp[i]=dp[i-1]+dp[i-2].
$$

决策是一次具体选择；状态转移描述作出决策后怎样从前一状态到达后一状态。把所有
可能的最后决策分类并合并对应结果，就得到状态转移方程。推导时不能从数列外观猜
公式，而要回答三个问题：

1. 当前阶段有哪些可能的最后决策或下一步决策？
2. 每一类对应哪个更小状态？
3. 这些类别是否互不重复且覆盖全部答案？

状态定义决定数组中每个值的含义，转移方程决定这些值之间怎样产生。只写 `dp[i] = dp[i - 1] + dp[i - 2]` 而不先定义 `dp[i]`，公式没有可以验证的语义。

## 初始状态

转移不断依赖更小位置，必须有无需继续转移就能确定的初始状态。

到达第 $0$ 级表示仍在地面，什么也不走恰好是一种空走法：

$$
dp[0]=1.
$$

到达第 $1$ 级只能走一步 $1$ 级：

$$
dp[1]=1.
$$

`dp[0] = 1` 很容易被误写成 `0`。它不是说地面有一级台阶，而是在计数问题中表示“完成空前缀的一种方式”。若写成 `0`，计算 `dp[2]` 时就会漏掉直接从地面走 $2$ 级的方案：

$$
dp[2]=dp[1]+dp[0]=1+1=2.
$$

状态 `0` 有明确的边界语义，因此符合本书为自定义序列保留位置 `0` 的约定；真实楼梯仍编号为 `1..n`。

## 计算顺序

计算 `dp[i]` 以前，`dp[i - 1]` 与 `dp[i - 2]` 必须已经得到。依赖总是从较小下标指向较大下标，所以按照 `i = 2, 3, ..., n` 递增计算：

```cpp
vector<ll> dp(n + 5, 0);
dp[0] = 1;
if (n >= 1) {
    dp[1] = 1;
}

for (int i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
}
```

判断 `n >= 1` 是为了允许输入 `n = 0`。虽然 `vector` 已经保留额外容量，问题语义上仍然不应把不存在的第 $1$ 级当作必须计算的状态。

循环结束后，题目询问从地面到第 `n` 级的走法数，答案正是：

```cpp
dp[n]
```

不能把“最后计算的某个临时变量”默认当作答案；每道动态规划都应当根据状态定义明确答案位于哪个状态。

## 状态表

以 `n = 5` 为例，递增填表过程是：

| `i` | `dp[i - 2]` | `dp[i - 1]` | `dp[i]` |
| ---: | ---: | ---: | ---: |
| `0` | — | — | `1` |
| `1` | — | — | `1` |
| `2` | `1` | `1` | `2` |
| `3` | `1` | `2` | `3` |
| `4` | `2` | `3` | `5` |
| `5` | `3` | `5` | `8` |

数组不是为了保存“某次循环算出的随意中间结果”，而是显式保存每个已经定义的子问题答案。后面的状态只读取已经完成的前置状态，不会重新展开递归树。

## 记忆化搜索

也可以保留最初“还剩多少级”的递归方向，并用数组记住每个状态第一次算出的答案。这种写法称为记忆化搜索：

```cpp
vector<ll> memo;

ll count_ways(int remaining) {
    if (remaining == 0) {
        return 1;
    }
    if (remaining < 0) {
        return 0;
    }
    if (memo[remaining] != -1) {
        return memo[remaining];
    }

    memo[remaining] = count_ways(remaining - 1) + count_ways(remaining - 2);
    return memo[remaining];
}
```

第一次调用前，根据输入执行 `memo.assign(n + 5, -1)`。所有合法答案都非负，所以 `-1` 可以无歧义地表示“这个状态尚未计算”。第一次遇到 `remaining` 时递归求值并保存；以后再次遇到时直接返回缓存。

记忆化搜索按照真正被递归访问的顺序按需计算状态；递推表按照预先确定的依赖顺序主动计算状态。两者合并的是同一批重复子问题，时间复杂度都从指数级降到 $O(n)$。

本题的依赖顺序非常简单，递推没有递归调用栈，也无需使用未计算哨兵，所以完整代码采用递推。状态关系更复杂、并非所有状态都能到达时，记忆化搜索可能更自然。

## 动态规划的组成

从这道题可以归纳出写一份阶段式动态规划时需要回答的问题：

| 组成 | 本题答案 |
| --- | --- |
| 阶段 | `i` 表示已经到达第 `i` 级 |
| 阶段内状态 | 没有额外状态；到达同一级后的选择条件相同 |
| 状态值 | `dp[i]` 是恰好到达第 `i` 级的走法数 |
| 决策 | 最后一步走 $1$ 级或 $2$ 级 |
| 状态转移 | `dp[i] = dp[i - 1] + dp[i - 2]` |
| 初始状态 | `dp[0] = 1`，`dp[1] = 1` |
| 计算顺序 | 从小到大计算 `i = 2..n` |
| 最终答案 | `dp[n]` |

动态规划可以用于计数、可行性、最小值、最大值等不同目标，不等于“寻找最优答案”。
真正共同的结构是：问题按阶段推进；影响后续的历史被压缩成有限状态；决策把状态
连接起来；同一状态的答案只计算一次。

## 与分治和搜索比较

暴力搜索保留每一条选择分支，即使不同分支后来面对完全相同的子问题，也可能重新计算。

记忆化搜索仍然使用 DFS 生成状态，但同一个状态只展开一次。递推动态规划则先确定状态之间的依赖顺序，再直接填表。

分治也把大问题拆成小问题，但典型分治子问题彼此独立，例如归并排序的左半和右半；动态规划特别关心不同分支产生的子问题重叠。二者都可能使用递归，区别不在代码是否有 `dfs`，而在子问题关系。

## 正确性

证明 `dp[i]` 正确，可以对 `i` 递增归纳。

`dp[0] = 1` 对应唯一空走法，`dp[1] = 1` 对应唯一的一步走法，所以初始状态正确。

假设 `dp[i - 1]` 和 `dp[i - 2]` 已经分别正确统计到达两级位置的走法。任意一条到达第 `i` 级的走法，最后一步必定是：

- 从 `i - 1` 走 $1$ 级；或
- 从 `i - 2` 走 $2$ 级。

删除最后一步后，分别与两个前置状态中的一种走法一一对应。两类最后步长不同，因此不重不漏，`dp[i - 1] + dp[i - 2]` 正确统计 `dp[i]`。

按照递增顺序，每次计算新状态时两个前置状态都已正确，所以归纳得到 `dp[0..n]` 全部正确，最终输出 `dp[n]` 即为题目答案。

## 完整代码

输入 `0 <= n <= 91`。答案可以用 64 位整数保存：

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

int main() {
    int n;
    scanf("%d", &n);

    vector<ll> dp(n + 5, 0);
    dp[0] = 1;

    if (n >= 1) {
        dp[1] = 1;
    }

    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }

    printf("%lld\n", dp[n]);
    return 0;
}
```

输入：

```text
5
```

输出：

```text
8
```

`n = 91` 时答案为 `7540113804746346429`，仍在 64 位整数范围内；`n = 92` 时数学答案已经超出这个范围。算法复杂度没有变化，但保存答案的数据类型容量不再足够，需要题目给出取模要求或使用高精度整数。

## 复杂度

递推只计算 `dp[0..n]`，每个状态做一次加法，所以时间复杂度是 $O(n)$。`dp` 数组和 `+5` 容量余量共占用 $O(n)$ 空间。

本题每个状态只依赖前两个状态，确实可以只保存两个滚动变量，把额外空间降到 $O(1)$。但完整数组能直接展示状态定义、检查中间结果，并为后续需要恢复方案或依赖更多旧状态的问题保留统一结构。本篇优先把状态与转移写清楚，不提前做空间压缩。

## 常见错误

### 没有定义状态

先背出一个递推式，再猜数组每格是什么，很容易在“到达”“还剩”“前 `i` 个”等方向之间混淆。应先用完整句子定义 `dp[i]`，再根据定义推导公式。

### 把 `dp[0]` 设为零

计数问题中的空方案常常贡献 `1`。本题若令 `dp[0] = 0`，直接走 $2$ 级的方案无法进入 `dp[2]`，后续答案都会错误。

### 按错误顺序计算

`dp[i]` 依赖 `dp[i - 1]` 和 `dp[i - 2]`，必须先得到它们。从大到小循环会读取尚未计算的默认值。

### 状态缺少后续所需信息

能够到达同一位置不一定总能合并。若未来规则还取决于上一次选择、已经使用的资源或其他条件，这些信息也必须进入状态。

### 只写转移，不写答案位置

有些问题答案在 `dp[n]`，有些需要对多个终止状态取和、最小值或最大值。答案位置必须由状态定义和题目目标共同确定。

### 忽略数值溢出

动态规划可能在很短时间内计算出远超类型容量的计数。时间复杂度可行不代表数值一定能被 `long long` 保存。

## 基础练习

1. 手动列出 `dp[0..6]`，并用实际走法检查 `dp[4] = 5`。
2. 执行暴力递归 `count_ways(6)`，统计每个 `remaining` 被调用多少次；再加入 `memo` 比较。
3. 将允许步长改成 $1$ 或 $3$，重新定义初始状态并推导转移。
4. 将允许步长改成集合 `steps[1..k]`，写出枚举最后一步的通用转移。
5. 增加若干不能停留的台阶，令这些状态的走法数为 `0`，其余转移保持不变。
6. 修改题目为求到达第 `n` 级的最少步数，思考状态值、合并方式和不可达状态分别怎样改变。

## 需要记住什么

1. 暴力递归为什么会反复计算同一个子问题？
2. 阶段、阶段内状态、状态值和决策分别回答什么问题？
3. 为什么当前爬楼梯问题每个阶段只有一个状态？禁止连续两次走 $2$ 级后要增加
   什么状态信息？
4. `dp[i]` 的完整定义是什么？
5. 怎样按最后一步决策把所有到达 `i` 的走法分成不重不漏的两类？
6. 为什么 `dp[0] = 1` 而不是 `0`？
7. 状态依赖怎样决定计算顺序？
8. 记忆化搜索与递推分别在什么时候计算状态？
9. 一份动态规划需要明确哪些组成部分？
10. 为什么动态规划不只用于最优化问题？
11. 如何从状态定义确定最终答案的位置？

滚动数组只是减少空间的实现技巧；更复杂的状态设计、方案恢复、无后效性的严格讨论与各种具体 DP 模型会在后续文章中逐步出现。当前最重要的是先定义子问题，再从不重不漏的分类推导转移。

在 [线性动态规划](maximum-subarray-sum.md) 中，状态会沿输入序列推进，并用“恰好以当前位置
结尾”等限制补足转移所需的信息。

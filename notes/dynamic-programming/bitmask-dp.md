# 状态压缩 DP

> 最近修订：2026-08-17 08:05 +10:00（未审阅）

有些动态规划需要知道“哪些元素已经选择或访问”。直接把一个集合放进数组下标并不
可行；当元素数量较小时，可以用一个整数的二进制位表示集合，再把它作为状态。

这种方法称为状态压缩动态规划，常简称状压 DP。本篇以旅行商问题的小规模版本为例：
从点 `1` 出发，访问每个点恰好一次，最后回到点 `1`，求最小总权值。

## 用二进制位表示集合

有 `n` 个点时，用整数 `mask` 的第 `u-1` 位表示点 `u` 是否已经访问。

点编号仍使用 `1..n`；位编号遵循二进制的自然位置 `0..n-1`。两者只在下列接口
处转换：

```cpp
int bit = u - 1;
```

判断点 `u` 是否在集合中：

```cpp
(mask >> (u - 1)) & 1
```

把点 `u` 加入集合：

```cpp
int next_mask = mask | (1 << (u - 1));
```

全部点都已访问的集合是：

```cpp
int full_mask = (1 << n) - 1;
```

例如 `n=4` 时，`mask=1101₂` 表示点 `1、3、4` 已访问，点 `2` 未访问。

## 为什么只记录集合还不够

只知道已经访问的点集，无法确定下一步从哪里出发。访问同一集合但停在不同终点，
后续代价可能完全不同。

因此定义：

```cpp
f[mask][u]
```

表示：

- 已访问点集合恰好为 `mask`；
- 当前停在点 `u`；
- 从点 `1` 出发并满足上述条件的最小路径长度。

状态必须满足点 `u` 已经包含在 `mask` 中。

## 初始状态

开始时只访问了点 `1`，并停在点 `1`：

```cpp
int start_mask = 1 << 0;
f[start_mask][1] = 0;
```

其他状态初始化为 `INF`，表示尚未构造出合法访问顺序。

这里不把“回到起点”提前放入状态。先构造从起点出发、访问所有点的 Hamilton 路径，
最后再补一条回到点 `1` 的边。

## 加入一个未访问点

从状态 `f[mask][u]` 出发，枚举尚未访问的点 `v`。经过边 `u -> v` 后：

```cpp
int next_mask = mask | (1 << (v - 1));
f[next_mask][v] = min(
    f[next_mask][v],
    f[mask][u] + weight[u][v]
);
```

每次转移恰好增加一个点，所以状态依赖只从较小集合指向较大集合，不会形成循环。

按 `mask` 从小到大枚举是可行的：加入一个二进制位一定会让整数值增大，因此所有
前驱状态都会先被处理。

## 最后回到起点

当 `mask=full_mask` 时，所有点都已经访问。当前终点可能是任意 `u`，补上边
`u -> 1`：

$$
\text{answer}
=\min_{u=1}^{n}
\left\{
f[\text{full\_mask}][u]+w(u,1)
\right\}.
$$

代码为：

```cpp
ll answer = INF;
for (int u = 1; u <= n; u++) {
    answer = min(answer, f[full_mask][u] + weight[u][1]);
}
```

若要求从点 `1` 出发、访问全部点但不要求回来，就直接取
`min(f[full_mask][u])`。

## 一个小例子

设有三个点。初始状态：

```text
f[001][1] = 0
```

第一步可以走到点 `2` 或点 `3`：

```text
f[011][2] = weight[1][2]
f[101][3] = weight[1][3]
```

访问全部点并停在点 `3` 的状态，可以从停在点 `2` 的状态转移：

```text
f[111][3] = f[011][2] + weight[2][3]
```

也可能存在其他访问顺序到达同一状态，`min` 会保留最短的一条。状态把不同排列中
具有相同“已访问集合 + 当前终点”的后缀问题合并起来，避免完整枚举 `n!` 种顺序。

## 阶段、状态与决策

- **阶段**：已访问点数，即 `mask` 中 `1` 的数量；
- **状态**：已访问集合 `mask` 与当前终点 `u`；
- **决策**：下一步选择哪个未访问点 `v`。

代码不必显式按集合大小分层，因为加入新位会自然从小集合走向大集合；集合大小仍是
理解依赖顺序的阶段。

## 为什么仍然只能处理小规模

`n` 个元素共有 $2^n$ 个子集，每个集合还可能搭配 `n` 个终点，因此状态数量为：

$$
O(2^n n).
$$

每个状态再枚举下一个点，时间复杂度为：

$$
O(2^n n^2).
$$

它比 `n!` 好得多，但仍是指数算法。`n` 每增加 `1`，子集数量就翻倍。完整代码
限制 `n\le18`；能否放宽必须结合内存限制和时间限制重新估算。

## 下标与位运算边界

表达式 `1 << n` 使用 32 位整数。本文限制 `n\le18`，因此安全。若需要超过
`30` 位，应改用 `1LL << n`，但 $2^n$ 状态数量早已无法存储，通常没有实际意义。

位运算的括号要写清楚：

```cpp
if ((mask >> (u - 1)) & 1) {
    // u 已访问
}
```

不要把点编号 `u` 直接当位编号，否则会浪费最低位，并让全部状态公式错一位。

## 正确性

对已访问点数归纳。

初始状态只访问点 `1`，长度为零，正确。

假设所有包含 `k` 个点的可达状态都保存了相应最短路径。任意包含 `k+1` 个点、
终点为 `v` 的合法路径，在到达 `v` 前必然停在某个 `u`，并且此前访问集合为
`mask` 去掉点 `v`。这个前驱状态含 `k` 个点，根据归纳假设已经最优；算法会枚举
决策 `v` 并尝试这条最后边。

所有可能的前驱终点 `u` 都会被枚举，`min` 因而得到目标状态的最短路径。归纳到
全部点集合后，每种最后一个点都正确；再枚举回到起点的最后一条边，就得到最短
Hamilton 回路。

## 完整代码

程序读取 `n\le18` 的完整带权有向图邻接矩阵，求从点 `1` 出发、访问每个点恰好
一次并回到点 `1` 的最小总权值。

```cpp
#include <bits/stdc++.h>

using namespace std;

typedef long long ll;

const ll INF = 1LL << 62;

int n;
vector<vector<ll>> weight;
vector<vector<ll>> f;

ll solve() {
    int state_count = 1 << n;
    int full_mask = state_count - 1;

    f.assign(state_count, vector<ll>(n + 5, INF));
    f[1][1] = 0;

    for (int mask = 1; mask < state_count; mask++) {
        if ((mask & 1) == 0) {
            continue;
        }

        for (int u = 1; u <= n; u++) {
            if (((mask >> (u - 1)) & 1) == 0 ||
                f[mask][u] == INF) {
                continue;
            }

            for (int v = 1; v <= n; v++) {
                if ((mask >> (v - 1)) & 1) {
                    continue;
                }

                int next_mask = mask | (1 << (v - 1));
                f[next_mask][v] = min(
                    f[next_mask][v],
                    f[mask][u] + weight[u][v]
                );
            }
        }
    }

    ll answer = INF;
    for (int u = 1; u <= n; u++) {
        answer = min(
            answer,
            f[full_mask][u] + weight[u][1]
        );
    }
    return answer;
}

int main() {
    scanf("%d", &n);

    weight.assign(n + 5, vector<ll>(n + 5, 0));
    for (int u = 1; u <= n; u++) {
        for (int v = 1; v <= n; v++) {
            scanf("%lld", &weight[u][v]);
        }
    }

    printf("%lld\n", solve());
    return 0;
}
```

## 常见错误

### 状态没有记录当前终点

同一个访问集合停在不同点时，下一步代价不同，不能只用一维 `f[mask]`。

### 把点编号直接当位编号

点 `u` 对应第 `u-1` 位。点使用 1-based，二进制位从零开始。

### 忘记初始集合必须包含点 `1`

`f[0][1]` 不能表示“停在点 `1` 却没有访问它”。正确初始状态是 `f[1][1]`。

### 把指数算法用于过大的 `n`

优化常数不能改变 $2^n$ 的增长。写代码前必须先估算状态数与内存。

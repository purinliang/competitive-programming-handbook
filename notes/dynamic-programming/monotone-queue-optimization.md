# 单调队列优化

> 最近修订：2026-08-17 08:28 +10:00（未审阅）

有些动态规划的转移需要在一个滑动区间内取最大值或最小值：

$$
dp[i]=a[i]+\max_{i-k\le j<i}dp[j].
$$

若每个 `i` 都重新扫描最多 `k` 个前驱，时间复杂度是 $O(nk)$。当窗口从
`i` 移动到 `i+1` 时，大部分候选并没有改变；单调队列维护当前窗口中仍可能
成为最优值的候选，把总复杂度降为 $O(n)$。

## 问题：限制跳跃距离的最大得分

有 `n` 个位置，经过位置 `i` 获得 `a[i]` 分。必须从位置 `1` 出发，每次向右
跳 `1..k` 步，最终到达 `n`，求最大总得分。

定义：

$$
dp[i]=\text{到达位置 }i\text{ 的最大总得分}.
$$

初始状态：

$$
dp[1]=a[1].
$$

到达 `i` 的上一个位置 `j` 必须满足：

$$
i-k\le j<i.
$$

所以：

$$
dp[i]
=a[i]+\max_{i-k\le j<i}dp[j].
$$

阶段是当前到达位置 `i`；决策是选择窗口内哪个 `j` 作为前驱。

## 朴素转移的重复工作

对位置 `i`，候选窗口是：

```text
[i-k, i-1]
```

下一位置 `i+1` 的候选窗口是：

```text
[i-k+1, i]
```

只有两处变化：

- 最左端旧下标可能过期；
- 新计算的下标 `i` 进入窗口。

其余候选完全相同。重新扫描整个窗口浪费了大量工作。

## 队列保存下标

使用双端队列 `que` 保存候选下标，并维持：

```text
dp[que[0]] > dp[que[1]] > ... > dp[que.back()]
```

队首始终是当前窗口内 `dp` 最大的下标。

保存下标而不是只保存数值，是因为需要同时知道：

- 候选值 `dp[j]`；
- 候选是否已经落到窗口左端以外。

## 删除过期下标

计算 `dp[i]` 前，合法下标至少为 `i-k`。队首若更小，就已过期：

```cpp
while (!que.empty() && que.front() < i - k) {
    que.pop_front();
}
```

过期只可能从队首发生，因为下标按照加入时间递增。

删除完成后，队首就是合法窗口内最大 `dp`：

```cpp
dp[i] = a[i] + dp[que.front()];
```

## 删除被支配候选

新状态 `i` 进入队列前，若队尾 `j` 满足：

```cpp
dp[j] <= dp[i]
```

那么 `j` 以后永远不会成为最优候选：

- `dp[i]` 不小于 `dp[j]`；
- `i > j`，所以 `i` 比 `j` 更晚过期。

`i` 在数值和有效期限两方面都不差，`j` 被完全支配，可以删除：

```cpp
while (!que.empty() &&
       dp[que.back()] <= dp[i]) {
    que.pop_back();
}
que.push_back(i);
```

删除所有不优队尾后，队列中的 `dp` 值保持严格递减。

## 一次迭代的顺序

对 `i = 2..n`：

1. 从队首删除下标小于 `i-k` 的过期候选；
2. 用当前队首计算 `dp[i]`；
3. 从队尾删除 `dp` 不大于 `dp[i]` 的候选；
4. 把下标 `i` 加入队尾。

必须先删除过期元素，再读取队首。也必须先计算 `dp[i]`，才能用它支配旧候选。

初始时只有位置 `1` 已经计算：

```cpp
deque<int> que;
que.push_back(1);
```

## 为什么总复杂度是线性

每个下标：

- 只从队尾加入一次；
- 最多从队首因过期删除一次，或从队尾因被支配删除一次；
- 一旦删除就不会重新加入。

虽然代码中有两个 `while`，全部下标的入队和出队次数合计仍为 $O(n)$。这是均摊
分析，与单调栈和凸包构造中的弹出过程相同。

## 最小值版本

若转移需要窗口最小值：

$$
dp[i]=a[i]+\min dp[j],
$$

队列应维护 `dp` 递增。加入新状态时删除：

```cpp
dp[que.back()] >= dp[i]
```

窗口过期规则不变。单调方向由“要取最大还是最小”决定。

## 完整代码

保证 `1 <= k < n`，所有 `a[i]` 和答案都在 64 位整数范围内。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

int n, k;
vector<ll> a;
vector<ll> dp;

ll maximum_score() {
    deque<int> que;
    dp.assign(n + 5, 0);

    dp[1] = a[1];
    que.push_back(1);

    for (int i = 2; i <= n; i++) {
        while (!que.empty() &&
               que.front() < i - k) {
            que.pop_front();
        }

        dp[i] = a[i] + dp[que.front()];

        while (!que.empty() &&
               dp[que.back()] <= dp[i]) {
            que.pop_back();
        }
        que.push_back(i);
    }

    return dp[n];
}

void solve() {
    cin >> n >> k;

    a.assign(n + 5, 0);
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
    }

    cout << maximum_score() << '\n';
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    solve();
    return 0;
}
```

本题保证每个位置都可达，因此删除过期元素后队列不会为空。更一般的转移若允许
某些状态不可达，读取队首前必须检查队列，并为不可达状态使用无歧义的负无穷。

## 复杂度

- 每个下标入队一次、出队至多一次；
- 时间复杂度：$O(n)$；
- `dp` 与队列空间复杂度：$O(n)$。

若只需要最终答案，`dp` 仍需保留队列中候选下标对应的值；也可以让队列直接保存
`(index,value)`，但保存统一的 `dp` 数组更容易核对状态定义。

## 常见错误

- 队列只保存 `dp` 数值，无法判断下标是否过期；
- 计算 `dp[i]` 前没有先删除过期队首；
- 最大值转移却维护递增队列；
- 新状态加入时从队首删除被支配值，而不是从队尾；
- 只比较数值，没有利用新下标更晚过期的优势；
- 窗口边界 `[i-k,i-1]` 写错一位；
- 把嵌套 `while` 误判为 $O(n^2)$；
- 队列可能为空的题目中直接访问 `front()`。

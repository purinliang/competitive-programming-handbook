# 概率与期望 DP

> 最近修订：2026-08-17 08:17 +10:00（未审阅）

随机过程中的下一步不是由我们选择最优决策，而是按照给定概率进入不同状态。
虽然单次结果不确定，大量可能过程的成功概率与期望代价仍能由状态转移精确描述。

概率与期望 DP 的关键仍是：

- 阶段：过程推进到哪里；
- 状态：哪些信息决定未来概率分布；
- 转移：下一步以什么概率进入哪些状态；
- 边界：成功、失败或结束状态的值是什么。

不同之处是合并后继时使用概率加权，而不是取最大值、最小值或简单计数。

## 概率状态

设 `probability[u]` 表示从状态 `u` 出发最终成功的概率。若下一步以 `p_i`
进入状态 `v_i`：

$$
probability[u]
=\sum_i p_i\cdot probability[v_i].
$$

这是全概率公式：按照互斥的下一步结果分类，再把每类发生概率乘以后续成功概率。

终止状态通常定义：

```text
成功状态：probability = 1
失败状态：probability = 0
```

若所有后继已经计算，就能反向得到当前状态。

## 期望状态

设 `expectation[u]` 表示从状态 `u` 到过程结束还需要的期望代价。

若转移到 `v_i` 的概率为 `p_i`，这一步本身付出 `cost_i`：

$$
expectation[u]
=\sum_i p_i
\bigl(cost_i+expectation[v_i]\bigr).
$$

每种结果中，总代价都分成：

```text
当前一步代价 + 到达后继以后的期望代价
```

再按照结果概率加权。

若每一步代价恒为 `1`，并且下一步概率总和为 `1`：

$$
expectation[u]
=1+\sum_i p_i expectation[v_i].
$$

公式中的 `1` 很容易漏掉。`expectation[v_i]` 只描述下一状态以后的代价，不含
当前已经执行的一步。

## 例子：掷骰子走到终点

棋盘位置为 `0..n`，从 `0` 开始。每次掷一个有 `sides` 个面的公平骰子，点数
为 `1..sides`，向前移动对应步数；到达或越过 `n` 时结束。

定义：

$$
dp[i]=\text{从位置 }i\text{ 到结束还需掷骰子的期望次数}.
$$

终点：

$$
dp[n]=0.
$$

从位置 `i<n` 出发，当前必定先掷一次。每个点数概率都是
$1/sides$，下一位置为：

$$
\min(n,i+roll).
$$

所以：

$$
dp[i]
=1+\frac{1}{sides}
\sum_{roll=1}^{sides}
dp[\min(n,i+roll)].
$$

## 阶段、状态与决策

这道题没有由选手控制的“决策”，但仍有随机结果分支。

- 阶段：当前位置离终点的进度；
- 状态：位置 `i`；
- 随机结果：骰子点数 `roll`；
- 转移概率：每种点数均为 `1/sides`；
- 状态值：到终点的期望剩余次数；
- 边界：`dp[n]=0`。

所有后继位置都比 `i` 大，因此依赖从右向左：

```cpp
for (int i = n - 1; i >= 0; i--) {
    // 计算 dp[i]
}
```

计算顺序来自依赖关系，不是因为期望 DP 固定要倒序。

## 为什么直接平均后继期望

假设骰子有两个面。从位置 `i`：

```text
一半概率进入 i+1
一半概率进入 i+2
```

长期重复实验中，约一半过程承担第一种后续代价，另一半承担第二种。平均剩余代价
就是：

$$
\frac{dp[i+1]+dp[i+2]}{2}.
$$

再加当前必掷的一次。这里不要求每次过程都恰好等于期望；期望是所有随机结果的
概率加权平均。

## 出现自环时

若状态 `u` 有概率 `p` 仍然回到自己，直接转移可能出现：

$$
E[u]
=p(1+E[u])
+\sum_i p_i(1+E[v_i]).
$$

右侧含有 `E[u]`，不能把它当作已经计算的后继值。移项：

$$
(1-p)E[u]
=p+\sum_i p_i(1+E[v_i]).
$$

再除以 `1-p`。

更复杂的环可能形成多元线性方程组。概率过程有环时，不能因为写出了递归公式就
直接按照普通 DAG DP 填表；必须检查依赖是否能代数消元、是否需要高斯消元，以
及过程是否几乎必然终止。

若有正概率永远无法结束，某些期望可能是无穷大。

## 完整代码

输入终点 `n` 和公平骰子面数 `sides`，输出从位置 `0` 到达或越过终点的期望
投掷次数。

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
int sides;
vector<double> dp;

void solve() {
    cin >> n >> sides;

    dp.assign(n + 5, 0.0);
    dp[n] = 0.0;

    for (int i = n - 1; i >= 0; i--) {
        double next_expectation = 0.0;

        for (int roll = 1; roll <= sides; roll++) {
            int next = min(n, i + roll);
            next_expectation += dp[next];
        }

        dp[i] =
            1.0 + next_expectation / sides;
    }

    cout << fixed << setprecision(10);
    cout << dp[0] << '\n';
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    solve();
    return 0;
}
```

## 复杂度

- 状态数：$n+1$；
- 每个非终止状态枚举 `sides` 个骰子结果；
- 时间复杂度：$O(n\cdot sides)$；
- 空间复杂度：$O(n)$。

若骰子面数很大，可以进一步用滑动窗口和维护后继期望之和，将转移优化为 $O(n)$；
那属于区间转移优化，不改变本篇期望方程。

## 常见错误

- 期望转移只平均 `dp[next]`，忘记当前一步代价；
- 把概率相加公式与期望代价公式混在一起；
- 不按照转移概率加权，直接平均概率不相等的后继；
- 终止状态仍增加一步，写成 `dp[n]=1`；
- 后继依赖更大下标，却从小到大填表；
- 出现 `E[u]` 自环时仍直接读取未求出的自身；
- 没有检查随机过程是否能够以概率 `1` 结束；
- 使用整数除法计算概率。

## 需要记住什么

- 最终成功概率怎样按下一步结果分类转移？
- 期望转移中的“当前代价”和“后继期望”分别是什么？
- 公平骰子问题为什么从 `n-1` 向 `0` 计算？
- 自环导致方程右侧出现 `E[u]` 时应怎样处理？
- 为什么“有转移公式”不代表带环过程能直接按普通 DP 填表？

# 最长公共子序列

> 最近修订：2026-08-16 16:43 +10:00（未审阅）

[最长上升子序列](longest-increasing-subsequence.md) 已经说明，子序列可以删除任意元素，但必须保留剩余元素的原有顺序。本篇同时给出两个字符串，寻找它们共同拥有的最长子序列，并由此建立最基础的二维前缀动态规划。

## 问题

给定两个字符串 `s` 与 `t`，最长公共子序列（Longest Common Subsequence，LCS）是同时为二者子序列、并且长度最大的字符串。

例如：

```text
s = abcde
t = ace
```

从 `s` 中删除 `b,d`，从 `t` 中什么也不删除，都能得到 `ace`，所以它是长度为 `3` 的公共子序列。这个例子中不存在更长答案，因此 LCS 长度是 `3`。

公共子序列不要求字符连续。`ace` 在 `abcde` 中不是子串，却仍然是子序列。若要求公共字符必须连续，问题就变成最长公共子串，需要另一种状态转移。

LCS 也可能不唯一。例如 `abc` 与 `bac` 的最长公共子序列既可以是 `ac`，也可以是 `bc`；只求长度时不必区分它们，恢复方案时输出任意一种即可。

## 暴力枚举

长度为 `n` 的字符串共有 $2^n$ 个子序列。可以枚举 `s` 的所有子序列，再检查它是否也是 `t` 的子序列，并保留最长者。

即使暂时忽略检查时间，仅枚举子序列就需要 $O(2^n)$。若同时枚举两个字符串的子序列，候选数量还会达到 $O(2^{n+m})$。

大量不同选择会面对相同的后续问题。例如，在两个字符串中都已经处理完若干前缀以后，未来能够怎样匹配，只取决于两个前缀的边界，不需要记住此前具体跳过了哪些字符。

因此，可以按照两个字符串已经处理到的位置合并重复子问题。

## 前缀状态

令 `s[1..i]` 表示 `s` 的前 `i` 个字符，`t[1..j]` 表示 `t` 的前 `j` 个字符。定义：

$$
dp[i][j]=\text{字符串 }s[1..i]\text{ 与 }t[1..j]\text{ 的 LCS 长度}.
$$

这里：

- `i` 表示第一个字符串已经纳入问题的前缀长度；
- `j` 表示第二个字符串已经纳入问题的前缀长度；
- `dp[i][j]` 合并了得到这两个前缀的所有选择历史。

只保存一个下标不够。增加 `s` 的字符和增加 `t` 的字符都会改变可匹配范围，必须同时知道两个前缀的边界。

这个状态没有规定答案必须选择 `s[i]` 或 `t[j]`。它保存的是两个完整前缀中的全局最好答案，状态转移需要讨论末尾字符是否被使用。

## 末尾字符相同

若：

```text
s[i] == t[j]
```

可以先求 `s[1..i-1]` 与 `t[1..j-1]` 的 LCS，再在末尾同时接上这个相同字符：

$$
dp[i][j]=dp[i-1][j-1]+1.
$$

例如：

```text
s[1..4] = abca
t[1..3] = bda
```

两个末尾字符都是 `a`。前缀 `abc` 与 `bd` 的 LCS 可以取 `b`，接上共同末尾字符以后得到 `ba`。

为什么不需要再考虑跳过这个相同字符？两个前缀的任意公共子序列，删除至多一个末尾字符后，都能放入更短的两个前缀中，所以它的长度不可能超过 `dp[i - 1][j - 1] + 1`；而接上共同末尾字符已经能达到这个上界。因此必定存在一种最优答案使用这两个末尾字符。

代码是：

```cpp
if (s[i] == t[j]) {
    dp[i][j] = dp[i - 1][j - 1] + 1;
}
```

## 末尾字符不同

若：

```text
s[i] != t[j]
```

一条公共子序列不可能同时把两个不同字符作为自己的最后一个字符。因此，任何答案至少跳过其中一个：

- 跳过 `s[i]`，问题变为 `s[1..i-1]` 与 `t[1..j]`；
- 跳过 `t[j]`，问题变为 `s[1..i]` 与 `t[1..j-1]`。

两种情况分别由 `dp[i - 1][j]` 与 `dp[i][j - 1]` 保存，选择较大值：

$$
dp[i][j]=\max\bigl(dp[i-1][j],\ dp[i][j-1]\bigr).
$$

```cpp
else {
    dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
}
```

这两类可能包含同一个公共子序列，但这里只保存最大长度，不把候选数量相加，所以重复覆盖不会造成重复计数。

## 空前缀

任意字符串与空字符串都没有可选择的公共字符，所以：

$$
dp[0][j]=0,
\qquad
dp[i][0]=0.
$$

位置 `0` 在这里表示长度为 `0` 的空前缀，不是第一个真实字符。二维状态表初始化为 `0` 后，这两条边界自然已经成立：

```cpp
dp.assign(n + 5, vector<int>(m + 5, 0));
```

当 `s[1] == t[1]` 时，转移读取 `dp[0][0] + 1`，正确得到长度 `1`。空前缀提供了递推边界，不需要为第一行和第一列分别编写特殊转移。

## 计算顺序

每个 `dp[i][j]` 只依赖：

```text
dp[i - 1][j - 1]  左上方
dp[i - 1][j]      上方
dp[i][j - 1]      左方
```

因此可以让 `i` 从 `1` 增加到 `n`，并在每一行让 `j` 从 `1` 增加到 `m`：

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= m; j++) {
        if (s[i] == t[j]) {
            dp[i][j] = dp[i - 1][j - 1] + 1;
        } else {
            dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
        }
    }
}
```

计算当前格子以前，它的左上方、上方和左方都已经完成。交换两层循环同样能满足这些依赖，但不能让两个下标都从大到小计算尚未得到的状态。

两个完整字符串分别是 `s[1..n]` 与 `t[1..m]`，所以最终长度直接位于：

```cpp
dp[n][m]
```

## 填表过程

对 `s = abcde`、`t = ace`，表格的行对应 `s` 的前缀，列对应 `t` 的前缀：

| `dp[i][j]` | 空 | `a` | `c` | `e` |
| --- | ---: | ---: | ---: | ---: |
| 空 | `0` | `0` | `0` | `0` |
| `a` | `0` | `1` | `1` | `1` |
| `b` | `0` | `1` | `1` | `1` |
| `c` | `0` | `1` | `2` | `2` |
| `d` | `0` | `1` | `2` | `2` |
| `e` | `0` | `1` | `2` | `3` |

例如 `s[3] == t[2] == 'c'`，所以：

$$
dp[3][2]=dp[2][1]+1=2.
$$

位置 `(4, 2)` 比较的是 `d` 与 `c`，二者不同，于是从上方和左方选择较大值，仍为 `2`。最后的 `dp[5][3] = 3` 对应公共子序列 `ace`。

## 恢复一种方案

状态表只直接保存长度。要恢复一种实际 LCS，可以从 `(n, m)` 沿产生当前值的前置状态反向移动。

若 `s[i] == t[j]`，当前状态可以由左上方接上这个字符得到。记录字符，并同时减小两个下标：

```cpp
if (s[i] == t[j]) {
    answer.push_back(s[i]);
    i--;
    j--;
}
```

若末尾字符不同，沿数值较大的前置状态移动：

```cpp
else if (dp[i - 1][j] >= dp[i][j - 1]) {
    i--;
} else {
    j--;
}
```

两边相等时选择哪一边都能保留最优长度。本篇固定优先向上移动，使同一输入得到稳定输出。

反向移动时先遇到答案中靠后的字符，所以最后需要反转：

```cpp
reverse(answer.begin(), answer.end());
```

`answer` 是原生 `string`，这里直接使用标准库的 0-based 迭代器半开区间；其中保存的字符顺序与自定义 `s[1..n]`、`t[1..m]` 的位置约定并不冲突。

## 字符串下标转换

C++ 的 `string` 原生使用 0-based 下标，本书自定义字符串算法使用 1-based 字符位置。输入以后先保存真实长度，再在开头补一个不参与匹配的占位字符：

```cpp
cin >> s >> t;

n = s.size();
m = t.size();

s = " " + s;
t = " " + t;
```

此后 `s[1..n]` 与 `t[1..m]` 是真实字符，位置 `0` 只作占位。补完占位字符后，`string.size()` 已经比真实长度多 `1`，不能再用它重算 `n,m`。

## 题目共享状态

两个字符串、真实长度和状态表由输入、填表与方案恢复共同使用，因此保存为题目级全局状态：

```cpp
int n, m;
string s, t;
vector<vector<int>> dp;
```

`solve` 每次读入以后使用 `assign` 重新分配并清空 `dp`，不会保留上一次调用的状态。恢复过程使用局部的 `i,j`，因为它们只描述当前沿状态表移动到的位置。

## 正确性

按照 `i,j` 递增证明每个 `dp[i][j]` 都符合定义。

当 `i = 0` 或 `j = 0` 时，至少一个字符串为空，不存在非空公共子序列，所以边界值 `0` 正确。

假设当前状态依赖的左上方、上方和左方状态都已经正确。

- 若 `s[i] == t[j]`，在两个更短前缀的 LCS 后接上共同末尾字符，得到长度 `dp[i - 1][j - 1] + 1` 的公共子序列；任何公共子序列的长度又都不会超过这个值，所以转移正确。
- 若 `s[i] != t[j]`，任意公共子序列至少不使用两个末尾字符中的一个。两类候选分别被 `dp[i - 1][j]` 与 `dp[i][j - 1]` 覆盖，取最大值恰好得到当前答案。

按照依赖顺序完成整个表以后，`dp[n][m]` 正确表示两个完整字符串的 LCS 长度。

恢复时，相同字符的左上移动会为答案增加一个真实公共字符；末尾字符不同时，算法只移动到具有相同最优值的前置状态，不会降低仍可恢复的答案长度。下标每次至少减小一个，最终到达空前缀。反转记录的字符后，得到顺序正确、长度等于 `dp[n][m]` 的一种公共子序列。

## 完整代码

输入两个只含小写英文字母的非空字符串，保证 `1 <= n,m <= 3000`。程序输出 LCS 长度和任意一种实际方案：

```cpp
#include <bits/stdc++.h>
using namespace std;

int n, m;
string s, t;
vector<vector<int>> dp;

void solve() {
    cin >> s >> t;

    n = s.size();
    m = t.size();
    s = " " + s;
    t = " " + t;

    dp.assign(n + 5, vector<int>(m + 5, 0));

    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (s[i] == t[j]) {
                dp[i][j] = dp[i - 1][j - 1] + 1;
            } else {
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
    }

    string answer;
    int i = n;
    int j = m;

    while (i >= 1 && j >= 1) {
        if (s[i] == t[j]) {
            answer.push_back(s[i]);
            i--;
            j--;
        } else if (dp[i - 1][j] >= dp[i][j - 1]) {
            i--;
        } else {
            j--;
        }
    }

    reverse(answer.begin(), answer.end());

    cout << dp[n][m] << '\n';
    cout << answer << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
abcde
ace
```

输出：

```text
3
ace
```

若两个字符串没有相同字符，第一行输出 `0`，第二行输出空行。

## 复杂度

状态表共有 `(n + 1)(m + 1)` 个有效格子，每个格子只进行常数次比较和加法，因此时间复杂度是 $O(nm)$，空间复杂度是 $O(nm)$。

恢复过程每次至少让 `i` 或 `j` 减少 `1`，最多移动 `n + m` 次，时间复杂度是 $O(n+m)$；它不会改变总体复杂度。

若只求长度，可以使用滚动数组把空间降到 $O(m)$。但恢复方案需要知道反向移动经过的状态；本篇保留完整二维表，使状态定义、转移和恢复路径直接对应。

## 常见错误

### 把子序列当成子串

LCS 允许跳过字符，只保留相对顺序。要求字符连续的是最长公共子串，两者的状态定义与转移不同。

### 只使用一个前缀下标

两个字符串都在变化，只知道 `s` 的处理位置无法确定 `t` 中还能使用哪些字符。状态必须同时包含 `i,j`。

### 末尾字符不同时同时减小两个下标

不同字符只说明它们不能同时作为公共子序列末尾，不代表两个都必须丢弃。应比较跳过其中一个的两个状态。

### 把两个候选相加

`dp[i][j]` 保存最长长度，不是方案数量。末尾字符不同时应取 `max`，不能把两个前缀答案相加。

### 忘记空前缀边界

第一行和第一列的 `0` 表示与空字符串的 LCS 长度。它们让第一个真实字符能够直接读取左上方、上方或左方状态。

### 恢复以后忘记反转

从 `(n, m)` 反向行走时先遇到 LCS 的最后一个字符，记录结果与正确顺序相反。

### 补占位字符后重新读取长度

真实长度必须在添加占位字符以前保存。否则循环会把占位后的额外长度也当成真实字符范围。

## 基础练习

1. 手算 `abc` 与 `bac` 的完整状态表，并分别找出 `ac` 与 `bc` 两种最优方案对应的恢复路径。
2. 对两个完全相同的字符串运行程序，说明状态表对角线为什么连续增加。
3. 对两个没有相同字符的字符串运行程序，检查长度和空行输出。
4. 修改恢复时的平局规则，观察同一状态表怎样输出不同的 LCS。
5. 只保留两行状态，将空间降到 $O(m)$；说明为什么这份表不能直接沿原方法恢复方案。
6. 修改问题为判断一个字符串是否为另一个字符串的子序列，并思考是否仍需要完整的二维动态规划。

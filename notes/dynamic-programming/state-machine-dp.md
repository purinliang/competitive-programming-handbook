# 动态规划：状态机 DP

> 最近修订：2026-08-13 22:51 +10:00（未审阅）

有些线性问题处理到同一个位置时，未来允许的操作仍取决于当前处境。例如股票交易中，持有股票时可以卖出却不能再次买入；没有持股时可以买入却不能卖出。

若只用“已经处理到第几天”作为状态，就会把未来操作集合不同的历史错误合并。状态机 DP 在每个输入位置额外区分若干种互斥状态，并只沿题目允许的状态变化进行转移。

本篇用最基础的股票交易模型推导两个状态、不可达初始化、逐日转移和最终状态选择。

## 股票交易

已知一只股票连续 `n` 天的价格 `price[1..n]`。初始没有股票，每天最多执行以下一种操作：

- 没有持股时，可以按当天价格买入一股；
- 持有一股时，可以按当天价格卖出；
- 也可以什么都不做。

任何时候最多持有一股，可以进行任意多次完整的买卖，但第 `n` 天结束时必须不持股。求最终最大利润。

程序把初始现金净额记为 `0`。买入时减去价格，允许净额暂时为负，不额外设置本金限制；卖出时加回价格。持有状态中的股票市值不计入现金，只有卖出后才实现利润。

例如价格为：

```text
7 1 5 3 6 4
```

可以在价格 `1` 时买入、`5` 时卖出，得到 `4`；再在 `3` 时买入、`6` 时卖出，得到 `3`，总利润为 `7`。

## 暴力搜索

每天根据是否持股都有两个选择：保持当前状态，或执行一次合法交易。直接递归会形成一棵深度为 `n`、每层最多两个分支的搜索树，时间上界为 $O(2^n)$。

不同交易历史可能在同一天结束后都处于“持有”状态。例如一个历史已经完成过一次盈利交易后再次买入，另一个历史刚完成第一次买入。它们过去的操作不同，但未来都只能继续持有或卖出。

若两个历史到达同一天、同一种持股状态，并且其中一个现金净额更高，那么未来执行任何相同操作后，它都会继续不差于另一个历史。较低现金的历史不可能产生更优最终答案，可以丢弃。

因此每一天、每种持股状态只需要保留最大现金净额，不必保存完整交易序列。

## 两个互斥状态

定义：

$$
not\_holding[i]
=\text{第 }i\text{ 天结束后不持股时的最大现金净额},
$$

$$
holding[i]
=\text{第 }i\text{ 天结束后持有一股时的最大现金净额}.
$$

同一条交易历史在一天结束时不可能同时持有和不持有股票，所以两个状态互斥。但算法需要同时保留它们，因为第二天允许的操作不同。

状态之间允许的变化是：

```text
not_holding --不操作----------> not_holding
not_holding --买入，减 price[i]-> holding
holding     --不操作----------> holding
holding     --卖出，加 price[i]-> not_holding
```

没有“未持有时卖出”或“持有时再次买入”的边，因为这些操作违反题目限制。状态机 DP 的转移只能来自真实允许的状态变化。

## 第零天

在任何价格出现以前，初始现金为 `0` 且没有持股：

$$
not\_holding[0]=0.
$$

第零天不可能已经持有股票。需要给这个不可达状态一个不会被 `max` 误选的极小值：

```cpp
const ll NEG_INF = -(1LL << 60);
holding[0] = NEG_INF;
```

不能把 `holding[0]` 初始化为 `0`。否则第一天可以从这个虚构的免费股票执行卖出，凭空得到 `price[1]` 的利润。

在本文约束下，任何真实现金净额的绝对值都远小于 $2^{60}$，所以 `NEG_INF` 不会与合法结果混淆；加上一个价格也不会溢出 64 位整数。

## 未持有状态的转移

第 `i` 天结束后不持股，只可能来自两种情况。

### 前一天也不持股

当天什么都不做，现金不变：

$$
not\_holding[i-1].
$$

### 前一天持股

当天按 `price[i]` 卖出，现金增加当天价格：

$$
holding[i-1]+price[i].
$$

取两种来源的较大值：

$$
not\_holding[i]
=\max\left(not\_holding[i-1],\ holding[i-1]+price[i]\right).
$$

## 持有状态的转移

第 `i` 天结束后持有一股，也只有两种来源。

### 前一天已经持股

当天什么都不做，现金不变：

$$
holding[i-1].
$$

### 前一天不持股

当天买入一股，现金减少当天价格：

$$
not\_holding[i-1]-price[i].
$$

因此：

$$
holding[i]
=\max\left(holding[i-1],\ not\_holding[i-1]-price[i]\right).
$$

两条转移都只读取第 `i - 1` 天，表示每天最多执行一次交易。买入和卖出不会在同一天通过刚更新的状态连续发生。

## 逐日填表

对价格：

```text
7 1 5 3 6 4
```

状态变化为：

| 天数 `i` | `price[i]` | `not_holding[i]` | `holding[i]` |
| ---: | ---: | ---: | ---: |
| `0` | — | `0` | 不可达 |
| `1` | `7` | `0` | `-7` |
| `2` | `1` | `0` | `-1` |
| `3` | `5` | `4` | `-1` |
| `4` | `3` | `4` | `1` |
| `5` | `6` | `7` | `1` |
| `6` | `4` | `7` | `3` |

`holding[4] = 1` 表示此前已经实现利润 `4`，再以价格 `3` 买入一股后，现金净额还剩 `1`。它不是说股票本身只值 `1`，也没有把持有股票的市值加入现金。

最后一天的 `holding[6] = 3` 来自在利润 `7` 后又以价格 `4` 买入，但这股股票尚未卖出，不符合结束时必须空仓的要求。

## 最终答案

题目要求第 `n` 天结束后不持股，所以答案是：

```cpp
not_holding[n]
```

不能机械地对两个状态取最大值。每个动态规划的答案位置由题目的终止条件决定；若结束时持有的资产也按照某种价格计入结果，状态定义和答案选择都会改变。

当 `n = 0` 时没有交易日，`not_holding[0] = 0` 正好表示什么都不做的利润为 `0`。

## 正确性

对天数 `i` 归纳证明两个状态都符合定义。

第零天只有“不持股、现金为零”可达，持有状态不可达，所以初始状态正确。

假设第 `i - 1` 天的两个状态已经分别保存对应持股状态下的最大现金。任意一条第 `i` 天结束后不持股的合法交易历史，当天要么保持未持有，要么从持有状态卖出；两类正是 `not_holding[i]` 的两个候选。任意一条结束后持股的历史，当天要么继续持有，要么从未持有状态买入；两类正是 `holding[i]` 的两个候选。

每类候选都来自合法前置状态并执行合法操作，所以不会产生非法历史；所有可能的最后操作又全部被列出，所以不会遗漏。取最大值后，两个新状态都正确。

归纳到第 `n` 天，`not_holding[n]` 就是所有合法空仓结束历史中的最大现金净额，也就是最大利润。

## 完整代码

输入第一行是天数 `n`，第二行是 `n` 个非负价格。保证 `0 <= n <= 2 * 10^5`、每个价格不超过 `10^9`。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

const ll NEG_INF = -(1LL << 60);

int main() {
    int n;
    scanf("%d", &n);

    vector<ll> price(n + 5);
    for (int i = 1; i <= n; i++) {
        scanf("%lld", &price[i]);
    }

    vector<ll> not_holding(n + 5, NEG_INF);
    vector<ll> holding(n + 5, NEG_INF);
    not_holding[0] = 0;

    for (int i = 1; i <= n; i++) {
        not_holding[i] = max(not_holding[i - 1],
                             holding[i - 1] + price[i]);
        holding[i] = max(holding[i - 1],
                         not_holding[i - 1] - price[i]);
    }

    printf("%lld\n", not_holding[n]);
    return 0;
}
```

输入：

```text
6
7 1 5 3 6 4
```

输出：

```text
7
```

## 为什么保留完整状态表

两个状态都只依赖前一天，确实可以用四个变量保存“旧的未持有、旧的持有、新的未持有、新的持有”，把额外空间降到 $O(1)$。

但若直接原地更新：

```cpp
not_holding = max(not_holding, holding + price[i]);
holding = max(holding, not_holding - price[i]);
```

第二行读取的 `not_holding` 已经可能是第 `i` 天卖出后的新值，不再严格对应本文“每天至多一次交易”的上一天状态。即使在当前无手续费模型中同日卖出再买入不改变最终数值，这种代码也破坏了转移语义，加入手续费、冷却期或其他限制后更容易出错。

本篇保留两条完整数组，让所有右侧都明确来自第 `i - 1` 天。需要压缩时也应先把旧状态保存到临时变量，再同时计算新状态。

## 复杂度

每天计算两个状态，每个状态只比较两个候选，所以时间复杂度是 $O(n)$。价格和两条状态数组共使用 $O(n)$ 空间。

只保留前一天状态可以把 DP 额外空间降到 $O(1)$，但不会改变时间复杂度。

## 与贪心方法

在本文“无限次交易、无手续费、无冷却期”的特定规则下，也可以把所有相邻上涨的差值相加得到答案。但这种贪心结论依赖当前规则。

状态机 DP 直接表达允许的持股状态和操作。加入手续费、冷却期、最多交易次数等限制时，可以增加状态或修改转移，而不是重新猜测一条贪心规律。本篇选择股票问题，是为了学习状态机建模，不是声称它只能用动态规划解决。

## 常见错误

### 只按天数定义状态

同一天结束时，持有与未持有状态允许的下一步不同，不能合并成一个最大利润。

### 把不可达状态初始化为零

`holding[0] = 0` 相当于初始免费拥有一股股票，第一天就能凭空卖出获利。不可达的最大值状态必须使用足够小的哨兵。

### 买入时增加现金

买入支付 `price[i]`，所以从未持有转向持有时应减去价格；卖出才增加价格。

### 从错误的前置状态交易

买入只能来自未持有，卖出只能来自持有。转移以前应先列出状态之间允许的边。

### 原地更新后读取新状态

若压缩空间，不能让第二个状态无意读取第一个刚更新的当天结果。先保存全部旧状态，再计算新状态。

### 最后对所有状态取最大值

题目要求空仓结束，答案只能来自 `not_holding[n]`。持有状态中的股票还没有变回现金。

## 基础练习

1. 手动填写价格 `5 4 3 2 1` 的两个状态，解释为什么最终利润为 `0`。
2. 画出未持有和持有两个状态以及四条允许的转移边。
3. 写出暴力 DFS，枚举每天保持或交易，与状态机 DP 随机对拍。
4. 加入每次卖出收取固定手续费的规则，判断手续费应当放在哪一条转移上。
5. 加入卖出后第二天不能买入的冷却期，思考为什么需要增加一个状态。
6. 限制最多完成一次买卖，设计“是否已经完成交易”的额外状态。
7. 使用四个滚动变量压缩空间，保证所有新状态都只读取保存好的旧状态。

## 需要记住什么

1. 为什么只知道处理到第几天不足以合并所有交易历史？
2. `not_holding[i]` 和 `holding[i]` 的完整含义分别是什么？
3. 两个状态之间有哪些合法转移，分别怎样改变现金？
4. `holding[0]` 为什么不可达？错误初始化为 `0` 会产生什么非法操作？
5. 为什么较低现金的同日同状态历史可以丢弃？
6. 两条转移为什么都只读取第 `i - 1` 天？
7. 为什么最终答案只能取未持有状态？
8. 空间压缩时为什么要先保存全部旧状态？
9. 什么样的问题适合在同一位置设置多个互斥状态？

状态机 DP 没有固定的状态数量。状态应当恰好保存未来合法操作所需的信息；过少会错误合并历史，过多则会制造无用复杂度。

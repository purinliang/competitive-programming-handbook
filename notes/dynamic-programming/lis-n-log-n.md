# 最长上升子序列：$O(n\log n)$ 优化

> 最近修订：2026-08-17 02:28 +10:00（未审阅）

基础 LIS 定义 `dp[i]` 为恰好以位置 `i` 结尾的最长长度，并枚举所有更早位置，
时间复杂度是 $O(n^2)$。若只需要最长长度，可以换一种状态：不再区分具体结束位置，
而是对每个可能长度只保留“最容易继续延伸”的结尾值。

## 相同长度只需保留更小结尾

假设当前已经得到两条长度都是 `len` 的严格上升子序列，它们的结尾分别是 `5`
和 `8`。

任何能够接在 `8` 后面的新值都大于 `8`，因此也一定能接在 `5` 后面；有些介于
`5` 与 `8` 之间的值只能接在 `5` 后面。

所以在长度相同时，较小结尾不会失去任何未来选择，反而至少同样容易延伸。只需保存
最小结尾值。

## 状态定义

依次处理原序列前缀，定义：

$$
tail[len]=\text{当前前缀中，长度恰好为 }len\text{ 的严格上升子序列的最小结尾值}.
$$

若当前已知的最长长度为 `length`，有效状态是 `tail[1..length]`。

这些状态值严格递增：任意长度为 `len` 的严格上升子序列，删除最后一个元素后会
得到长度为 `len-1` 的严格上升子序列，后者结尾小于前者；而 `tail[len-1]` 又是
所有较短结尾中的最小值，所以：

$$
tail[len-1]<tail[len].
$$

正因为 `tail` 有序，才能使用二分查找。

## 新元素应该放在哪里

处理新值 `x` 时，寻找第一个满足：

```text
tail[position] >= x
```

的位置。

### 找到了位置

若 `position>1`，前一项满足：

```text
tail[position - 1] < x
```

因此 `x` 可以接在某条长度为 `position-1` 的上升子序列后面，形成长度为
`position` 的上升子序列。

把：

```cpp
tail[position] = x;
```

不会降低已知长度，只是让这一长度的最小结尾变得更小或保持不变，为后续留下更多
可能。

### 没有找到位置

若所有已有结尾都小于 `x`，那么 `x` 可以接在当前最长子序列后面，产生新长度：

```cpp
length++;
tail[length] = x;
```

## 为什么使用 lower_bound

C++ 的 `lower_bound` 寻找第一个不小于 `x` 的位置：

```cpp
int position = lower_bound(
    tail.begin() + 1,
    tail.begin() + length + 1,
    x
) - tail.begin();
```

本篇要求严格递增。遇到与某个结尾相等的 `x` 时，必须替换该位置，不能把长度增加。
所以使用第一个 `>=x` 的 `lower_bound`。

若题目要求最长非递减子序列，相等值可以接在后面，应改用寻找第一个 `>x` 的
`upper_bound`。两者的差别来自状态语义，不是可以随意互换的写法。

`tail` 是本书自定义状态，逻辑位置使用 `1..length`；传给 STL 的迭代器区间仍按
原生左闭右开规则写成 `[begin()+1,begin()+length+1)`。

## 填表过程

对序列：

```text
3 1 2 5 4 7
```

处理过程是：

| 新值 | 更新后的 `tail[1..length]` | 说明 |
| ---: | --- | --- |
| `3` | `3` | 新增长度 1 |
| `1` | `1` | 长度 1 的结尾变小 |
| `2` | `1 2` | 接在 1 后面 |
| `5` | `1 2 5` | 新增长度 3 |
| `4` | `1 2 4` | 长度 3 的结尾由 5 改成 4 |
| `7` | `1 2 4 7` | 新增长度 4 |

最终 `length=4`。

`tail` 的每个位置都对应某条真实上升子序列，但更新后的整行数值不一定共同来自同一
条原序列路径。它是为求最长长度压缩出的状态表，不应直接当作恢复出的 LIS 输出。

## 正确性

归纳维护两个不变量：

1. 对每个 `1<=len<=length`，`tail[len]` 是当前前缀中长度为 `len` 的上升
   子序列最小结尾；
2. `tail[1..length]` 严格递增。

处理 `x` 时，设 `position` 是第一个 `tail[position]>=x` 的位置。

若位置存在，`position=1` 时单独选择 `x` 就能形成长度 1；`position>1` 时，由
二分位置可知 `tail[position-1]<x`，所以能形成长度为 `position`、结尾为 `x`
的合法上升子序列。更短位置的结尾小于 `x`，无需改变；更长位置若存在，则原值
严格大于等于当前位置旧值，也不可能被 `x` 直接改成更长的合法状态。把当前位置
改成 `x` 正好得到新的最小结尾，并继续保持严格递增。

若位置不存在，所有已有结尾都小于 `x`，所以 `x` 能把当前最长子序列延长一位；
又不存在比 `length+1` 更长的旧状态，因此新增长度恰好正确。

归纳结束后，有效状态的最大下标 `length` 就是最长严格上升子序列长度。

## 完整代码

```cpp
#include <bits/stdc++.h>

using namespace std;

typedef long long ll;

int n;
vector<ll> a;
vector<ll> tail;

int main() {
    scanf("%d", &n);

    a.assign(n + 5, 0);
    tail.assign(n + 5, 0);
    for (int i = 1; i <= n; i++) {
        scanf("%lld", &a[i]);
    }

    int length = 0;
    for (int i = 1; i <= n; i++) {
        int position = lower_bound(
            tail.begin() + 1,
            tail.begin() + length + 1,
            a[i]
        ) - tail.begin();

        tail[position] = a[i];
        if (position > length) {
            length = position;
        }
    }

    printf("%d\n", length);
    return 0;
}
```

输入：

```text
6
3 1 2 5 4 7
```

输出：

```text
4
```

## 复杂度

每个元素在长度至多为 `n` 的有序 `tail` 中做一次二分查找，时间复杂度是
$O(n\log n)$，状态数组使用 $O(n)$ 空间。

基础 $O(n^2)$ DP 更直接地保留结束位置和前驱，容易恢复具体方案；本篇状态压缩
更快，但若要恢复方案，还需额外记录每个元素被放入的长度、对应前驱位置以及各长度
当前结尾来自哪个原数组位置。

## 常见错误

### 把 tail 直接输出成答案

不同位置可能在不同时间被替换，整行 `tail` 不保证来自同一条原序列路径。它只保证
每个长度分别存在某个最小结尾。

### 严格上升使用 upper_bound

`upper_bound` 会把相等值放到已有相等结尾以后，使相等元素增加长度，求成非递减
子序列。

### 把替换理解成删除已有答案

替换较大结尾不会让这一长度消失；新值本身已经构成同长度方案，而且更容易被未来
元素延伸。

### 二分包含未初始化位置

只搜索逻辑有效区间 `tail[1..length]`，对应迭代器右端是
`tail.begin()+length+1`。

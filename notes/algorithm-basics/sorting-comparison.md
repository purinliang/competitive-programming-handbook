# 排序方法比较

> 最近修订：2026-08-16 11:50 +10:00（未审阅）

排序方法不能只按一个时间复杂度判断好坏。输入规模、原有顺序、值域、额外内存、
稳定性和数据的存储方式都可能改变选择。

前面分别推导了冒泡、选择、插入、计数、快速与归并排序。本篇不再增加一套模板，
而是把这些方法放在同一套口径中比较，并回答实际比赛中应当使用哪一种。

## 比较口径

阅读排序算法的复杂度表时，至少要分清以下问题：

- 最好、平均和最坏时间是否不同；
- 空间写的是额外空间，还是连输入本身也算在内；
- 是否原地修改输入；
- 是否保持相等关键字记录的原相对顺序；
- 成本是否依赖整数值域；
- 算法需要随机访问，还是只需顺序向前读取。

“平均”还需要一个输入分布假设，不等于“多数时候大概如此”。本篇只在快速排序
的经典平均分析中使用它；提交题目时仍要关注最坏情况是否可能被构造。

## 基础方法总表

以下结论对应本书前面给出的具体实现：

| 方法 | 最好时间 | 平均时间 | 最坏时间 | 额外空间 | 稳定 |
| --- | ---: | ---: | ---: | ---: | --- |
| 冒泡排序（提前结束） | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 是 |
| 选择排序 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 否 |
| 插入排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 是 |
| 计数排序（整数频次重建） | $O(n+k)$ | $O(n+k)$ | $O(n+k)$ | $O(k)$ | 不适用于记录稳定性 |
| 快速排序（原地 Hoare 分区） | $O(n\log n)$ | $O(n\log n)$ | $O(n^2)$ | 平均 $O(\log n)$ | 否 |
| 归并排序（数组） | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | 是 |

其中 $k=\text{max\_value}-\text{min\_value}+1$。快速排序的额外空间来自递归
调用栈；极端不均衡时会达到 $O(n)$，表中列的是平均情况。

“原地”通常表示除递归栈等少量辅助状态外，不建立与输入规模同阶的新元素存储。
本书会把递归栈单独计入额外空间，因此快速排序不能简单写成“空间永远是 $O(1)$”。

## 比较排序与值域排序

冒泡、选择、插入、快速、归并以及 `std::sort` 都通过元素之间的比较获得顺序，
属于比较排序。若只允许比较任意两个元素，对所有可能排列进行通用排序，最坏情况
需要至少 $\Omega(n\log n)$ 次比较。

这不与插入排序的最好 $O(n)$ 冲突：下界讨论的是所有输入中的最坏情况，不要求每个
输入都花费 $n\log n$。也不与计数排序的 $O(n+k)$ 冲突：计数排序利用了整数值能
直接映射到计数位置的额外信息，并非只靠元素比较。

计数排序只有在 $k$ 足够小时才有优势。值域稀疏或非常大时，哪怕元素数量很少，
$O(k)$ 的扫描和内存也可能远比 $O(n\log n)$ 更差。

## 稳定性属于具体实现

稳定排序要求关键字相等的记录保持原来的相对顺序。它是记录排序中的性质；只观察
一串相等整数，无法看出它们是否交换过身份。

本书采用以下准确结论：

- 冒泡排序只交换严格逆序的相邻元素，因此稳定；
- 插入排序只右移严格大于 `key` 的元素，因此稳定；
- 朴素选择排序会进行远距离交换，因此不稳定；
- 本书的原地快速分区会进行远距离交换，因此不稳定；
- 归并排序在相等时先取左半区，因而稳定；若改为先取右侧就不稳定；
- `std::sort` 不保证稳定，需要稳定时使用 `stable_sort`；
- 本书的计数排序只保存整数频次，已经丢失相等键记录的身份，不能拿来保持记录
  顺序；稳定计数排序需要累计最终位置并建立额外输出数组。

因此，不能背诵“某个算法名字天然稳定”。比较条件、交换方式、合并顺序和辅助
存储都会影响具体实现。

## 数组与链表

数组能常数时间访问任意下标，也能直接交换两个位置，适合快速排序的左右分区。
数组归并排序则需要 $O(n)$ 临时数组，避免写入结果时覆盖尚未读取的元素。

单向链表不适合从右端向左扫描或按下标随机访问，因此数组式快速分区很别扭。归并
两个有序链表只需顺序查看当前节点，并通过修改 `next` 重新连接已有节点；不计递归
栈时，合并可以只用常数个指针。所以链表排序通常优先考虑归并排序。

插入排序也能在链表中通过重新连接节点完成，但寻找插入位置仍可能使总时间达到
$O(n^2)$。选择数据结构不会自动消除算法本身的主要工作量。

## 实际比赛怎样选择

一般排序首先考虑标准库：

1. 只要求得到有序结果时，使用 `sort`；
2. 必须保持相等关键字记录的原顺序时，使用 `stable_sort`；
3. 整数值域很小且内存允许时，考虑计数排序；
4. 输入规模很小或序列接近有序时，插入排序可以作为简单局部方法；
5. 题目要求手写、研究逆序对、处理链表或需要确定的 $O(n\log n)$ 最坏时间时，
   再考虑归并排序；
6. 学习分区、题目明确要求手写，或某个问题本身需要快速选择式划分时，再使用
   快速排序思想。

冒泡排序和选择排序主要用于建立循环不变量、交换与稳定性概念。普通竞赛题不会
因为它们代码短，就值得用 $O(n^2)$ 替代可靠的 `sort`。

## 对记录使用稳定排序

例如，输入若干学生的分数与名字，只按分数升序排列；同分学生要保持输入顺序。
比较器只比较分数，`stable_sort` 负责保留等价记录的原顺序：

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Student {
    int score;
    string name;
};

bool cmp(const Student& a, const Student& b) {
    return a.score < b.score;
}

void solve() {
    int n;
    cin >> n;

    vector<Student> student(n);
    for (int i = 0; i < n; i++) {
        cin >> student[i].score >> student[i].name;
    }

    stable_sort(student.begin(), student.end(), cmp);

    for (const Student& item : student) {
        cout << item.score << ' ' << item.name << '\n';
    }
}

int main() {
    solve();
    return 0;
}
```

这里直接使用 STL 容器接口，因此沿用 `vector` 的 0-based 下标和
`[begin(),end())` 左闭右开范围。比较器只回答 `a` 是否严格排在 `b` 前，不能用
`<=`。同分时两个方向都返回 `false`，它们在排序规则下等价。

输入：

```text
4
90 Alice
80 Bob
90 Carol
80 Dave
```

输出：

```text
80 Bob
80 Dave
90 Alice
90 Carol
```

## 其他排序方法的位置

还有许多排序方法，但不需要同时进入基础主线：

- 堆排序具有 $O(n\log n)$ 最坏时间和 $O(1)$ 主要额外空间，但不稳定；学习二叉堆
  后再理解更自然；
- 基数排序从低位到高位分趟处理，每一趟必须稳定，才能保留已经建立的低位顺序；
- 桶排序把值域分段，稳定性取决于入桶、桶内排序和拼接方式；
- 希尔排序按逐渐缩小的间隔进行插入式整理，不稳定，而且复杂度依赖间隔序列，基础
  路线只要求知道其名称和大致思想。

这些方法不是因为“没有用”而被放到扩展阅读，而是它们不是当前阶段理解和解决常见
问题的必要前置。

## 常见错误

### 只看平均复杂度

快速排序平均是 $O(n\log n)$，最坏仍可能是 $O(n^2)$。能否接受要结合输入来源、
实现保护和题目限制判断。

### 把 O(n + k) 简写成一律 O(n)

计数排序的值域项不能消失。`k` 远大于 `n` 时，它可能完全不可用。

### 认为严格比较就一定稳定

选择排序和快速排序即使只用严格比较，远距离交换仍可能让相等记录跨越。

### 忽略递归栈

原地快速分区没有辅助数组，但递归调用仍占空间；最坏递归深度还可能达到 $O(n)$。

### 把 stable_sort 当成默认 sort 的属性

`sort` 不保证相等元素原顺序。题目需要稳定性时，应明确调用 `stable_sort` 或证明
自己的实现稳定。

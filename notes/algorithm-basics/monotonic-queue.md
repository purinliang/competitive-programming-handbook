# 单调队列

> 最近修订：2026-08-15 21:23 +10:00（未审阅）

给定数组 `a[1..n]` 和固定窗口长度 `k`，窗口从左向右移动：

```text
[1, k]
[2, k + 1]
...
[n - k + 1, n]
```

需要输出每个窗口的最大值。

逐个扫描每个窗口需要 $O(nk)$ 时间。标准队列能删除离开窗口的最早元素，却不能保证队首就是最大值；优先队列能取得最大值，但删除已经离开窗口的任意旧元素需要额外的过期处理。

单调队列使用一个双端队列保存仍有资格成为当前或未来窗口最大值的下标：

- 队首删除已经离开窗口的下标；
- 队尾删除已经被新元素支配的下标；
- 队首始终是当前窗口最大值的位置。

每个下标最多进入和离开双端队列一次，全部窗口可以在 $O(n)$ 时间内处理。

## 为什么保存下标

队列中的候选必须同时回答两个问题：

1. 它的数值是否足够大；
2. 它是否仍在当前窗口内。

保存下标 `u` 后，可以用 `a[u]` 比较数值，也可以用 `u` 判断是否过期。若只保存数值，相同数值来自哪个位置会丢失，窗口左端移动时就无法准确删除旧元素。

## 删除过期下标

扫描到窗口右端点 `i` 时，完整窗口是：

```text
[i - k + 1, i]
```

所有满足：

```text
u < i - k + 1
```

的下标都已经离开窗口。等价地：

```text
u <= i - k
```

队列中的下标从前到后递增，所以过期位置只可能连续出现在队首：

```cpp
while (!q.empty() && q.front() <= i - k) {
    q.pop_front();
}
```

不需要扫描队列中间；后面的下标只会更新，不会比队首更早过期。

## 删除被支配的候选

准备加入新位置 `i`。若队尾位置 `u` 满足：

```text
a[u] <= a[i]
```

那么 `u` 从此不可能再成为窗口最大值：

- 新位置 `i` 的数值不小于 `u`；
- `i` 比 `u` 更靠右，会比 `u` 更晚离开未来窗口。

无论后续窗口怎样移动，只要 `u` 仍在窗口中，`i` 也仍在窗口中，并且 `i` 至少同样大。因此可以永久删除 `u`：

```cpp
while (!q.empty() && a[q.back()] <= a[i]) {
    q.pop_back();
}
q.push_back(i);
```

相等时保留更新的下标 `i`，因为它生存得更久；旧的相等下标没有任何额外价值。

删除完成后，队列中的数值从前到后严格递减：

```text
a[q[0]] > a[q[1]] > ...
```

队首于是保存所有有效候选中的最大值。

## 完整处理顺序

对每个右端点 `i = 1..n`：

1. 从队首删除所有过期下标；
2. 从队尾删除数值不大于 `a[i]` 的候选；
3. 把 `i` 加到队尾；
4. 若 `i >= k`，输出窗口 `[i-k+1,i]` 的最大值 `a[q.front()]`。

```cpp
for (int i = 1; i <= n; i++) {
    while (!q.empty() && q.front() <= i - k) {
        q.pop_front();
    }
    while (!q.empty() && a[q.back()] <= a[i]) {
        q.pop_back();
    }
    q.push_back(i);

    if (i >= k) {
        answer[i - k + 1] = a[q.front()];
    }
}
```

前 `k-1` 个位置还没有形成完整窗口，但它们仍要正常加入候选队列，为第一个窗口准备状态。

## 扫描示例

数组为：

```text
1 3 -1 -3 5 3 6 7
```

窗口长度 `k=3`。队列写成 `下标(数值)`：

| `i` | 加入值 | 队列（前到后） | 当前窗口最大值 |
| ---: | ---: | --- | ---: |
| 1 | 1 | `1(1)` | 尚未成窗 |
| 2 | 3 | `2(3)` | 尚未成窗 |
| 3 | -1 | `2(3), 3(-1)` | 3 |
| 4 | -3 | `2(3), 3(-1), 4(-3)` | 3 |
| 5 | 5 | `5(5)` | 5 |
| 6 | 3 | `5(5), 6(3)` | 5 |
| 7 | 6 | `7(6)` | 6 |
| 8 | 7 | `8(7)` | 7 |

扫描 `i=5` 时，下标 `2` 已过期；新值 `5` 又依次支配队尾的 `-3` 和 `-1`，所以队列最终只剩 `5(5)`。

## 完整代码

双端队列使用标准库 `deque<int>`，其中保存 1-based 原数组下标。函数返回 1-based 窗口答案：`answer[l]` 对应窗口 `[l,l+k-1]`。

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> sliding_window_maximum(const vector<int>& a, int n, int k) {
    vector<int> answer(n + 5);
    deque<int> q;

    for (int i = 1; i <= n; i++) {
        while (!q.empty() && q.front() <= i - k) {
            q.pop_front();
        }
        while (!q.empty() && a[q.back()] <= a[i]) {
            q.pop_back();
        }
        q.push_back(i);

        if (i >= k) {
            answer[i - k + 1] = a[q.front()];
        }
    }

    return answer;
}

int main() {
    int n, k;
    scanf("%d%d", &n, &k);

    vector<int> a(n + 5);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &a[i]);
    }

    vector<int> answer = sliding_window_maximum(a, n, k);
    int window_count = n - k + 1;
    for (int l = 1; l <= window_count; l++) {
        if (l > 1) {
            printf(" ");
        }
        printf("%d", answer[l]);
    }
    printf("\n");
    return 0;
}
```

输入：

```text
8 3
1 3 -1 -3 5 3 6 7
```

输出：

```text
3 3 5 5 6 7
```

完整代码假设 `1<=k<=n`。若题目没有保证，需要先处理 `k` 非法或没有完整窗口的情况。

## 正确性

队首删除保证队列中所有下标都位于当前窗口。队尾删除只移除被新位置 `i` 支配的候选：`i` 数值不小于它，并且离开窗口更晚，所以被删除位置不可能在任何未来窗口中优于 `i`。

每次加入后，队列数值严格递减。因此队首数值不小于其他所有仍有效、未被支配的候选。任何被删除的有效位置又都有一个更新且不小的候选替代，所以当前窗口的真实最大值不可能丢失。于是 `a[q.front()]` 正是当前窗口最大值。

## 复杂度

每个下标恰好从队尾加入一次。它以后至多因为过期从队首删除一次，或因为被支配从队尾删除一次；删除以后不会重新加入。

虽然每一步包含两个 `while`，所有入队和出队操作合计仍是 $O(n)$，所以总时间复杂度是 $O(n)$。双端队列、答案数组和输入数组占用 $O(n)$ 空间；队列本身最多保存 $k$ 个窗口内候选，是 $O(k)$。

## 与单调栈的区别

[单调栈](monotonic-stack.md) 中的位置一旦找到最近更大元素就完成并弹出；它主要回答位置之间的最近关系。

单调队列中的候选还受滑动窗口边界限制：

- 队首负责时间顺序和过期；
- 队尾负责数值单调性和支配关系。

因此单调队列必须操作两端，底层使用 `deque`。两者都利用“一个候选一旦被证明永远不可能再成为答案，就立即删除”的思想，但不能只按名称互换代码。

## 常见错误

### 只保存数值

窗口移动需要知道候选何时过期，必须保存下标，并通过原数组取得数值。

### 过期边界少一个等号

当前窗口左端是 `i-k+1`，所以 `u<=i-k` 已经过期。写成 `<i-k` 会让一个窗口外元素多停留一步。

### 从错误的一端删除

最早过期的下标在队首，被新值支配的候选连续位于队尾。两种删除不能交换端点。

### 未成窗就输出

只有 `i>=k` 时 `[i-k+1,i]` 才是合法完整窗口。

### 不理解相等元素

使用 `<=` 弹出旧的相等值，保留更新位置，因为新位置更晚过期。使用 `<` 保留多个相等值也能求最大值，但队列更长，过期行为也不同；同一份证明和代码必须采用一致规则。

### 把两个 while 算成平方复杂度

一个下标离开队列后不会回来。按每个下标的完整生命周期计数，总操作数仍是线性的。

## 基础练习

1. 手动模拟示例数组，分别标出队首过期和队尾被支配的删除。
2. 测试 `k=1`、`k=n`、严格递增、严格递减和全部相等的数组。
3. 把 `<=` 改成 `<`，观察重复最大值在队列中的保留方式和最终答案。
4. 反转比较关系，求每个窗口最小值。
5. 使用 $O(nk)$ 的逐窗口扫描作为参考程序，与单调队列随机对拍。
6. 同时维护一个最大值队列和一个最小值队列，输出每个窗口的极差。

## 需要记住什么

1. 单调队列为什么保存下标而不是只保存数值？
2. 扫描到右端点 `i` 时，窗口左端在哪里？哪些下标已经过期？
3. 为什么新位置可以永久删除队尾所有不大于它的候选？
4. 队列中的下标顺序和数值顺序分别是什么？
5. 为什么队首就是当前窗口最大值？
6. 为什么相等时保留更新的下标是安全的？
7. 两个 `while` 为什么没有让总复杂度变成 $O(n^2)$？
8. 单调栈和单调队列分别多维护了什么关系？

多重背包、动态规划转移和其他带代价函数的单调队列优化，需要先把转移式改写成滑动候选窗口，不属于本篇固定窗口最大值。

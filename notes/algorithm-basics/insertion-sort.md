# 插入排序

> 最近修订：2026-08-16 18:00 +10:00（未审阅）

整理扑克牌时，我们常把新拿到的一张牌插入手中已经排好序的牌：先为它向左寻找
位置，把更大的牌依次右移，再放进留下的空位。插入排序把这个过程应用到数组。

[冒泡排序](bubble-sort.md) 和 [选择排序](selection-sort.md) 每轮确定一个最终位置；
插入排序维护的是一个已经有序的前缀，并把下一个元素插入其中。

## 已经有序的前缀

单元素前缀 `a[1..1]` 天然有序。假设 `a[1..i-1]` 已经有序，现在要把 `a[i]`
插入进去。

先保存这个待插入值：

```cpp
int key = a[i];
```

不能只记住下标 `i`。稍后右移元素时，`a[i]` 会被覆盖；若没有提前保存，原来的
值就会丢失。

令 `j` 从有序前缀末尾 `i - 1` 开始。只要 `a[j] > key`，它就应该位于 `key`
右边，因此向右移动一格：

```cpp
int j = i - 1;
while (j >= 1 && a[j] > key) {
    a[j + 1] = a[j];
    j--;
}
```

循环停止有两种可能：

- `j == 0`，说明 `key` 小于整个原前缀，应放在开头；
- `a[j] <= key`，说明 `key` 应放在 `a[j]` 后面。

两种情况的插入位置都是 `j + 1`：

```cpp
a[j + 1] = key;
```

## 一次插入

以有序前缀 `2 4 5` 和新值 `3` 为例：

```text
2 4 5 [3]
2 4 _ 5
2 _ 4 5
2 3 4 5
```

先保存 `3`，再把 `5`、`4` 各向右移动一格。遇到不大于 `3` 的 `2` 后停止，
把 `3` 放入空位。

右移过程中，空位从位置 `4` 逐步向左移动；`a[j + 1] = key` 填补最后留下的
空位。它不是额外插入一个元素，数组长度没有改变。

## 不断扩大有序前缀

`n` 和 `a` 是整道题共享的输入状态，放在全局；`i`、`j` 和 `key` 只描述当前
一轮插入，保留为函数内部的局部状态。完整函数为：

```cpp
int n;
vector<int> a;

void insertion_sort() {
    for (int i = 2; i <= n; i++) {
        int key = a[i];
        int j = i - 1;

        while (j >= 1 && a[j] > key) {
            a[j + 1] = a[j];
            j--;
        }

        a[j + 1] = key;
    }
}
```

每轮开始前，前缀 `a[1..i-1]` 已经非递减有序。循环只把其中大于 `key` 的
后缀整体右移，它们原来的相对顺序没有改变；其余元素不大于 `key`。把 `key`
放在两部分之间后，`a[1..i]` 仍然有序。

初始前缀只有一个元素，不变量成立。每轮使有序前缀扩大一格；处理完 `i = n`
以后，整个数组就是有序前缀。

## 边界条件的顺序

条件必须先判断 `j >= 1`，再访问 `a[j]`：

```cpp
while (j >= 1 && a[j] > key) {
```

`&&` 具有短路求值：若 `j >= 1` 已经为假，右侧 `a[j] > key` 不会执行。这样
当 `key` 需要插到第一个位置时，不会访问 `a[0]`。

虽然本书的容器额外保留了位置 `0`，这里仍不应依靠其中恰好保存的值作为哨兵。
显式边界条件能准确表达合法范围，也不会把代码正确性绑定到某个特殊初始值。

## 复杂度

若数组已经有序，每轮第一次检查就发现 `a[i - 1] <= key`，只做常数工作；总时间
复杂度是 $O(n)$。

若数组严格递减，第 `i` 轮要移动前面的 `i - 1` 个元素，总移动次数是：

$$
1+2+\cdots+(n-1)=\frac{n(n-1)}2,
$$

最坏时间复杂度是 $O(n^2)$。

每次右移恰好消除 `key` 与一个较大前驱形成的逆序，因此插入排序的实际移动次数
与数组逆序对数量同阶。输入接近有序时，它通常比固定完成全部比较的选择排序更快。

算法只使用 `key` 和下标变量，额外空间复杂度是 $O(1)$，属于原地排序。

## 稳定性

本篇只在 `a[j] > key` 时右移。若 `a[j] == key`，循环停止，新元素会插在已有
相等元素后面，所以相等元素的原有顺序不变，这份实现是稳定的。

若把条件改成 `a[j] >= key`，已有相等元素也会右移，新元素可能插到它们前面，
稳定性就会被破坏。

## 完整代码

下面的程序使用 1-based 下标和 `+5` 余量排列整数数组：

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
vector<int> a;

void insertion_sort() {
    for (int i = 2; i <= n; i++) {
        int key = a[i];
        int j = i - 1;

        while (j >= 1 && a[j] > key) {
            a[j + 1] = a[j];
            j--;
        }

        a[j + 1] = key;
    }
}

void solve() {
    scanf("%d", &n);

    a.assign(n + 5, 0);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &a[i]);
    }

    insertion_sort();

    for (int i = 1; i <= n; i++) {
        if (i > 1) {
            printf(" ");
        }
        printf("%d", a[i]);
    }
    printf("\n");
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
5
4 2 5 1 3
```

输出：

```text
1 2 3 4 5
```

`n <= 1` 时外层循环不会执行，数组已经有序。

## 常见错误

### 没有提前保存 key

第一次执行 `a[j + 1] = a[j]` 就可能覆盖原来的 `a[i]`。必须先复制待插入值。

### 忘记填回空位

右移只为 `key` 腾出位置；循环结束后还要执行 `a[j + 1] = key`。

### 把插入位置写成 j

停止时，`j` 位于最后一个不大于 `key` 的元素处，或者已经变成 `0`。空位是
它后面的 `j + 1`。

### 先访问 a[j] 再检查边界

不要写成 `a[j] > key && j >= 1`。当 `j == 0` 时，左侧已经先被求值。

### 用大于等于移动相等元素

这样仍能得到非递减序列，但会破坏本篇实现原有的稳定性。

## 需要记住什么

1. 第 `i` 轮开始前，哪个前缀已经有序？
2. 为什么必须先把 `a[i]` 保存为 `key`？
3. 哪些元素需要右移？循环停止后空位为什么是 `j + 1`？
4. 边界判断为什么要写在数组访问以前？
5. 插入排序最好与最坏时间复杂度分别是多少？
6. 为什么输入接近有序时移动次数较少？
7. 本篇实现为什么稳定？把 `>` 改成 `>=` 会怎样？
8. 为什么实际比赛的一般排序仍优先使用 `sort`？

# 递推

> 最近修订：2026-08-16 10:06 +10:00（未审阅）

一个数列的较晚项经常由较早项决定。只要初始值和依赖关系已经明确，就可以从已知
项出发，按照依赖顺序依次产生后面的每一项；这种计算方式称为**递推**。

上一篇 [递归与问题分解](recursive-problem-solving.md) 曾把斐波那契关系直接翻译成
函数调用。本篇使用同一个数列，观察怎样从初始值开始，自底向上计算每个结果。

## 初始值与递推关系

本篇使用下面的斐波那契数列定义：

$$
F_0=0,\qquad F_1=1,
$$

$$
F_i=F_{i-1}+F_{i-2}\qquad(i\ge2).
$$

两个初始值直接给出递推起点；递推关系说明第 `i` 项怎样由更早的两项得到。

只有关系而没有初始值，无法确定具体数列。例如同样满足
$x_i=x_{i-1}+x_{i-2}$ 的数列，可以从 `1,1` 开始，也可以从 `2,3` 开始。
只有初始值而没有关系，也无法产生后面的项。

## 按依赖顺序计算

计算 `f[i]` 前，`f[i - 1]` 与 `f[i - 2]` 必须已经确定。因此从 `f[0]`、
`f[1]` 出发，按照下标递增顺序计算：

```cpp
vector<ll> f(n + 5);
f[0] = 0;

if (n >= 1) {
    f[1] = 1;
}

for (int i = 2; i <= n; i++) {
    f[i] = f[i - 1] + f[i - 2];
}
```

本书自定义对象通常使用 1-based 下标；这里保留数学定义中的 $F_0$，因为第 `0`
项本身有明确数列含义，不是为了迎合底层容器而出现的空位置。尾部仍预留 `+5`
空间。

若从 `n` 向 `2` 递减计算，第一次使用的 `f[n - 1]` 和 `f[n - 2]` 还没有产生，
只能读到初始化值。递推顺序必须与依赖方向一致。

## 手动递推

计算 $F_6$ 时，可以逐项填写：

| `i` | `f[i - 2]` | `f[i - 1]` | `f[i]` |
| ---: | ---: | ---: | ---: |
| 0 | — | — | 0 |
| 1 | — | — | 1 |
| 2 | 0 | 1 | 1 |
| 3 | 1 | 1 | 2 |
| 4 | 1 | 2 | 3 |
| 5 | 2 | 3 | 5 |
| 6 | 3 | 5 | 8 |

每一行只读取已经出现在表格上方的结果。手算前几项能同时检查初始值数量、循环
起点、依赖下标和加法是否正确。

## 从递归调用改成递推

朴素递归函数会为了 `fibonacci(n - 1)` 和 `fibonacci(n - 2)` 展开两棵子调用树：

```cpp
ll fibonacci(int n) {
    if (n <= 1) {
        return n;
    }
    return fibonacci(n - 1) + fibonacci(n - 2);
}
```

其中相同参数会出现很多次。例如计算 `fibonacci(5)` 时，`fibonacci(3)` 至少
在两个不同分支中重新计算。

递推数组让每个 `f[i]` 只产生一次。后面的项通过下标直接读取已经保存的结果，
不再重新展开调用。因此递推循环只有 $n-1$ 次更新，而朴素递归的调用节点数量
呈指数增长。

这种改写依赖一个重要条件：所有依赖项都能按照某种顺序先被计算。本例的下标依赖
总是从大指向小，所以从小到大填表即可。

## 正确性

可以按照下标归纳证明递推数组正确。

初始位置 `f[0] = 0`、`f[1] = 1` 与数列定义相同。

假设 `f[i - 2]` 与 `f[i - 1]` 已经分别等于 $F_{i-2}$ 和 $F_{i-1}$。循环按照
定义计算：

$$
f[i]=f[i-1]+f[i-2]=F_{i-1}+F_{i-2}=F_i.
$$

由于循环按下标递增执行，计算当前项所需的两个前提都已经成立。最终 `f[n]`
等于目标 $F_n$。

## 保存全部项或滚动变量

数组保存 `f[0..n]`，可以在后续代码中访问任意一项，空间复杂度是 $O(n)$。

若题目只要求最终的 $F_n$，当前更新只需要前两项，可以使用两个变量：

```cpp
ll previous = 0;
ll current = 1;

for (int i = 2; i <= n; i++) {
    ll next = previous + current;
    previous = current;
    current = next;
}
```

这样额外空间降为 $O(1)$。不过当 `n == 0` 时答案是 `previous`，`n >= 1` 时
答案是 `current`；边界表达比直接读取 `f[n]` 更分散。

教学推导和后续需要中间项时优先保留数组。只有确认旧项不会再被访问，才使用滚动
变量压缩空间。节省少量内存不应以破坏下标含义为代价。

## 递推与动态规划

递推只要求初始值、依赖关系和合法计算顺序。本例的数列定义已经直接给出唯一更新，
没有从题目中选择“用哪些信息代表子问题”，也没有在多种决策之间合并答案。

动态规划会进一步研究怎样设计状态、识别重复子问题、列出决策并推导状态转移。
它经常最终表现为一张按依赖顺序填写的递推表，但“代码中有数组和递推式”并不
足以让所有问题都变成动态规划。

## 完整代码

输入保证 `0 <= n <= 92`，输出 $F_n$。这个范围内的答案可以使用 64 位整数保存：

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

void solve() {
    int n;
    cin >> n;

    vector<ll> f(n + 5);
    f[0] = 0;

    if (n >= 1) {
        f[1] = 1;
    }

    for (int i = 2; i <= n; i++) {
        f[i] = f[i - 1] + f[i - 2];
    }

    cout << f[n] << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
6
```

输出：

```text
8
```

循环计算 `f[2..n]`，每项只做固定次数的整数运算，所以时间复杂度是 $O(n)$；
数组空间复杂度是 $O(n)$。

## 常见错误

### 初始值数量不足

递推式依赖前两项，就必须先提供足以开始计算的两项。只写 `f[0]` 无法确定
`f[1]`。

### 循环起点覆盖初始值

初始值已经给出到 `f[1]`，循环应从 `i = 2` 开始。错误地从 `1` 开始会用
尚不符合公式定义的下标覆盖初值。

### 计算方向与依赖相反

本例的较大下标依赖较小下标，因此要从小到大。不能只因为习惯某种循环方向就忽略
数据依赖。

### 滚动更新顺序错误

若先覆盖 `current`，再尝试用旧的 `current` 计算下一项，所需信息已经丢失。
先用临时变量保存 `next`，再整体推进两个旧值。

### 忽略整数范围

斐波那契数列增长很快。算法是 $O(n)$ 不代表数值一定能由当前类型保存；本篇把
输入限制到 `n <= 92`，正是为了避免 64 位整数溢出。

# 桶排序

> 最近修订：2026-08-17 00:42 +10:00（未审阅）

[计数排序](counting-sort.md)为每个可能的整数值保存出现次数。若值域很大，这种“一值一格”的方法会消耗过多时间和内存。

桶排序不再让一个位置对应一个具体值，而是把整个值域划分成若干连续范围。每个范围称为一个**桶**：元素先进入所属桶，桶内分别排序，最后按桶的范围顺序拼接。

一个桶可能包含许多不同值，所以桶排序与计数排序不是同一种算法。

## 划分值域

假设输入范围是 `0..99`，可以划分为十个桶：

```text
第 1 桶： 0.. 9
第 2 桶：10..19
...
第 10 桶：90..99
```

对输入：

```text
42 7 31 18 25 3
```

入桶后：

```text
第 1 桶：7 3
第 2 桶：18
第 3 桶：25
第 4 桶：31
第 5 桶：42
```

先分别把每个桶排好：

```text
第 1 桶：3 7
第 2 桶：18
第 3 桶：25
第 4 桶：31
第 5 桶：42
```

再从编号较小的桶到编号较大的桶拼接，得到：

```text
3 7 18 25 31 42
```

## 为什么拼接后整体有序

桶的值域必须按顺序划分，并且不能交叉。对任意两个桶 $i<j$：

$$
\text{桶 }i\text{ 中的每个值}\le
\text{桶 }j\text{ 中的每个值}.
$$

因此：

- 同一个桶内的顺序由桶内排序保证；
- 不同桶之间的顺序由值域划分保证。

这两个条件合在一起，就能证明按桶编号拼接后的序列整体非递减。

若桶的范围相互重叠，或者拼接顺序与范围顺序不同，仅仅“每个桶内部有序”还不能保证整体有序。

## 根据最小值与桶宽映射

令：

- `min_value` 是最小值；
- `max_value` 是最大值；
- `bucket_count` 是桶数；
- `range = max_value - min_value + 1` 是整数值域长度。

选择能够覆盖值域的桶宽：

```cpp
ll width = (range + bucket_count - 1) / bucket_count;
```

这是正整数的向上取整除法。值 `value` 对应的 1-based 桶编号是：

```cpp
int index = (value - min_value) / width + 1;
```

实际代码使用 64 位整数先计算差值，避免两个极端 `int` 相减时溢出：

```cpp
int index = (1LL * value - min_value) / width + 1;
```

同一个桶覆盖至多 `width` 个连续整数值。最后一个桶可以没有填满整个理论范围。

## 桶内仍然需要排序

入桶只建立不同范围之间的顺序。同一桶内的元素仍可能无序，例如 `7 3` 都落在 `0..9`。

桶内可以根据问题选择：

- 直接调用 `sort`；
- 桶很小时使用插入排序；
- 若桶内值域仍适合计数，再使用计数排序；
- 桶本身已经按顺序接收元素时，不再排序。

本篇代码对每个 `vector` 桶调用 `sort`。这让实现可靠，但也说明它不是在任何输入上都优于直接排序。

## 桶的数量怎样影响效率

桶太少时，许多元素挤在同一桶，主要工作退化成桶内排序。桶太多时，大量空桶会增加存储与遍历成本。

本篇为 $n$ 个元素建立 $n$ 个桶。这是经典平均分析中常用的选择：若数据近似均匀分布，每个桶的期望元素数量为常数，桶内工作很小。

但“近似均匀”是额外假设，不是桶排序自动保证的性质。若所有元素相等，它们会全部进入同一个桶；本篇使用 `sort` 处理该桶，时间会达到 $O(n\log n)$。

真实题目若已经给出自然分区，例如分数段、日期月份或空间网格，可以直接使用这些有意义的桶，不必机械令桶数等于 $n$。

## 复杂度

设有 $k$ 个桶，第 $i$ 个桶包含 $m_i$ 个元素，并且：

$$
\sum_{i=1}^{k}m_i=n.
$$

入桶需要 $O(n)$，扫描桶需要 $O(k)$。若各桶使用比较排序，桶内总成本是：

$$
\sum_{i=1}^{k}O(m_i\log m_i).
$$

所以更完整的时间表达是：

$$
O\left(n+k+\sum_{i=1}^{k}m_i\log m_i\right).
$$

数据均匀、桶数与 $n$ 同阶、每桶元素期望为常数时，期望时间可以接近 $O(n)$。所有元素集中到一个桶时，本篇实现是 $O(n\log n)$。

所有桶合计保存 $n$ 个元素，桶容器本身有 $k$ 个，额外空间是 $O(n+k)$。

若桶内改用插入排序，均匀分布时仍可能有良好期望时间，但极端集中时最坏会成为 $O(n^2)$。复杂度必须与具体桶内算法一起说明。

## 与计数排序比较

| 问题 | 计数排序 | 桶排序 |
| --- | --- | --- |
| 一个存储位置对应什么 | 一个具体整数值 | 一段值域 |
| 位置内部保存什么 | 出现次数 | 多个原始元素 |
| 是否还需内部排序 | 不需要 | 通常需要 |
| 主要附加条件 | 整数值域足够小 | 能设计有效分桶且分布较均衡 |
| 额外空间 | $O(\text{值域})$ | $O(n+\text{桶数})$ |

一些资料把各种“分桶”方法统称桶排序，也可能口语化地把计数排序称为桶排序。本书为避免混淆，始终使用上表中的严格区分。

## 完整代码

下面对 1-based `int` 数组进行桶排序。桶数取 `n`，代码支持负数和重复值；桶内使用标准库 `sort`。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

int n;
vector<int> a;

void bucket_sort() {
    if (n <= 1) {
        return;
    }

    int min_value = a[1];
    int max_value = a[1];

    for (int i = 2; i <= n; i++) {
        min_value = min(min_value, a[i]);
        max_value = max(max_value, a[i]);
    }

    int bucket_count = n;
    ll range = 1LL * max_value - min_value + 1;
    ll width = (range + bucket_count - 1) / bucket_count;

    vector<vector<int>> bucket(bucket_count + 5);

    for (int i = 1; i <= n; i++) {
        int index = (1LL * a[i] - min_value) / width + 1;
        bucket[index].push_back(a[i]);
    }

    int position = 1;

    for (int index = 1; index <= bucket_count; index++) {
        sort(bucket[index].begin(), bucket[index].end());

        for (int value : bucket[index]) {
            a[position] = value;
            position++;
        }
    }
}

void solve() {
    cin >> n;

    a.assign(n + 5, 0);

    for (int i = 1; i <= n; i++) {
        cin >> a[i];
    }

    bucket_sort();

    for (int i = 1; i <= n; i++) {
        if (i > 1) {
            cout << ' ';
        }
        cout << a[i];
    }
    cout << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
8
42 -3 7 31 18 25 -10 3
```

输出：

```text
-10 -3 3 7 18 25 31 42
```

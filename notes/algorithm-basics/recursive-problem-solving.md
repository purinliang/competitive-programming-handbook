# 递归与问题分解

> 最近修订：2026-08-16 10:00 +10:00（未审阅）

[递归](../cpp/recursion.md) 已经解释了函数调用自身时，参数、局部变量和返回位置
怎样进入调用栈。本篇不再讲一遍调用机制，而是解决另一个问题：怎样把一个待求的
答案准确写成更小的同类问题，并由此设计出递归函数。

递归不是先写一次函数名，再期待程序自动找到答案。一个可推导的递归算法必须明确
函数定义、基本情况、规模缩小方式和答案组合方式。

## 函数定义

设计递归函数以前，先用一句完整的话规定它接收什么、返回什么。以阶乘为例：

> `factorial(n)` 返回非负整数 $n$ 的阶乘 $n!$。

函数定义是后续推导的契约。若只写“处理 `n`”或“递归一下”，就无法判断较小
调用返回的值能否直接用于当前问题，也无法证明最终结果正确。

阶乘定义为：

$$
n!=1\times2\times\cdots\times n.
$$

当 $n>0$ 时，把最后一个因子 $n$ 单独取出：

$$
n!=n\times(n-1)!.
$$

右边的 $(n-1)!$ 正是参数更小的同类问题，所以可以交给
`factorial(n - 1)`。

## 基本情况

问题不能无限缩小。阶乘在 $n=0$ 时有直接答案：

$$
0!=1.
$$

这就是基本情况：不再发起更小调用，直接返回结果。

```cpp
ll factorial(int n) {
    if (n == 0) {
        return 1;
    }
    return n * factorial(n - 1);
}
```

把基本情况写在递归调用以前，可以让读者先看见终点。这里的函数只接收非负整数；
若允许负数，`n - 1` 会不断变小却永远到不了 `0`，原来的函数定义也没有说明负数
阶乘是什么。

## 假设较小问题已经正确

理解递归式时，不需要在同一时刻展开无限层。分析 `factorial(n)` 可以暂时假设：

> 参数更小的 `factorial(n - 1)` 已经按照函数定义，正确返回 $(n-1)!$。

当前层只需把这个结果乘以 `n`，就得到 $n!$。这种思考不是跳过证明，而是把证明
分成两个局部问题：较小规模为何正确，以及当前层怎样从它组成正确答案。

按照非负整数归纳：

1. `factorial(0)` 直接返回 $1=0!$；
2. 假设 `factorial(n - 1)` 返回 $(n-1)!$；
3. 当前层返回 $n\times(n-1)!=n!$。

因此所有合法参数都满足函数定义。

## 调用与返回顺序

计算 `factorial(4)` 时，调用先不断缩小参数：

```text
factorial(4)
└─ 4 * factorial(3)
       └─ 3 * factorial(2)
              └─ 2 * factorial(1)
                     └─ 1 * factorial(0)
                            └─ 1
```

到达基本情况以后，答案按相反方向逐层返回：

```text
factorial(0) = 1
factorial(1) = 1 * 1  = 1
factorial(2) = 2 * 1  = 2
factorial(3) = 3 * 2  = 6
factorial(4) = 4 * 6  = 24
```

“调用向下、返回向上”解释了为什么当前层能够等待较小问题的答案。每一层都在调用
栈中保留自己的参数 `n`，直到内层返回后再完成乘法。

## 终止性

存在基本情况还不够；每条递归调用链都必须向它靠近。

在阶乘函数中，可以把参数 `n` 当作问题规模：

- 合法输入满足 $n\ge0$；
- 只要不在基本情况，每次调用都把 `n` 减少 $1$；
- 非负整数不可能无限次严格减小而一直不到 `0`。

所以每条调用链最终都会到达基本情况。

下面的代码虽然有基本情况，却无法保证终止：

```cpp
ll wrong(int n) {
    if (n == 0) {
        return 1;
    }
    return n * wrong(n); // 参数没有缩小
}
```

证明递归正确时，必须同时证明“返回值符合定义”和“调用一定结束”。

## 多个较小问题

一个当前问题也可能依赖多个较小的同类问题。斐波那契数列满足：

$$
F_0=0,\qquad F_1=1,
$$

$$
F_n=F_{n-1}+F_{n-2}\qquad(n\ge2).
$$

直接翻译成递归函数：

```cpp
ll fibonacci(int n) {
    if (n <= 1) {
        return n;
    }
    return fibonacci(n - 1) + fibonacci(n - 2);
}
```

函数定义和返回值是正确的，两条调用链也都会缩小到基本情况；但是它会重复计算
相同问题。例如 `fibonacci(5)` 的两大分支都会计算 `fibonacci(3)`。

朴素调用树的节点数量随 $n$ 指数增长，所以这段代码只适合很小的输入。递归表达
正确不等于算法高效；以后学习动态规划时，会把重复子问题的结果保存并复用。本篇
只留下这个问题，不提前引入记忆化。

## 递归与递推

递归描述程序怎样求值：函数为了得到当前答案，调用自身求较小问题。递推关系描述
数值之间怎样依赖，例如 $F_n=F_{n-1}+F_{n-2}$。

同一个关系可以用递归函数自顶向下求值，也可以从初始值开始，用循环按下标递增
地计算。下一篇 [递推](recurrence.md) 会重点讨论后一种计算顺序。两种写法应当共享
同一份数学定义，但运行过程和复杂度可能完全不同。

## 完整代码

下面的程序读取 `0..20` 的整数 `n`，输出 `n!`。这个范围保证答案可以用 64 位
整数保存：

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

ll factorial(int n) {
    if (n == 0) {
        return 1;
    }
    return n * factorial(n - 1);
}

void solve() {
    int n;
    cin >> n;
    cout << factorial(n) << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
5
```

输出：

```text
120
```

`factorial(n)` 到 `factorial(0)` 一共有 $n+1$ 层调用，每层只做固定次数的工作，
所以时间复杂度是 $O(n)$，调用栈空间复杂度是 $O(n)$。

## 常见错误

### 没有准确的函数定义

如果不知道较小调用应当返回什么，就无法正确组合当前答案。先写一句可验证的函数
契约，再写递归式。

### 遗漏基本情况

没有直接返回的终点，函数会不断调用并最终耗尽调用栈。

### 参数没有严格缩小

基本情况存在不代表一定能到达。必须找到一个有下界的规模量，并证明每次调用都让
它严格变小。

### 基本情况与合法输入不匹配

只处理 `n == 0` 的阶乘函数要求输入非负。若输入域改变，终止证明和函数定义都要
重新检查。

### 只证明答案，不分析重复调用

递归函数可以返回正确答案，却因为重复子问题而非常慢。画出小规模调用树，检查
同一参数是否反复出现。

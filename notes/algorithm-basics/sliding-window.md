# 双指针：滑动窗口

> 最近修订：2026-08-13 20:43 +10:00（未审阅）

[双指针](two-pointers.md) 已经说明，只要两个下标都沿着已经证明的方向移动，就可以用总移动次数得到线性复杂度。本篇让两个下标共同围出一个连续区间，并在端点移动时维护区间中的信息。这种同向双指针称为滑动窗口。

## 和至少为目标值的最短连续子数组

给定一个长度为 $n$ 的 1-based 正整数数组 `a[1..n]` 和一个正整数 `target`，寻找和至少为 `target` 的最短非空连续子数组。不存在时输出 `0`。

例如：

```text
a = 2 3 1 2 4 3 1
target = 7
```

区间 `[5, 6]` 的和是 $4 + 3 = 7$，长度是 $2$，并且不存在长度为 $1$ 的合法区间，所以答案为 $2$。

这里要求的是连续区间，不能跳过中间元素。数组中的数全部为正数，这个条件将决定端点能否只向右移动。

## 枚举左右端点

最直接的方法枚举左端 `l`，再从 `l` 开始向右累加：

```cpp
int answer = n + 1;

for (int l = 1; l <= n; l++) {
    ll sum = 0;
    for (int r = l; r <= n; r++) {
        sum += a[r];
        if (sum >= target) {
            answer = min(answer, r - l + 1);
            break;
        }
    }
}
```

固定 `l` 后，正整数只会让区间和不断增大。第一次达到 `target` 时已经得到这个左端对应的最短区间，因此可以 `break`；继续增大 `r` 只会得到更长的区间。

但是下一个左端从 `l + 1` 开始时，这段代码又把右端放回去重新累加。最坏情况下，每个左端都扫描到数组末尾，时间复杂度仍然是 $O(n^2)$。

## 保留连续窗口

右端没有必要回到前面。用闭区间 `[l, r]` 表示当前窗口，并用 `sum` 保存窗口内所有数的和：

$$
sum = a[l] + a[l + 1] + \cdots + a[r]
$$

开始时还没有元素进入窗口，可以把状态理解为：

```cpp
int l = 1;
ll sum = 0;
```

右端 `r` 将在循环中从 `1` 开始向右扩展。还没有执行第一轮时，窗口为空；执行 `sum += a[r]` 后，`[l, r]` 才成为当前非空窗口。

## 扩展右端

为了让区间和达到 `target`，先把新的右端元素加入窗口：

```cpp
for (int r = 1; r <= n; r++) {
    sum += a[r];
}
```

若加入后仍有 `sum < target`，当前窗口不合法。由于数组元素都是正数，从左端删除元素只会让和更小，因此不存在一个以当前 `r` 结尾、左端更靠右的合法区间。此时只能继续扩展右端。

## 收缩左端

若加入 `a[r]` 后满足：

```cpp
sum >= target
```

当前 `[l, r]` 已经是一段合法区间，先用它更新最短长度：

```cpp
answer = min(answer, r - l + 1);
```

但它不一定是以 `r` 结尾的最短合法区间。删除左端 `a[l]` 后，区间变短了，剩余和仍可能达到 `target`：

```cpp
sum -= a[l];
l++;
```

因此这里必须使用 `while`，持续记录并收缩，直到窗口和第一次小于 `target`：

```cpp
while (sum >= target) {
    answer = min(answer, r - l + 1);
    sum -= a[l];
    l++;
}
```

更新答案必须发生在删除左端以前。否则当前合法区间可能在尚未记录时就被破坏。

## 完整查找函数

把扩展和收缩放在一起：

```cpp
int minimum_length(const vector<int>& a, int n, ll target) {
    int l = 1;
    ll sum = 0;
    int answer = n + 1;

    for (int r = 1; r <= n; r++) {
        sum += a[r];

        while (sum >= target) {
            answer = min(answer, r - l + 1);
            sum -= a[l];
            l++;
        }
    }

    if (answer == n + 1) {
        return 0;
    }
    return answer;
}
```

合法非空区间的长度最多为 `n`，所以 `n + 1` 不可能是真实答案，可以表示“尚未找到”。最后将这个内部哨兵转换成题目要求的 `0`。

`sum` 使用 64 位整数。即使每个 `a[i]` 都能放入 32 位整数，许多元素的总和仍可能超出 32 位范围。

## 手动过程

对示例：

```text
a = 2 3 1 2 4 3 1
target = 7
```

窗口变化如下。每行先检查当前窗口，再执行“处理”：

| `r` | 当前窗口 | `sum` | 处理 | `answer` |
| ---: | --- | ---: | --- | ---: |
| 1 | `[1, 1]` | 2 | 和不足，停止收缩 | 尚未找到 |
| 2 | `[1, 2]` | 5 | 和不足，停止收缩 | 尚未找到 |
| 3 | `[1, 3]` | 6 | 和不足，停止收缩 | 尚未找到 |
| 4 | `[1, 4]` | 8 | 记录长度 4，删除 `a[1]` | 4 |
| 4 | `[2, 4]` | 6 | 和不足，停止收缩 | 4 |
| 5 | `[2, 5]` | 10 | 记录长度 4，删除 `a[2]` | 4 |
| 5 | `[3, 5]` | 7 | 记录长度 3，删除 `a[3]` | 3 |
| 5 | `[4, 5]` | 6 | 和不足，停止收缩 | 3 |
| 6 | `[4, 6]` | 9 | 记录长度 3，删除 `a[4]` | 3 |
| 6 | `[5, 6]` | 7 | 记录长度 2，删除 `a[5]` | 2 |
| 6 | `[6, 6]` | 3 | 和不足，停止收缩 | 2 |
| 7 | `[6, 7]` | 4 | 和不足，停止收缩 | 2 |

最终最短区间是 `[5, 6]`，长度为 $2$。

## 端点移动的正确性

每次右端固定后只会出现两种状态。

### 窗口和小于目标值

此时删除左端只会使正整数之和进一步减小。以当前 `r` 结尾且左端更靠右的区间都不可能合法，所以停止收缩并扩展右端是安全的。

### 窗口和达到目标值

当前区间合法，必须记录它。为了寻找以同一个 `r` 结尾的更短区间，随后删除左端并继续检查；直到和小于目标值，才说明以当前 `r` 结尾的其他更短区间都不合法。

一个左端 `l` 被删除时，区间 `[l, r]` 已经被记录。未来若右端变成 `r' > r`，区间 `[l, r']` 只会更长，不可能改善最短长度。因此这个左端以后不必回来。

右端依次考虑所有结束位置，左端只在已经证明无需保留时前进，所以算法不会漏掉最短合法区间。

## 嵌套循环的线性复杂度

代码中虽然有 `for` 套 `while`，但不能直接据此写成 $O(n^2)$。

- `r` 从 `1` 增加到 `n`，总共移动 $n$ 次；
- `l` 只向右移动，每个数组位置最多被删除一次，总共也至多移动 $n$ 次；
- 加入和删除一个元素都只做 $O(1)$ 次运算。

因此总时间复杂度是 $O(n)$，额外空间复杂度是 $O(1)$。滑动窗口的关键不是有没有嵌套循环，而是两个端点都不会回退。

## 正数条件

本文要求 `a[i] > 0`，因为移动端点必须对窗口和产生可预测的影响：扩展右端会增大和，收缩左端会减小和。

若元素允许为 `0`，这份算法仍然正确：端点移动时窗口和可能保持不变，但不会向相反方向变化，每个位置仍只加入和删除一次。

若数组含有负数，结论就会失效。例如窗口和小于目标值时，删除一个负数反而可能让和增大；窗口和达到目标值后，未来加入负数也可能让更长区间的和减小。此时不能照搬本篇的移动规则，需要根据新问题建立其他结构。

例如：

```text
a = 1 -1 5
target = 5
```

右端到达 `3` 时，窗口 `[1, 3]` 的和是 $5$，算法先记录长度 $3$。删除 `a[1] = 1` 后，窗口和降为 $4$，于是停止收缩；但若继续删除负数 `a[2] = -1`，真正的最短窗口 `[3, 3]` 的和会重新增加到 $5$。这正是正数条件消失后，原有停止条件不再可靠的地方。

滑动窗口不是“看见连续区间就套模板”。使用前必须证明：某个端点移动后，被丢弃的状态不会在未来重新变得更优。

## 固定长度窗口

若题目规定区间长度恰好为 `k`，窗口不需要根据数值条件反复收缩。每当右端加入一个元素，若长度超过 `k`，就删除唯一多出的左端元素：

```cpp
sum += a[r];
if (r > k) {
    sum -= a[r - k];
}
```

当 `r >= k` 时，`sum` 就是长度为 `k` 的区间 `[r - k + 1, r]` 的和。固定长度窗口同样让每个元素只加入一次、删除一次，因此也是 $O(n)$。

本篇主问题中的窗口长度可变，所以左端由 `while (sum >= target)` 决定；固定长度窗口的左端则完全由 `r` 和 `k` 决定。两者共同点都是在端点移动时增量维护区间状态，不重新扫描整个区间。

## 完整代码

下面的程序读入正整数数组，输出和至少为 `target` 的最短非空连续子数组长度；不存在时输出 `0`。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

int minimum_length(const vector<int>& a, int n, ll target) {
    int l = 1;
    ll sum = 0;
    int answer = n + 1;

    for (int r = 1; r <= n; r++) {
        sum += a[r];

        while (sum >= target) {
            answer = min(answer, r - l + 1);
            sum -= a[l];
            l++;
        }
    }

    if (answer == n + 1) {
        return 0;
    }
    return answer;
}

int main() {
    int n;
    ll target;
    scanf("%d%lld", &n, &target);

    vector<int> a(n + 5);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &a[i]);
    }

    printf("%d\n", minimum_length(a, n, target));
    return 0;
}
```

输入：

```text
7 7
2 3 1 2 4 3 1
```

输出：

```text
2
```

## 常见错误

### 只收缩一次

一个右端可能对应多段合法区间。使用 `if` 只删除一次，会错过继续缩短后仍然合法的区间；应当使用 `while` 收缩到条件不再成立。

### 删除以后才更新答案

删除 `a[l]` 可能让窗口立即变得不合法。必须先记录当前合法长度，再修改 `sum` 和 `l`。

### 长度漏写加一

本书使用闭区间 `[l, r]`，长度是 `r - l + 1`，不是 `r - l`。

### 使用 32 位整数保存窗口和

窗口可能包含许多 32 位整数，总和应当使用 64 位整数。

### 忘记转换失败哨兵

`n + 1` 只是函数内部表示“尚未找到”的哨兵。题目要求不存在时输出 `0`，返回前必须完成转换。

### 对含负数数组直接套用

负数会破坏“扩展不减、收缩不增”的单调关系。端点移动规则必须根据题目的真实条件重新证明。

## 基础练习

1. 手动完成示例表，分别记录每次加入和删除后的 `l`、`r`、`sum` 与 `answer`。
2. 测试单个元素恰好达到目标、所有元素之和仍不足、答案为整个数组和存在多个最短区间的情况。
3. 把滑动窗口与两层枚举随机对拍，验证最短长度一致。
4. 构造总和超出 32 位整数的数组，检查 `sum` 的类型。
5. 找出长度恰好为 `k` 的连续子数组最大和，只在端点变化时加入或删除一个元素。
6. 将输入放宽为非负整数，用包含许多 `0` 的数据验证端点仍然不会回退。
7. 构造一个含负数的反例，说明本文移动规则为什么会漏掉答案。

## 需要记住什么

1. 滑动窗口用哪两个端点表示当前连续区间？窗口状态为什么可以增量维护？
2. 当前窗口和小于目标值时，为什么不能继续移动左端？
3. 当前窗口和达到目标值时，为什么要先更新答案再删除左端？
4. 收缩为什么必须使用 `while` 而不是 `if`？
5. 一个已经删除的左端为什么不可能在未来得到更短答案？
6. 代码含有嵌套循环，为什么总时间复杂度仍然是 $O(n)$？
7. 正数或非负数条件为端点移动提供了什么单调性？负数为什么会破坏它？
8. 固定长度窗口和可变长度窗口怎样决定左端？它们共同维护了什么？
9. 闭区间 `[l, r]` 的长度怎样计算？不存在答案时怎样表示？

# 排序：归并排序

> 最近修订：2026-08-13 20:22 +10:00（未审阅）

[排序：快速排序](quicksort.md) 先把原区间分到基准值两侧，再递归排序两个仍然无序的部分。归并排序采用另一种分治顺序：先递归把左右两半分别排好，再把两个有序区间合并成一个更大的有序区间。

归并排序的关键不是“把数组从中间切开”，而是回答：已经有两个有序序列时，怎样在线性时间内得到它们的有序合并结果？

## 合并两个有序序列

假设有两个已经升序排列的序列：

```text
left:  1 4 7
right: 2 3 8
```

整个结果中的最小值一定是两个序列当前首元素中更小的那个：这里比较 `1` 与 `2`，先取 `1`。

取走 `1` 后，左侧剩余 `4 7`，右侧仍是 `2 3 8`。下一项只需要比较新的两个首元素 `4` 与 `2`，取走 `2`。重复这个过程：

| 左侧当前值 | 右侧当前值 | 取出 | 已合并结果 |
| ---: | ---: | ---: | --- |
| 1 | 2 | 1 | `1` |
| 4 | 2 | 2 | `1 2` |
| 4 | 3 | 3 | `1 2 3` |
| 4 | 8 | 4 | `1 2 3 4` |
| 7 | 8 | 7 | `1 2 3 4 7` |

左侧已经取完，右侧剩余的 `8` 直接接到末尾，得到：

```text
1 2 3 4 7 8
```

每个元素只被取出一次，因此合并两个总长度为 $n$ 的有序序列只需要 $O(n)$ 时间，而不是重新做平方数量级的比较。

## 三个位置变量

对相邻的两个有序闭区间 `a[l..mid]`、`a[mid+1..r]`，需要三个位置：

- `i`：左半区当前尚未合并的第一个元素；
- `j`：右半区当前尚未合并的第一个元素；
- `position`：临时数组中下一个写入位置。

初始化为：

```cpp
int i = l;
int j = mid + 1;
int position = l;
```

只要两边都还有元素，就比较 `a[i]` 与 `a[j]`：

```cpp
while (i <= mid && j <= r) {
    if (a[i] <= a[j]) {
        temporary[position++] = a[i++];
    } else {
        temporary[position++] = a[j++];
    }
}
```

每次把两个候选首元素中更小的一个写入结果，并让对应指针向后移动。`position` 也同时向后移动，保证结果连续写入。

## 为什么局部选择正确

左半区已经有序，所以 `a[i]` 是左侧所有剩余元素的最小值；右半区同理，`a[j]` 是右侧所有剩余元素的最小值。

整个未合并部分的最小值因此只能是二者中更小的一个。把它放到下一个结果位置不会错过任何更小元素。写入后，问题重新变成“合并两个更短的有序后缀”，相同理由可以继续使用。

在合并循环的每一步，`temporary[l..position-1]` 已经是所有取出元素的有序排列，而且这些值不大于两侧尚未取出的元素。这就是合并过程保持的不变量。

## 处理剩余元素

主循环在其中一边用完时停止。另一边本身已经有序，而且其中所有元素都不小于已经写入的结果，因此可以依次复制：

```cpp
while (i <= mid) {
    temporary[position++] = a[i++];
}

while (j <= r) {
    temporary[position++] = a[j++];
}
```

两段 `while` 中最多只有一段会实际执行。完成后，`temporary[l..r]` 是整个区间的升序排列。

## 写回原数组

合并时不能直接不断写入 `a[l..r]`。若先覆盖了左半区尚未读取的位置，原来的元素会丢失。因此先写入独立的临时数组，全部合并完成后再复制回去：

```cpp
for (int k = l; k <= r; k++) {
    a[k] = temporary[k];
}
```

一次 `merge` 的完整实现是：

```cpp
void merge(vector<int>& a, vector<int>& temporary, int l, int mid, int r) {
    int i = l;
    int j = mid + 1;
    int position = l;

    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) {
            temporary[position++] = a[i++];
        } else {
            temporary[position++] = a[j++];
        }
    }

    while (i <= mid) {
        temporary[position++] = a[i++];
    }
    while (j <= r) {
        temporary[position++] = a[j++];
    }

    for (int k = l; k <= r; k++) {
        a[k] = temporary[k];
    }
}
```

## 稳定性来自等号

当 `a[i] == a[j]` 时，两个值按照排序关键字等价。代码使用 `a[i] <= a[j]`，优先取原数组中位于左半区的元素。

左右半区分别保持了各自内部相等元素的原顺序；合并时又让原来更靠左的等值元素先进入结果，所以整个归并排序稳定。

若把条件写成 `a[i] < a[j]`，相等时会先取右半区元素，跨越左右分界的等值记录就会颠倒顺序，失去稳定性。对纯整数输出看不出区别，但对带有原编号的记录会产生不同结果。

## 递归拆分

要排序闭区间 `a[l..r]`：

- 若 `l >= r`，区间最多一个元素，已经有序；
- 否则在 `mid` 处分成 `a[l..mid]` 与 `a[mid+1..r]`；
- 递归排序左半区；
- 递归排序右半区；
- 合并两个已经有序的半区。

```cpp
void merge_sort(vector<int>& a, vector<int>& temporary, int l, int r) {
    if (l >= r) {
        return;
    }

    int mid = l + (r - l) / 2;
    merge_sort(a, temporary, l, mid);
    merge_sort(a, temporary, mid + 1, r);
    merge(a, temporary, l, mid, r);
}
```

递归调用返回时，它负责的闭区间已经有序。两个子调用分别保证左右半区有序，随后 `merge` 保证完整 `a[l..r]` 有序。这是归并排序在每一层保持的递归不变量。

## 正确性

可以按区间长度归纳：

- 长度不超过 $1$ 时，区间天然有序；
- 假设所有更短区间都能被正确排序；
- 当前区间的左右两半更短，因此两个递归调用结束后分别有序；
- 合并过程每次取两个剩余最小值中更小者，得到包含左右全部元素的有序结果；
- 写回后，当前区间有序且元素没有增加或丢失。

因此从最短区间向上，每个递归调用都正确；最外层 `a[1..n]` 最终有序。

## 时间复杂度

每次把长度约为 $n$ 的区间分成两半，因此递归树深度是 $O(\log n)$。

在递归树的同一层，若干区间互不重叠，它们的总长度仍为 $n$。每个区间只在线性合并中处理一次元素，所以每层总工作量是 $O(n)$。

共有 $O(\log n)$ 层，每层 $O(n)$，因此无论原数组是升序、逆序还是随机排列，归并排序的时间复杂度都是：

$$
O(n\log n)
$$

这与快速排序不同：归并排序不会因为分区极不均衡退化到 $O(n^2)$，但它需要额外的临时存储。

## 空间复杂度

临时数组 `temporary` 与原数组长度相同，需要 $O(n)$ 空间。递归每次把区间减半，调用栈深度为 $O(\log n)$，每层只保存固定数量的边界和指针。

总额外空间是：

$$
O(n)+O(\log n)=O(n)
$$

临时数组应当在最外层只建立一次，并通过引用传给所有递归调用。若在每个 `merge_sort` 调用中重新建立与区间同长的 `vector`，不仅增加分配开销，也让实现的真实空间行为更难分析。

## 与快速排序比较

| 性质 | 快速排序基础实现 | 归并排序基础实现 |
| --- | --- | --- |
| 核心顺序 | 先分区，再递归 | 先递归，再合并 |
| 平均时间 | $O(n\log n)$ | $O(n\log n)$ |
| 最坏时间 | $O(n^2)$ | $O(n\log n)$ |
| 主要额外空间 | 递归栈 | $O(n)$ 临时数组 |
| 稳定性 | 不稳定 | 稳定 |

数组上的快速排序通常具有很好的原地性能；归并排序则提供稳定且确定的 $O(n\log n)$ 时间，并自然扩展到逆序对计数、链表排序和外部排序等问题。普通竞赛代码只需要得到排序结果时，仍优先调用 `std::sort`。

## 完整代码

下面的程序使用共享临时数组，对 1-based 闭区间 `a[1..n]` 进行归并排序。空数组调用 `merge_sort(a, temporary, 1, 0)` 时立即返回。

```cpp
#include <bits/stdc++.h>
using namespace std;

void merge(vector<int>& a, vector<int>& temporary, int l, int mid, int r) {
    int i = l;
    int j = mid + 1;
    int position = l;

    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) {
            temporary[position++] = a[i++];
        } else {
            temporary[position++] = a[j++];
        }
    }

    while (i <= mid) {
        temporary[position++] = a[i++];
    }
    while (j <= r) {
        temporary[position++] = a[j++];
    }

    for (int k = l; k <= r; k++) {
        a[k] = temporary[k];
    }
}

void merge_sort(vector<int>& a, vector<int>& temporary, int l, int r) {
    if (l >= r) {
        return;
    }

    int mid = l + (r - l) / 2;
    merge_sort(a, temporary, l, mid);
    merge_sort(a, temporary, mid + 1, r);
    merge(a, temporary, l, mid, r);
}

int main() {
    int n;
    scanf("%d", &n);

    vector<int> a(n + 5);
    vector<int> temporary(n + 5);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &a[i]);
    }

    merge_sort(a, temporary, 1, n);

    for (int i = 1; i <= n; i++) {
        if (i > 1) {
            printf(" ");
        }
        printf("%d", a[i]);
    }
    printf("\n");
    return 0;
}
```

输入：

```text
8
5 1 4 2 3 3 -1 8
```

输出：

```text
-1 1 2 3 3 4 5 8
```

## 常见错误

### 子区间还没排好就合并

`merge` 的前提是 `a[l..mid]` 与 `a[mid+1..r]` 已经分别有序。因此递归调用必须位于合并之前。

### 主循环后遗漏剩余元素

两边中只有一边会先用完，另一边的剩余部分仍要完整复制到临时数组。

### 合并时直接覆盖原数组

合并过程中左右指针还要继续读取原区间。过早写回 `a` 可能覆盖尚未使用的元素，因此先写 `temporary`，完成后统一复制。

### 相等时先取右边

稳定实现使用 `a[i] <= a[j]`，相等时保留左半区元素在前。使用严格 `<` 仍能得到数值有序结果，但不再保证稳定。

### 每层重新分配临时数组

在 `main` 中建立一次 `temporary(n + 5)`，所有递归调用通过引用复用。不要在每个递归节点重新分配大型容器。

### 混淆闭区间边界

左半区是 `[l,mid]`，右半区是 `[mid+1,r]`，复制和剩余循环都包含各自右端。本篇不混用 STL 的左闭右开区间。

## 需要记住什么

1. 两个有序序列的下一个最小值为什么一定在两个当前首元素中？
2. `i`、`j`、`position` 分别表示什么？主循环什么时候停止？
3. 一侧用完后，为什么另一侧可以直接复制？
4. 为什么合并时需要先写临时数组，再复制回原数组？
5. 相等时优先选择左半区怎样保证稳定性？
6. 归并排序为什么先递归再合并？每个调用返回时保证什么？
7. 为什么每层合并总工作量是 $O(n)$？递归树有多少层？
8. 归并排序的时间与额外空间复杂度分别是多少？是否依赖输入原有顺序？
9. 快速排序与归并排序在最坏时间、额外空间和稳定性上怎样取舍？

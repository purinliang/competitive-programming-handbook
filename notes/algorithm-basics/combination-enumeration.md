# 组合枚举

> 最近修订：2026-08-16 16:08 +10:00（未审阅）

[排列枚举](permutation-enumeration.md) 关心元素出现的先后顺序，所以 `[1, 3, 4]` 与 `[4, 1, 3]` 是两个不同排列。许多题目只要求从若干元素中选出一组，选择顺序没有意义；若仍按排列生成，同一组元素会重复出现许多次。

本篇用严格递增的下标序列为每个集合规定唯一表示，再把这条规则写进递归参数和循环边界，直接生成固定大小的全部组合。

## 从 n 个数中选择 k 个

给定整数 `n,k`，按照字典序输出从 `1..n` 中选择 `k` 个不同整数得到的全部组合。组合内部按照递增顺序输出。

当 `n = 5,k = 3` 时，答案是：

```text
1 2 3
1 2 4
1 2 5
1 3 4
1 3 5
1 4 5
2 3 4
2 3 5
2 4 5
3 4 5
```

`{1, 2, 3}` 只有一行表示。`2 1 3`、`3 2 1` 等其他顺序描述的是同一个集合，不能再次输出。

## 从排列中过滤

一种直接办法是先枚举 `1..n` 中任意 `k` 个互不相同数字的有序序列，再忽略顺序。

这样的序列数量是：

$$
n(n-1)\cdots(n-k+1).
$$

每个包含 `k` 个元素的集合会按照 $k!$ 种顺序重复出现。可以只保留满足

$$
choice[1]<choice[2]<\cdots<choice[k]
$$

的序列，但其他顺序已经被完整生成，浪费了绝大部分搜索。

更好的方法是在构造过程中始终保持严格递增。这样每个集合只会沿唯一的一条路径出现。

## 唯一的递增表示

任意包含 `k` 个不同整数的集合，都可以把元素从小到大排列成唯一序列：

$$
x_1<x_2<\cdots<x_k.
$$

因此可以直接把组合定义成一个严格递增序列。进入 `dfs(position, minimum)` 时维护：

1. `choice[1..position-1]` 已经严格递增；
2. `minimum` 是当前位置允许选择的最小值；
3. 位置 `position..k` 还没有确定。

初始调用是：

```cpp
dfs(1, 1);
```

第一个位置可以从 `1` 开始选择。若当前位置选了 `value`，下一位置必须比它大，所以递归调用为：

```cpp
choice[position] = value;
dfs(position + 1, value + 1);
```

严格递增已经保证同一个数字不会重复，因此不再需要排列枚举中的 `used` 数组。

## 最基本的循环边界

当前位置的候选从 `minimum` 到 `n`：

```cpp
for (int value = minimum; value <= n; value++) {
    choice[position] = value;
    dfs(position + 1, value + 1);
}
```

这份写法能够得到正确答案，但可能进入明知无法填满剩余位置的状态。

例如 `n = 5,k = 3`，第一位若选择 `5`，后面还需要两个更大的数，却已经没有候选。递归最终不会输出错误答案，但这条分支从一开始就不可能完成。

## 给剩余位置留出数字

正在填写位置 `position` 时，选完当前值以后还剩

$$
k-position
$$

个位置。这些位置都需要使用比当前值更大的数字。

若当前选择 `value`，它后面一共有 `n - value` 个整数。必须满足：

$$
n-value\ge k-position.
$$

移项得到：

$$
value\le n-(k-position).
$$

于是当前位置的最大候选是：

```cpp
int maximum = n - (k - position);
```

循环改为：

```cpp
for (int value = minimum; value <= maximum; value++) {
    choice[position] = value;
    dfs(position + 1, value + 1);
}
```

这个边界不是为了背诵的技巧，而是把“后面还要填多少个位置”翻译成当前选择必须保留的空间。它只排除不可能完成的前缀，不会删掉任何合法组合。

## 为什么不需要撤销标记

排列枚举通过共享数组 `used` 限制后续选择，因此离开分支时必须恢复标记。

组合枚举把限制放进函数参数 `minimum`。每次递归都按值传入新的 `value + 1`；返回父调用后，父调用自己的 `minimum` 没有改变。`choice[position]` 也会在下一个候选开始时被覆盖。

所以本篇仍然在遍历一棵选择树，却没有额外共享状态需要显式撤销。是否出现一行“撤销代码”，取决于状态怎样保存，不决定一个算法是否属于回溯搜索。

## 完整组合

当 `position == k + 1` 时，位置 `1..k` 都已经确定，应当输出当前组合：

```cpp
if (position == k + 1) {
    for (int i = 1; i <= k; i++) {
        printf("%d", choice[i]);
        if (i == k) {
            printf("\n");
        } else {
            printf(" ");
        }
    }

    if (k == 0) {
        printf("\n");
    }
    return;
}
```

当 `k = 0` 时，空集也是唯一的组合。循环不会输出数字，因此单独输出一个换行表示空组合。普通竞赛题若只要求计数，终止状态直接让答案增加 `1` 即可。

## 不遗漏也不重复

证明 `dfs(position, minimum)` 恰好生成所有以当前前缀开头、后续元素不小于 `minimum` 的合法组合。

当 `position == k + 1` 时，已经选择 `k` 个严格递增的 `1..n` 中整数，它们构成唯一完整组合，函数输出一次。

对于尚未完成的状态，任意合法组合在当前位置都有唯一的下一个值 `value`。它必须满足 `value >= minimum`；因为组合还要放下剩余元素，也必然满足 `value <= maximum`。循环会经过这个值，因此不会遗漏。

不同循环分支在当前位置选择不同的值，最终组合的递增序列也不同，所以不会重复。每个无序集合又只有一个递增排列，因此同一组元素不会通过另一种顺序再次生成。

## 复杂度

从 `n` 个元素中选择 `k` 个的组合数量是：

$$
\binom{n}{k}.
$$

输出每个组合需要写出 `k` 个数字，所以包含输出的时间复杂度是：

$$
O\left(k\binom{n}{k}\right).
$$

`choice` 和递归调用栈都只需要 $O(k)$ 空间。

当 `k` 接近 `n / 2` 时，组合数量可能很大。直接生成全部组合以前仍需估算候选规模；严格递增只消除了重复顺序，不会让真实存在的组合消失。

## 与位掩码枚举的比较

[子集与位掩码枚举](subset-bitmask-enumeration.md) 会生成全部 $2^n$ 个子集，再检查每个子集选择了多少元素。它适合需要同时处理所有大小的子集，或者每个候选天然需要一个位掩码状态的题目。

本篇只生成大小恰好为 `k` 的组合，候选数是 $\binom{n}{k}$。当 `k` 很小而 `n` 相对较大时，直接组合枚举通常比遍历全部掩码更合适。

选择方法前应先确定候选对象：题目需要所有子集，还是只需要固定大小的组合。两种方法都正确，但实际生成的状态数量不同。

## 完整代码

输入保证 `0 <= k <= n <= 20`：

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
int k;
vector<int> choice;

void dfs(int position, int minimum) {
    if (position == k + 1) {
        for (int i = 1; i <= k; i++) {
            printf("%d", choice[i]);
            if (i == k) {
                printf("\n");
            } else {
                printf(" ");
            }
        }

        if (k == 0) {
            printf("\n");
        }
        return;
    }

    int maximum = n - (k - position);

    for (int value = minimum; value <= maximum; value++) {
        choice[position] = value;
        dfs(position + 1, value + 1);
    }
}

void solve() {
    scanf("%d%d", &n, &k);
    choice.assign(k + 5, 0);
    dfs(1, 1);
}

int main() {
    solve();
    return 0;
}
```

## 常见错误

### 仍然枚举所有顺序

先生成排列再排序或去重，会让每个组合重复 $k!$ 次。若顺序没有意义，应从一开始就规定递增的唯一表示。

### 下一层仍从 minimum 开始

选中 `value` 后，下一层必须从 `value + 1` 开始。若仍传入原来的 `minimum`，数字会重复并且序列不再严格递增。

### 最大候选少减或多减一

当前位置之后还剩 `k - position` 个位置，因此当前值最多是 `n - (k - position)`。最可靠的方法是重新写出“剩余数字个数不少于剩余位置个数”的不等式，而不是背一个容易错位的公式。

### 忘记空组合

当题目允许 `k = 0` 时，选择零个元素有且只有一种方案：空集。计数程序的终止状态应贡献 `1`，输出程序则可以用一个空行表示。

### 把组合数当成多项式

$\binom{n}{k}$ 在 `k` 接近 `n / 2` 时增长很快。即使递归没有重复分支，输出全部答案仍然可能不可行。

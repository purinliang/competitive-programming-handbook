# 状态空间与隐式图

> 最近修订：2026-08-16 16:03 +10:00（未审阅）

[枚举](enumeration.md) 通过循环直接生成候选，[图的深度优先搜索](../graph-theory/graph-depth-first-search.md) 则沿邻接表访问已经给出的点和边。许多搜索题恰好位于两者之间：题目没有给出一张图，却允许我们连续做出若干选择。

本篇用“输出所有 01 序列”建立连接两种写法的共同模型：一个尚未完成的方案就是一个状态，一次合法选择就是一条边。只要能够从当前状态生成下一步，就可以直接遍历这张没有显式存下来的图。

## 长度可变的枚举

给定正整数 `n`，按照字典序输出所有长度为 `n`、每一位只能是 `0` 或 `1` 的序列。

当 `n = 3` 时，答案是：

```text
000
001
010
011
100
101
110
111
```

每个位置有两种选择，共有 $2^n$ 个完整序列。

若 `n` 固定为 `3`，可以写三层循环：

```cpp
for (int first = 0; first <= 1; first++) {
    for (int second = 0; second <= 1; second++) {
        for (int third = 0; third <= 1; third++) {
            printf("%d%d%d\n", first, second, third);
        }
    }
}
```

但循环层数已经写进源代码。输入中的 `n` 改变时，程序不能在运行期间自动增加或删除几层 `for`。真正需要抽象的是“当前已经决定了多少位”，而不是提前写死每一层。

## 部分方案就是状态

使用 `choice[1..n]` 保存当前序列，令 `position` 表示下一次要决定的位置。进入 `dfs(position)` 时：

- `choice[1..position-1]` 已经确定；
- `choice[position..n]` 还没有确定；
- 当前函数负责尝试位置 `position` 的所有合法取值。

例如 `n = 3` 时，状态可以排列成一棵树：

```text
空序列
├── 0
│   ├── 00
│   │   ├── 000
│   │   └── 001
│   └── 01
│       ├── 010
│       └── 011
└── 1
    ├── 10
    │   ├── 100
    │   └── 101
    └── 11
        ├── 110
        └── 111
```

根节点表示还没有决定任何位置。深度为 `k` 的状态保存一个长度为 `k` 的前缀；从它出发的两条边分别表示在末尾追加 `0` 或 `1`。

这里的“点”不是输入中的整数编号，而是一个部分方案。状态的全部信息由已经确定的前缀和下一个位置共同描述。

## 选择生成边

在位置 `position` 依次尝试 `0` 和 `1`：

```cpp
for (int value = 0; value <= 1; value++) {
    choice[position] = value;
    dfs(position + 1);
}
```

执行 `choice[position] = value` 相当于沿一条边走到新的状态。递归调用处理更长的前缀；调用返回以后，循环再生成另一条出边。

这张树不需要提前建立邻接表。每个状态的后继都能由“当前位置可以填 `0` 或 `1`”这一规则立即产生，所以它是一张**隐式图**：点和边由问题规则定义，程序只在访问状态时生成所需邻居。

与之相对，普通图遍历中的边来自输入，必须先保存到 `g[u]` 等结构中。两者使用相同的 DFS 过程，但取得下一条边的方式不同。

## 完整序列是终止状态

当 `position == n + 1` 时，位置 `1..n` 已经全部确定。这个状态对应一个完整答案，应当输出后立即返回：

```cpp
if (position == n + 1) {
    for (int i = 1; i <= n; i++) {
        printf("%d", choice[i]);
    }
    printf("\n");
    return;
}
```

终止条件写成 `n + 1`，是因为 `position` 表示“下一次要处理的位置”。进入第 `n + 1` 层时，最后一个真实位置 `n` 已经在上一层完成。

若在 `position == n` 时就输出，最后一位还没有选择；若终止后不返回，程序还会尝试写入不存在的 `choice[n + 1]`。

## 为什么不需要访问标记

显式图可能有环，同一个点也可能从不同路径到达，因此图 DFS 通常使用 `vis[u]` 防止重复访问和无限递归。

本题每走一条边都会把前缀长度增加 `1`。状态不可能回到更短的前缀；每个具体前缀也只有唯一的上一个前缀。因此隐式状态图是一棵树，没有环，也不会从两条不同路径到达同一个状态，不需要 `vis`。

“隐式图”并不自动表示没有环。若状态是棋盘位置、字符串或某个数值，一次操作可能回到已经出现过的状态，仍然需要访问标记。是否标记由状态转移关系决定，不能只看代码是否使用邻接表。

## 循环枚举、DFS 枚举与图 DFS

三种写法的区别可以放在同一张表里：

| 方法 | 候选或点怎样表示 | 下一步从哪里来 | 是否通常需要 `vis` |
| --- | --- | --- | --- |
| 固定循环枚举 | 若干个循环变量 | 源代码中写死的下一层循环 | 不需要 |
| DFS 枚举 | 部分方案 | 当前状态允许的下一项选择 | 状态树无环时不需要 |
| 显式图 DFS | 点编号 `u` | 已经存入 `g[u]` 的边 | 图可能有环，通常需要 |

DFS 枚举不是另一种毫无关系的 DFS。它仍然从一个状态出发，访问每条出边，再继续处理到达的状态；只是这张图由选择规则隐式定义。

以后学习回溯时，还会在离开一条边以后撤销它对共享状态的影响。当前例子中 `choice[position]` 会在尝试下一项时被直接覆盖，旧值不影响任何更浅层状态，因此暂时没有需要显式撤销的标记。

## 正确性

证明 `dfs(position)` 会恰好输出所有以 `choice[1..position-1]` 为前缀的长度为 `n` 的 01 序列。

当 `position == n + 1` 时，前缀长度已经是 `n`，符合此前选择的完整序列只有当前 `choice[1..n]`，函数输出一次后返回，结论成立。

假设更深一层的调用都符合结论。任意以当前前缀开头的完整序列，其第 `position` 位只能是 `0` 或 `1`：

- 循环选择 `0` 时，`dfs(position + 1)` 恰好输出这一位为 `0` 的全部序列；
- 循环选择 `1` 时，`dfs(position + 1)` 恰好输出这一位为 `1` 的全部序列。

两类互不重合，并且覆盖全部可能，所以当前调用不会遗漏或重复。由归纳可知，初始调用 `dfs(1)` 恰好输出全部长度为 `n` 的 01 序列。

## 复杂度

共有 $2^n$ 个完整序列，输出每个序列需要写出 `n` 个字符，所以仅输出答案就需要

$$
O(n2^n)
$$

时间。递归还会访问所有非叶状态，但整棵二叉树的点数小于 $2^{n+1}$，不会改变包含输出成本后的复杂度。

`choice` 和递归调用栈都最多保存 `n` 层，额外空间复杂度是 $O(n)$。输出规模本身已经是指数级；DFS 只让状态生成适应可变的 `n`，不会减少答案数量。

## 完整代码

输入保证 `1 <= n <= 20`。实际题目还会根据输出限制给出更小的 `n`；这里的上界只保证位数和递归深度很小。

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
vector<int> choice;

void dfs(int position) {
    if (position == n + 1) {
        for (int i = 1; i <= n; i++) {
            printf("%d", choice[i]);
        }
        printf("\n");
        return;
    }

    for (int value = 0; value <= 1; value++) {
        choice[position] = value;
        dfs(position + 1);
    }
}

void solve() {
    scanf("%d", &n);
    choice.assign(n + 5, 0);
    dfs(1);
}

int main() {
    solve();
    return 0;
}
```

## 常见错误

### 把循环层数写死

固定三层循环只能处理长度为 `3` 的序列。输入决定选择次数时，应把“已经处理到哪一层”放进状态。

### 混淆当前位置与已选数量

本文的 `position` 是下一次要写入的位置，所以完整状态满足 `position == n + 1`。若改用“已经选择了多少项”作为参数，终止条件会变成 `count == n`；定义不同，边界也必须跟着改变。

### 无条件添加访问标记

当前状态树没有环，而且每个前缀只有唯一父状态。加入一个只按 `position` 标记的 `vis` 反而会把同一深度的不同前缀错误合并。

### 误以为 DFS 降低了指数复杂度

程序必须输出全部 $2^n$ 个序列，任何正确算法都至少需要与输出量相当的时间。DFS 改善的是表示和组织方式，不是候选数量。

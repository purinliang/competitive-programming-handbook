# 贪心选择与正确性证明

> 最近修订：2026-08-17 10:16 +10:00（未审阅）

有些问题需要连续作出多次选择。贪心算法每一步只根据当前情况选择一个
看起来最好的选项，不再回头修改，希望这些局部选择最终组成全局最优解。

“看起来最好”只是候选规则，不是正确性证明。一个贪心选择真正安全，必须说明：
即使现在固定这个选择，也仍然至少保留一组全局最优解。

## 最少纸币数量

一台自助设备只使用 `100`、`10` 和 `1` 元三种纸币。给定一个非负整数金额
`amount`，用尽量少的纸币恰好支付这个金额。

例如 `amount = 126`时，可以使用：

```text
1 张 100 元 + 2 张 10 元 + 6 张 1 元
```

一共需要 `9` 张。

这里的面额不是为了排除其他算法而添加的奇怪限制。它描述了真实的找零和拆分
场景，而且每个大面额恰好等于十个下一级面额，这条结构正好能够证明贪心选择。

## 每次选择最大面额

对当前剩余金额，先尽量使用 `100` 元纸币，再处理余数；接着尽量使用
`10` 元纸币，最后才使用 `1` 元纸币。

整数除法给出当前面额能够使用的最大张数，余数则是交给更小面额的剩余金额：

```cpp
ll hundreds = amount / 100;
amount %= 100;

ll tens = amount / 10;
amount %= 10;

ll ones = amount;
```

对 `126` 的处理过程是：

| 当前面额 | 剩余金额 | 选择张数 | 新的剩余金额 |
| ---: | ---: | ---: | ---: |
| 100 | 126 | 1 | 26 |
| 10 | 26 | 2 | 6 |
| 1 | 6 | 6 | 0 |

算法没有枚举“少用一张 `100` 元会不会更好”，而是直接固定当前能使用的
最多张数。这就是本题的贪心选择。

## 为什么可以尽量使用大面额

先只比较 `10` 元和 `1` 元。若一组方案同时使用了至少十张 `1` 元纸币，就可以
把其中十张换成一张 `10` 元：

- 支付的总金额不变；
- 纸币数量减少九张。

因此，任何最优方案都不会留下十张或更多 `1` 元纸币。它必须先使用尽量多的
`10` 元纸币，只把不足 `10` 元的余数交给 `1` 元。

同理，十张 `10` 元可以换成一张 `100` 元，金额不变而纸币数量减少。所以任何
最优方案都必须先使用尽量多的 `100` 元纸币。

这是一次交换证明：若某个候选解没有遵守贪心选择，就用一次交换把它改成遵守
该选择的方案，并且证明答案不会变差。本例中交换后甚至严格使用了更少的纸币。

## 剩余问题

确定 `100` 元纸币的张数后，剩余金额不足 `100`，问题变成“只用 `10` 和
`1` 元纸币完成支付”。目标仍是使用尽量少的纸币，只是候选面额变少了。

每一步都需要同时检查两件事：

1. 当前选择能否通过交换或其他论证保留最优解；
2. 做出选择后，剩余部分是否仍然是结构相同的更小问题。

只有两点都成立，才能不断重复局部选择。

## 完整代码

输入一个能够由 64 位整数保存的非负整数金额，输出最少纸币数量：

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

void solve() {
    ll amount;
    cin >> amount;

    const int denomination[3] = {100, 10, 1};
    ll answer = 0;

    for (int i = 0; i < 3; i++) {
        answer += amount / denomination[i];
        amount %= denomination[i];
    }

    cout << answer << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
126
```

输出：

```text
9
```

面额数量记为 $k$ 时，从大到小扫描一次需要 $O(k)$ 时间，只使用固定数量的额外
变量。本题的 $k=3$ 是固定常数，因此也可以把总运行时间写成 $O(1)$。

## 贪心规则不能随意搬用

把面额改成 `4`、`3`、`1`，支付 `6` 时，优先选最大面额会得到：

```text
4 + 1 + 1
```

一共三枚；最优方案却是：

```text
3 + 3
```

只需两枚。原证明使用了“十个下一级面额恰好能换成一个上一级面额”的结构；
面额改变后，这个交换理由不再成立，结论也随之失效。

贪心规则总是与具体问题结构和目标绑定。在一道新题中看见“选最大”、“选最小”
或“选最早”都不能立即得出贪心结论；先尝试构造反例，再寻找能够保留最优解的证明。

## 基础练习

1. 对金额 `305`、`99` 和 `0` 手算贪心过程。
2. 把面额改成 `1000`、`100`、`10`、`1`，修改程序并重新说明交换理由。
3. 在面额 `4`、`3`、`1` 中，再找一个“优先选最大面额”不是最优的金额。
4. 把目标从“纸币数量最少”改成“使用的面额种类最少”，思考原证明是否仍然适用。

## 需要记住什么

1. 贪心算法的局部选择有什么特点？为什么看起来合理还不够？
2. 本题为什么先尽量使用 `100` 元纸币？
3. 交换十张小面额纸币时，哪些量保持不变，哪个目标变得更好？
4. 确定一种大面额的张数后，剩余部分为什么仍然是同类问题？
5. 面额 `4`、`3`、`1` 为什么能否定“找零一定先选最大面额”这个泛化结论？
6. 面对新的贪心规则时，为什么要先寻找反例，再给出保留最优解的证明？

后面的贪心单元会学习需要排序、交换顺序或允许撤销早期选择的更完整模型。
当前只需建立一条底线：贪心选择必须由问题结构证明，不能由样例或直觉决定。

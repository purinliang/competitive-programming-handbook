# 贪心选择与正确性证明

> 最近修订：2026-08-16 15:42 +10:00（未审阅）

有些问题需要从许多候选项中逐个选择，最终构造一个合法答案。贪心算法每一步只根据当前信息作出一个不可撤销的选择，希望这些局部选择最终组成全局最优解。

“看起来最好”不是证明。一个正确的贪心规则必须回答：为什么现在选择它以后，仍然至少存在一个全局最优解？本篇用最多不重叠区间问题，完整推导一次贪心选择和交换论证。

## 最多不重叠区间

给定 $n$ 个闭区间 `[l, r]`，选择尽量多的区间，使任意两个被选区间都不重叠。

本篇采用闭区间约定。若一个已选区间的右端是 `last_right`，下一个区间必须满足：

```cpp
current.l > last_right
```

端点相等表示两个闭区间共享这个点，仍然算重叠。

例如：

```text
[1, 4]  [3, 5]  [5, 7]  [8, 9]
```

可以选择 `[1, 4]`、`[5, 7]` 和 `[8, 9]`，一共三个区间。`[3, 5]` 与前两个区间都有重叠，不能加入这组答案。

## 枚举所有选择

每个区间都有“选择”和“不选择”两种可能。最直接的办法枚举全部子集，再检查子集内部是否互不重叠。

$n$ 个区间共有 $2^n$ 个子集。即使检查一个子集只需要 $O(n)$ 时间，总时间也会达到 $O(n2^n)$，只能处理很小的 $n$。

为了避免枚举，需要找到一个可以立刻确定的选择，并证明至少有一组最优答案包含它。随后删除与它冲突的区间，对剩余候选重复相同过程。

## 最早开始并不正确

一种直觉是先选择左端最小、开始最早的区间。但它可能长时间占据可选范围：

```text
[1, 10]
[2, 3] [4, 5] [6, 7] [8, 9]
```

最早开始的 `[1, 10]` 只能单独选择；放弃它却可以选择后面四个短区间。

“开始得早”没有控制它会在什么时候释放后面的空间，因此不是安全的贪心规则。

## 最短区间也不正确

选择长度最短的区间同样可能同时挡住左右两侧的两个候选：

```text
[1, 4]  [4, 5]  [5, 8]
```

闭区间 `[4, 5]` 最短，却分别与 `[1, 4]`、`[5, 8]` 共享端点。选择它只能得到一个区间；选择 `[1, 4]` 和 `[5, 8]` 可以得到两个。

区间长度只描述自身占用多少范围，没有说明它把剩余可选区域切在什么位置。

## 最早结束

现在选择右端最小、结束最早的区间。

它在所有候选中最先释放右侧空间。无论第一步选择哪一个区间，后面能够继续选择的候选都必须位于它的右端之后；右端越小，留下的未来候选只会更多，不会更少。

先按照右端从小到大排序：

```cpp
struct interval {
    ll l;
    ll r;
};

bool compare_interval(const interval& a, const interval& b) {
    if (a.r != b.r) {
        return a.r < b.r;
    }
    return a.l < b.l;
}
```

右端相同时按左端排序只用于固定输出和执行顺序，不影响能够选择的最大数量。关键字段是右端。

```cpp
sort(intervals.begin() + 1, intervals.begin() + n + 1, compare_interval);
```

自定义区间数组使用 `1..n`，调用 `sort` 时把闭区间转换成 STL 的左闭右开迭代器范围。

## 记录最后一个右端

排序后从左到右扫描。变量 `last_right` 保存最近一个已选区间的右端；`answer` 保存已经选择的数量。

第一个区间没有前驱，可以直接选择。为了不让某个具体数值同时充当“尚未选择”的哨兵，另用 `has_selected` 记录是否已经选择过区间：

```cpp
bool has_selected = false;
ll last_right = 0;
int answer = 0;
```

当前区间与上一个已选区间不重叠时，接受它并更新状态：

```cpp
if (!has_selected || intervals[i].l > last_right) {
    has_selected = true;
    last_right = intervals[i].r;
    answer++;
}
```

不能把 `last_right` 初始化成某个“很小”的常量并假设输入一定更大。布尔状态直接表达“还没有已选区间”，不会与合法端点冲突。

## 完整选择函数

区间数量与区间数组会被读入、排序和选择过程共同使用，因此保存为题目级共享状态：

```cpp
int n;
vector<interval> intervals;

int maximum_non_overlapping() {
    sort(intervals.begin() + 1, intervals.begin() + n + 1, compare_interval);

    bool has_selected = false;
    ll last_right = 0;
    int answer = 0;

    for (int i = 1; i <= n; i++) {
        if (!has_selected || intervals[i].l > last_right) {
            has_selected = true;
            last_right = intervals[i].r;
            answer++;
        }
    }

    return answer;
}
```

扫描到一个兼容区间时立即选择它。由于区间已经按右端排序，它就是当前所有还能选择的候选中结束最早的一个。

## 交换第一步

直觉说明“最早结束会留下更多空间”，但还要证明选择它不会失去最优答案。

令 $g$ 是全部候选中右端最小的区间。再任取一组全局最优答案，把其中最早结束的第一个区间记为 $o$，二者的右端分别是 $r_g$ 和 $r_o$。

因为 $g$ 的右端在全部候选中最小，所以：

$$
r_g \le r_o
$$

把最优答案中的 $o$ 换成 $g$。原来位于 $o$ 后面的每个已选区间，其左端 $l_{next}$ 都满足：

$$
l_{next} > r_o
$$

结合 $r_g \le r_o$，必然还有：

$$
l_{next} > r_g
$$

所以替换以后，$g$ 与后面所有区间仍然不重叠；区间数量也没有改变。由此得到：至少存在一组全局最优答案，把最早结束的区间作为第一项。

这一步不是声称“每组最优答案原本都选择了 $g$”，而是证明任意最优答案都能在不变差的前提下交换出一个选择 $g$ 的最优答案。

## 重复同一个问题

选择 $g$ 后，与它重叠的区间都不能再选。剩余问题只包含满足：

```text
interval.l > r_g
```

的区间，目标仍然是在其中选择最多个互不重叠区间，与原问题形式完全相同。

交换论证已经证明，当前最早结束的区间可以安全地成为某组最优答案的第一项。对剩余问题重复同一论证，每一步选择都能保留一组最优答案。候选处理完时，贪心算法得到的区间数量因此是全局最大值。

这就是贪心算法常见的证明结构：

1. 明确当前局部选择；
2. 证明某组最优答案可以包含这个选择；
3. 做出选择后，剩余部分仍是同类问题；
4. 重复直到答案完整。

本篇第 2 步使用的是交换论证：把最优答案中的某一项替换成贪心选择，并证明合法性和答案质量都不变。

## 手动过程

考虑七个闭区间：

```text
[1, 4] [3, 5] [0, 6] [5, 7] [3, 9] [8, 9] [6, 10]
```

它们已经按照右端排序；右端同为 `9` 时，左端较小的 `[3, 9]` 在前。

| 当前区间 | 与最后选择是否兼容 | 操作 | `last_right` | `answer` |
| --- | --- | --- | ---: | ---: |
| `[1, 4]` | 尚未选择 | 选择 | 4 | 1 |
| `[3, 5]` | $3 \le 4$ | 跳过 | 4 | 1 |
| `[0, 6]` | $0 \le 4$ | 跳过 | 4 | 1 |
| `[5, 7]` | $5 > 4$ | 选择 | 7 | 2 |
| `[3, 9]` | $3 \le 7$ | 跳过 | 7 | 2 |
| `[8, 9]` | $8 > 7$ | 选择 | 9 | 3 |
| `[6, 10]` | $6 \le 9$ | 跳过 | 9 | 3 |

最终选择三个区间。

## 时间与空间复杂度

排序需要 $O(n\log n)$ 时间，排序后的扫描需要 $O(n)$ 时间，所以总时间复杂度是 $O(n\log n)$。

排序后的扫描只保存 `has_selected`、`last_right` 和 `answer`，额外空间是 $O(1)$。主流 `sort` 实现还会使用 $O(\log n)$ 的辅助调用栈，因此把排序过程也计入时，算法的额外空间通常写作 $O(\log n)$。输入区间数组由调用者提供，不计入额外空间。

## 完整代码

下面的程序读入 $n$ 个闭区间，输出最多能选择多少个两两不重叠区间。输入保证每个区间满足 `l <= r`。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

struct interval {
    ll l;
    ll r;
};

int n;
vector<interval> intervals;

bool compare_interval(const interval& a, const interval& b) {
    if (a.r != b.r) {
        return a.r < b.r;
    }
    return a.l < b.l;
}

int maximum_non_overlapping() {
    sort(intervals.begin() + 1, intervals.begin() + n + 1, compare_interval);

    bool has_selected = false;
    ll last_right = 0;
    int answer = 0;

    for (int i = 1; i <= n; i++) {
        if (!has_selected || intervals[i].l > last_right) {
            has_selected = true;
            last_right = intervals[i].r;
            answer++;
        }
    }

    return answer;
}

void solve() {
    scanf("%d", &n);

    intervals.assign(n + 5, {});
    for (int i = 1; i <= n; i++) {
        scanf("%lld%lld", &intervals[i].l, &intervals[i].r);
    }

    printf("%d\n", maximum_non_overlapping());
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
7
1 4
3 5
0 6
5 7
3 9
8 9
6 10
```

输出：

```text
3
```

## 端点是否允许相接

本文使用闭区间，所以 `[1, 4]` 与 `[4, 6]` 在点 `4` 重叠，兼容条件是：

```cpp
current.l > last_right
```

有些日程问题把一次活动的结束时刻与下一次活动的开始时刻相同视为可以衔接。那是另一种题意，兼容条件应改成：

```cpp
current.l >= last_right
```

排序与交换论证保持不变，但等号是否允许必须服从题面，不能只凭“区间调度模板”猜测。

## 带权区间

本文目标是让选择数量最多，每个区间的价值都视为 $1$。若每个区间有不同收益，最早结束不一定让总收益最大。

例如一个很长区间的收益可能超过许多短区间收益之和。此时需要比较“选择当前区间”和“不选择当前区间”的最优总收益，通常会形成带权区间调度的动态规划，不能继续使用本篇结论。

贪心规则总是与目标函数绑定。证明“数量最多”并不能自动证明“总长度最小”“收益最大”或其他目标。

## 常见错误

### 只凭样例猜局部规则

最早开始、长度最短和其他直觉都可能在小样例上成功。必须尝试构造反例，并为最终规则给出保持最优解的证明。

### 按左端排序

当前问题要为未来留下尽可能早的可用位置，因此关键是右端，而不是左端。

### 闭区间使用大于等于

两个闭区间端点相同就已经重叠。只有题面明确允许结束和开始在同一时刻衔接时，才使用 `>=`。

### 忘记排序

“遇到兼容区间就选择”只有在候选按右端非递减排列后才等价于“选择当前最早结束者”。按输入顺序扫描没有正确性保证。

### 用固定数值表示尚未选择

端点可能包含负数甚至 64 位边界。使用 `has_selected` 明确保存状态，不让合法端点与哨兵混淆。

### 把无权结论用于带权问题

区间价值不同时，选择数量和选择总收益是不同目标，最早结束规则不再保证最优。

## 基础练习

1. 对手动示例逐行模拟 `has_selected`、`last_right` 和 `answer`。
2. 分别构造反例否定“最早开始”和“长度最短”两种规则。
3. 测试空集合、单个区间、全部互相重叠、全部互不重叠、相同右端和负数端点。
4. 枚举小规模区间的全部子集，与贪心答案随机对拍。
5. 把题意改成端点相同可以衔接，修改兼容条件并重新检查交换证明。
6. 输出实际选中的区间，而不只统计数量。
7. 为带权区间构造一个最早结束规则失败的反例。

## 需要记住什么

1. 贪心算法每一步做出的选择有什么特点？为什么“看起来合理”还不够？
2. 最早开始和长度最短为什么不能保证选择数量最多？
3. 为什么最早结束的区间会为后续留下不小于其他选择的空间？
4. 交换论证怎样把某组最优答案的第一项替换成贪心选择？
5. 为什么替换以后，后续已经选择的区间仍然合法？
6. 选择第一个区间以后，剩余问题为什么仍与原问题相同？
7. 排序和扫描分别需要多少时间？
8. 闭区间与“端点可以衔接”的日程模型分别使用什么兼容条件？
9. 为什么带权区间不能直接沿用本文的最早结束规则？

贪心算法没有一份适用于所有题目的固定排序模板。遇到新的局部选择时，仍要根据目标重新建立反例检查和正确性证明。

# 选择排序

> 最近修订：2026-08-16 17:59 +10:00（未审阅）

[冒泡排序](bubble-sort.md) 每轮通过许多次相邻交换把最大值送到右端。若我们先在
未排序部分找出最小值，再只交换一次，就得到选择排序。

选择排序的重点不在实际比赛中替代 [sort](../cpp/sort.md)，而在于理解一种很
直接的构造方法：每轮选择当前最应该放到前面的位置，并让正确前缀扩大一格。

## 每轮选择最小值

给定 1-based 数组 `a[1..n]`。第一轮要确定 `a[1]`，因此在整个区间
`a[1..n]` 中寻找最小值；第二轮要确定 `a[2]`，因此只在 `a[2..n]` 中寻找。

令 `i` 表示本轮要确定的位置，`min_pos` 表示目前找到的最小值下标：

```cpp
int min_pos = i;
for (int j = i + 1; j <= n; j++) {
    if (a[j] < a[min_pos]) {
        min_pos = j;
    }
}
```

开始时，暂时把 `a[i]` 当作最小值。每检查一个新位置 `j`，若它更小，就更新
`min_pos`。循环结束后，`min_pos` 指向 `a[i..n]` 中的一个最小值。

这段代码比较的是 `a[j]` 与 `a[min_pos]`，而不是下标 `j` 与 `min_pos`。下标
只表示位置，真正决定大小的是位置中保存的值。

## 把最小值放到当前位置

找到最小值以后，交换 `a[i]` 与 `a[min_pos]`：

```cpp
swap(a[i], a[min_pos]);
```

以 `4 2 5 1 3` 为例：

| 轮次 | 未排序部分 | 找到的最小值 | 交换后的数组 |
| ---: | --- | ---: | --- |
| 1 | `4 2 5 1 3` | `1` | `1 2 5 4 3` |
| 2 | `2 5 4 3` | `2` | `1 2 5 4 3` |
| 3 | `5 4 3` | `3` | `1 2 3 4 5` |
| 4 | `4 5` | `4` | `1 2 3 4 5` |

第 `i` 轮结束后，`a[i]` 已经是原来未排序部分的最小值，因而位于最终位置。
它以后不再参与选择。

即使 `min_pos == i`，调用 `swap(a[i], a[i])` 也不会改变数组。可以加条件省掉
这次自交换，但不是正确性所必需的。

## 正确前缀

`n` 和 `a` 是整道题共享的输入状态，因此放在全局；排序函数只接收通过局部循环
产生的位置，不重复传递整份数组。完整循环为：

```cpp
int n;
vector<int> a;

void selection_sort() {
    for (int i = 1; i < n; i++) {
        int min_pos = i;

        for (int j = i + 1; j <= n; j++) {
            if (a[j] < a[min_pos]) {
                min_pos = j;
            }
        }

        swap(a[i], a[min_pos]);
    }
}
```

每轮开始前保持两个事实：

1. 前缀 `a[1..i-1]` 已经位于最终位置并按升序排列；
2. 前缀中的每个值都不大于未排序后缀中的每个值。

本轮从 `a[i..n]` 中取出最小值放到 `a[i]`，所以这两个事实继续对更长的前缀
成立。处理到 `i = n - 1` 后，最后一个位置只剩唯一的元素，自然正确。

这就是选择排序的不变量。它与冒泡排序的“正确后缀”方向相反，但证明方法相同：
先说明开始时成立，再说明一轮操作会把正确范围扩大一格。

## 复杂度

第 `i` 轮需要比较 `n - i` 次，总比较次数固定为：

$$
(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}2.
$$

因此，无论输入已经有序、逆序还是随机排列，时间复杂度都是 $O(n^2)$。与带提前
结束的冒泡排序不同，朴素选择排序不能仅凭一轮找到最小值就证明剩余部分已经有序。

每轮至多交换一次，总交换次数至多为 $n-1$。这比冒泡排序可能进行的平方数量级
交换少，但没有改变总时间复杂度，因为寻找最小值仍需平方数量级的比较。

算法只使用下标变量，额外空间复杂度是 $O(1)$，属于原地排序。

## 稳定性

本篇的朴素选择排序不稳定。考虑带身份的三个记录：

```text
2a 2b 1
```

第一轮找到 `1`，再将它与开头的 `2a` 直接交换：

```text
1 2b 2a
```

两个关键字同为 `2` 的记录原来是 `2a` 在前，现在变成 `2b` 在前。虽然寻找
最小值时使用严格小于号，远距离交换仍然可能让相等元素改变相对顺序。

可以通过移动一段元素而不是直接交换来设计稳定版本，但那已经不是本篇最朴素的
原地实现。判断稳定性时应检查具体操作，不能只观察比较符号。

## 完整代码

下面的程序使用 1-based 下标和 `+5` 余量排列整数数组：

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
vector<int> a;

void selection_sort() {
    for (int i = 1; i < n; i++) {
        int min_pos = i;

        for (int j = i + 1; j <= n; j++) {
            if (a[j] < a[min_pos]) {
                min_pos = j;
            }
        }

        swap(a[i], a[min_pos]);
    }
}

void solve() {
    scanf("%d", &n);

    a.assign(n + 5, 0);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &a[i]);
    }

    selection_sort();

    for (int i = 1; i <= n; i++) {
        if (i > 1) {
            printf(" ");
        }
        printf("%d", a[i]);
    }
    printf("\n");
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
5
4 2 5 1 3
```

输出：

```text
1 2 3 4 5
```

当 `n` 为 `0` 或 `1` 时，外层循环不会执行，程序仍能得到正确结果。

## 常见错误

### 每次发现更小值就立即交换

选择排序先完成整轮寻找，再把最终最小值交换到 `a[i]`。在内层循环中反复交换
可能仍能排好序，但失去了“每轮只交换一次”的结构，也更接近另一种交换排序。

### 比较下标而不是元素值

`j < min_pos` 只是在比较位置，不能找出较小元素。正确条件是
`a[j] < a[min_pos]`。

### 让内层从 1 开始

`a[1..i-1]` 已经确定。再次扫描它们会破坏不变量或引入无用工作；候选范围应当是
`a[i..n]`。

### 误以为交换少就是线性时间

交换最多只有 $n-1$ 次，但比较次数仍是 $n(n-1)/2$。复杂度必须统计所有主要
操作，不能只统计交换。

### 认为严格比较自动保证稳定

远距离交换可能跨过相等元素，所以本篇实现仍然不稳定。

## 需要记住什么

1. 第 `i` 轮在哪个范围寻找最小值？
2. `min_pos` 保存下标还是数值？为什么需要它？
3. 每轮结束后，哪个前缀已经位于最终位置？
4. 为什么外层循环只需执行到 `n - 1`？
5. 选择排序的比较次数为什么不随输入顺序变化？
6. 交换次数少为什么不代表时间复杂度是 $O(n)$？
7. `2a 2b 1` 为什么能说明朴素选择排序不稳定？
8. 实际比赛的一般排序为什么仍然优先使用 `sort`？

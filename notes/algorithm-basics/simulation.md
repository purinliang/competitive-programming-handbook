# 模拟

> 最近修订：2026-08-16 17:10 +10:00（未审阅）

有些题目已经完整规定了对象的初始状态和每一种操作，只要求依次执行操作后报告最终结果。这类题目通常不需要寻找隐藏公式，而是需要把规则准确翻译成状态更新。这种按照题意重现过程的方法称为模拟。

模拟题的困难经常不在复杂算法，而在状态遗漏、操作顺序、边界与代码重复。本篇用四向机器人说明怎样确定足够的状态，为每种命令写出唯一转移，并证明程序处理的状态始终与题面过程一致。

## 四向机器人

一个机器人初始位于平面坐标 `(0, 0)`，朝向北方。现在给出 $m$ 条命令：

- `F`：朝当前方向前进一步；
- `L`：原地向左转 $90$ 度；
- `R`：原地向右转 $90$ 度。

执行全部命令后，输出机器人的横坐标、纵坐标和朝向。

例如命令序列：

```text
FFRFFLFF
```

最终到达 `(2, 4)`，朝向北方。

命令必须按照输入顺序执行。转弯会改变后续前进的方向，因此不能排序、合并或只统计三种字符各出现多少次。

## 确定完整状态

处理下一条命令以前，程序需要知道哪些信息？

`L` 与 `R` 只需要当前朝向；`F` 需要当前坐标和朝向。过去命令的具体内容已经通过这些量反映在当前状态中，不必完整回看历史。

因此状态由三个量组成：

```cpp
struct robot {
    ll x;
    ll y;
    int direction;
};
```

- `x`：当前横坐标；
- `y`：当前纵坐标；
- `direction`：当前朝向。

初始状态是：

```cpp
robot state = {0, 0, 0};
```

坐标使用 64 位整数。题目仍需保证执行全部前进命令后的坐标可以在 64 位整数中保存。

## 朝向编号

直接用字符保存朝向也能实现，但每次转弯都要分别判断四种方向。四个朝向按顺时针排列成一个循环：

```text
          0: N
            ^
            |
3: W  <-----+----->  1: E
            |
            v
          2: S
```

统一编号为：

| `direction` | 朝向 | 横坐标变化 | 纵坐标变化 |
| ---: | --- | ---: | ---: |
| 0 | 北 `N` | 0 | 1 |
| 1 | 东 `E` | 1 | 0 |
| 2 | 南 `S` | 0 | -1 |
| 3 | 西 `W` | -1 | 0 |

这里的 `0..3` 是四种循环状态的编号，不是题目数组下标。顺时针编号让右转等价于移动到下一个编号，左转等价于移动到上一个编号。

## 向右转

向右转的变化为：

```text
0 -> 1 -> 2 -> 3 -> 0
```

先加一，再对四取余即可回到范围 `0..3`：

```cpp
state.direction = (state.direction + 1) % 4;
```

例如西方编号为 `3`，右转后 `(3 + 1) % 4 == 0`，回到北方。

## 向左转

向左转应当移动到前一个编号：

```text
0 -> 3 -> 2 -> 1 -> 0
```

不能直接依赖 `(direction - 1) % 4`。在 C++ 中，`0 - 1` 对 `4` 取余会得到 `-1`，不能作为方向编号。先加上一个完整周期再取余：

```cpp
state.direction = (state.direction + 3) % 4;
```

加 `3` 与减 `1` 在模 `4` 的循环中表示同一个变化，同时结果始终位于 `0..3`。

## 向前移动

四个方向对应的坐标变化已经在表格中给出。按照 `direction` 编号排列成两个查找表：

```cpp
const int dx[4] = {0, 1, 0, -1};
const int dy[4] = {1, 0, -1, 0};
```

`dx[direction]` 是当前方向的横坐标增量，`dy[direction]` 是纵坐标增量。因此 `F` 命令只需要：

```cpp
state.x += dx[state.direction];
state.y += dy[state.direction];
```

这两个长度为四的数组是由方向状态编号访问的固定查找表。它们把四段几乎相同的坐标判断压缩成一次统一更新，避免某个方向漏改或正负号写反。

## 逐条处理命令

输入命令保存在 1-based 数组 `commands[1..m]` 中。按照原顺序扫描：

```cpp
for (int i = 1; i <= m; i++) {
    char command = commands[i];

    if (command == 'F') {
        state.x += dx[state.direction];
        state.y += dy[state.direction];
    } else if (command == 'L') {
        state.direction = (state.direction + 3) % 4;
    } else if (command == 'R') {
        state.direction = (state.direction + 1) % 4;
    }
}
```

题目保证命令只包含 `F`、`L`、`R`。若题面允许非法命令，就必须另外规定忽略、报错还是执行其他行为，不能自行猜测。

把状态建立、方向表和命令循环合在一个函数中：

```cpp
robot simulate(const vector<char>& commands, int m) {
    const int dx[4] = {0, 1, 0, -1};
    const int dy[4] = {1, 0, -1, 0};

    robot state = {0, 0, 0};

    for (int i = 1; i <= m; i++) {
        char command = commands[i];

        if (command == 'F') {
            state.x += dx[state.direction];
            state.y += dy[state.direction];
        } else if (command == 'L') {
            state.direction = (state.direction + 3) % 4;
        } else if (command == 'R') {
            state.direction = (state.direction + 1) % 4;
        }
    }

    return state;
}
```

三个返回值共同描述一个机器人状态，因此使用专门的 `struct` 返回，而不是通过三个输出引用参数修改调用者变量。

## 手动过程

对命令 `FFRFFLFF`，逐步状态为：

| 已处理命令 | 操作 | 坐标 | 朝向编号 | 朝向 |
| ---: | --- | --- | ---: | --- |
| 0 | 初始 | `(0, 0)` | 0 | `N` |
| 1 | `F` | `(0, 1)` | 0 | `N` |
| 2 | `F` | `(0, 2)` | 0 | `N` |
| 3 | `R` | `(0, 2)` | 1 | `E` |
| 4 | `F` | `(1, 2)` | 1 | `E` |
| 5 | `F` | `(2, 2)` | 1 | `E` |
| 6 | `L` | `(2, 2)` | 0 | `N` |
| 7 | `F` | `(2, 3)` | 0 | `N` |
| 8 | `F` | `(2, 4)` | 0 | `N` |

每行只使用上一行状态和当前一条命令。手算表也是调试模拟题的有效方法：找到程序第一次与表格不同的步骤，错误通常就在这一条转移或此前状态定义中。

## 循环不变量

进入第 `i` 轮循环以前，`state` 恰好等于机器人执行前 `i - 1` 条命令后的状态。

- 循环开始前还没有执行命令，初始化值正是题面初始状态；
- 若第 `i` 条是 `F`，程序按照当前朝向增加对应坐标，结果与前进一步相同；
- 若第 `i` 条是 `L` 或 `R`，程序只更新循环方向编号，坐标保持不变，与原地转弯相同；
- 因此本轮结束后，`state` 恰好是执行前 `i` 条命令后的状态。

按顺序重复到 `i == m`，函数返回的就是执行全部命令后的状态。

模拟的正确性通常来自这种逐步对应：先保证初始状态一致，再证明每种操作都把正确的旧状态变成正确的新状态。

## 时间与空间复杂度

每条命令只处理一次，每次只进行固定次数的比较和整数运算，所以模拟函数的时间复杂度是 $O(m)$。

除调用者提供的命令数组外，函数只保存机器人状态和两个固定长度方向表，额外空间
复杂度是 $O(1)$。完整程序为了保存全部输入命令使用 $O(m)$ 空间；若题目不需要
回看或复用命令，也可以在读入每个字符后立即执行，把整个程序的额外空间降为
$O(1)$。

## 完整代码

下面的程序先读入命令数量 $m$，再读入恰好 $m$ 个命令字符。命令之间可以连续书写，也可以由空白分隔。输出最终横坐标、纵坐标和朝向字符。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

struct robot {
    ll x;
    ll y;
    int direction;
};

robot simulate(const vector<char>& commands, int m) {
    const int dx[4] = {0, 1, 0, -1};
    const int dy[4] = {1, 0, -1, 0};

    robot state = {0, 0, 0};

    for (int i = 1; i <= m; i++) {
        char command = commands[i];

        if (command == 'F') {
            state.x += dx[state.direction];
            state.y += dy[state.direction];
        } else if (command == 'L') {
            state.direction = (state.direction + 3) % 4;
        } else if (command == 'R') {
            state.direction = (state.direction + 1) % 4;
        }
    }

    return state;
}

void solve() {
    int m;
    cin >> m;

    vector<char> commands(m + 5);
    for (int i = 1; i <= m; i++) {
        cin >> commands[i];
    }

    robot answer = simulate(commands, m);
    const char direction_name[4] = {'N', 'E', 'S', 'W'};

    cout << answer.x << ' ' << answer.y << ' ';
    cout << direction_name[answer.direction] << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
8
FFRFFLFF
```

输出：

```text
2 4 N
```

## 常见错误

### 保存的状态不完整

只保存坐标而不保存朝向，遇到下一条 `F` 时就不知道怎样移动。决定状态时要检查下一步所需的全部信息，而不是只记录最终要求输出的量。

### 用操作次数代替操作顺序

`RF` 与 `FR` 都包含一次右转和一次前进，但结果不同。只要操作不满足任意交换，程序就必须按输入顺序处理。

### 左转得到负数编号

C++ 中 `(0 - 1) % 4` 是 `-1`。使用 `(direction + 3) % 4`，让中间值与最终编号始终非负。

### 方向表顺序不一致

朝向编号、`dx`、`dy` 和输出名称必须共享同一顺序。若编号按 `N, E, S, W`，三个查找表也必须分别按照这个顺序排列。

### 前进后再使用新方向

`F` 不改变方向，`L` 与 `R` 不改变坐标。每种命令只更新题面规定的状态部分，不要把下一条命令提前合入当前步骤。

### 混淆处理前后的状态

明确循环不变量是“进入第 `i` 轮前已经处理前 `i - 1` 条”。手算表也使用相同边界，就能避免少执行或多执行一条命令。

### 过早压缩代码

复杂模拟中，把多种规则塞进一个长表达式会让执行顺序和边界难以核对。先为状态取准确名称，并让每个分支直接对应一条题面规则；确认正确后再消除真正重复的部分。

## 需要记住什么

1. 模拟题开始编码前，为什么要先确定完整状态？
2. 本例为什么只需要坐标与朝向，不需要保存已经执行的全部历史？
3. 为什么把朝向按顺时针编号后，左右转可以使用模运算？
4. 为什么左转不直接写成 `(direction - 1) % 4`？
5. `dx`、`dy` 与方向名称必须保持什么对应关系？
6. 循环不变量怎样证明逐条执行命令后的状态正确？
7. 为什么模拟不能只统计各种命令的出现次数？
8. 怎样从命令数量和单步成本分析总时间复杂度？保存命令与在线处理的空间有什么区别？
9. 调试模拟题时，逐步手算表怎样帮助定位第一次状态分歧？

模拟没有一份适用于所有题目的固定代码。需要保持的是工作方法：用足够但不过度的状态描述当前局面，让每个操作分支只实现一条明确定义的规则，并始终核对更新顺序与边界。

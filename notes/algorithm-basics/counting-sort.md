# 计数排序

> 最近修订：2026-08-16 18:02 +10:00（未审阅）

前面的排序通过比较两个元素决定先后。当元素都是整数，并且可能取到的整数范围不
大时，还可以换一种思路：不再记录每个元素应该与谁交换，只统计每个值出现了多少
次，再按值从小到大恢复序列。

这种方法称为计数排序。它能绕开比较排序常见的 $O(n\log n)$ 量级，但代价是时间
和空间都依赖值域大小，不能无条件替代 [sort](../cpp/sort.md)。

## 统计每个值的次数

假设数组为：

```text
4 2 2 5 1 4 2
```

逐个统计后得到：

| 值 | 1 | 2 | 3 | 4 | 5 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 次数 | 1 | 3 | 0 | 2 | 1 |

之后从小到大遍历所有值，输出一次 `1`、三次 `2`、零次 `3`、两次 `4` 和一次
`5`，就得到有序序列：

```text
1 2 2 2 4 4 5
```

没有任何一步比较“两个输入元素谁更小”。顺序直接来自整数值本身。

## 用偏移保存负数

数组下标不能直接表示负值。令：

- `min_value` 为数组最小值；
- `max_value` 为数组最大值；
- `range = max_value - min_value + 1` 为不同整数值可能占据的位置数。

本书保留 `count[0]`，把整数 `value` 映射到 1-based 下标：

$$
\text{index}=\text{value}-\text{min\_value}+1.
$$

反向恢复时：

$$
\text{value}=\text{min\_value}+\text{index}-1.
$$

例如最小值是 `-2` 时，`-2`、`-1`、`0` 分别映射到下标 `1`、`2`、`3`。
这种整体平移只改变保存位置，不改变整数之间的先后顺序。

先扫描数组求值域，再统计频次：

```cpp
int min_value = a[1];
int max_value = a[1];

for (int i = 2; i <= n; i++) {
    min_value = min(min_value, a[i]);
    max_value = max(max_value, a[i]);
}

ll range = 1LL * max_value - min_value + 1;
vector<int> count(range + 5);

for (int i = 1; i <= n; i++) {
    ll index = 1LL * a[i] - min_value + 1;
    count[index]++;
}
```

乘以 `1LL` 让减法先在 64 位整数中完成，避免两个极端 `int` 相减时先发生 32 位
整数溢出。它不能解决值域本身过大造成的内存问题；是否适合计数排序仍需先看题目
约束。

## 根据次数恢复数组

令 `pos` 表示下一个要写入的原数组位置。按映射下标从小到大遍历，每次写入该值
`count[index]` 次：

```cpp
int pos = 1;

for (ll index = 1; index <= range; index++) {
    int value = min_value + index - 1;

    while (count[index] > 0) {
        a[pos] = value;
        pos++;
        count[index]--;
    }
}
```

每个输入元素使某个计数增加一次，恢复时又对应一次写入。因此最终恰好写回 `n`
个元素，不会增加或丢失元素。外层按值递增，写回结果自然非递减。

这里直接减小 `count[index]`，是因为恢复完成后不再需要频次数组。若后续还要查询
原始频次，可以改用另一个循环变量重复写入。

## 复杂度与适用条件

令：

$$
k=\text{max\_value}-\text{min\_value}+1.
$$

求最值和统计次数各扫描 $n$ 个元素，恢复时扫描 $k$ 个可能值并总共写入 $n$ 个
元素，所以时间复杂度是：

$$
O(n+k).
$$

频次数组长度与值域相同，额外空间复杂度是 $O(k)$。

当 `n = 100000`，所有值都位于 `0..1000` 时，`k = 1001`，计数排序很合适。
若只有两个值 `-1000000000` 和 `1000000000`，虽然 `n = 2`，却需要约二十亿个
计数位置，时间和内存都不可接受。

因此使用前必须同时确认：

1. 元素可以映射成连续整数值；
2. 值域大小 `k` 足够小；
3. $O(k)$ 内存符合题目限制。

计数排序不是原地排序，因为它需要额外的频次数组。

## 计数排序不是桶排序

有些 OI 资料会把计数排序口语化地称为“桶排序”，但本书严格区分两者：

- 计数排序为每个离散整数值保存出现次数，按次数直接恢复顺序；
- 桶排序把较大的值域划分成若干范围，每个桶可能包含许多不同值，桶内仍需继续
  排序，最后再按桶顺序拼接。

本篇的一个计数位置只对应一个具体整数，不存在“桶内怎样排序”的问题，因此统一
称为计数排序。

## 相等记录与稳定性

若输入只是整数，相等的 `2` 彼此无法区分，按频次恢复已经足够。但真实记录可能
同时带有编号、姓名或其他字段：

```text
(2, a) (1, x) (2, b)
```

本篇频次数组只保存“键 `2` 出现两次”，已经丢失记录 `a` 与 `b`，因此不能用于
保持它们的原始顺序，也不能据此宣称完成了稳定的记录排序。

稳定计数排序需要把次数转换成每个键的最终位置边界，再按恰当方向把完整记录放入
额外输出数组。本篇只解决整数序列排序；这套稳定扩展会在后面的排序方法比较中说明
定位，不把两种实现混在同一份基础模板里。

## 完整代码

下面的程序支持负整数。`n` 和 `a` 是整道题共享的输入状态，放在全局；`count`
只在一次计数排序过程中存在，仍然保留为函数内部的局部状态。程序假定输入值域
足够小，可以分配 `range + 5` 个计数位置：

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

int n;
vector<int> a;

void counting_sort() {
    if (n <= 1) {
        return;
    }

    int min_value = a[1];
    int max_value = a[1];

    for (int i = 2; i <= n; i++) {
        min_value = min(min_value, a[i]);
        max_value = max(max_value, a[i]);
    }

    ll range = 1LL * max_value - min_value + 1;
    vector<int> count(range + 5);

    for (int i = 1; i <= n; i++) {
        ll index = 1LL * a[i] - min_value + 1;
        count[index]++;
    }

    int pos = 1;
    for (ll index = 1; index <= range; index++) {
        int value = min_value + index - 1;

        while (count[index] > 0) {
            a[pos] = value;
            pos++;
            count[index]--;
        }
    }
}

void solve() {
    scanf("%d", &n);

    a.assign(n + 5, 0);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &a[i]);
    }

    counting_sort();

    for (int i = 1; i <= n; i++) {
        if (i > 1) {
            printf(" ");
        }
        printf("%d", a[i]);
    }
    printf("\n");
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
7
4 -2 2 5 -2 4 2
```

输出：

```text
-2 -2 2 2 4 4 5
```

## 常见错误

### 只看元素数量，不看值域

复杂度中的 `k` 不是不同值实际出现的数量，而是最小值到最大值之间整个连续整数
范围的长度。

### 直接用负数作为下标

必须通过减去 `min_value` 完成平移。本篇再加 `1`，是为了遵循自定义数组 1-based
的统一约定。

### 用 int 直接计算值域差

`max_value - min_value` 可能先在 32 位整数中溢出。应先提升到 64 位整数计算；
即使算得出来，也仍要判断对应内存是否可用。

### 把计数排序和桶排序混为一谈

计数位置对应具体整数；桶对应一段范围且可能需要桶内排序。两者适用条件和实现并不
相同。

### 用频次重建带附加信息的记录

只保存次数会丢失相等键记录的身份与附加字段。需要稳定记录排序时必须使用完整的
稳定版本，而不是这份整数模板。

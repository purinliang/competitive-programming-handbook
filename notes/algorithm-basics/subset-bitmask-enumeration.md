# 枚举：子集与位掩码

> 最近修订：2026-08-13 21:25 +10:00（未审阅）

[枚举](enumeration.md) 中的一个候选由固定数量的下标组成，可以直接用固定层数的循环生成。现在让数组中的每个元素都可以独立选择或不选择，一个候选可能包含零个到 $n$ 个元素，无法预先用固定数量的下标描述。

每个位置只有两种选择，恰好可以用一个二进制位记录。[表达式：位运算符](../cpp/bitwise-operators.md) 已经说明怎样生成并查询单个位；把所有位置的选择位合在一个整数中，就得到表示整个子集的位掩码（bitmask）。

## 子集和计数

给定一个长度为 $n$ 的整数数组 `a[1..n]` 和目标 `target`，统计有多少个下标子集满足所选元素之和等于 `target`。

例如：

```text
a = 3 5 6 8
target = 11
```

有两个合法子集：

```text
选择下标 {1, 4}: 3 + 8 = 11
选择下标 {2, 3}: 5 + 6 = 11
```

本篇枚举下标子集。若数组中两个位置的数值相同，选择第一个位置与选择第二个位置仍然是两个不同子集。

空集也属于子集，它没有选择任何元素，元素和为 `0`。因此 `target == 0` 时，空集应当计入答案。

## 每个位置两种选择

从 `a[1]` 开始逐个决定：

```text
a[1]：不选 / 选
a[2]：不选 / 选
...
a[n]：不选 / 选
```

第一个位置有两种选择。每确定一种以后，第二个位置仍各有两种选择，所以前两个位置共有 $2\times2=2^2$ 种状态。继续到 $n$ 个位置，共有：

$$
2^n
$$

个下标子集。

这种指数增长很快。$n=20$ 时约有一百万个子集；$n=30$ 时已经超过十亿个。位掩码让子集表示和生成更加紧凑，但不会把 $2^n$ 个候选自动变少。

## 选择状态变成二进制位

整数的二进制位从第 `0` 位开始编号，而本书自定义数组从下标 `1` 开始。统一建立映射：

```text
元素 a[i]  <->  mask 的第 i-1 位
```

这一处 `i - 1` 是 1-based 数组与 0-based 二进制位之间的接口转换。

约定某一位为：

- `0`：不选择对应元素；
- `1`：选择对应元素。

以三个元素 `a[1..3]` 为例：

| `mask` | 三位二进制 | 选择状态 | 对应下标子集 |
| ---: | --- | --- | --- |
| 0 | `000` | 全部不选 | `{}` |
| 1 | `001` | 只选 `a[1]` | `{1}` |
| 2 | `010` | 只选 `a[2]` | `{2}` |
| 3 | `011` | 选择 `a[1], a[2]` | `{1, 2}` |
| 4 | `100` | 只选 `a[3]` | `{3}` |
| 5 | `101` | 选择 `a[1], a[3]` | `{1, 3}` |
| 6 | `110` | 选择 `a[2], a[3]` | `{2, 3}` |
| 7 | `111` | 全部选择 | `{1, 2, 3}` |

从 `0` 到 `7` 恰好覆盖全部 $2^3$ 种三位状态。一般地，使用低 $n$ 位时，最小掩码是全为 `0` 的 `0`，最大掩码是低 $n$ 位全为 `1` 的 $2^n-1$。

## 枚举全部掩码

本篇限制 $0\le n\le20$，因此可以安全地用 `int` 保存 `n` 位掩码。先计算掩码总数：

```cpp
int total_masks = 1 << n;
```

`1 << n` 等于 $2^n$。所有合法掩码就是左闭右开整数范围 `[0, total_masks)`：

```cpp
for (int mask = 0; mask < total_masks; mask++) {
    // mask 表示一个子集
}
```

这里从 `0` 开始不是改变数组下标约定，而是整数 `0` 自然表示低 $n$ 位全为 `0` 的空集。最后一个实际访问的掩码是 `total_masks - 1`。

不要使用浮点函数 `pow(2, n)` 生成掩码数量。这里需要的是精确整数幂，而且左移已经直接表达“把唯一的 `1` 移到第 `n` 位”。

## 查询一个元素是否被选择

要查询 `a[i]`，先构造只有第 `i - 1` 位为 `1` 的整数：

```cpp
int bit = 1 << (i - 1);
```

再用按位与保留这一位：

```cpp
bool selected = (mask & bit) != 0;
```

若结果非零，说明 `mask` 的对应位为 `1`，当前子集选择了 `a[i]`。

把判断直接放入数组循环：

```cpp
for (int i = 1; i <= n; i++) {
    if ((mask & (1 << (i - 1))) != 0) {
        // 当前子集选择了 a[i]
    }
}
```

位运算两侧主动使用括号，明确先生成单个位、再按位与、最后判断是否为零。

## 计算当前子集和

每个掩码开始时，当前子集还没有加入任何元素，所以：

```cpp
ll sum = 0;
```

扫描数组全部位置，只把被选择的元素加入 `sum`：

```cpp
for (int i = 1; i <= n; i++) {
    if ((mask & (1 << (i - 1))) != 0) {
        sum += a[i];
    }
}
```

内层循环结束后，`sum` 恰好是 `mask` 表示的子集元素和。若等于目标，就把答案增加一：

```cpp
if (sum == target) {
    answer++;
}
```

完整计数函数为：

```cpp
ll count_subset_sum(const vector<ll>& a, int n, ll target) {
    int total_masks = 1 << n;
    ll answer = 0;

    for (int mask = 0; mask < total_masks; mask++) {
        ll sum = 0;

        for (int i = 1; i <= n; i++) {
            if ((mask & (1 << (i - 1))) != 0) {
                sum += a[i];
            }
        }

        if (sum == target) {
            answer++;
        }
    }

    return answer;
}
```

元素、子集和、目标与答案都使用 64 位整数。题目仍需保证任意子集和不会超出 64 位整数范围。

## 不遗漏也不重复

一个下标子集对每个位置 `i` 都有唯一的真假结论：选择或不选择。按照映射把这些结论分别写进第 `i - 1` 位，就得到唯一的 `n` 位掩码。

反过来，任意 `0 <= mask < 2^n` 都只有低 $n$ 位可能为 `1`。读取每一位，就能唯一恢复对应的下标子集。

因此下标子集与 `[0, 2^n)` 中的整数一一对应：

- 每个子集都有一个掩码，所以不会遗漏；
- 不同子集至少有一个位置的选择不同，对应位也不同，所以不会重复；
- 每个掩码只在外层循环中出现一次。

位掩码不是靠碰巧排列出所有组合，而是给候选集合建立了一个双向唯一表示。

## 手动过程

对前三个数：

```text
a = 3 5 6
target = 8
```

逐个掩码计算：

| `mask` | 选择的下标 | 所选数值 | `sum` | 是否计数 |
| ---: | --- | --- | ---: | --- |
| `000` | `{}` | 无 | 0 | 否 |
| `001` | `{1}` | `3` | 3 | 否 |
| `010` | `{2}` | `5` | 5 | 否 |
| `011` | `{1, 2}` | `3, 5` | 8 | 是 |
| `100` | `{3}` | `6` | 6 | 否 |
| `101` | `{1, 3}` | `3, 6` | 9 | 否 |
| `110` | `{2, 3}` | `5, 6` | 11 | 否 |
| `111` | `{1, 2, 3}` | `3, 5, 6` | 14 | 否 |

答案为 `1`。若目标改成 `0`，掩码 `000` 表示的空集会成为至少一个合法答案；若数组还含正负数，也可能有其他非空子集的和为 `0`。

## 时间与空间复杂度

外层循环枚举 $2^n$ 个掩码。对每个掩码，内层检查 $n$ 个位置，因此时间复杂度是：

$$
O(n2^n).
$$

数组由调用者提供。函数只保存掩码、循环下标、当前和和答案，额外空间复杂度是 $O(1)$。

虽然位掩码只用一个整数保存选择状态，但算法仍然明确访问了全部 $2^n$ 个子集。空间表示紧凑不等于时间复杂度降低。

本篇用 `n <= 20` 同时保证 `1 << n` 的移位合法，并让约两千万次位置检查通常具有实际可行性。若只改变整数类型，就算能够表示更多位，也不代表有时间枚举 $2^n$ 个子集。

## 完整代码

下面的程序读入 $0\le n\le20$ 个整数和目标值，输出元素和等于目标的下标子集数量。输入保证任意子集和可以使用 64 位整数保存。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

ll count_subset_sum(const vector<ll>& a, int n, ll target) {
    int total_masks = 1 << n;
    ll answer = 0;

    for (int mask = 0; mask < total_masks; mask++) {
        ll sum = 0;

        for (int i = 1; i <= n; i++) {
            if ((mask & (1 << (i - 1))) != 0) {
                sum += a[i];
            }
        }

        if (sum == target) {
            answer++;
        }
    }

    return answer;
}

int main() {
    int n;
    ll target;
    scanf("%d%lld", &n, &target);

    vector<ll> a(n + 5);
    for (int i = 1; i <= n; i++) {
        scanf("%lld", &a[i]);
    }

    printf("%lld\n", count_subset_sum(a, n, target));
    return 0;
}
```

输入：

```text
4 11
3 5 6 8
```

输出：

```text
2
```

## 常见错误

### 混淆元素下标与位编号

数组元素使用下标 `1..n`，二进制位使用编号 `0..n-1`。元素 `a[i]` 对应第 `i - 1` 位，不是第 `i` 位。

### 漏掉空集

掩码必须从 `0` 开始。空集是合法子集；它是否通过判定取决于题目条件，而不是在生成阶段擅自删除。

### 少枚举最后一个掩码

合法范围是 `[0, 2^n)`，循环写成 `mask < total_masks`。最大掩码是 `total_masks - 1`，表示全部选择。

### 把 pow 用于掩码数量

`pow` 进行浮点计算，不能直接提供整数位模式。满足移位范围时使用 `1 << n`；需要更宽的掩码时必须先选择合适的无符号整数类型。

### 忘记每个掩码重新清零

不同掩码表示彼此独立的子集。`sum = 0` 必须放在外层循环内部，否则会把前一个子集的和带入下一个子集。

### 把相同数值位置合并

本题枚举下标子集。数值相同的两个位置仍有各自的选择位，不能因为值相等就删除其中一个。

### 只检查掩码是否能保存

更宽的整数可以保存更多选择位，却无法消除指数数量的候选。必须同时估算 `2^n` 个子集和每个子集的检查成本。

## 基础练习

1. 写出 `n = 4` 时掩码 `0`、`5`、`10`、`15` 的二进制形式和对应下标子集。
2. 测试 `n = 0`、目标为 `0`、全为负数、重复数值和存在多个零和子集的情况。
3. 修改程序，输出每个子集所选择的下标，而不是统计子集和。
4. 统计恰好选择 $k$ 个元素且元素和为目标的子集。
5. 给每个元素增加重量与价值，枚举总重量不超过上限的子集并求最大总价值。
6. 用递归为每个位置分别尝试“不选”和“选”，与位掩码版本比较候选顺序和答案。
7. 构造小规模随机数组，用独立递归枚举与位掩码枚举对拍。
8. 估算 `n = 20, 25, 30` 时 $n2^n$ 的操作数量，判断直接枚举是否现实。

## 需要记住什么

1. 为什么 $n$ 个各有两种选择的位置共有 $2^n$ 个子集？
2. 1-based 元素 `a[i]` 对应位掩码中的第几位？为什么需要转换？
3. 为什么全部子集对应掩码范围 `[0, 2^n)`？
4. 怎样判断当前掩码是否选择了 `a[i]`？
5. 为什么下标子集与掩码之间是一一对应的？
6. 空集由哪个掩码表示？它什么时候应当计入答案？
7. 基础子集枚举为什么需要 $O(n2^n)$ 时间和 $O(1)$ 额外空间？
8. 为什么使用一个整数保存状态并没有降低候选数量？
9. 使用 `1 << n` 前需要同时检查哪两类限制？

本篇只枚举全部子集并逐个扫描元素。只遍历掩码中的 `1`、枚举某个掩码的全部子掩码、按元素数量分层以及状态压缩动态规划，都需要新的目标或复杂度分析，不在基础代码中提前加入。

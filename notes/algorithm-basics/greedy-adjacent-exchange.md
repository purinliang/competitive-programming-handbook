# 邻项交换证明

> 最近修订：2026-08-16 15:50 +10:00（未审阅）

有些贪心问题不是逐个挑选元素，而是要决定全部元素的排列顺序。我们通常会猜测“按照某个关键字排序”，但仍要回答：为什么这个顺序能够达到全局最优？

邻项交换证明先研究排列中相邻的两项。若它们的相对顺序不符合目标，就证明交换二者不会让答案变差；随后不断消除这样的逆序，最终把任意排列变成目标顺序。只要每次交换都不变差，目标顺序就不会差于任何原排列。

本篇用“最小化总等待时间”推导一次完整过程。

## 最小化总等待时间

有 $n$ 个任务等待同一台机器处理，第 $i$ 个任务需要 `duration[i]` 单位时间。机器一次只能处理一个任务，任务开始处理后不会中断。

一个任务的等待时间，是它前面所有任务的处理时间之和。需要安排任务顺序，使所有任务的等待时间总和最小。

例如按 `3, 1, 4` 的顺序处理：

| 任务时长 | 等待时间 |
| ---: | ---: |
| 3 | 0 |
| 1 | 3 |
| 4 | 4 |

总等待时间为 `0 + 3 + 4 = 7`。

## 暴力枚举顺序

$n$ 个任务共有 $n!$ 种排列。可以枚举每种顺序，再计算它的总等待时间，但阶乘增长非常快。

为了找到排序规则，不必一次比较两种完整排列。先固定除相邻两个任务以外的全部位置，只研究交换这两个任务会怎样改变答案。

## 只看相邻两个任务

设一对相邻任务的时长依次是 $x$、$y$，它们之前的任务总共耗时 $S$。

原顺序是 $x$ 在前、$y$ 在后：

```text
x 的等待时间：S
y 的等待时间：S + x
```

这两个任务对总等待时间的贡献是：

$$
S+(S+x)
$$

交换后，$y$ 在前、$x$ 在后：

```text
y 的等待时间：S
x 的等待时间：S + y
```

贡献变成：

$$
S+(S+y)
$$

原贡献减去交换后的贡献是：

$$
x-y
$$

若 $x>y$，交换后总等待时间会减少 $x-y$。因此较长任务排在较短任务前面，是一个可以立即改进的逆序。

## 为什么其他任务不受影响

交换只改变 $x$、$y$ 两个任务的先后：

- 它们之前的任务完全没有变化；
- 它们之后的第一个任务仍然在 $S+x+y$ 时刻开始；
- 更后面的任务也因此保持原等待时间。

所以比较相邻两项时，只计算这两个任务的贡献就足够了。不能忽略这一步；若交换还会改变其他部分，就必须把受影响的部分一起计入比较。

## 从局部顺序得到全局顺序

只要排列中存在相邻的 $x>y$，交换它就会让答案严格变小。不断交换这类相邻逆序，最终会得到：

```text
duration[1] <= duration[2] <= ... <= duration[n]
```

也就是按任务时长非递减排列。

这与冒泡排序消除逆序的过程相同。任意初始排列都能通过有限次相邻交换变成有序排列，而每一步都不会让答案变差，因此有序排列的答案不会大于任意初始排列。它就是全局最优解。

这解释了邻项交换为什么能推出全局结论：

1. 目标顺序可以用“相邻两项不逆序”刻画；
2. 每个相邻逆序都能安全交换；
3. 不断交换一定会到达目标顺序；
4. 整条变换路径上的答案始终不增。

若 $x=y$，交换前后答案相同。因此相同时采用什么顺序都不影响最小总等待时间。

## 排序后计算答案

先把任务时长排序：

```cpp
sort(duration.begin() + 1, duration.begin() + n + 1);
```

`elapsed` 表示前面任务的总时长，也就是当前任务的等待时间：

```cpp
ll elapsed = 0;
ll answer = 0;

for (int i = 1; i <= n; i++) {
    answer += elapsed;
    elapsed += duration[i];
}
```

必须先把 `elapsed` 加入答案，再加入当前任务时长；当前任务不需要等待自己完成。

## 手动过程

输入任务时长：

```text
3 1 4 1 5
```

排序后为：

```text
1 1 3 4 5
```

| 当前时长 | 当前等待时间 `elapsed` | 累计答案 |
| ---: | ---: | ---: |
| 1 | 0 | 0 |
| 1 | 1 | 1 |
| 3 | 2 | 3 |
| 4 | 5 | 8 |
| 5 | 9 | 17 |

最小总等待时间是 `17`。

## 完整代码

下面读入所有任务时长，输出最小总等待时间。输入保证时长为非负整数。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

int n;
vector<ll> duration;

ll minimum_total_waiting_time() {
    sort(duration.begin() + 1, duration.begin() + n + 1);

    ll elapsed = 0;
    ll answer = 0;
    for (int i = 1; i <= n; i++) {
        answer += elapsed;
        elapsed += duration[i];
    }
    return answer;
}

void solve() {
    scanf("%d", &n);

    duration.assign(n + 5, 0);
    for (int i = 1; i <= n; i++) {
        scanf("%lld", &duration[i]);
    }

    printf("%lld\n", minimum_total_waiting_time());
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
5
3 1 4 1 5
```

输出：

```text
17
```

## 正确性

若某个任务顺序中存在相邻任务 $x>y$，交换它们只会改变这两个任务的等待时间，并使总等待时间减少 $x-y>0$。因此任何包含这类相邻逆序的排列都不是最优排列。

对任意排列不断交换相邻逆序，最终得到时长非递减的排列。每次交换都不会增加总等待时间，所以最终有序排列的答案不大于初始排列。由于初始排列可以任取，有序排列不劣于任何合法排列，因此算法得到全局最小总等待时间。

## 复杂度

排序需要 $O(n\log n)$ 时间，扫描需要 $O(n)$ 时间，总时间复杂度是 $O(n\log n)$。除输入数组与 `sort` 使用的调用栈外，扫描只使用常数个变量。

## 何时可以尝试邻项交换

当问题要求给全部对象确定顺序，并且目标可以写成各位置贡献之和时，可以尝试：

1. 只固定一对相邻对象；
2. 分别计算 `x,y` 与 `y,x` 两种顺序的贡献；
3. 化简差值，判断什么条件下其中一种顺序不差；
4. 检查交换是否会影响其他对象；
5. 证明消除全部相邻逆序会到达一个全局确定的顺序。

差值有时会得到 `x.key <= y.key` 这样的排序规则，也可能得到交叉相乘形式。不能先猜排序字段，再省略受影响部分。

## 常见错误

### 只比较两个任务，不说明其他任务

邻项交换能够局部计算，是因为后续任务的开始时刻仍为 $S+x+y$。其他问题不一定具有这个性质，必须单独验证。

### 证明一次交换更好，却没有证明最终顺序

还需要说明不断交换会终止，并且终止时恰好得到目标顺序。这里使用的是逆序数不断减少，最终得到非递减排列。

### 把当前任务时长计入自己的等待时间

等待时间只包含它前面的任务。循环中先执行 `answer += elapsed`，再更新 `elapsed`。

### 使用 32 位整数累计

单个时长可能放进 32 位整数，但一个时长会被计入许多后续任务的等待时间。模板用 `ll` 保存时长、前缀时间和答案。

### 误用到不同目标

若目标改成最大化收益、最小化最大迟到时间，或允许任务中断，交换式会改变。必须从新目标重新计算两种相邻顺序，不能直接套用“短任务优先”。

## 基础练习

1. 手算 `4, 2, 7, 1` 在输入顺序和排序顺序下的总等待时间。
2. 对相邻时长 `x=8, y=3`，计算交换前后贡献的差。
3. 说明为什么交换相邻任务不会改变它们后面任务的等待时间。
4. 把目标改成所有任务完成时间之和，重新计算相邻交换式。
5. 输出一种最优任务编号顺序；时长相同时按原编号排序。
6. 枚举较小 $n$ 的全部排列，与排序算法的答案随机对拍。

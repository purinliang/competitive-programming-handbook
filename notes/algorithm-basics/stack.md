# 栈

> 最近修订：2026-08-16 11:00 +10:00（未审阅）

数组和链表允许从许多位置读取或修改元素，但有些问题只关心“最后放进去、还没有取出来”的那一项：

- 程序进入一层 [调用栈](../cpp/function-call-stack.md) 后，要先结束最内层调用才能返回外层；
- 编辑器撤销时，最后完成的操作最先被撤销；
- 扫描括号时，右括号必须先匹配最近一个尚未匹配的左括号。

把访问方式限制为“只能在同一端加入、查看和删除”，就得到栈。

## 后进先出

栈遵循后进先出（Last In, First Out，LIFO）：最后进入栈的元素最先离开。

把 `3`、`5`、`8` 依次加入栈，可以从下到上表示为：

```text
top -> 8
       5
       3
```

第一次删除得到 `8`，此后新的栈顶是 `5`。不能越过 `8` 直接删除或读取中间的 `5`；这条限制正是栈的结构语义。

## 四个基础操作

栈只需要四个基础操作：

| 操作 | 含义 |
| --- | --- |
| `push(value)` | 把新元素放到栈顶 |
| `top()` | 读取栈顶，但不删除 |
| `pop()` | 删除栈顶，但不返回它 |
| `empty()` | 判断栈中是否没有元素 |

`top()` 和 `pop()` 只能用于非空栈。需要取出并删除栈顶时，先调用 `top()` 保存结果，再调用 `pop()`：

```cpp
int value = top();
pop();
```

本篇先理解这些操作为什么足够表示后进先出。[stack](../cpp/stack.md) 会教授标准库中完全对应的接口。

## 数组实现

栈中的元素始终从底部到顶部排列，不会在中间插入或删除，因此可以用数组的前缀 `a[1..top_index]` 保存。

变量 `top_index` 同时表示当前元素数量和栈顶下标：

```cpp
vector<int> a(capacity + 5);
int top_index = 0;
```

`top_index == 0` 表示空栈。压入新元素时，先扩大有效区间，再写入新栈顶：

```cpp
top_index++;
a[top_index] = value;
```

也可以合写为：

```cpp
a[++top_index] = value;
```

读取栈顶就是访问 `a[top_index]`：

```cpp
int value = a[top_index];
```

删除栈顶只要缩短有效前缀：

```cpp
top_index--;
```

旧数值可能仍留在 `a[top_index + 1]`，但它已经位于逻辑栈之外，不需要清零。每个操作只修改固定数量的变量和数组位置，因此 `push`、`top`、`pop`、`empty` 都是 $O(1)$。

## 容量与下溢

数组实现必须保证 `push` 前还有容量。题目最多进行 $q$ 次压栈时，可以分配：

```cpp
vector<int> a(q + 5);
```

若 `top_index == capacity` 仍然压栈，就会写出已分配范围。标准库 `stack` 通常使用能够自动扩容的底层容器，但可用内存仍然不是无限的。

空栈上调用 `top` 或 `pop` 称为下溢。它们没有合法结果；程序必须通过题目条件证明栈非空，或先判断：

```cpp
if (top_index > 0) {
    int value = a[top_index];
    top_index--;
}
```

## 为什么不允许访问中间

数组底层当然能够读取 `a[i]`，但栈这个抽象结构故意只暴露栈顶。限制接口有两个作用：

- 代码明确表达“只能按后进先出处理”的问题规律；
- 以后可以把底层从数组换成链表，而不改变使用栈的算法。

如果算法经常需要读取第 $k$ 个元素或删除中间项，它需要的是数组、链表或其他结构，不应一边称它为栈，一边绕过接口任意访问底层存储。

## 链表实现

把单向链表的 `head` 视为栈顶，也能实现栈：

- `push` 在 `head` 前插入新节点；
- `top` 读取 `head` 节点；
- `pop` 删除 `head` 节点；
- `empty` 判断 `head == 0`。

四个操作同样都是 $O(1)$。数组实现连续、简单，通常具有更好的局部性；链表实现按需建立节点，但每个元素还要保存链接。栈描述的是操作规则，不限定必须使用哪一种底层结构。

## 括号匹配

考虑只包含 `()`、`[]`、`{}` 的字符串。一个合法括号序列需要满足：

1. 每个右括号都有一个尚未匹配的左括号；
2. 右括号类型与最近的未匹配左括号相同；
3. 扫描结束后没有剩余左括号。

为什么必须匹配“最近”的左括号？例如：

```text
([ ])
```

读到 `]` 时，最近尚未匹配的是 `[`，它们组成内部的一层；随后 `)` 才与更早的 `(` 匹配。嵌套结构总是先结束最内层，恰好符合后进先出。

## 扫描过程

从左到右处理每个字符 `c`：

- 若 `c` 是左括号，把它压入栈；
- 若 `c` 是右括号而栈为空，它没有对应左括号，立即不合法；
- 否则读取栈顶左括号，类型不匹配则立即不合法；
- 类型匹配时删除栈顶，继续扫描。

以 `{[()]}` 为例：

| 读入字符 | 操作 | 栈中内容（底到顶） |
| --- | --- | --- |
| `{` | 压入 | `{` |
| `[` | 压入 | `{ [` |
| `(` | 压入 | `{ [ (` |
| `)` | 匹配并弹出 | `{ [` |
| `]` | 匹配并弹出 | `{` |
| `}` | 匹配并弹出 | 空 |

扫描结束时栈为空，所以整个字符串合法。

只检查扫描过程中有没有错误还不够。字符串 `((` 从未遇到错误右括号，但结束后仍有两个左括号没有匹配，因此必须最后检查 `empty()`。

## 字符栈

根据数组实现，可以把括号匹配需要的字符栈封装为一个对象：

```cpp
struct CharStack {
    vector<char> a;
    int top_index;

    CharStack(int capacity) {
        a.resize(capacity + 5);
        top_index = 0;
    }

    bool empty() const {
        return top_index == 0;
    }

    void push(char value) {
        a[++top_index] = value;
    }

    char top() const {
        return a[top_index];
    }

    void pop() {
        top_index--;
    }
};
```

`CharStack` 只暴露栈操作，不让括号算法依赖内部下标。构造时以字符串长度为容量，因为每个字符最多导致一次压栈。

## 完整代码

先分别定义“是否为左括号”和“一对括号是否匹配”，再把扫描规则翻译成代码：

```cpp
#include <bits/stdc++.h>
using namespace std;

struct CharStack {
    vector<char> a;
    int top_index;

    CharStack(int capacity) {
        a.resize(capacity + 5);
        top_index = 0;
    }

    bool empty() const {
        return top_index == 0;
    }

    void push(char value) {
        a[++top_index] = value;
    }

    char top() const {
        return a[top_index];
    }

    void pop() {
        top_index--;
    }
};

bool is_opening(char c) {
    return c == '(' || c == '[' || c == '{';
}

bool matches(char opening, char closing) {
    return (opening == '(' && closing == ')') ||
           (opening == '[' && closing == ']') ||
           (opening == '{' && closing == '}');
}

bool is_valid(const string& s) {
    int n = s.size();
    CharStack st(n);

    for (char c : s) {
        if (is_opening(c)) {
            st.push(c);
            continue;
        }

        if (st.empty() || !matches(st.top(), c)) {
            return false;
        }
        st.pop();
    }

    return st.empty();
}

void solve() {
    string s;
    getline(cin, s);
    cout << (is_valid(s) ? "Yes" : "No") << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
{[()]}
```

输出：

```text
Yes
```

设字符串长度为 $n$。每个字符至多压栈一次、弹栈一次，每次操作是 $O(1)$，所以时间复杂度是 $O(n)$。最坏情况下所有字符都是左括号，栈需要保存 $n$ 个字符，空间复杂度是 $O(n)$。

完整代码按整行读入，因此空串也会被判断为合法括号序列。它假设非空内容只包含六种括号；若题目还允许普通字符，必须先根据题意决定忽略它们还是判为非法，不能让未定义字符默认进入右括号分支。

## 常见错误

### 先 top 再判断空

右括号出现时必须先检查 `empty()`，再调用 `top()`。条件 `st.empty() || !matches(st.top(), c)` 利用逻辑或的短路规则：栈为空时不会继续访问栈顶。

### 匹配任意更早的左括号

合法嵌套要求右括号匹配最近的未匹配左括号，只能检查栈顶，不能跳过它寻找更早节点。

### 匹配后忘记 pop

一对括号已经配对后，左括号必须从未匹配集合中删除，否则后续右括号会重复使用它。

### 扫描结束不检查空栈

过程中没有出现多余右括号，不代表所有左括号都已经匹配。最终返回值必须是 `st.empty()`。

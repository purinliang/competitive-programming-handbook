# 复杂度

> 最近修订：2026-08-16 06:44 +10:00（未审阅）

同一个问题往往有许多正确做法。输入只有十个数时，两层循环和一次排序都能很快结束；输入扩大到二十万个数后，两层循环要检查约四百亿对元素，排序的主导运算却仍在百万到千万量级。

仅凭一组样例的运行时间无法判断程序能否处理最大数据。我们需要描述输入规模增大时，算法所需运算次数和存储量怎样增长，这就是时间复杂度和空间复杂度。

## 输入规模

复杂度中的变量必须对应问题规模。处理一个长度为 $n$ 的数组时，通常用 $n$ 表示元素数量；处理一张有 $n$ 个点、$m$ 条边的图时，需要同时使用 $n,m$。

同一个字母不能脱离题意理解。字符串算法中的 $n$ 可能是文本长度，矩阵问题中的 $n,m$ 可能是行数和列数。分析开始前，先说清楚每个规模变量表示什么。

## 不测秒数，计算增长

考虑顺序扫描 $n$ 个元素并求和：

```cpp
ll sum = 0;
for (int i = 1; i <= n; i++) {
    sum += a[i];
}
```

循环执行 $n$ 次。每轮进行下标访问、加法、赋值和循环控制等固定数量的基础操作，因此总运算次数可以写成：

$$
c_1n+c_2
$$

$c_1,c_2$ 会随编译器、处理器和具体代码改变，但当 $n$ 增大时，主导增长的是 $n$。我们把这种增长记作 $O(n)$。

复杂度不是实际运行秒数。两个同为 $O(n)$ 的程序可能因为常数、缓存、输入输出和语言实现而速度不同；复杂度首先排除的是增长速度完全不合适的方案。

## 大 O 记号

$O(f(n))$ 表示：当输入足够大时，所需资源能够被某个固定常数倍的 $f(n)$ 控制。竞赛中通常给出已经证明的、尽可能紧的简单上界。

例如：

$$
3n+10=O(n)
$$

$$
5n^2+7n+20=O(n^2)
$$

常数倍和增长更慢的项不会改变最终数量级，因此通常使用这些化简规则：

- $O(3n)=O(n)$；
- $O(n+100)=O(n)$；
- $O(n^2+n)=O(n^2)$；
- $O(2^n+n^3)=O(2^n)$。

严格来说，一个 $O(n)$ 算法也属于 $O(n^2)$，因为 $n$ 最终不超过 $n^2$；但后者丢失了更有价值的信息。本书说“时间复杂度是 $O(n)$”时，默认选择能够表达实际主导增长的紧致上界，而不是故意写得更宽松。

## 常数时间

执行次数不随输入规模增长的操作记作 $O(1)$：

```cpp
int first = a[1];
int last = a[n];
int larger = max(first, last);
```

$O(1)$ 不表示恰好执行一条机器指令，只表示运算次数被一个与 $n$ 无关的常数限制。一次整数加法、比较和数组下标访问都可以在当前分析层级视为 $O(1)$。

若一个“基础操作”处理的对象本身会随输入增长，就必须继续分析。例如逐项复制一个长度为 $n$ 的序列不是 $O(1)$，而是 $O(n)$；比较两个长字符串也可能需要逐字符扫描。

## 常见增长速度

输入增大时，常见复杂度从慢到快大致排列为：

$$
O(1)<O(\log n)<O(n)<O(n\log n)<O(n^2)<O(n^3)<O(2^n)<O(n!)
$$

这里的“慢到快”指资源需求的增长速度，而不是算法运行得越来越快。复杂度增长越慢，通常越能处理较大的输入。

当 $n=200000$ 时，$n^2$ 约为四百亿，而 $n\log_2 n$ 只有几百万量级。即使一次比较的实际成本并不相同，这种数量级差距通常也足以决定方案能否完成。

不能只背一张“某个 $n$ 应选什么复杂度”的表。时间限制、常数、输入输出、数据类型和机器环境都会影响实际速度；应先用题目上限估算主要操作数量，再为边界留下余量。

## 最坏情况与平均情况

同一算法在不同输入上的执行次数可能不同。顺序查找若第一个元素就是目标，只检查一次；目标位于末尾或根本不存在时，需要检查全部 $n$ 个元素。

除非特别注明，本书和多数竞赛题分析使用最坏时间复杂度，因为程序必须在所有合法测试数据上通过。若说平均、期望或均摊复杂度，会明确指出它依赖的含义：

- 平均复杂度需要说明输入按照什么分布出现；
- 期望复杂度常来自算法自身的随机选择；
- 均摊复杂度把一串操作的总成本平均到每次操作，例如 `vector::push_back()`。

这三种概念不能都简写成“平均”。当前只需要在看到相应词语时知道它们不是单次最坏保证。

## 空间复杂度

空间复杂度描述算法需要的存储量怎样随输入规模增长。

保存 $n$ 个整数需要 $O(n)$ 空间。若代码按照题目上限预先开辟固定容量，也应按
实际开辟的容量计算内存，而不是只看这次输入恰好用了多少个位置。

只使用固定数量的整数变量需要 $O(1)$ 空间：

```cpp
ll sum = 0;
int maximum = 0;
```

二维 `n` 行、`m` 列表格需要 $O(nm)$ 空间。只看变量声明的数量不够；容器内部元素数量同样必须计算。

递归调用也会占用空间。每一层尚未返回的调用都保留自己的参数、局部变量和返回位置；若递归最深达到 $d$ 层，调用栈通常需要 $O(d)$ 空间。具体机制见 [调用栈](../cpp/function-call-stack.md)。

## 总空间与额外空间

有时我们统计包括输入存储在内的总空间，有时只关心算法在输入之外新增的额外空间，必须写清楚口径。

假设输入已经保存在从 `1` 开始的数组 `values` 中，再求和：

```cpp
ll sum = 0;
for (int i = 1; i <= n; i++) {
    sum += values[i];
}
```

容器本身使用 $O(n)$ 空间，求和过程只新增 $O(1)$ 额外空间。

若题目只要求总和，可以边读边加，不必保存输入：

```cpp
ll sum = 0;
for (int i = 1; i <= n; i++) {
    int value;
    scanf("%d", &value);
    sum += value;
}
```

这整个程序对输入数值只使用 $O(1)$ 空间。若后面的操作还需要重新访问各个元素，就不能为了降低空间而丢弃它们。

## 完整代码

下面的程序读入正整数 $n$ 和随后的 $n$ 个整数，输出总和、最大值和正数个数。所有统计量都能在读到当前元素时更新，因此不保存整个数组。

第一个数单独读入，用它初始化 `maximum`，避免凭空选择一个可能与题目范围冲突的初值：

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

void solve() {
    int n;
    scanf("%d", &n);

    int value;
    scanf("%d", &value);

    ll sum = value;
    int maximum = value;
    int positive_count = value > 0;

    for (int i = 2; i <= n; i++) {
        scanf("%d", &value);
        sum += value;
        if (value > maximum) {
            maximum = value;
        }
        if (value > 0) {
            positive_count++;
        }
    }

    printf("%lld %d %d\n", sum, maximum, positive_count);
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
6
3 -2 7 0 5 -1
```

输出：

```text
12 7 3
```

每个输入整数只处理一次，每次只做固定数量的运算，所以时间复杂度是 $O(n)$。程序只保存当前值、三个统计量和循环变量，额外空间复杂度是 $O(1)$；它没有建立 $O(n)$ 的输入数组。

## 基础练习

1. 分别说明处理数组和处理图时，输入规模变量可以表示什么。
2. 把 $5n^2+7n+20$ 化成大 $O$ 记号，并说明省略了什么。
3. 判断读取一个数组元素和复制整个数组为什么不是同一种复杂度。
4. 比较“先保存全部输入再求和”和“边读边求和”的总空间与额外空间。
5. 找出一个递归函数的最大递归深度，并把调用栈计入空间复杂度。
6. 对 $n=200000$，分别估算 $n$、$n\log_2 n$ 与 $n^2$ 的数量级。

## 需要记住什么

1. 为什么复杂度描述增长速度，而不是某次运行的秒数？
2. 分析开始前为什么必须说明 $n,m$ 分别表示什么？
3. 为什么常数倍和低阶项通常可以省略？
4. 默认所说的时间复杂度通常对应最坏、平均还是单次最好情况？
5. $O(1)$ 是否表示恰好一条指令？复制长度为 $n$ 的容器为什么不是 $O(1)$？
6. 总空间复杂度与额外空间复杂度有什么区别？递归调用栈是否需要计入空间？
7. 怎样把题目最大输入规模代入复杂度，比较两个方案的数量级？

大 $O$ 以外的渐近记号及其形式化定义见扩展阅读 [渐近记号](asymptotic-notation.md)。

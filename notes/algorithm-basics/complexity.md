# 复杂度：时间与空间

> 最近修订：2026-08-13 05:00 +10:00（未审阅）

同一个问题往往有许多正确做法。输入只有十个数时，两层循环和一次排序都能很快结束；输入扩大到二十万个数后，两层循环要检查约四百亿对元素，排序的主导运算却仍在百万到千万量级。

仅凭一组样例的运行时间无法判断程序能否处理最大数据。我们需要描述输入规模增大时，算法所需运算次数和存储量怎样增长，这就是时间复杂度和空间复杂度。

## 输入规模

复杂度中的变量必须对应问题规模。处理一个长度为 $n$ 的数组时，通常用 $n$ 表示元素数量；处理一张有 $n$ 个点、$m$ 条边的图时，需要同时使用 $n,m$。

同一个字母不能脱离题意理解。字符串算法中的 $n$ 可能是文本长度，矩阵问题中的 $n,m$ 可能是行数和列数。分析开始前，先说清楚每个规模变量表示什么。

## 不测秒数，计算增长

考虑顺序扫描 $n$ 个元素并求和：

```cpp
ll sum = 0;
for (int i = 1; i <= n; i++) {
    sum += a[i];
}
```

循环执行 $n$ 次。每轮进行下标访问、加法、赋值和循环控制等固定数量的基础操作，因此总运算次数可以写成：

$$
c_1n+c_2
$$

$c_1,c_2$ 会随编译器、处理器和具体代码改变，但当 $n$ 增大时，主导增长的是 $n$。我们把这种增长记作 $O(n)$。

复杂度不是实际运行秒数。两个同为 $O(n)$ 的程序可能因为常数、缓存、输入输出和语言实现而速度不同；复杂度首先排除的是增长速度完全不合适的方案。

## 大 O 记号

$O(f(n))$ 表示：当输入足够大时，所需资源能够被某个固定常数倍的 $f(n)$ 控制。竞赛中通常给出已经证明的、尽可能紧的简单上界。

例如：

$$
3n+10=O(n)
$$

$$
5n^2+7n+20=O(n^2)
$$

常数倍和增长更慢的项不会改变最终数量级，因此通常使用这些化简规则：

- $O(3n)=O(n)$；
- $O(n+100)=O(n)$；
- $O(n^2+n)=O(n^2)$；
- $O(2^n+n^3)=O(2^n)$。

严格来说，一个 $O(n)$ 算法也属于 $O(n^2)$，因为 $n$ 最终不超过 $n^2$；但后者丢失了更有价值的信息。本书说“时间复杂度是 $O(n)$”时，默认选择能够表达实际主导增长的紧致上界，而不是故意写得更宽松。

## 常数时间

执行次数不随输入规模增长的操作记作 $O(1)$：

```cpp
int first = a[1];
int last = a[n];
int larger = max(first, last);
```

$O(1)$ 不表示恰好执行一条机器指令，只表示运算次数被一个与 $n$ 无关的常数限制。一次整数加法、数组下标访问以及 `vector::size()` 都可以在当前分析层级视为 $O(1)$。

若一个“基础操作”处理的对象本身会随输入增长，就必须继续分析。例如复制一个长度为 $n$ 的 `vector` 不是 $O(1)$，而是 $O(n)$；比较两个长字符串也可能需要逐字符扫描。

## 顺序结构相加

两段循环依次执行时，运算次数相加：

```cpp
for (int i = 1; i <= n; i++) {
    // O(1)
}

for (int i = 1; i <= n; i++) {
    // O(1)
}
```

总时间是：

$$
O(n)+O(n)=O(2n)=O(n)
$$

若第一段处理 $n$ 个元素，第二段处理 $m$ 个元素，则是 $O(n+m)$。当题目没有说明 $n,m$ 的固定关系时，不能擅自把它化成其中一个变量。

条件分支只会执行其中一边。最坏时间取可能执行的较慢分支：

```cpp
if (condition) {
    // O(n)
} else {
    // O(n log n)
}
```

这段整体的最坏时间是 $O(n\log n)$。

## 嵌套结构相乘

内层循环会为外层的每一次执行重新运行：

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= n; j++) {
        // O(1)
    }
}
```

外层 $n$ 次，每次执行内层 $n$ 次，总共 $n\times n=n^2$ 次，因此是 $O(n^2)$。

两个规模不同时：

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= m; j++) {
        // O(1)
    }
}
```

总时间是 $O(nm)$。

不能仅看见两层循环就立即写 $O(n^2)$。例如：

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= i; j++) {
        // O(1)
    }
}
```

实际执行次数是：

$$
1+2+\cdots+n=\frac{n(n+1)}{2}=O(n^2)
$$

结论仍然是平方，但理由来自所有内层次数之和，而不是循环语法本身。后续双指针算法甚至可以写成嵌套的 `while`，却因为两个指针总共只单向移动 $O(n)$ 次而保持线性。

## 折半与对数

若每轮把剩余规模缩小为原来的一半：

```cpp
for (int length = n; length > 1; length /= 2) {
    // O(1)
}
```

执行后的规模依次约为：

$$
n,\frac n2,\frac n4,\frac n8,\ldots,1
$$

经过 $k$ 轮后约为 $n/2^k$。让它缩小到 $1$，需要 $2^k\ge n$，因此轮数是 $O(\log n)$。

复杂度中省略对数底数，因为不同固定底数只相差常数倍：

$$
\log_2 n=\frac{\log_3 n}{\log_3 2}=O(\log_3 n)
$$

所以通常直接写 $O(\log n)$。二分查找每轮丢弃一半候选范围，就是最常见的对数时间算法。

## 常见增长速度

输入增大时，常见复杂度从慢到快大致排列为：

$$
O(1)<O(\log n)<O(n)<O(n\log n)<O(n^2)<O(n^3)<O(2^n)<O(n!)
$$

这里的“慢到快”指资源需求的增长速度，而不是算法运行得越来越快。复杂度增长越慢，通常越能处理较大的输入。

当 $n=200000$ 时，$n^2$ 约为四百亿，而 $n\log_2 n$ 只有几百万量级。即使一次比较的实际成本并不相同，这种数量级差距通常也足以决定方案能否完成。

不能只背一张“某个 $n$ 应选什么复杂度”的表。时间限制、常数、输入输出、数据类型和机器环境都会影响实际速度；应先用题目上限估算主要操作数量，再为边界留下余量。

## 最坏情况与平均情况

同一算法在不同输入上的执行次数可能不同。顺序查找若第一个元素就是目标，只检查一次；目标位于末尾或根本不存在时，需要检查全部 $n$ 个元素。

除非特别注明，本书和多数竞赛题分析使用最坏时间复杂度，因为程序必须在所有合法测试数据上通过。若说平均、期望或均摊复杂度，会明确指出它依赖的含义：

- 平均复杂度需要说明输入按照什么分布出现；
- 期望复杂度常来自算法自身的随机选择；
- 均摊复杂度把一串操作的总成本平均到每次操作，例如 `vector::push_back()`。

这三种概念不能都简写成“平均”。当前只需要在看到相应词语时知道它们不是单次最坏保证。

## 空间复杂度

空间复杂度描述算法需要的存储量怎样随输入规模增长。

保存 $n$ 个整数的 `vector` 需要 $O(n)$ 空间：

```cpp
vector<int> values(n);
```

只使用固定数量的整数变量需要 $O(1)$ 空间：

```cpp
ll sum = 0;
int maximum = 0;
```

二维 `n` 行、`m` 列表格需要 $O(nm)$ 空间。只看变量声明的数量不够；容器内部元素数量同样必须计算。

递归调用也会占用空间。每一层尚未返回的调用都保留自己的参数、局部变量和返回位置；若递归最深达到 $d$ 层，调用栈通常需要 $O(d)$ 空间。具体机制见 [函数：调用栈](../cpp/function-call-stack.md)。

## 总空间与额外空间

有时我们统计包括输入存储在内的总空间，有时只关心算法在输入之外新增的额外空间，必须写清楚口径。

下面的做法先保存全部输入，再求和：

```cpp
vector<int> values(n);
// 读入 values

ll sum = 0;
for (int value : values) {
    sum += value;
}
```

容器本身使用 $O(n)$ 空间，求和过程只新增 $O(1)$ 额外空间。

若题目只要求总和，可以边读边加，不必保存输入：

```cpp
ll sum = 0;
for (int i = 1; i <= n; i++) {
    int value;
    scanf("%d", &value);
    sum += value;
}
```

这整个程序对输入数值只使用 $O(1)$ 空间。若后面的操作还需要重新访问各个元素，就不能为了降低空间而丢弃它们。

## 从代码得到复杂度

分析一段程序时，可以依次完成四步：

1. 说明输入规模变量分别是什么；
2. 找出随规模重复执行的核心操作，而不是机械计算每个标点；
3. 对顺序部分相加，对真正嵌套执行的部分相乘，并分析循环变量怎样变化；
4. 分别统计输入存储、额外数组、递归深度和其他会随规模增长的对象。

最后用题目给出的最大规模代入主要项，检查数量级是否合理。复杂度分析必须对应实际代码；一句“用了两层循环”或“这是某某算法”都不能代替对执行次数的说明。

## 完整代码

下面的程序读入正整数 $n$ 和随后的 $n$ 个整数，输出总和、最大值和正数个数。所有统计量都能在读到当前元素时更新，因此不保存整个数组。

第一个数单独读入，用它初始化 `maximum`，避免凭空选择一个可能与题目范围冲突的初值：

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

int main() {
    int n;
    scanf("%d", &n);

    int value;
    scanf("%d", &value);

    ll sum = value;
    int maximum = value;
    int positive_count = value > 0;

    for (int i = 2; i <= n; i++) {
        scanf("%d", &value);
        sum += value;
        maximum = max(maximum, value);
        if (value > 0) {
            positive_count++;
        }
    }

    printf("%lld %d %d\n", sum, maximum, positive_count);
    return 0;
}
```

输入：

```text
6
3 -2 7 0 5 -1
```

输出：

```text
12 7 3
```

每个输入整数只处理一次，每次只做固定数量的运算，所以时间复杂度是 $O(n)$。程序只保存当前值、三个统计量和循环变量，额外空间复杂度是 $O(1)$；它没有建立 $O(n)$ 的输入数组。

## 基础练习

1. 分析三段依次执行的长度为 $n$ 的循环，说明为什么总时间仍是 $O(n)$。
2. 分析一个外层执行 $n$ 次、内层执行 $m$ 次的循环。
3. 写出循环 `for (int length = n; length > 1; length /= 2)` 的取值序列并分析复杂度。
4. 分析只遍历矩阵主对角线和遍历整个 $n\times n$ 矩阵的区别。
5. 比较“先保存全部输入再求和”和“边读边求和”的总空间与额外空间。
6. 找出一个递归函数的最大递归深度，并把调用栈计入空间复杂度。
7. 对 $n=200000$，分别估算 $n$、$n\log_2 n$ 与 $n^2$ 的数量级。

## 需要记住什么

1. 为什么复杂度描述增长速度，而不是某次运行的秒数？
2. 分析开始前为什么必须说明 $n,m$ 分别表示什么？
3. 为什么常数倍和低阶项通常可以省略？
4. 顺序执行的部分怎样合并复杂度？嵌套执行的部分为什么通常相乘？
5. 为什么不能只根据循环层数判断复杂度？
6. 每轮把规模减半为什么产生 $O(\log n)$？对数底数为什么通常省略？
7. 默认所说的时间复杂度通常对应最坏、平均还是单次最好情况？
8. $O(1)$ 是否表示恰好一条指令？复制长度为 $n$ 的容器为什么不是 $O(1)$？
9. 总空间复杂度与额外空间复杂度有什么区别？递归调用栈是否需要计入空间？
10. 怎样把题目最大输入规模代入复杂度，比较两个方案的数量级？

渐近记号的形式化极限定义、$\Theta$ 与 $\Omega$ 的证明、主定理和摊还分析的完整方法不属于本篇的基础目标。遇到具体递归、数据结构和随机算法时，再在对应文章中推导需要的分析工具。

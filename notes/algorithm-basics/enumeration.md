# 枚举

> 最近修订：2026-08-16 16:20 +10:00（未审阅）

许多题目的答案来自一个有限的候选集合。只要候选数量能够承受，最可靠的办法就是按照明确顺序生成每个候选，检查它是否满足条件，再更新答案。这种方法称为枚举。

枚举的核心不只是“写循环”。一份正确的枚举必须回答三个问题：枚举对象是什么、怎样保证不遗漏也不重复、检查全部候选需要多少时间。本篇用下标对计数完整处理这三个问题。

## 目标和下标对

给定一个长度为 $n$ 的无序整数数组 `a[1..n]` 和目标 `target`，统计有多少对下标 `(i, j)` 满足：

$$
1\le i<j\le n
$$

并且：

$$
a[i]+a[j]=target.
$$

例如：

```text
a = 1 4 2 3 3
target = 6
```

合法下标对是：

```text
(2, 3): 4 + 2 = 6
(4, 5): 3 + 3 = 6
```

所以答案为 `2`。

这里统计的是下标对，不是不同的数值对。即使两个位置保存相同数值，只要下标不同，也可以组成一对；同一组下标不能交换顺序后再计一次。

## 先确定枚举对象

题目中的一个候选答案由两个不同下标组成。若直接让 `i`、`j` 都遍历 `1..n`：

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= n; j++) {
        // 检查 (i, j)
    }
}
```

这会产生三类候选：

- `i == j`：同一个位置被使用两次，不合法；
- `i < j`：需要检查的下标对；
- `i > j`：与 `(j, i)` 表示同一对下标，会重复。

可以生成后再用条件排除，但更直接的方法是给每一对规定唯一表示：较小下标永远放在前面，也就是只生成 `i < j`。

## 把限制写进循环边界

固定第一个下标 `i` 后，第二个下标只能从 `i + 1` 开始：

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = i + 1; j <= n; j++) {
        // 此时自动满足 i < j
    }
}
```

这样不需要在循环内部反复判断 `i != j`，也不会同时生成 `(i, j)` 与 `(j, i)`。

当 `i == n` 时，`j` 从 `n + 1` 开始，内层循环不会执行。也可以把外层边界写成
`i < n`；两种写法生成的候选完全相同。本篇保留 `i <= n`，让 `i` 的完整下标
范围更加直观。

## 不遗漏也不重复

先证明这两个循环恰好生成题目要求的全部下标对。

对于任意合法下标对 `(x, y)`，题目已经规定 `x < y`：

- 外层循环到 `i == x` 时一定会经过 `x`；
- 内层从 `x + 1` 走到 `n`，因此一定会经过 `j == y`。

所以合法下标对不会遗漏。

反过来，每次循环都满足 `1 <= i < j <= n`，产生的候选一定是合法的不同位置。一个固定下标对只有唯一的较小下标 `i` 和较大下标 `j`，因此不可能在另一轮再次产生。

“先规定唯一表示，再用循环边界生成它”是避免重复枚举的常用方法。无序点对、无向边和选取若干递增位置时都会使用类似约定。

## 检查当前候选

候选生成正确以后，再检查当前两个位置的数值和：

```cpp
ll sum = 1LL * a[i] + a[j];
if (sum == target) {
    answer++;
}
```

数组元素使用 32 位整数，但两个元素相加可能超出 32 位范围，所以在加法前把一个操作数转换成 64 位整数。

`answer` 也使用 64 位整数。若所有下标对都满足条件，答案可能达到：

$$
\frac{n(n-1)}{2},
$$

它可能超出 32 位整数范围。

完整计数函数是：

```cpp
ll count_pair_sum(const vector<int>& a, int n, ll target) {
    ll answer = 0;

    for (int i = 1; i <= n; i++) {
        for (int j = i + 1; j <= n; j++) {
            ll sum = 1LL * a[i] + a[j];
            if (sum == target) {
                answer++;
            }
        }
    }

    return answer;
}
```

循环负责生成候选，`if` 负责判定候选，`answer` 只保存已经通过判定的数量。这三个职责分开以后，修改题目条件时通常只需要改变判定和答案更新方式。

## 手动过程

对数组：

```text
下标： 1 2 3 4 5
数值： 1 4 2 3 3
```

循环生成的下标对依次是：

| `i` | 依次枚举的 `j` | 当前数值对 | 是否计数 |
| ---: | --- | --- | --- |
| 1 | 2, 3, 4, 5 | `(1,4), (1,2), (1,3), (1,3)` | 否 |
| 2 | 3, 4, 5 | `(4,2), (4,3), (4,3)` | 第一对是 |
| 3 | 4, 5 | `(2,3), (2,3)` | 否 |
| 4 | 5 | `(3,3)` | 是 |
| 5 | 无 | 无 | 否 |

总共生成：

$$
4+3+2+1=10
$$

个下标对，其中两对的数值和为 `6`。

注意第一行中两个 `(1,3)` 是相同的数值对，却分别来自下标 `(1,4)` 和 `(1,5)`。它们是不同候选，只是都没有通过本例的目标和判定。

## 候选数量

当 `i = 1` 时，内层枚举 $n-1$ 次；当 `i = 2` 时枚举 $n-2$ 次；最后分别是 $1$ 次和 $0$ 次。总候选数量为：

$$
(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2}.
$$

每个候选只进行固定次数的加法、比较和计数，所以时间复杂度是 $O(n^2)$。函数只使用固定数量的变量，额外空间复杂度是 $O(1)$。

不能只因为看见两层循环就停止分析。这里确实是 $O(n^2)$，依据是实际生成了平方数量级的下标对；某些嵌套循环中的指针总共只移动 $O(n)$ 次，复杂度可能仍是线性的。

## 枚举是否可行

写算法前应先估算候选数量，而不是默认“暴力一定会超时”。若 $n$ 只有几千，
$O(n^2)$ 可能正是题目预期；若 $n$ 达到 $2\times10^5$，约 $2\times10^{10}$ 个
下标对通常无法逐个检查。

还要把单个候选的检查成本乘进去。若生成 $O(n^2)$ 个候选，而每个候选又用 $O(n)$ 时间检查，总时间会成为 $O(n^3)$。

枚举常有三种价值：

- 数据范围允许时，它就是最简单、最可靠的正式算法；
- 推导更快算法前，它明确展示了全部候选以及重复工作来自哪里；
- 小规模枚举可以作为对拍中的可信基准，检验复杂算法是否遗漏边界。

## 利用限制缩小候选

优化枚举的第一步，不一定是换用新的数据结构，而是把题目已经给出的限制直接写进生成过程。

本例若先枚举 `1 <= i, j <= n`，会生成 $n^2$ 个有序下标对，再用 `i < j`
过滤。改成让 `j` 从 `i + 1` 开始以后，候选数量变为 $n(n-1)/2$，并且代码
直接表达了每对只出现一次。

这没有改变 $O(n^2)$ 的渐进复杂度，却减少了无效候选和出错机会。处理更复杂问题时也应依次检查：

1. 哪些变量可以由前面选择唯一确定，不必再次枚举？
2. 哪些大小、顺序或范围限制可以直接变成循环边界？
3. 是否存在单调性，让一批候选能够被整体排除？
4. 是否存在重复状态，可以保存并复用已经计算的结果？

后两项会分别导向双指针、二分、动态规划等其他方法。使用它们以前仍应先说清楚排除或复用为什么正确。

## 与双指针的区别

[双指针](two-pointers.md) 中的两数之和要求数组有序，并且只寻找任意一组答案。顺序关系证明了当前和太小或太大时，可以一次排除某个端点参与的全部候选，因此只需 $O(n)$ 次移动。

本篇数组无序，并且要统计所有下标对。当前一对的和不能推导其他未检查位置，重复数值还会产生不同的合法下标组合，所以基础做法逐对枚举。

不能因为题目都出现了两个下标，就直接复制双指针。先写出候选集合和目标，再判断是否存在能够安全排除一批候选的额外性质。

## 完整代码

下面的程序读入一个无序数组和 64 位目标和，输出满足条件的下标对数量。输入保证数组元素可以使用 32 位整数保存。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

ll count_pair_sum(const vector<int>& a, int n, ll target) {
    ll answer = 0;

    for (int i = 1; i <= n; i++) {
        for (int j = i + 1; j <= n; j++) {
            ll sum = 1LL * a[i] + a[j];
            if (sum == target) {
                answer++;
            }
        }
    }

    return answer;
}

void solve() {
    int n;
    ll target;
    cin >> n >> target;

    vector<int> a(n + 5);
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
    }

    cout << count_pair_sum(a, n, target) << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
5 6
1 4 2 3 3
```

输出：

```text
2
```

## 常见错误

### 重复统计顺序

若 `i`、`j` 都枚举 `1..n`，下标对 `(2, 3)` 和 `(3, 2)` 会各出现一次。本题中的一对没有顺序，统一规定 `i < j`。

### 使用同一个位置两次

循环若允许 `i == j`，当 `2 * a[i] == target` 时会把一个元素使用两次。`j` 从 `i + 1` 开始可以直接避免这种候选。

### 把数值对当成下标对

数组中相同数值可能出现在多个位置。题目若统计下标对，每种不同位置组合都应计数；若题目要求不同数值对，则候选对象已经改变，需要专门去重。

### 先找到一对就停止

“是否存在”“找到任意一对”和“统计全部对数”是三个不同目标。本篇必须扫描全部候选，不能在第一次相等时 `return`。

### 只计算生成成本

总时间等于候选数量乘以每个候选的检查成本。检查若不是 $O(1)$，必须继续计入复杂度。

### 忽略加法与答案范围

两个 32 位元素相加以及平方数量级的对数都可能超出 32 位整数。分别使用 64 位整数保存 `sum` 和 `answer`。

## 需要记住什么

1. 枚举算法必须先明确哪三个问题？
2. 本篇为什么枚举下标对而不是数值对？
3. 为什么只生成 `i < j` 能同时避免自配对和重复顺序？
4. 两层循环怎样证明每个合法下标对恰好出现一次？
5. 怎样从候选数量与单次检查成本得到总时间复杂度？
6. 为什么“数据范围允许的枚举”可以直接作为正式算法？
7. 为什么枚举适合用作复杂算法的随机对拍基准？
8. 哪些题目限制可以直接进入循环边界？哪些额外性质可能导向更快算法？
9. 目标从“存在一对”改成“统计全部对数”时，程序控制流程有什么变化？

本篇只讨论由固定数量下标构成的候选。每个元素都能独立选择或不选择时，候选数量不再是固定次方，而会形成 $2^n$ 个子集。

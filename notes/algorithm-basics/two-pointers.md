# 双指针

> 最近修订：2026-08-16 15:30 +10:00（未审阅）

枚举数组中的两个位置通常需要两层循环。若两个位置之间存在顺序关系，并且一个位置移动后，另一批候选能够被整体排除，就不必反复从头尝试所有组合。

双指针让两个下标按照已经证明的方向移动。每个指针通常只走过数组一次，因此能把许多 $O(n^2)$ 的两位置枚举降低到 $O(n)$。

## 有序数组两数之和

给定一个非递减排列的 1-based 数组 `a[1..n]` 和目标 `target`，寻找两个不同位置 `l < r`，使：

$$
a[l] + a[r] = target
$$

例如：

```text
a = 1 2 4 6 9 12
target = 10
```

可以选择下标 `1, 5`，因为 $1 + 9 = 10$；也可以选择 `3, 4`，因为 $4 + 6 = 10$。题目只要求找到任意一组。

## 两层枚举

最直接的方法枚举左位置，再枚举右位置：

```cpp
for (int l = 1; l <= n; l++) {
    for (int r = l + 1; r <= n; r++) {
        if (1LL * a[l] + a[r] == target) {
            return {l, r};
        }
    }
}
```

最坏需要检查约 $n(n - 1)/2$ 对位置，时间复杂度是 $O(n^2)$。

数组有序却没有被这段代码利用。固定右端时，左端越向右，和不会减小；固定左端时，右端越向左，和不会增大。这种单调关系允许一次排除整行候选组合。

## 从两端开始

令 `l` 指向最小的候选元素，`r` 指向最大的候选元素：

```cpp
int l = 1;
int r = n;
```

只要 `l < r`，两个位置不同，当前组合合法：

```cpp
while (l < r) {
    ll sum = 1LL * a[l] + a[r];
    // 根据 sum 移动一个指针
}
```

使用 64 位整数计算 `sum`，因为两个 32 位整数相加可能超出 32 位范围。

## 当前和等于目标

若：

```cpp
sum == target
```

当前两个下标就是一组答案，可以立即返回：

```cpp
return {l, r};
```

## 当前和太小

若：

$$
a[l] + a[r] < target
$$

右端 `a[r]` 已经是当前候选区间中的最大值。保持 `l` 不变，换成任何更小的右端 `r' < r`，都有：

$$
a[l] + a[r'] \le a[l] + a[r] < target
$$

因此下标 `l` 不可能与任何剩余右端组成目标和，可以把包含它的全部候选一次排除：

```cpp
l++;
```

注意，和太小时不能移动 `r` 向左，那只会让和更小。

## 当前和太大

若：

$$
a[l] + a[r] > target
$$

左端 `a[l]` 已经是当前候选区间中的最小值。保持 `r` 不变，换成任何更大的左端 `l' > l`，都有：

$$
a[l'] + a[r] \ge a[l] + a[r] > target
$$

因此下标 `r` 不可能与任何剩余左端组成目标和，可以排除它：

```cpp
r--;
```

和太大时移动 `l` 向右只会让和更大。

## 完整查找函数

```cpp
struct Answer {
    int l;
    int r;
};

Answer find_pair_sum(const vector<int>& a, int n, ll target) {
    int l = 1;
    int r = n;

    while (l < r) {
        ll sum = 1LL * a[l] + a[r];
        if (sum == target) {
            return {l, r};
        }
        if (sum < target) {
            l++;
        } else {
            r--;
        }
    }

    return {-1, -1};
}
```

`{-1, -1}` 不可能是合法的 1-based 下标对，因此表示不存在答案。

## 候选区间不变量

循环开始时，若仍存在尚未找到的答案，那么至少一组答案的两个位置都在 `[l, r]` 中。

- 和太小时，已经证明当前 `l` 与区间内任何右端都不能成功，所以删除 `l` 不会丢掉所有答案；
- 和太大时，已经证明当前 `r` 与区间内任何左端都不能成功，所以删除 `r` 同样安全；
- 和相等时直接返回答案。

若循环以 `l >= r` 结束，候选区间中不足两个不同位置。根据不变量，原数组不存在合法位置对，因此返回失败正确。

每次移动不是“凭感觉让和靠近目标”，而是通过有序性证明某个端点参与的全部候选都不可能成功。

## 手动过程

对：

```text
a = 1 2 4 6 9 12
target = 10
```

过程为：

| `l` | `r` | 当前值 | 和 | 操作 |
| ---: | ---: | --- | ---: | --- |
| 1 | 6 | `1 + 12` | 13 | 太大，`r--` |
| 1 | 5 | `1 + 9` | 10 | 找到答案 |

若目标为 `8`：

| `l` | `r` | 当前值 | 和 | 操作 |
| ---: | ---: | --- | ---: | --- |
| 1 | 6 | `1 + 12` | 13 | `r--` |
| 1 | 5 | `1 + 9` | 10 | `r--` |
| 1 | 4 | `1 + 6` | 7 | `l++` |
| 2 | 4 | `2 + 6` | 8 | 找到答案 |

两个指针始终向中间移动，不会返回已经排除的位置。

## 时间复杂度

`l` 只从 `1` 向右移动，最多增加 $n-1$ 次；`r` 只从 `n` 向左移动，最多减少 $n-1$ 次。每轮至少移动其中一个指针，所以总循环次数是 $O(n)$。

算法没有建立新数组，额外空间是 $O(1)$。

不能因为问题涉及两个下标就直接写 $O(n^2)$，也不能因为代码可能出现嵌套循环就只数语法层数。复杂度要看每个指针在整个算法期间总共移动多少次。

## 重复值与不同位置

循环条件使用 `l < r`，保证不会用同一个数组位置两次。两个位置的数值可以相同：

```text
a = 1 3 3 7
target = 6
```

下标 `2, 3` 是合法答案。双指针会保留这两个不同位置，不会因为数值相等而合并它们。

题目若要求统计不同数值对、所有下标对或不重复输出，需要在找到一组后继续移动并专门处理重复段；那是当前“找任意一组”之外的新计数问题，不能只删除 `return` 就认为完成。

## 为什么必须有序

和二分查找一样，排除依据来自数组顺序。若数组无序，`a[l] + a[r]` 太小时，不能推出当前 `l` 与中间任意元素组合也太小。

无序输入可以先排序，再用双指针，时间是 $O(n\log n)$。但排序会改变原下标；若
题目要求输出原位置，需要把每个值与原编号组成一个结构体后一起排序。

若只做一次两数之和查询，后续学习哈希表后还可以在平均 $O(n)$ 时间内处理无序数组，并保留原下标。结构选择取决于输入是否有序、查询次数和输出要求。

## 同向双指针

双指针不一定从两端相向移动。归并排序合并两个有序区间时，`i`、`j` 分别从两个区间开头向右移动；每个元素只经过一次，仍然是双指针的线性过程。

另一类常见形式让右指针扩展一段连续区间，左指针在条件不满足时向右缩小：

```text
[ left ........ right ]
```

只要两个指针都不回退，它们总移动次数仍是 $O(n)$。这种维护连续区间的同向双指针称为滑动窗口；[滑动窗口](sliding-window.md) 会单独推导怎样维护区间信息。

并非任何两个变量都叫双指针。关键是它们分别表示序列位置，并利用单调移动避免重新枚举已经排除的组合。

## 完整代码

下面的程序读入一个非递减排列的数组和 64 位目标和，输出任意一组合法的 1-based 下标；不存在时输出 `-1 -1`。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

struct Answer {
    int l;
    int r;
};

Answer find_pair_sum(const vector<int>& a, int n, ll target) {
    int l = 1;
    int r = n;

    while (l < r) {
        ll sum = 1LL * a[l] + a[r];
        if (sum == target) {
            return {l, r};
        }
        if (sum < target) {
            l++;
        } else {
            r--;
        }
    }

    return {-1, -1};
}

void solve() {
    int n;
    ll target;
    cin >> n >> target;

    vector<int> a(n + 5);
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
    }

    Answer answer = find_pair_sum(a, n, target);
    cout << answer.l << ' ' << answer.r << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
6 8
1 2 4 6 9 12
```

输出：

```text
2 4
```

输出的下标对应 $a[2] + a[4] = 2 + 6 = 8$。若存在多组答案，程序输出由指针过程最先遇到的一组，不保证字典序最小。

## 常见错误

### 无序输入直接移动

没有非递减顺序时，当前和不能证明某个端点与其他位置的所有组合都失败，移动会漏掉答案。

### 和太小时移动右端

右端已经是当前最大候选。和太小时再减小右端只会使和不增，应当增加左端。

### 和太大时移动左端

左端已经是当前最小候选。和太大时再增加左端只会使和不减，应当减小右端。

### 循环允许 l == r

题目要求两个不同位置，所以候选区间至少要有两个元素，循环条件是 `l < r`。

### 使用 int 保存和

两个合法的 32 位整数之和可能溢出，比较前转换并保存为 `ll`。

### 只看嵌套层数分析复杂度

双指针复杂度来自整个过程中每个指针的总移动次数。即使后续滑动窗口写成外层 `for` 加内层 `while`，只要左指针不回退，总移动仍可为 $O(n)$。

2. 有序两数之和为什么从最小值与最大值开始？
3. 当前和小于目标时，为什么可以排除左端参与的所有剩余组合？
4. 当前和大于目标时，为什么可以排除右端参与的所有剩余组合？
5. 循环不变量怎样保证移动指针不会漏掉所有答案？
6. 为什么 `l < r` 能保证使用两个不同位置？重复数值是否允许？
7. 两个指针怎样从总移动次数推导出 $O(n)$？
8. 无序输入为什么不能直接使用这套移动规则？先排序会带来哪些成本和信息变化？
9. 相向双指针与同向双指针有什么共同点？

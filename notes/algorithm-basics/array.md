# 数组

> 最近修订：2026-08-16 10:49 +10:00（未审阅）

[一维数组](../cpp/one-dimensional-arrays.md) 已经说明怎样在 C++ 中声明数组，[vector](../cpp/vector.md) 则提供了运行时长度和自动扩容。现在暂时不关心具体使用哪种语法，而是把数组视为一种数据结构，分析它为什么能够快速访问任意位置，以及各类操作需要多少时间。

## 有顺序的同类元素

数组把若干类型相同的元素按照位置排成一列。每个位置都有唯一的下标，因此“第 $i$ 个元素”可以直接写成 `a[i]`。

本书自定义算法默认使用 1-based 下标。一个长度为 $5$ 的逻辑数组可以表示为：

| 下标 | 1 | 2 | 3 | 4 | 5 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| `a[i]` | 10 | 20 | 30 | 40 | 50 |

这里的顺序属于结构本身。即使两个位置保存相同数值，它们仍然是两个不同元素；交换 `a[2]` 与 `a[4]` 也会改变数组的排列。

## 连续存储

数组的元素类型相同，因此每个元素占用相同大小的空间；相邻元素又连续存放。若 `a[1]` 的地址是数组起点，那么 1-based 元素 `a[i]` 的地址可以由下面的关系得到：

$$
\text{起点地址}+(i-1)\times\text{单个元素大小}
$$

计算机不需要从 `a[1]` 开始逐个走到 `a[i]`，只要代入下标就能直接算出目标地址。下标访问和修改因此都是 $O(1)$：

```cpp
int value = a[i];
a[i] = 100;
```

这种能力称为随机访问。这里的“随机”不是随机数，而是“无论目标位置在哪里，都能直接访问”。

连续存储还让依次遍历相邻元素通常具有良好的内存局部性，但实际速度会受缓存、元素类型和访问模式影响；复杂度层面只需要记住一次合法下标访问是 $O(1)$。

## 逻辑长度与存储容量

数组能够存放多少元素是容量，当前真正参与问题的元素数量是逻辑长度。两者不能混用。

例如，为最多 $100000$ 个元素预留空间：

```cpp
const int MAXN = 1e5 + 5;
int a[MAXN];
int n;
```

`MAXN` 是存储容量，`n` 是本次输入的逻辑长度，有效元素是 `a[1..n]`。第 `0` 格和末尾余量不是逻辑数据。

使用 `vector` 作为底层存储时，本书的自定义算法同样预留 `+5`：

```cpp
vector<int> a(n + 5);
```

此时 `a.size()` 是 `n + 5`，并不等于逻辑长度 `n`。若直接教学 `vector` 原生接口，则仍然使用它自己的 0-based 下标和真实 `size()`；两种语境要明确区分。

## 遍历

处理所有元素必须依次访问 $n$ 个位置：

```cpp
for (int i = 1; i <= n; i++) {
    printf("%d\n", a[i]);
}
```

每次访问是 $O(1)$，一共执行 $n$ 次，因此遍历时间是 $O(n)$。

数组占用的空间由容量决定。保存 $n$ 个逻辑元素通常需要 $O(n)$ 空间；只用循环变量遍历它们，新增的额外空间是 $O(1)$。

## 查找

下标访问快，不代表按数值查找也快。如果只知道“寻找数值 `target`”，却不知道它在哪个下标，无序数组只能从头检查：

```cpp
int position = -1;
for (int i = 1; i <= n; i++) {
    if (a[i] == target) {
        position = i;
        break;
    }
}
```

最坏情况下，目标位于末尾或根本不存在，需要检查全部 $n$ 个元素，时间复杂度是 $O(n)$。

若数组已经有序，可以利用顺序排除大量位置，后续的二分查找能把时间降低到 $O(\log n)$。因此应区分两个问题：

- 已知下标读取 `a[i]`：$O(1)$；
- 只知道数值，寻找它出现的下标：无序时最坏 $O(n)$。

## 在中间插入

考虑向下标 $3$ 插入 `25`：

| 状态 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 插入前 | 10 | 20 | 30 | 40 | 50 | 空 |
| 插入后 | 10 | 20 | 25 | 30 | 40 | 50 |

原来的 `a[3]` 及其后所有元素都要向右移动一格。为了避免先覆盖 `a[4]`，移动必须从末尾向插入位置倒序进行：

```cpp
for (int i = n; i >= position; i--) {
    a[i + 1] = a[i];
}
a[position] = value;
n++;
```

插入前必须保证容量仍有空位。若在最前面插入，需要移动 $n$ 个元素，时间是 $O(n)$；若在最后一个逻辑元素之后插入，不需要移动，操作本身是 $O(1)$。

`vector::insert` 会替我们处理移动和必要的扩容，但连续存储的本质没有改变，中间插入仍是 $O(n)$。

## 从中间删除

删除下标 `position` 后，它右边的元素要依次向左补上空位：

```cpp
for (int i = position; i < n; i++) {
    a[i] = a[i + 1];
}
n--;
```

例如从 `10 20 25 30 40 50` 删除下标 $4$，得到 `10 20 25 40 50`。

删除最前面的元素需要移动 $n-1$ 个元素，是 $O(n)$；删除最后一个元素只要把逻辑长度减一，是 $O(1)$。

执行 `n--` 后，原来最后一格中的旧数值可能仍留在内存中，但它已经位于新的逻辑区间之外，不再属于数组内容，不需要特意清零。

## 操作复杂度

设当前逻辑长度为 $n$：

| 操作 | 时间复杂度 | 原因 |
| --- | ---: | --- |
| 已知下标访问或修改 | $O(1)$ | 由起点、元素大小和下标直接计算地址 |
| 遍历全部元素 | $O(n)$ | 每个位置访问一次 |
| 无序数组按值查找 | $O(n)$ | 最坏检查全部元素 |
| 中间或开头插入 | $O(n)$ | 移动后缀 |
| 中间或开头删除 | $O(n)$ | 移动后缀 |
| 已有空余容量时在末尾插入 | $O(1)$ | 不移动已有元素 |
| 删除末尾元素 | $O(1)$ | 只缩短逻辑长度 |

这些结论同时适用于内置数组和以 `vector` 实现的连续序列。`vector::push_back()` 还要考虑偶尔扩容，因此它是均摊 $O(1)$，已在 [序列容器：vector](../cpp/vector.md#size-与-capacity) 中解释。

## 数组适合什么问题

数组适合：

- 元素能够按整数位置编号；
- 经常需要通过下标直接访问；
- 主要操作是遍历、修改和末尾追加；
- 很少在开头或中间插入、删除。

如果题目需要频繁在已知位置附近插入或删除，连续存储导致的大量移动会成为瓶颈。[链表](linked-list.md) 会用分散的节点换取 $O(1)$ 的已知位置连接修改，但它也会失去数组的 $O(1)$ 随机访问和连续存储优势。

## 完整代码

下面的程序使用 `vector` 提供底层空间，但把 `a[1..n]` 当作一个 1-based 逻辑数组。程序先在指定位置插入一个值，再从插入后的数组中删除一个位置。

调用者已经分配 `n + 5` 个位置，并且本程序只插入一次，因此 `insert_at` 不需要另外处理容量不足：

```cpp
#include <bits/stdc++.h>
using namespace std;

void insert_at(vector<int>& a, int& n, int position, int value) {
    for (int i = n; i >= position; i--) {
        a[i + 1] = a[i];
    }
    a[position] = value;
    n++;
}

void erase_at(vector<int>& a, int& n, int position) {
    for (int i = position; i < n; i++) {
        a[i] = a[i + 1];
    }
    n--;
}

void solve() {
    int n;
    scanf("%d", &n);

    vector<int> a(n + 5);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &a[i]);
    }

    int insert_position, value;
    scanf("%d%d", &insert_position, &value);
    insert_at(a, n, insert_position, value);

    int erase_position;
    scanf("%d", &erase_position);
    erase_at(a, n, erase_position);

    for (int i = 1; i <= n; i++) {
        if (i > 1) {
            printf(" ");
        }
        printf("%d", a[i]);
    }
    printf("\n");
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
5
10 20 30 40 50
3 25
4
```

输出：

```text
10 20 25 40 50
```

本例的插入和删除各自最坏移动 $O(n)$ 个元素，输出也需要 $O(n)$ 时间，因此总时间复杂度是 $O(n)$。底层数组保存 $O(n)$ 个整数；两个操作函数只使用循环变量，额外空间都是 $O(1)$。

## 边界条件

对当前长度为 $n$ 的 1-based 数组：

- 合法访问和删除位置是 `1..n`；
- 合法插入位置是 `1..n+1`；
- 插入前必须保证容量至少还能容纳一个元素；
- 删除后必须先缩短逻辑长度，再按新的 `1..n` 使用数组。

完整代码假设输入位置全部合法。真实题目若不保证，需要在调用操作前按照题意处理非法位置，不能让循环访问容量之外的空间。

## 基础练习

1. 写出 1-based 数组 `a[i]` 相对 `a[1]` 的地址偏移，并解释随机访问为什么是 $O(1)$。
2. 区分存储容量、逻辑长度和 `vector::size()`，说明哪些位置是真正的数据。
3. 手动模拟在数组开头、中间和末尾插入元素，分别统计移动次数。
4. 手动模拟删除第一个、中间和最后一个元素，观察逻辑区间之外的旧值。
5. 实现无序数组按值查找，分别构造最好和最坏输入。
6. 修改完整程序，让它先删除再插入，并验证所有合法边界位置。
7. 比较内置数组、`array` 和 `vector` 作为底层存储时，哪些操作复杂度来自数组结构本身，哪些能力由容器接口提供。

## 需要记住什么

1. 数组由哪些性质组成？元素为什么能够通过下标直接定位？
2. 什么是随机访问？它为什么不是“随机选择一个元素”？
3. 已知下标访问与只知道数值查找的复杂度为什么不同？
4. 逻辑长度与存储容量分别表示什么？为什么尾部余量不能算作有效元素？
5. 为什么中间插入必须从右向左移动？中间删除为什么从左向右移动？
6. 数组开头、中间和末尾的插入删除分别需要多少时间？
7. 内置数组和 `vector` 为什么具有相同的中间插入删除复杂度？
8. 数组的总存储空间和一次原地移动操作的额外空间分别是多少？
9. 什么样的操作模式适合数组？频繁中间增删为什么需要考虑其他结构？

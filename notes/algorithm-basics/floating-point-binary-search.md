# 浮点数二分

> 最近修订：2026-08-16 14:40 +10:00（未审阅）

[二分答案](binary-search-on-answer.md) 在有限的整数候选中寻找真假分界。实数范围没有
“相邻两个候选”这一自然终止条件：任意两个不同实数之间仍有更多实数，因此不能把
整数模板简单换成 `double` 后继续等待 `l > r`。

浮点数二分仍然利用单调性缩小区间，但要另外规定近似精度。本篇用平方根说明怎样
维护边界、采用固定迭代次数，并区分输出位数与答案误差。

## 平方根也是分界

给定非负实数 $x$，求 $\sqrt{x}$。对候选值 $y\ge 0$，定义：

$$
feasible(y)\iff y^2\le x.
$$

当 $y$ 从小到大变化时，判定形如：

```text
true true ... true | false false ...
```

真假分界就是 $\sqrt{x}$。因此可以维护一个包含答案的实数区间，每次检查中点并保留
含有分界的一半。

为方便限定范围：

```cpp
double l = 0.0;
double r = max(1.0, x);
```

当 $0\le x\le 1$ 时，平方根位于 `[0,1]`；当 $x>1$ 时，平方根小于 `x`，所以
这两个边界覆盖所有非负输入。

## 每轮缩小一半

中点为：

```cpp
double mid = (l + r) / 2.0;
```

若 `mid * mid <= x`，说明中点位于分界左侧或恰好等于答案，应抬高左边界：

```cpp
l = mid;
```

否则中点过大，应降低右边界：

```cpp
r = mid;
```

这里不写 `mid + 1` 或 `mid - 1`。`1` 对实数近似来说不是“下一个候选”，会直接
跳过大量可能答案。

循环中始终保持：

- `l * l <= x`，左边界不超过真实平方根；
- `r * r >= x`，右边界不小于真实平方根；
- 答案位于闭区间 `[l,r]`。

每轮把区间长度减半，所以两个边界会越来越接近。

## 固定迭代次数

竞赛模板优先使用固定次数：

```cpp
for (int iteration = 1; iteration <= 100; iteration++) {
    double mid = (l + r) / 2.0;
    if (mid * mid <= x) {
        l = mid;
    } else {
        r = mid;
    }
}
```

经过 $t$ 轮后，区间长度变成初始长度的 $2^{-t}$。`double` 本身只有有限精度，
对常见竞赛数据进行 100 次二分已经会让区间缩小到远低于通常输出要求的量级；继续
进行极多轮通常只会让中点因舍入而等于某个边界，不再获得有效信息。

固定次数有三个优点：

1. 一定终止；
2. 不必为每道题重新设计循环中的误差条件；
3. 不会因为数值尺度不同而让 `r - l > eps` 过早或过晚结束。

迭代次数仍要结合初始范围与所需精度选择，`100` 不是所有任意精度计算的数学常量。
本篇假定 `x <= 10^18`，并输出小数点后 10 位。

## 为什么不用相等判断终止

许多十进制小数无法被二进制浮点精确表示，算术运算还会产生舍入。等待：

```cpp
mid * mid == x
```

可能永远无法成立；即使偶然成立，也不能覆盖没有有限浮点表示的平方根。

浮点数算法通常要求结果误差在允许范围内，而不是内部表达必须与数学实数逐位相同。
二分结束后可以返回区间中点：

```cpp
return (l + r) / 2.0;
```

它与真实答案的绝对误差不超过当前区间长度的一半，再叠加浮点舍入误差。

## 绝对误差与相对误差

绝对误差衡量数值差：

$$
|answer-correct|.
$$

相对误差衡量差值相对正确答案的比例：

$$
\frac{|answer-correct|}{|correct|}.
$$

正确答案接近 $0$ 时，相对误差分母也接近 $0$，不能单独使用；答案很大时，只限制
固定绝对误差又可能比题目实际要求严格得多。评测通常会规定接受绝对误差或相对误差
不超过某个阈值，具体以题面为准。

若手写 `while (r - l > eps)`，它只直接控制绝对区间长度。固定次数并没有让误差
概念消失，只是把“循环何时结束”转换成可预测的区间缩小次数。

## 输出精度不是计算精度

```cpp
cout << fixed << setprecision(10) << answer << '\n';
```

`fixed` 让 `setprecision(10)` 表示小数点后 10 位。它只控制文本怎样输出，不会让
`double` 的内部计算突然增加到 10 位或更多有效精度，也不会修复错误算法。

输出位数通常应比题目允许误差多留几位，避免最后一次十进制舍入把结果推到容许
边界外。

## 完整代码

下面的程序读入 `0 <= x <= 10^18`，输出其非负平方根：

```cpp
#include <bits/stdc++.h>
using namespace std;

double square_root(double x) {
    double l = 0.0;
    double r = max(1.0, x);

    for (int iteration = 1; iteration <= 100; iteration++) {
        double mid = (l + r) / 2.0;
        if (mid * mid <= x) {
            l = mid;
        } else {
            r = mid;
        }
    }

    return (l + r) / 2.0;
}

void solve() {
    double x;
    cin >> x;

    cout << fixed << setprecision(10);
    cout << square_root(x) << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
2
```

输出的一种可能形式：

```text
1.4142135624
```

## 复杂度

若固定执行 100 轮，程序进行常数次迭代；从参数化角度看，执行 $t$ 轮的时间复杂度
是 $O(t)$，额外空间是 $O(1)$。

若希望把初始区间长度 $W$ 缩小到不超过 $\varepsilon$，需要满足：

$$
\frac{W}{2^t}\le\varepsilon,
$$

因此需要 $O(\log(W/\varepsilon))$ 轮。这个表达式解释了范围、精度与迭代次数的
关系。

## 常见错误

### 使用 mid + 1 或 mid - 1

实数没有相邻候选，边界直接更新为 `mid`。

### 等待浮点数完全相等

二进制浮点舍入使精确等式通常不可靠。使用固定轮数或经过证明的误差条件。

### 把输出位数当成算法精度

`setprecision` 只格式化输出。区间没有充分缩小，打印再多位也不会得到正确答案。

### 忽略答案范围

二分前必须证明初始 `[l,r]` 包含分界。平方根在 `x < 1` 时可能大于 `x`，因此
右端使用 `max(1.0,x)`，不能一律写成 `x`。

### 机械使用一个绝对 eps

不同数值尺度与评测规则可能需要不同误差口径。先读清绝对误差和相对误差要求。

### 判定表达式发生溢出

本篇约束保证 `mid * mid` 在 `double` 范围内。其他问题即使边界本身可表示，中间
乘法、指数或总和仍要单独检查。

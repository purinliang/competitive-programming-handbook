# 栈的应用：出栈序列判定

> 最近修订：2026-08-13 21:39 +10:00（未审阅）

[栈](stack.md) 已经说明后进先出，[容器适配器：stack](../cpp/stack.md) 已经给出标准库接口。现在研究第一个完整应用：入栈顺序固定时，一个目标排列能否成为出栈顺序。

这类题不需要枚举所有压栈、弹栈方案。只要盯住“下一个必须输出的元素”，当前操作其实会被强制确定。

## 固定入栈顺序

数字 `1, 2, ..., n` 按照这个顺序等待入栈。每个数字恰好入栈一次、出栈一次，但可以在任意合法时刻选择压入下一个数字或弹出栈顶。

给定一个 `1..n` 的排列 `target[1..n]`，判断它能否成为完整出栈序列。

例如 $n=5$ 时：

```text
3 2 1 5 4
```

可以通过以下操作得到：

```text
push 1, push 2, push 3, pop 3,
pop 2, pop 1,
push 4, push 5, pop 5, pop 4
```

而：

```text
3 1 2 5 4
```

不可能得到。输出 `3` 后，栈顶是 `2`，数字 `1` 被压在它下面；不先弹出 `2` 就无法取出 `1`，但下一个目标偏偏要求先输出 `1`。

题目保证目标序列是 `1..n` 的排列。检查重复值、缺失值和越界值属于输入合法性问题，不混入本篇的栈顺序判定。

## 枚举全部操作

一种直接想法是递归尝试每一步：

- 若还有数字未入栈，可以选择 `push`；
- 若栈非空，可以选择 `pop`；
- 弹出元素与目标当前位置不同时，当前方案失败。

一共要执行 $n$ 次压栈与 $n$ 次弹栈。许多时刻都有两种操作选择，枚举全部合法操作序列会产生指数数量的分支。

但我们的目标不是生成所有可能出栈序列，而是判断一个已经给定的序列。下一个目标值会消除这些分支。

## 栈顶吻合时必须弹出

假设下一个必须输出的值是 `desired`，而当前栈顶正好等于它。

此时应当立即弹出：

```cpp
st.pop();
```

如果反而继续压入一个新数字，新数字会盖在 `desired` 上面。要再次看到 `desired`，就必须先弹出这个新数字，但那会让出栈序列的下一项变成错误值。

所以栈顶吻合时，弹出不是一种“看起来不错”的选择，而是任何合法方案都必须执行的操作。

## 栈顶不吻合时只能压入

若栈为空，或者栈顶不等于 `desired`，当前不能弹栈：弹出会输出错误数字。

只要还有数字等待入栈，唯一可能让 `desired` 到达栈顶的操作就是继续按照固定顺序压栈。

因此整个判定过程可以表述为：

1. 为当前目标不断压入尚未入栈的数字；
2. 当前目标来到栈顶时立即弹出；
3. 若目标已经入栈却不在栈顶，它被别的数字压住，立即失败。

每一步都没有第二种可能保持目标前缀正确的操作，所以不需要回溯。

## 下一个等待入栈的数字

用 `next_push` 表示最小的、尚未入栈的数字：

```cpp
int next_push = 1;
```

每次压入它以后递增：

```cpp
st.push(next_push);
next_push++;
```

由于入栈顺序固定为 `1..n`，当当前目标是 `desired` 时：

- 若 `next_push <= desired`，说明 `desired` 还没有入栈，需要依次压入直到它进入栈；
- 若 `next_push > desired`，说明 `desired` 早已入栈，它现在只能位于栈中或已经出栈。

目标是排列，过去没有重复要求过 `desired`，所以它不会已经出栈。于是先执行：

```cpp
while (next_push <= desired) {
    st.push(next_push);
    next_push++;
}
```

这段循环不仅压入 `desired`，也压入固定顺序中位于当前等待位置与它之间的所有数字；不能跳过中间值。

## 检查栈顶

压入所有必须先经过的数字以后，检查：

```cpp
if (st.empty() || st.top() != desired) {
    return false;
}
```

若栈顶不是 `desired`，那么 `desired` 已经被压在某个尚未输出的数字下面。继续压入只会增加更多遮挡，弹出当前栈顶又会违反目标顺序，因此不存在合法方案。

条件先检查 `st.empty()`，再访问 `st.top()`；逻辑或会短路，空栈时不会继续读取栈顶。

栈顶吻合时，把它弹出并处理目标序列下一项：

```cpp
st.pop();
```

## 完整判定函数

```cpp
bool is_valid_pop_sequence(const vector<int>& target, int n) {
    stack<int> st;
    int next_push = 1;

    for (int i = 1; i <= n; i++) {
        int desired = target[i];

        while (next_push <= desired) {
            st.push(next_push);
            next_push++;
        }

        if (st.empty() || st.top() != desired) {
            return false;
        }
        st.pop();
    }

    return true;
}
```

`i` 表示正在匹配目标序列的第几个位置，`desired` 是这一位置要求的出栈值，`next_push` 是输入序列尚未进入栈的第一项，`st` 保存已经入栈但尚未出栈的数字。

## 合法序列过程

对目标：

```text
3 2 1 5 4
```

过程如下。栈内容按照从底到顶书写：

| `desired` | 本轮压入 | 弹出前的栈 | 操作后的栈 | `next_push` |
| ---: | --- | --- | --- | ---: |
| 3 | `1, 2, 3` | `1 2 3` | `1 2` | 4 |
| 2 | 无 | `1 2` | `1` | 4 |
| 1 | 无 | `1` | 空 | 4 |
| 5 | `4, 5` | `4 5` | `4` | 6 |
| 4 | 无 | `4` | 空 | 6 |

五个目标都在检查时位于栈顶，因此序列合法。

## 非法序列过程

对目标：

```text
3 1 2 5 4
```

第一项 `3` 让程序压入 `1, 2, 3` 并弹出 `3`，此时：

```text
stack: 1 2 <- top
next_push: 4
```

下一目标是 `1`。因为 `next_push > 1`，`1` 已经入栈，不再压入任何数字；但栈顶是 `2`，不是 `1`。

若弹出 `2`，下一项输出错误；若继续压入 `4`，`1` 只会被压得更深。程序立即返回 `false`，与所有可能操作都失败的事实一致。

## 正确性

进入目标位置 `i` 以前，保持以下状态：

- 已经按顺序输出 `target[1..i-1]`；
- `1..next_push-1` 都已经入过栈；
- 栈中恰好保存这些已入栈但尚未输出的数字，并保持真实的上下顺序。

令当前目标为 `desired`。

若 `desired` 尚未入栈，固定入栈顺序要求先把 `next_push..desired` 全部压入。没有其他操作能够让 `desired` 出现，所以这段压栈是所有合法方案共同的前缀。

随后 `desired` 已经入栈：

- 若它位于栈顶，任何合法方案都必须立刻弹出它；程序这样做以后，状态继续满足下一轮不变量；
- 若它不在栈顶，另一个尚未输出的数字位于它上方。弹出上方数字会违反当前目标，继续压栈也不能移走上方数字，所以任何方案都不可能成功，程序返回失败正确。

若全部 $n$ 个目标都成功弹出，程序实际构造出了一条合法操作序列，因此返回成功。成功与失败两个方向都得到证明。

## 时间与空间复杂度

外层处理 $n$ 个目标。虽然其中有 `while`，`next_push` 在整个程序中只从 `1` 增加到 `n + 1`，每个数字最多压栈一次；每个目标又恰好弹栈一次。

所以总时间复杂度是 $O(n)$，不是 $O(n^2)$。

最坏情况下先把全部数字压栈，栈中同时保存 $n$ 个元素，因此额外空间复杂度是 $O(n)$。输入目标数组同样需要 $O(n)$ 空间，但不计入判定函数的额外工作空间。

## 完整代码

下面的程序读入 $n$ 和一个 `1..n` 的排列，合法输出 `Yes`，否则输出 `No`。

```cpp
#include <bits/stdc++.h>
using namespace std;

bool is_valid_pop_sequence(const vector<int>& target, int n) {
    stack<int> st;
    int next_push = 1;

    for (int i = 1; i <= n; i++) {
        int desired = target[i];

        while (next_push <= desired) {
            st.push(next_push);
            next_push++;
        }

        if (st.empty() || st.top() != desired) {
            return false;
        }
        st.pop();
    }

    return true;
}

int main() {
    int n;
    scanf("%d", &n);

    vector<int> target(n + 5);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &target[i]);
    }

    printf("%s\n", is_valid_pop_sequence(target, n) ? "Yes" : "No");
    return 0;
}
```

输入：

```text
5
3 2 1 5 4
```

输出：

```text
Yes
```

将输入排列改成 `3 1 2 5 4` 时，输出为 `No`。

## 常见错误

### 任意选择 push 或 pop

针对固定目标序列，当前栈顶吻合时必须弹出，不吻合时不能弹出。枚举两个分支只会重复尝试已经能由目标排除的错误操作。

### 跳过中间数字直接压入目标

入栈顺序固定为 `1..n`。为了压入 `desired`，必须先把所有尚未入栈且小于它的数字依次压入，它们会留在 `desired` 下方。

### 栈顶不匹配时弹出

弹出的每个数字都会立刻成为出栈序列下一项。不能为了寻找更深的 `desired` 而暂时弹出别的值。

### 先访问 top 再判空

检查必须写成 `st.empty() || st.top() != desired`。交换逻辑顺序会在空栈时先访问不存在的栈顶。

### 把嵌套循环判为平方时间

内层 `while` 共享同一个单调递增的 `next_push`，每个数字在全部外层循环中总共只压入一次。复杂度要按总操作次数分析。

### 忘记目标是排列

`while (next_push <= desired)` 利用了目标值属于 `1..n` 且各不相同的前置条件。题面不保证时，应先独立验证输入，而不是让栈过程同时猜测非法值含义。

## 基础练习

1. 手动模拟 `1 2 3 4 5`、`5 4 3 2 1` 和 `2 1 4 3 5`，判断并写出操作序列。
2. 对 `3 1 2` 找到第一次不匹配的状态，并解释为什么继续压栈也无济于事。
3. 修改程序，在合法时输出完整的 `push`、`pop` 操作序列。
4. 用递归枚举小规模所有合法压栈、弹栈操作，与线性判定随机对拍。
5. 把固定入栈序列改成一个任意但元素互异的数组，增加“值到入栈位置”的映射后重新设计判定。
6. 统计 `n` 较小时一共有多少个不同合法出栈序列，观察它们与所有 $n!$ 个排列的数量差异。

## 需要记住什么

1. 本问题的固定入栈顺序和目标出栈顺序分别是什么？
2. 为什么栈顶等于下一个目标时必须立即弹出？
3. 为什么栈顶不等于目标时不能弹出，只能继续压栈？
4. `next_push` 始终表示什么？为什么它只会单调增加？
5. 为什么需要把 `next_push..desired` 中的所有数字依次压栈？
6. 目标已经入栈却不在栈顶时，为什么任何方案都不可能成功？
7. 判定函数的循环不变量怎样描述已输出、已入栈和栈内元素？
8. 为什么代码中有嵌套循环，总时间仍然是 $O(n)$？
9. 本算法依赖目标序列具有什么输入前置条件？

本篇判断一条给定排列是否可行，不计数所有合法排列，也不生成第 $k$ 个出栈序列。后两类问题会引出组合计数等不同目标，不属于基础判定。

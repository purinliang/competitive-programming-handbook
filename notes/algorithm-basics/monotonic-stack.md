# 单调栈

> 最近修订：2026-08-15 21:19 +10:00（未审阅）

给定数组 `a[1..n]`，对每个位置 `u`，寻找它右边第一个严格大于 `a[u]` 的位置；若不存在，答案为 `0`。

例如：

```text
下标： 1  2  3  4  5
数值： 2  1  4  3  5
答案： 3  3  5  5  0
```

从每个位置向右逐个寻找，最坏需要 $O(n^2)$ 时间。单调栈在从左到右扫描时，保存“还没有遇到答案的位置”；新元素一旦足够大，就连续解决栈顶的一批位置。每个位置只会入栈和出栈一次，总时间降为 $O(n)$。

本篇只推导“右边第一个严格更大元素”。最近更小、左边第一个以及允许相等的版本都由同一套比较规则变化得到。

## 等待答案的位置

扫描到位置 `i` 时，之前有些位置已经找到了右边第一个更大值，有些还没有。

栈只保存尚未找到答案的位置。若栈顶是 `u` 且：

```cpp
a[u] < a[i]
```

那么 `i` 就是 `u` 的答案：

- `i` 位于 `u` 右边；
- `a[i]` 严格更大；
- 扫描在到达 `i` 以前没有弹出 `u`，说明中间没有更早的严格更大值。

记录答案以后，`u` 已经完成，不会再参与后续查询，应当立即弹出：

```cpp
answer[u] = i;
st.pop();
```

同一个新元素可能比多个栈顶都大，因此这里需要 `while`，不能只检查一次：

```cpp
while (!st.empty() && a[st.top()] < a[i]) {
    int u = st.top();
    st.pop();
    answer[u] = i;
}
```

处理完能够解决的位置以后，把当前下标 `i` 压入栈，等待未来的更大值。

## 为什么保存下标

题目要回答的是位置，而且比较时还需要取得对应数值。栈中保存下标可以同时完成两件事：

```cpp
int u = st.top();
if (a[u] < a[i]) {
    answer[u] = i;
}
```

若只保存 `a[u]`，相同数值来自哪个位置会丢失，也无法把答案写回正确下标。竞赛中的单调栈通常保存下标，数值通过原数组读取。

## 单调性怎样形成

加入 `a[i]` 以前，所有严格小于它的栈顶都会被弹出。留下的元素都满足：

```text
a[栈底] >= ... >= a[栈顶] >= a[i]
```

把 `i` 压入后，栈中数值从底到顶保持单调不增。这就是“单调栈”名称的来源。

单调性不是额外排序得到的，而是“新元素解决所有比它小的栈顶”这一过程自然维持的。栈底到栈顶不一定下标相邻，但下标一定递增，因为扫描只会把更靠右的位置压到顶部。

## 扫描示例

处理数组：

```text
2 1 4 3 5
```

栈中写下标，并在括号中标出数值：

| 扫描位置 | 操作 | 栈（底到顶） | 新确定答案 |
| ---: | --- | --- | --- |
| `1`，值 `2` | 压入 `1` | `1(2)` | 无 |
| `2`，值 `1` | `1` 不大于 `2`，压入 | `1(2), 2(1)` | 无 |
| `3`，值 `4` | 连续弹出 `2,1` | `3(4)` | `answer[2]=3`，`answer[1]=3` |
| `4`，值 `3` | 压入 `4` | `3(4), 4(3)` | 无 |
| `5`，值 `5` | 连续弹出 `4,3` | `5(5)` | `answer[4]=5`，`answer[3]=5` |

扫描结束后，栈中剩余的位置右边没有更大值。答案数组初始化为 `0`，因此不需要再逐个改写。

## 严格与非严格比较

本文寻找“严格大于”。相等元素不能成为答案，所以弹出条件是：

```cpp
a[st.top()] < a[i]
```

若问题寻找“右边第一个大于等于”的位置，相等元素也能解决栈顶，条件改为：

```cpp
a[st.top()] <= a[i]
```

一个等号会改变重复元素的答案，不能只凭“栈递增还是递减”的模糊口诀决定。先写清楚题目要求的关系，再判断当前元素何时能够成为栈顶的答案。

## 完整代码

寻找过程只依赖本次参数，没有跨调用状态，因此使用普通函数。输入和输出位置保持 1-based；答案 `0` 表示不存在。

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> next_greater_right(const vector<int>& a, int n) {
    vector<int> answer(n + 5);
    stack<int> st;

    for (int i = 1; i <= n; i++) {
        while (!st.empty() && a[st.top()] < a[i]) {
            int u = st.top();
            st.pop();
            answer[u] = i;
        }
        st.push(i);
    }

    return answer;
}

int main() {
    int n;
    scanf("%d", &n);

    vector<int> a(n + 5);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &a[i]);
    }

    vector<int> answer = next_greater_right(a, n);
    for (int i = 1; i <= n; i++) {
        if (i > 1) {
            printf(" ");
        }
        printf("%d", answer[i]);
    }
    printf("\n");
    return 0;
}
```

输入：

```text
5
2 1 4 3 5
```

输出：

```text
3 3 5 5 0
```

## 正确性

考虑位置 `u` 被扫描到的 `i` 弹出。弹出条件保证 `a[i]>a[u]`。如果 `u` 与 `i` 之间存在更早的位置 `k` 也满足 `a[k]>a[u]`，扫描到 `k` 时 `u` 就已经满足弹出条件，不可能继续留在栈中直到 `i`。因此 `i` 恰好是右边第一个严格更大位置。

扫描结束仍在栈中的位置，从它入栈以后从未遇到严格更大的元素，所以答案确实不存在，保留为 `0`。

每个位置要么在遇到答案时恰好弹出一次，要么一直保留到扫描结束；算法不会遗漏，也不会为同一位置重复确定答案。

## 复杂度

外层循环执行 $n$ 次。虽然内层有 `while`，但每个下标只入栈一次、最多出栈一次，所以所有 `while` 迭代加起来不超过 $n$ 次。

总时间复杂度是 $O(n)$，不是 $O(n^2)$；栈和答案数组需要 $O(n)$ 空间。

这种分析称为均摊分析：不单独用最坏弹栈次数乘以外层次数，而是统计每个元素在整个算法生命周期中能被操作几次。

## 其他方向

当前算法从左到右扫描，让新元素解决左边仍在等待的位置。若要寻找左边第一个更大元素，可以保持扫描方向，从栈顶删除不可能成为当前答案的元素，再读取栈顶。

也可以从右到左扫描来直接寻找右侧候选。无论选择哪种写法，都应当先明确：

- 栈中保存的是哪些仍有资格的下标；
- 栈内数值从底到顶保持什么关系；
- 什么时候弹出；
- 当前答案在弹出的元素、新元素还是弹栈后的栈顶。

不要只背“求更大用递减栈”之类一句口诀。不同扫描方向和严格条件会让符号看起来相反，而上述四个问题始终能够重新推导代码。

## 常见错误

### 只使用 if 弹出一次

一个新元素可能同时是多个旧位置的第一个更大值，必须连续弹出所有严格更小的栈顶。

### 保存数值而不是下标

只保存数值会丢失答案应写入的位置，也无法区分相同数值的多个元素。

### 严格关系写错等号

寻找严格更大时，相等元素不能弹出。改成 `<=` 会把“更大”错误地变成“大于等于”。

### 认为 while 导致平方复杂度

同一个下标弹出以后永远不会重新入栈。统计全部入栈和出栈次数，内层总工作量是 $O(n)$。

### 把栈中元素当作连续区间

弹出会跳过许多下标，栈中剩余位置不一定相邻。它们只是仍在等待答案的候选。

## 基础练习

1. 手动模拟 `2 1 4 3 5`，记录每次入栈、出栈和答案写入。
2. 对全递增、全递减和全部相等的数组分别统计栈的最大大小与总弹出次数。
3. 把严格更大改成大于等于，并用含重复值的数组比较答案。
4. 修改比较方向，求右边第一个严格更小的位置。
5. 从右到左扫描，推导另一种求右边第一个严格更大位置的实现，并与本文程序随机对拍。
6. 用 $O(n^2)$ 的逐位置扫描作为参考程序，随机检查单调栈结果。

## 需要记住什么

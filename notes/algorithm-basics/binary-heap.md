# 二叉堆

> 最近修订：2026-08-15 21:02 +10:00（未审阅）

有一组不断变化的数，我们需要反复完成三件事：

- 加入一个数；
- 查看当前最大值；
- 删除当前最大值。

无序数组加入很快，但寻找最大值需要 $O(n)$；有序数组能直接找到最大值，但插入时可能要移动 $O(n)$ 个元素。二叉堆只维护“父节点不小于子节点”这一条局部规则，不要求整个序列有序，因此可以在两种代价之间取得平衡：

| 操作 | 时间复杂度 |
| --- | ---: |
| 查看最大值 | $O(1)$ |
| 加入元素 | $O(\log n)$ |
| 删除最大值 | $O(\log n)$ |

本篇推导保存整数最大值的**大根二叉堆**。C++ 比赛代码通常直接使用 [容器适配器：priority_queue](../cpp/priority-queue.md)；理解二叉堆以后，就能解释这些接口为什么具有上述复杂度。

## 完全二叉树

二叉堆首先是一棵完全二叉树：除最后一层以外，每一层都已经填满；最后一层的节点从左到右连续出现，中间不能留空。

这种形状可以按层从左到右编号，并直接保存在 1-based 数组中：

```text
                 1
              /     \
             2       3
           /  \     / \
          4    5   6   7
```

对节点 `u`：

```text
父节点：u / 2
左子节点：u * 2
右子节点：u * 2 + 1
```

数组位置 `1..n` 恰好连续保存全部节点，不需要为指针或不存在的中间位置额外留空间。位置 `0` 留空，使父子公式保持简单。

最后一个非叶节点是 `n / 2`。编号大于 `n / 2` 的节点都没有子节点，因为它们的左子节点编号已经超过 `n`。

## 大根堆性质

只有完全二叉树的形状还不能保证最大值容易找到。大根堆进一步要求每个父节点的值都不小于它的子节点：

```text
tree[u] >= tree[u * 2]
tree[u] >= tree[u * 2 + 1]
```

第二条只在右子节点存在时检查。

从任意节点沿父节点不断向上，数值不会变小。因此根节点 `tree[1]` 不小于树中任何节点，它就是全局最大值：

```cpp
int top() const {
    return tree[1];
}
```

堆并不保证同一层从左到右有序，也不保证左子节点和右子节点谁更大。下面两个数组都可能表示合法大根堆：

```text
10 8 7 3 5 2
10 7 8 2 3 5
```

只要每一条父子边满足规则，就足以保证根节点最大。

## 加入元素

完全二叉树不能随意改变形状。新元素只能先放在数组末尾，也就是最后一层最靠左的空位：

```cpp
n++;
tree[n] = val;
```

加入以前，旧节点之间的父子关系都合法。新元素只可能比自己的父节点大，因此只有从新位置到根的一条路径可能违反规则。

令新节点为 `u`，父节点为 `p = u / 2`：

- 若 `tree[p] >= tree[u]`，父子关系已经正确，可以停止；
- 否则交换父子，新元素向上移动，再检查新的父节点。

```cpp
void sift_up(int u) {
    while (u > 1) {
        int p = u / 2;
        if (tree[p] >= tree[u]) {
            break;
        }
        swap(tree[p], tree[u]);
        u = p;
    }
}
```

这个过程称为**上浮**。完全二叉树有 $O(\log n)$ 层，新元素每次至少上升一层，所以加入最多需要 $O(\log n)$ 时间。

## 删除最大值

最大值位于根节点，但直接删除根会在数组开头留下空位，破坏完全二叉树的连续形状。

先用最后一个节点覆盖根，再缩短逻辑长度：

```cpp
tree[1] = tree[n];
n--;
```

最后一个节点被移到根以后，它可能比子节点小。旧堆中的其他父子关系没有改变，因此仍然只有从根向下的一条路径可能违反规则。

当前节点 `u` 有两个子节点时，必须与较大的那个比较。若只选择较小的子节点交换，交换以后较大的子节点仍可能大于父节点：

```cpp
void sift_down(int u) {
    while (u * 2 <= n) {
        int v = u * 2;
        if (v + 1 <= n && tree[v + 1] > tree[v]) {
            v++;
        }
        if (tree[u] >= tree[v]) {
            break;
        }
        swap(tree[u], tree[v]);
        u = v;
    }
}
```

这里先让 `v` 指向左子节点；若右子节点存在且更大，再令 `v` 指向右子节点。若当前节点已经不小于较大的子节点，它自然也不小于另一个子节点，可以停止。否则交换并继续向下。

这个过程称为**下沉**。每次至少下降一层，因此删除最大值是 $O(\log n)$。

## 为什么局部修复足够

上浮以前，只有新加入节点与父节点的关系可能错误。一次交换以后：

- 较小的父节点来到下面，而新节点原本没有子节点，下面不会产生新的冲突；
- 较大的新节点来到上面，只需要继续检查它与更高父节点的关系。

所以上浮只沿一条路径检查就能恢复整个堆。

下沉以前，只有最后节点覆盖根以后可能与子节点冲突。它每次和较大的子节点交换：

- 较大的子节点来到上面，仍不小于自己的另一个子节点；
- 被换下去的节点只可能继续与新位置的子节点冲突。

所以下沉同样只需沿一条路径。二叉堆的效率来自“每次修改只破坏局部规则，局部规则又只需要沿一条树链修复”。

## 从数组建堆

把 $n$ 个元素逐个调用 `push`，总时间是 $O(n\log n)$。若全部元素一开始已经在数组 `tree[1..n]` 中，可以更快地从底向上建堆。

所有叶节点单独看都已经是合法堆。从最后一个非叶节点 `n / 2` 开始倒序，对每个节点执行下沉：

```cpp
for (int u = n / 2; u >= 1; u--) {
    sift_down(u);
}
```

处理 `u` 时，它的两个子树已经分别满足堆性质，因此一次下沉就能让以 `u` 为根的整棵子树成为堆。循环结束时，根节点对应的整棵树就是一个大根堆。

虽然单次下沉最坏是 $O(\log n)$，但大部分节点靠近叶层，实际只能下沉一两层。各节点能够下沉的总层数是 $O(n)$，因此从底向上建堆的总时间是 $O(n)$，不是 $O(n\log n)$。

## 完整代码

下面的 `BinaryHeap` 使用 `vector` 提供实际空间，但逻辑节点仍是 `tree[1..n]`。构造时按操作上限分配 `capacity + 5` 个位置；第 `0` 格留空，末尾余量保持本书数据结构的一致约定。

程序先读入初始元素并在 $O(n)$ 内建堆，再处理三类操作：

- `1 val`：加入 `val`；
- `2`：输出并删除当前最大值；
- `3`：输出当前最大值但不删除。

输入保证操作 `2` 和 `3` 出现时堆非空。

```cpp
#include <bits/stdc++.h>
using namespace std;

struct BinaryHeap {
    int n;
    vector<int> tree;

    BinaryHeap(int capacity) : n(0), tree(capacity + 5) {}

    bool empty() const {
        return n == 0;
    }

    int size() const {
        return n;
    }

    int top() const {
        return tree[1];
    }

    void sift_up(int u) {
        while (u > 1) {
            int p = u / 2;
            if (tree[p] >= tree[u]) {
                break;
            }
            swap(tree[p], tree[u]);
            u = p;
        }
    }

    void sift_down(int u) {
        while (u * 2 <= n) {
            int v = u * 2;
            if (v + 1 <= n && tree[v + 1] > tree[v]) {
                v++;
            }
            if (tree[u] >= tree[v]) {
                break;
            }
            swap(tree[u], tree[v]);
            u = v;
        }
    }

    void build(const vector<int>& values, int count) {
        n = count;
        for (int i = 1; i <= n; i++) {
            tree[i] = values[i];
        }
        for (int u = n / 2; u >= 1; u--) {
            sift_down(u);
        }
    }

    void push(int val) {
        n++;
        tree[n] = val;
        sift_up(n);
    }

    void pop() {
        tree[1] = tree[n];
        n--;
        if (n > 0) {
            sift_down(1);
        }
    }
};

int main() {
    int n, m;
    scanf("%d%d", &n, &m);

    vector<int> values(n + 5);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &values[i]);
    }

    BinaryHeap heap(n + m);
    heap.build(values, n);

    while (m--) {
        int op;
        scanf("%d", &op);

        if (op == 1) {
            int val;
            scanf("%d", &val);
            heap.push(val);
        } else if (op == 2) {
            printf("%d\n", heap.top());
            heap.pop();
        } else {
            printf("%d\n", heap.top());
        }
    }
    return 0;
}
```

输入：

```text
5 6
4 10 3 5 1
3
1 8
2
3
2
3
```

输出：

```text
10
10
8
8
5
```

初始最大值是 `10`。加入 `8` 后，删除操作仍先取出 `10`；新的最大值变为 `8`，再次删除后最大值变为 `5`。

初始建堆需要 $O(n)$ 时间。每次加入或删除需要 $O(\log n)$，每次查看顶部需要 $O(1)$；保存全部元素需要 $O(n)$ 空间。

## 小根堆

小根堆要求父节点不大于子节点，根节点因此是全局最小值。它与大根堆的形状、父子编号、上浮和下沉过程完全相同，只需要反转大小比较，并在下沉时选择较小的子节点。

实际比赛中不必复制整份代码手改。标准库已经提供：

```cpp
priority_queue<int, vector<int>, greater<int>> heap;
```

自定义二叉堆的价值主要是理解原理、支持标准适配器没有提供的特殊操作，或完成要求手写堆的题目。普通的动态最大值或最小值问题优先使用 `priority_queue`。

## 常见错误

### 把堆当成有序数组

堆只保证每个父节点与子节点的局部关系。除根以外，不能直接断言第二大元素在哪个固定位置，也不能把底层数组当作排序结果。

### 新元素不放在末尾

先保持完全二叉树的形状，再通过上浮恢复大小关系。若在中间寻找“看起来合适”的空位，会破坏连续编号和父子公式。

### 删除根后直接移动数组

不需要把 `tree[2..n]` 全部向前移动。用最后节点覆盖根，再下沉修复，才能保持 $O(\log n)$。

### 下沉时选错子节点

大根堆必须与较大的子节点比较和交换。只看左子节点，或随意选择一个子节点，都可能让另一个较大子节点留在父节点下面。

### 忘记右子节点可能不存在

进入下沉循环只保证左子节点 `u * 2` 存在。访问 `u * 2 + 1` 前仍要检查它不超过 `n`。

### 在空堆访问根

`top()` 和 `pop()` 都要求 `n > 0`。完整代码由输入保证这一条件；其他题目没有保证时，应在调用以前检查 `empty()`。

### 容量不足

完整代码按“初始元素数 + 操作数”分配容量，因为每次操作最多加入一个元素。修改接口或题意以后，仍要保证 `push` 不会超过底层存储。

## 基础练习

1. 对数组 `10 7 8 2 3 5` 逐条检查父子关系，判断它是否是大根堆。
2. 从空堆依次加入 `4,10,3,8,6`，画出每次上浮经过的节点。
3. 删除一个同时拥有两个子节点的根，构造“右子节点更大”的例子，验证为什么必须选择较大的子节点。
4. 用父子编号公式解释为什么 `n / 2 + 1..n` 都是叶节点。
5. 比较逐个 `push` 建堆与从底向上建堆的时间复杂度。
6. 把完整代码改成小根堆，并用随机数组与 `priority_queue<int, vector<int>, greater<int>>` 对拍。
7. 随机生成合法操作，用每次扫描 `vector` 最大值的朴素程序检查自定义二叉堆。

## 需要记住什么

1. 二叉堆为什么使用完全二叉树？1-based 编号下父节点和两个子节点分别怎样计算？
2. 大根堆性质是什么？为什么它能保证根节点是全局最大值？
3. 加入元素为什么先放在末尾？上浮只需要检查哪一条路径？
4. 删除根以后为什么用最后节点覆盖？下沉时为什么必须选择较大的子节点？
5. `push`、`top` 和 `pop` 的时间复杂度分别是什么？
6. 从底向上建堆从哪个节点开始？为什么总复杂度是 $O(n)$？
7. 堆数组是否整体有序？除根以外能否直接确定其他元素的全局名次？
8. 大根堆改成小根堆时，哪些比较关系需要反转？

堆排序、可以删除任意元素的索引堆、可合并堆以及标准库的具体内部实现不属于基础二叉堆。本篇只要求能够从完全二叉树和局部堆性质恢复 `sift_up`、`sift_down` 与建堆过程。

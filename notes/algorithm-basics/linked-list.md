# 链表的基本概念

> 最近修订：2026-08-17 00:02 +10:00（未审阅）

[数组](array.md)把元素连续存放，因此可以根据下标在 $O(1)$ 时间内访问任意位置；但在中间插入或删除元素时，后面的元素通常需要整体移动。

如果不要求相邻元素在内存中也紧挨着，可以把每个元素分别放进一个**节点**，再让节点记录下一个节点的位置。节点之间形成的链接决定逻辑顺序，这种线性结构就是**链表**。

## 节点与链接

最基础的单向链表节点包含两类信息：

- 当前节点保存的值；
- 下一个节点的位置。

使用整数编号表示位置时，可以写成：

```cpp
struct Node {
    int value;
    int next;
};
```

这里的 `next` 不是下一个节点的值，而是能够定位下一个节点的编号。真实实现也可以保存指针或迭代器；本书的数据结构模板优先使用整数编号，让 `0` 统一表示不存在的节点。

## 存储位置与逻辑顺序

假设三个节点保存在编号 `1`、`2`、`3` 的位置：

| 节点编号 `u` | `1` | `2` | `3` |
| ---: | ---: | ---: | ---: |
| `value` | `20` | `30` | `10` |
| `next` | `2` | `0` | `1` |

变量 `head = 3` 表示首节点是编号 `3`。从 `head` 沿 `next` 访问，得到：

```text
head -> 3 -> 1 -> 2 -> 0
          10   20   30
```

所以链表中的逻辑顺序是 `10, 20, 30`，不是节点编号顺序 `1, 2, 3`，也不是节点在内存中的排列顺序。

插入新节点时，只要修改链接，原有节点不必搬动或重新编号。因此，节点编号与“第几个元素”是两个不同概念。

## 首节点与空链接

变量 `head` 保存链表的入口：

```cpp
int head = 0;
```

本书约定：

- `head = 0` 表示空链表；
- 非空链表的 `head` 是第一个真实节点编号；
- 普通非循环链表的尾节点满足 `next = 0`；
- 真实节点编号从 `1` 开始。

预留 `0` 能让“不存在的节点”拥有统一表示，避免使用 `-1` 参与数组访问。后续实现虚拟头节点时，编号 `0` 还可以保存链表入口，但它始终不属于逻辑数据。

## 沿链接遍历

链表没有能够直接定位第 $k$ 个元素的下标公式。访问所有节点时，从 `head` 开始反复沿 `next` 前进：

```cpp
for (int u = head; u != 0; u = nodes[u].next) {
    cout << nodes[u].value << '\n';
}
```

若链表有 $n$ 个节点，完整遍历访问每个节点一次，时间复杂度是 $O(n)$。

寻找逻辑上的第 $k$ 个节点也必须从入口逐个经过前面的节点，最坏需要 $O(n)$ 时间。链表不能像数组那样在 $O(1)$ 时间内随机访问逻辑位置。

## 为什么修改链接可以很快

数组在中间插入元素时，通常要把后缀整体向后移动。链表已经知道目标节点或它的前驱时，只需修改固定数量的链接，就能接入或绕过节点，不需要搬动其他节点。

因此，常见说法“链表插入、删除是 $O(1)$”必须带上前提：目标节点或所需前驱已经找到。

如果题目只给出“第 $k$ 个位置”，仍要先沿链接寻找位置，查找最坏是 $O(n)$；随后 $O(1)$ 的链接修改不会把总复杂度变成 $O(1)$。

## 三种常见链表

链表按照保存的链接和末尾关系，可以形成几种常见结构。

### [单向链表](singly-linked-list.md)

每个节点只保存下一个节点的位置，只能沿一个方向自然遍历。已知前驱时可以快速插入和删除后继，但只知道某个节点时不能直接找到它的前驱。

### [双向链表](doubly-linked-list.md)

每个节点同时保存前驱与后继，可以向前或向后遍历。已知一个节点时，能够直接访问两侧节点，但每次修改都必须保持两个方向的链接一致。

### [循环链表](circular-linked-list.md)

尾节点不指向空位置，而是重新连接首节点。它适合需要处理完末尾后继续回到开头的过程，也意味着遍历不能再用“到达 `0`”作为自然停止条件。

“单向或双向”描述节点保存几个方向的链接，“普通或循环”描述尾端怎样连接。两组性质可以组合，例如双向循环链表。

## 与数组比较

设逻辑长度为 $n$：

| 操作 | 数组 | 链表 |
| --- | ---: | ---: |
| 根据第 $k$ 个逻辑位置访问 | $O(1)$ | $O(n)$ |
| 遍历全部元素 | $O(n)$ | $O(n)$ |
| 已经找到位置后的插入、删除 | 通常 $O(n)$ | $O(1)$ |
| 按第 $k$ 个位置插入、删除 | $O(n)$ | $O(n)$ |
| 存储方式 | 连续 | 由链接组织 |
| 额外信息 | 通常没有链接 | 每个节点保存一个或多个链接 |

数组擅长随机访问和连续扫描；链表擅长在已经持有节点位置时修改局部关系。选择结构时要看题目提供什么位置、主要执行什么操作，不能只背一句“链表增删更快”。

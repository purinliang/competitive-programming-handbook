# 从代码分析复杂度

> 最近修订：2026-08-16 09:31 +10:00（未审阅）

[复杂度](complexity.md) 已经建立了时间与空间增长的尺度。本篇只解决一个具体问题：面对一段代码，怎样根据循环变量的变化和代码块的执行次数得到时间复杂度。

## 每次增加固定值

```cpp
for (int i = 1; i <= n; i++) {
    cout << i << '\n';
}
```

`i` 依次取 $1,2,\ldots,n$，循环体执行 $n$ 次。若每轮只进行固定数量的操作，总时间是 $O(n)$。

从 $0$ 到 $n-1$ 也恰好有 $n$ 个值：

```cpp
for (int i = 0; i < n; i++) {
    // O(1)
}
```

复杂度不由使用 `<` 还是 `<=` 决定，而由循环变量一共取多少个值决定。

若每次增加固定正整数 `step`：

```cpp
for (int i = 1; i <= n; i += step) {
    // O(1)
}
```

循环体约执行 $n/\mathit{step}$ 次。`step` 不随 $n$ 增长时，它只带来常数倍，
所以复杂度仍是 $O(n)$。若步长本身由输入决定，就不能把它当作固定常数省略。

## 每次乘以固定倍数

```cpp
for (ll i = 1; i <= n; i *= 2) {
    // O(1)
}
```

`i` 依次约为 $1,2,4,8,\ldots$。执行 $k$ 轮以后，`i` 是 $2^k$；当 $2^k>n$ 时循环结束，因此轮数是 $O(\log n)$。

反过来，每轮把正整数规模除以 $2$ 也是对数次：

```cpp
while (n > 1) {
    n /= 2;
}
```

规模依次约为 $n,n/2,n/4,\ldots,1$。复杂度中通常省略固定对数底数，因为换底只产生常数倍。

左移和右移也能表达乘除 $2$，但分析复杂度时优先保留 `*= 2` 和 `/= 2`，让规模变化直接可见。

倍增变量的类型必须能够保存最后一次更新后的值。若使用 `int` 且越过可表示范围，
有符号整数溢出会产生未定义行为，循环甚至可能无法正常结束。完整示例使用 `ll`
承接 `int` 范围内的输入。

## 顺序代码相加

两段循环先后执行，执行次数相加：

```cpp
for (int i = 1; i <= n; i++) {
    // O(1)
}

for (int i = 1; i <= m; i++) {
    // O(1)
}
```

总时间是 $O(n+m)$。若两段都执行 $n$ 次，则是 $O(2n)=O(n)$。当题目没有给出 $n$ 和 $m$ 的固定关系时，不能擅自丢掉其中一个变量。

条件分支一次只选择一边。分析最坏情况时，取可能执行的较慢分支。

## 独立嵌套循环

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= m; j++) {
        // O(1)
    }
}
```

外层每个 `i` 都让内层完整执行 $m$ 次，总次数是 $n\times m$，因此是 $O(nm)$。只有两层都执行 $n$ 次时，才得到 $O(n^2)$。

## 内层范围依赖外层

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= i; j++) {
        // O(1)
    }
}
```

内层次数不是固定的 $n$，而是依次为 $1,2,\ldots,n$。总次数为：

$$
1+2+\cdots+n=\frac{n(n+1)}2=O(n^2).
$$

结论仍然是平方，但理由来自实际次数之和，不能用“看到两层循环”代替分析。

再看另一种依赖：

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= n; j += i) {
        // O(1)
    }
}
```

固定 `i` 时，内层约执行 $n/i$ 次。总次数约为：

$$
\frac n1+\frac n2+\cdots+\frac nn
=n\left(1+\frac12+\cdots+\frac1n\right)
=O(n\log n).
$$

这说明相互依赖的循环可能得到平方以外的复杂度。

其中调和和式的对数上界可以按 $2$ 的幂分组理解：

$$
1+\frac12+
\left(\frac13+\frac14\right)+
\left(\frac15+\cdots+\frac18\right)+\cdots
$$

每组的项数翻倍，但每一项至多是前一组最大项的一半，因此每组总和不超过常数；
从 $1$ 分到 $n$ 只有 $O(\log n)$ 组，所以整个和式是 $O(\log n)$。

## 嵌套写法不一定相乘

```cpp
int j = 1;
for (int i = 1; i <= n; i++) {
    while (j <= n && a[j] < a[i]) {
        j++;
    }
}
```

虽然 `while` 写在 `for` 内部，`j` 却没有在每轮外层循环重新变回 `1`。整个程序中 `j` 最多从 $1$ 增加到 $n+1$，因此内层循环体总共只执行 $O(n)$ 次，整体仍是 $O(n)$。

分析这种代码时，给每个只单向移动的下标统计整个程序中的总移动次数，而不是把每次外层循环都当成一次全新的内层遍历。

## 空间使用

代码中的循环次数不会自动增加空间。只使用固定数量的变量，额外空间是 $O(1)$；建立长度为 $n$ 的数组是 $O(n)$；建立 $n\times m$ 的二维数组是 $O(nm)$。

递归需要把尚未返回的调用保存在调用栈中。最大递归深度为 $d$ 且每层只保存固定信息时，调用栈空间通常是 $O(d)$。

## 分析步骤

1. 定义每个输入规模变量。
2. 找出会随规模重复的核心操作。
3. 写出循环变量的实际取值或总移动次数。
4. 顺序执行次数相加；真正独立地完整嵌套时才相乘。
5. 单独统计数组、容器和递归调用栈占用的空间。
6. 把最大输入规模代入主导项，检查数量级。

## 常见错误

### 根据循环层数直接下结论

两层循环可能是 $O(nm)$、$O(n^2)$、$O(n\log n)$，也可能因为内层下标从不
重置而总共只有 $O(n)$ 次。必须统计循环体的实际总执行次数。

### 把会重置的下标当成单向移动

只有同一个下标在整个程序中不回退、不重新初始化时，才能用“总共最多移动
$n$ 次”分析。若它在外层每轮都回到起点，内层扫描次数需要重新累计。

### 修改规模后忘记原值

`while (n > 1) n /= 2;` 会改变 `n`。只用它展示次数没有问题；实际程序若后面
还要使用原规模，应改用单独的 `length` 变量。

### 忽略倍增变量溢出

倍增循环的数学轮数可能是对数级，但代码仍必须保证循环变量不会在下一次乘法时
溢出。复杂度正确不能替代类型与边界正确。

## 完整代码

下面的程序包含一段线性循环和一段对数循环：

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

void solve() {
    int n;
    cin >> n;

    int linear_count = 0;
    for (int i = 1; i <= n; i++) {
        linear_count++;
    }

    int logarithmic_count = 0;
    for (ll i = 1; i <= n; i *= 2) {
        logarithmic_count++;
    }

    cout << linear_count << ' ' << logarithmic_count << '\n';
}

int main() {
    solve();
    return 0;
}
```

当输入为 `16` 时，第一段执行 $16$ 次，第二段的 `i` 取 $1,2,4,8,16$，执行 $5$ 次。

## 基础练习

1. 分析 `i += 3` 的循环为什么仍是 $O(n)$。
2. 分析外层 $n$ 次、内层 $m$ 次的独立嵌套循环。
3. 写出 `i *= 3` 的取值并说明为什么仍记作 $O(\log n)$。
4. 计算内层执行 `1+2+\cdots+n` 次的循环复杂度。
5. 分析一个不重置双指针的嵌套循环中，两个指针各自总共移动多少次。
6. 分析长度为 $n$ 的数组和深度为 $n$ 的递归分别占用多少空间。

## 需要记住什么

1. `i++` 与 `i *= 2` 为什么分别产生线性和对数轮数？
2. 顺序代码与独立嵌套代码怎样合并执行次数？
3. 为什么不能只根据循环层数判断复杂度？
4. 内层上界依赖外层变量时，应该怎样得到总次数？
5. 一个不重置、只单向移动的下标应按单轮还是整个程序统计？
6. 为什么倍增循环还需要检查循环变量的类型与溢出边界？

# 计数原理：加法原理

> 最近修订：2026-08-15 22:12 +10:00（未审阅）

一个任务可以通过若干种互不重叠的情形完成。已知每种情形分别有多少种方案，怎样计算总方案数？

例如从三个互不重叠的题库中任选一道题：基础题库有 `12` 道，提高题库有 `7` 道，挑战题库有 `5` 道。最终只选择其中一道，总方案数是：

$$
12+7+5=24.
$$

这就是加法原理。

## 互斥情形

设全部方案被分成 $k$ 个集合：

$$
S_1,S_2,\ldots,S_k.
$$

若任意一个完整方案只属于其中一个集合，也就是这些情形两两互斥，那么：

$$
|S_1\cup S_2\cup\cdots\cup S_k|
=|S_1|+|S_2|+\cdots+|S_k|.
$$

“互斥”表示同一个方案不会同时被两个情形统计。题库示例中，一道题只属于一个题库，所以把三个数量相加不会重复。

加法原理通常对应自然语言中的：

```text
选择情形 1，或者选择情形 2，或者……
```

这里的“或者”必须经过检查，不能只看见“或”字就机械相加。

## 完整覆盖

除了互不重叠，列出的情形还必须覆盖所有合法方案。

若题目允许从第四个题库选题，却只相加前三个题库，结果会遗漏；若某道题同时登记在两个题库，直接相加又会重复。

正确使用加法原理需要同时确认：

1. 每个合法方案至少属于一个情形；
2. 每个合法方案至多属于一个情形。

合在一起，就是每个合法方案恰好属于一个情形。

## 重叠情形

考虑 `1..30` 中“能被 `2` 整除或者能被 `3` 整除”的整数。

能被 `2` 整除的有 `15` 个，能被 `3` 整除的有 `10` 个，但直接计算：

$$
15+10=25
$$

会把 `6,12,18,24,30` 各统计两次。

一种修正方法是先把情形改成互斥：

- 能被 `2` 整除：`15` 个；
- 能被 `3` 整除但不能被 `2` 整除：`5` 个。

现在两类没有重叠，可以相加：

$$
15+5=20.
$$

也可以从两类数量之和中减去交集，这会发展成后续的容斥原理。本篇只要求先识别“直接相加必须互斥”。

## 按第一个差异分类

构造互斥分类的常用方法，是按照每个方案的第一个确定差异分类。

例如统计长度为 `n`、第一个非零数字出现在某个位置的十进制串，可以按“第一个非零位置”分类。一个字符串不可能同时拥有两个不同的第一个非零位置，因此这些情形天然互斥。

类似地，还可以按以下信息分类：

- 最后一步采用哪种操作；
- 第一个被选择的元素是谁；
- 最大元素出现在哪里；
- 某个固定对象处于哪一种状态。

分类标准必须让每个方案拥有唯一答案。若“第一个”“最后一个”或“唯一状态”无法确定，就要继续细分或改用其他计数方法。

## 翻译成代码

如果 `ways[i]` 已经表示第 `i` 个互斥情形的方案数，总数就是普通求和：

```cpp
ll answer = 0;
for (int i = 1; i <= k; i++) {
    answer += ways[i];
}
```

代码本身很短，真正的工作在代码之前：证明 `ways[1..k]` 覆盖全部方案且互不重叠。

若题目要求答案模 `MOD`，每次相加后取模即可：

```cpp
answer = (answer + ways[i]) % MOD;
```

取模不会修复错误分类；重复或遗漏仍然会保留在结果中。

## 完整代码

下面的程序读取 `k` 个两两互斥情形的方案数并求和。它假设准确总数能够放入 64 位整数。

```cpp
#include <bits/stdc++.h>

using namespace std;

typedef long long ll;

int main() {
    int k;
    scanf("%d", &k);

    vector<ll> ways(k + 5);
    ll answer = 0;
    for (int i = 1; i <= k; i++) {
        scanf("%lld", &ways[i]);
        answer += ways[i];
    }

    printf("%lld\n", answer);
    return 0;
}
```

输入：

```text
3
12 7 5
```

输出：

```text
24
```

## 与乘法原理的区别

加法原理在若干个完整情形中选择一个：

```text
用方法 A 完成，或者用方法 B 完成。
```

乘法原理则要依次完成多个步骤：

```text
先选择第一步，再选择第二步。
```

例如“从三个题库中任选一道”使用加法；“先从三个题库中选一个，再从所选题库中选一道”要先分析每个题库对应的第二步数量，可能同时出现乘法与加法。

不要根据公式希望得到加法还是乘法来分类，而要看一个完整方案究竟是在情形之间二选一，还是由多个步骤共同组成。

## 复杂度

若已经知道 `k` 个情形的方案数，求和需要 $O(k)$ 时间。示例程序保存了 `ways[1..k]`，使用 $O(k)$ 空间；若只需要总和，可以读入一个数就立即累加，将额外空间降到 $O(1)$。

实际计数题的主要复杂度通常来自“怎样求出每个情形的方案数”，而不是最后这次相加。

## 常见错误

### 重复统计交集

两个条件可以同时成立时，直接相加会重复。应把情形改成互斥，或使用容斥原理处理交集。

### 分类没有覆盖全部方案

情形互斥但不完整时仍会漏算。需要证明每个合法方案至少落入一个情形。

### 把连续步骤相加

如果一个完整方案需要同时做出多个选择，通常应使用乘法原理，而不是把各步选择数相加。

### 只写公式，不定义一种方案

计数以前先明确“两个方案在什么情况下不同”。若题目中的对象、顺序或选择过程没有定义清楚，互斥和完整都无法判断。

### 忽略答案容量

多个非负方案数相加仍可能超过 64 位整数。根据题目范围选择精确类型或按指定模数计算。

## 基础练习

1. 从红、蓝、绿三个互不重叠的盒子中任选一个球，分别有 `4,7,2` 个球，计算方案数。
2. 判断“能被 `2` 整除”和“能被 `3` 整除”为什么不能直接使用加法原理。
3. 把 `1..100` 中能被 `2` 或 `5` 整除的整数拆成两个互斥情形。
4. 设计一个按“最后一步操作”分类的简单计数问题，并说明分类为什么完整且互斥。
5. 修改完整代码，在固定模数下累加方案数。

## 需要记住什么

1. 加法原理适用于什么样的多个情形？
2. “互斥”和“完整覆盖”分别防止什么错误？
3. 有重叠的条件为什么不能直接相加？
4. 怎样按第一个差异把方案拆成互斥情形？
5. 加法原理与乘法原理描述的完整方案结构有何不同？
6. 为什么代码中的求和不是这类问题最困难的部分？

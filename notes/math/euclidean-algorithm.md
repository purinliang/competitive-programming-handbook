# 欧几里得算法

> 最近修订：2026-08-16 12:02 +10:00（未审阅）

[最大公约数与最小公倍数](greatest-common-divisor-and-least-common-multiple.md) 可以通过质因数分解求 `gcd`，但分解两个很大的整数通常比求它们的 `gcd` 困难得多。欧几里得算法（Euclidean algorithm，又称辗转相除法）不分解任何质因数，只反复做整除和取余。

## 保持不变的公约数

假设 $a\ge b>0$。整除 $a$ 与 $b$，得到商 $q$ 和余数 $r$：

$$
a=qb+r,\qquad 0\le r<b.
$$

也就是

$$
r=a-qb=a\bmod b.
$$

现在比较两对数 $(a,b)$ 和 $(b,r)$ 的公约数。

若 $d$ 同时整除 $a$ 和 $b$，根据整除对线性组合的封闭性，$d$ 也整除

$$
a-qb=r.
$$

所以 $(a,b)$ 的每个公约数都是 $(b,r)$ 的公约数。

反过来，若 $d$ 同时整除 $b$ 和 $r$，那么 $d$ 也整除

$$
qb+r=a.
$$

所以 $(b,r)$ 的每个公约数也是 $(a,b)$ 的公约数。两边的公约数集合完全相同，因此

$$
\gcd(a,b)=\gcd(b,a\bmod b).
$$

这就是整个算法的核心。

## 逐步缩小

计算 $\gcd(252,105)$：

$$
252=2\times105+42,
$$

$$
105=2\times42+21,
$$

$$
42=2\times21+0.
$$

对应的 `gcd` 问题依次变为

```text
gcd(252, 105)
= gcd(105, 42)
= gcd(42, 21)
= gcd(21, 0)
= 21
```

当第二个数变成 $0$ 时，使用 $\gcd(a,0)=|a|$ 结束。

每一步的新余数都严格小于当前的除数，非负整数不可能无限严格递减，所以算法一定结束。

## 递归写法

核心等式已经把一个 `gcd` 问题变成规模更小的同类问题，因此可以直接递归。下文沿用竞赛代码中 `typedef long long ll;` 定义的别名 `ll`：

```cpp
ll gcd(ll a, ll b) {
    if (b == 0) {
        return a;
    }
    return gcd(b, a % b);
}
```

当 `b == 0` 时，函数返回 `a`；否则把 $\gcd(a,b)$ 原样替换为 $\gcd(b,a\bmod b)$。每次递归的第二个参数都严格缩小，所以一定会到达终止条件。

竞赛中通常优先使用这份递归写法：代码短，并且与后续扩展欧几里得算法在递归返回时回代系数的结构一致。

主流竞赛题中的 `gcd` 通常接收非负整数，本文实现也采用这个输入约定。若自己的函数需要接收负数，应当在进入函数前统一处理符号；C++17 的 `std::gcd` 已经定义了有符号参数的行为。

## 非递归写法

同一个过程也可以写成循环。每次需要把

```text
(a, b)
```

换成

```text
(b, a % b)
```

为了避免更新 `a` 后丢失旧值，先把余数保存为 `r`：

```cpp
ll gcd(ll a, ll b) {
    while (b != 0) {
        ll r = a % b;
        a = b;
        b = r;
    }
    return a;
}
```

递归版和非递归版做的数学操作完全相同。非递归版多写了状态更新，但不使用递归调用栈。

## 完整代码

下面的完整程序使用更常见的递归写法：

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

ll gcd(ll a, ll b) {
    if (b == 0) {
        return a;
    }
    return gcd(b, a % b);
}

void solve() {
    ll a, b;
    scanf("%lld%lld", &a, &b);
    printf("%lld\n", gcd(a, b));
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
252 105
```

输出：

```text
21
```

## 复杂度

对正整数 $a,b$，欧几里得算法的递归或循环次数都是 $O(\log\min(a,b))$，所以两种写法的时间复杂度相同。

递归深度也是 $O(\log\min(a,b))$，因此递归版使用 $O(\log\min(a,b))$ 的调用栈空间。输入为 64 位整数时，递归深度不到 $100$ 层，通常可以忽略调用栈开销；非递归版只保存 `a,b,r`，额外空间为 $O(1)$。

最慢的情况与连续斐波那契数有关：每次的商都尽可能小，余数下降得最慢。这个结论只用于理解对数复杂度，不需要记忆证明。

## 基础练习

1. 手动写出计算 $\gcd(391,299)$ 时每一次参数变化，直到第二个参数成为 $0$。
2. 分别用递归版和非递归版计算同一组输入，确认两者经过的数对完全相同。
3. 解释为什么直接写 `a = b; b = a % b;` 会丢失哪一个旧值，并用临时变量修正。
4. 测试 $\gcd(a,0)$、$\gcd(0,b)$ 和 $\gcd(0,0)$，检查它们是否符合上一篇的边界约定。

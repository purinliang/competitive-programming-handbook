# 试除法：质数检测

> 最近修订：2026-08-16 20:53 +10:00（未审阅）

[质数](prime-numbers.md) 的定义要求一个大于 $1$ 的整数没有其他正因数。程序要判断
整数 `n` 是否为质数，最直接的办法就是逐个尝试可能的因数：只要找到一个能够除尽
`n` 的候选，`n` 就是合数；全部候选都失败时，`n` 才是质数。

这种方法称为**试除法**。本篇先写出完全按照定义工作的线性做法，再利用因数成对
出现，把检查范围缩短到平方根。

## 从定义直接枚举

若 `n > 1`，定义中可能让它成为合数的额外正因数位于 `2..n-1`。逐个尝试即可：

```cpp
bool is_prime_linear(ll n) {
    if (n < 2) {
        return false;
    }

    for (ll i = 2; i <= n - 1; i++) {
        if (n % i == 0) {
            return false;
        }
    }
    return true;
}
```

当 `n = 2` 时，循环范围为空，函数返回真；这正符合 $2$ 是质数。当 `n < 2` 时，
函数在循环前直接返回假，覆盖负数、$0$ 和 $1$。

最坏情况下 `n` 是质数，循环检查大约 `n` 个候选，因此时间复杂度是 $O(n)$，额外
空间复杂度是 $O(1)$。

## 因数成对出现

如果 `n` 是合数，就能写成：

$$
n=a\times b,
$$

其中 $1<a<n$ 且 $1<b<n$。因数 $a,b$ 成对出现。

假设两者都大于 $\sqrt n$，那么：

$$
a\times b>\sqrt n\times\sqrt n=n,
$$

与 $a\times b=n$ 矛盾。因此一对因数中至少有一个不超过 $\sqrt n$。如果 `n`
存在额外因数，我们一定能在 `2..sqrt(n)` 中找到一个；没有必要继续检查到
`n - 1`。

## 检查到平方根

最直观的循环边界是：

```cpp
for (ll i = 2; i * i <= n; i++) {
    if (n % i == 0) {
        return false;
    }
}
```

这里必须使用 `<=`。例如 $49=7^2$，若只检查 `i * i < n`，就会在尝试 $7$ 以前
结束，错误地把 $49$ 当作质数。

当 `n` 接近 64 位整数上限时，`i * i` 可能先溢出。对正整数，可以把
$i^2\leq n$ 等价改写为：

$$
i\leq\left\lfloor\frac ni\right\rfloor.
$$

代码不再先形成平方：

```cpp
bool is_prime(ll n) {
    if (n < 2) {
        return false;
    }

    for (ll i = 2; i <= n / i; i++) {
        if (n % i == 0) {
            return false;
        }
    }
    return true;
}
```

最多尝试到 $\lfloor\sqrt n\rfloor$，所以时间复杂度降为 $O(\sqrt n)$，额外空间
仍是 $O(1)$。

## 只枚举奇数

除了 $2$ 以外，偶数都不是质数。可以先单独处理偶数，再只尝试奇数候选：

```cpp
bool is_prime_odd_candidates(ll n) {
    if (n < 2) {
        return false;
    }
    if (n == 2) {
        return true;
    }
    if (n % 2 == 0) {
        return false;
    }

    for (ll i = 3; i <= n / i; i += 2) {
        if (n % i == 0) {
            return false;
        }
    }
    return true;
}
```

它大约减少一半候选，但渐进复杂度仍是 $O(\sqrt n)$。基础模板保留逐个检查
`2,3,4,...` 的版本已经足够清楚；只有常数确实重要时，才需要换成奇数候选版本。

## 为什么 100 以内只检查 2、3、5、7

任何不超过 $100$ 的合数都至少有一个不超过：

$$
\sqrt{100}=10
$$

的质因数。不超过 $10$ 的质数只有：

```text
2, 3, 5, 7
```

因此，判断一个不超过 $100$ 且大于 $1$ 的数是不是合数，只需检查它能否被
$2,3,5,7$ 中至少一个数整除。

这不是说所有合数的因数都只有 $2,3,5,7$。例如 $77$ 还有因数 $11$，但它同时有
较小因数 $7$；$91$ 有因数 $13$，也同时有较小因数 $7$。平方根结论保证每一对因数
至少能从较小的一侧发现。

## 三种边界写法

| 循环条件 | 含义 | 风险或前提 |
| --- | --- | --- |
| `i <= n - 1` | 完全按定义尝试 | $O(n)$，速度较慢 |
| `i * i <= n` | 尝试到平方根 | 乘法可能溢出 |
| `i <= n / i` | 尝试到平方根 | 要求这里讨论正的 `i,n` |

调用 `sqrt(n)` 得到浮点边界也能用于许多小规模题目，但整数判定没有必要引入浮点
舍入。`i <= n / i` 直接表达同一整数条件。

## 完整代码

程序读入一个 64 位整数，输出它是否为质数。使用平方根试除，并用除法形式避免
循环边界乘法溢出。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

bool is_prime(ll n) {
    if (n < 2) {
        return false;
    }

    for (ll i = 2; i <= n / i; i++) {
        if (n % i == 0) {
            return false;
        }
    }
    return true;
}

void solve() {
    ll n;
    scanf("%lld", &n);

    if (is_prime(n)) {
        printf("Yes\n");
    } else {
        printf("No\n");
    }
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
97
```

输出：

```text
Yes
```

## 适用范围

$O(\sqrt n)$ 适合判断少量不太大的整数。`n` 接近 $10^{18}$ 时，平方根接近
$10^9$，即使数值能够放进 64 位整数，十亿次试除也通常太慢。

需要一次找出 `1..n` 中的全部质数时，应使用后面的
[埃拉托斯特尼筛法](sieve-of-eratosthenes.md)，避免对每个整数重复试除。更大的
单点质数检测则需要 Miller–Rabin 等扩展算法。

## 常见错误

### 把 1 当作质数

质数必须大于 $1$。`n < 2` 要在候选循环以前直接返回假。

### 漏掉完全平方数的平方根

边界必须包含等号。$49$ 的因数 $7$ 正好等于平方根。

### 让 i 乘 i 先溢出

即使 `n` 使用 64 位整数，`i * i` 仍可能越界。使用 `i <= n / i` 可以避免形成
这个乘积。

### 认为只检查 2、3、5、7 适用于所有范围

这四个质数只覆盖“不超过 100”的平方根边界。范围扩大以后，需要检查的新质数
候选也会增加。

## 需要记住什么

1. 完全按定义的试除法枚举什么范围，时间复杂度是多少？
2. 为什么合数一定有一个不超过自身平方根的因数？
3. 为什么平方根循环边界必须包含等号？
4. `i <= n / i` 相比 `i * i <= n` 避免了什么问题？
5. 为什么判断 100 以内的数只需检查质因数 $2,3,5,7$？
6. 先处理 $2$、再只枚举奇数改变了渐进复杂度吗？
7. 为什么 $O(\sqrt n)$ 仍不适合判断接近 $10^{18}$ 的大质数？

# 模运算

> 最近修订：2026-08-15 21:23 +10:00（未审阅）

很多计数答案增长得非常快，题目只要求输出它除以正整数 `mod` 的余数。即使最终答案能写成一个公式，直接算出完整整数也可能早已超过 64 位范围。

模运算允许我们在加法、减法和乘法的每一步都取余，只保留 `0..mod-1` 中的代表值。这样可以控制数值大小，并且最终余数不会改变。

本篇解释模同余、三种基础运算和 C++ `%` 的符号规则。快速计算巨大指数会在 [快速幂](fast-power.md) 中单独推导；模意义下的除法需要模逆元，不能直接套用普通整数除法。

## 余数与同余

正整数 `mod` 固定时，两个整数 `a` 和 `b` 除以 `mod` 得到相同余数，就称它们模 `mod` 同余，记作：

$$
a\equiv b\pmod {mod}.
$$

例如：

$$
17\equiv5\pmod {12},
$$

因为 `17` 和 `5` 除以 `12` 的余数都是 `5`。它也等价于：

$$
mod\mid(a-b).
$$

这里 `17-5=12` 能被 `12` 整除。

所有相差 `mod` 整数倍的数属于同一个同余类：

```text
..., -19, -7, 5, 17, 29, ...
```

它们模 `12` 都可以统一用 `5` 表示。竞赛代码通常选取范围 `[0,mod-1]` 中唯一的非负代表值。

## 加法

若：

$$
a\equiv a'\pmod {mod},\qquad b\equiv b'\pmod {mod},
$$

那么：

$$
a+b\equiv a'+b'\pmod {mod}.
$$

因为 `a-a'` 和 `b-b'` 都是 `mod` 的倍数，它们的和仍是 `mod` 的倍数。

所以可以先分别取余，再相加并取余：

```cpp
ll result = (a % mod + b % mod) % mod;
```

若两个操作数已经在 `[0,mod-1]` 中，它们的和小于 `2*mod`，也可以相加后只减一次：

```cpp
ll result = a + b;
if (result >= mod) {
    result -= mod;
}
```

基础正文优先使用 `%` 表达数学关系；只有常数确实重要时，才把固定范围下的取余改成条件减法。

## 减法

同样有：

$$
a-b\equiv a'-b'\pmod {mod}.
$$

但 `a-b` 可能是负数。若 `a` 和 `b` 已经规范到 `[0,mod-1]`，可以先加一个 `mod`：

```cpp
ll result = (a - b + mod) % mod;
```

因为加上 `mod` 不会改变同余类，并且此时 `a-b+mod` 位于 `[0,2*mod-2]`，不会为负。

不能在不知道数值范围时机械地只加一次 `mod`。例如原始值可能远小于 `-mod`，应当先统一规范化。

## 乘法

同余也能相乘：

$$
ab\equiv a'b'\pmod {mod}.
$$

因此：

```cpp
ll result = a % mod * (b % mod) % mod;
```

数学上正确不代表中间乘积一定能放进 C++ 类型。若 `a` 和 `b` 已规范到 `[0,mod-1]`，乘积上界接近 $mod^2$：

- 常见 `mod=10^9+7` 时，乘积能够放进 64 位整数；
- `mod` 本身接近 64 位上限时，乘法会先溢出，再执行 `%`，结果错误。

题目使用一般 64 位模数时，需要根据环境使用 `__int128` 或另外实现安全乘法。这个问题属于整数容量，不是 `%` 会自动解决的事情。

## 为什么可以每一步取余

考虑表达式：

$$
(a+b)c-d.
$$

把 `a,b,c,d` 分别替换为同余的非负代表值，加法、乘法和减法每一步都会保持同余。因此可以写成：

```cpp
ll result = (a + b) % mod;
result = result * c % mod;
result = (result - d + mod) % mod;
```

最终 `result` 与完整整数表达式同余，同时每一步都把值压回可控范围。

这条规则适用于只由加、减、乘组成的任意表达式。括号结构仍然必须按照原表达式执行；取余不会允许我们改变本来不成立的运算顺序。

## C++ 的负余数

数学中通常希望模 `mod` 的结果落在 `[0,mod-1]`。C++ 的 `%` 是整数余数运算，结果与左操作数同号或为 `0`：

```cpp
printf("%d\n", -5 % 3);
```

输出是：

```text
-2
```

因此不能把 `x % mod` 无条件当成数学上的非负模。规范化一个 64 位整数可以写成：

```cpp
ll normalize(ll x, ll mod) {
    x %= mod;
    if (x < 0) {
        x += mod;
    }
    return x;
}
```

第一次 `%` 后，`x` 位于 `-(mod-1)..mod-1`，所以负数时加一次 `mod` 就足够回到 `[0,mod-1]`。

也常见：

```cpp
(x % mod + mod) % mod
```

它同样正确，但会执行两次 `%`。明确知道第一次余数范围时，条件加法更直接。

## 除法不能直接取模

普通整数中，如果 `a=b*c`，常常可以通过除法恢复 `b`。模意义下，直接写：

```cpp
(a / b) % mod
```

并不等于“模 `mod` 除以 `b`”。整数除法会先舍弃余数，而且某些数在给定模数下根本不能被消去。

例如模 `4` 时：

$$
2\times1\equiv2\times3\pmod4,
$$

但 `1` 与 `3` 并不同余。若直接在两边约去 `2`，就会得到错误结论。

模除法需要寻找一个数 `b^{-1}`，使：

$$
bb^{-1}\equiv1\pmod {mod}.
$$

这个数称为模逆元，而且只有满足特定条件时才存在。[模逆元（正文待写）](../CATALOG.md#05-数学) 会从线性同余方程解释存在条件和计算方法。本篇只记住：加、减、乘可以逐步取模，除法不能照搬。

## 完整代码

下面的程序计算：

$$
(a+b)c-d\pmod {10^9+7}.
$$

输入的四个数都在 64 位整数范围内，可以为负数。先分别规范化，再按照表达式顺序运算。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

const ll MOD = 1e9 + 7;

ll normalize(ll x) {
    x %= MOD;
    if (x < 0) {
        x += MOD;
    }
    return x;
}

int main() {
    ll a, b, c, d;
    scanf("%lld%lld%lld%lld", &a, &b, &c, &d);

    a = normalize(a);
    b = normalize(b);
    c = normalize(c);
    d = normalize(d);

    ll result = (a + b) % MOD;
    result = result * c % MOD;
    result = (result - d + MOD) % MOD;

    printf("%lld\n", result);
    return 0;
}
```

输入：

```text
-2 5 4 3
```

输出：

```text
9
```

原表达式为 `(-2+5)*4-3=9`。若中间值很大或为负，程序仍会输出 `[0,MOD-1]` 中与它同余的唯一代表值。

对固定数量的运算，程序时间和额外空间都是 $O(1)$。在循环或动态规划中使用相同规则时，总复杂度由实际执行的运算次数决定。

## 常见错误

### 只在最后取余

最终结果也许只需要一个余数，但中间乘积可能早已溢出。只要运算允许，就应在每一步把值压回模数范围。

### 负数直接使用百分号

C++ 的负余数可能为负。需要数学上的标准非负代表值时，先规范化到 `[0,mod-1]`。

### 减法忘记补模

两个规范值相减仍可能为负。已知两者范围时使用 `(a-b+mod)%mod`。

### 认为先乘后取模不会溢出

`a*b%mod` 会先完成 C++ 乘法。必须根据规范化后的乘积上界选择足够宽的类型。

### 把普通除法当成模除法

模意义下不能一般地约去因子。需要除法时，先检查模逆元是否存在，并把除法转换成乘逆元。

### 模数不是正数

本书模运算统一假设 `mod>0`。模数为 `0` 时 `%` 没有合法意义；负模数也不采用本篇 `[0,mod-1]` 的代表范围。

## 基础练习

1. 写出 `17,-7,29` 模 `12` 的标准非负代表值，并验证它们是否同余。
2. 用整除 `mod|(a-b)` 的定义验证同余的加法和乘法规则。
3. 比较 C++ 中 `-5%3` 与数学标准非负模的结果，并使用 `normalize` 转换。
4. 在 `mod=7` 下逐步计算 `(10+20)*30-40`，每一步都保留标准代表值。
5. 构造一个 32 位整数乘法在取余以前溢出的例子，再改用 64 位整数。
6. 在模 `4` 下寻找不能直接约去因子 `2` 的另一组同余式。

## 需要记住什么

1. `a` 与 `b` 模 `mod` 同余有哪两种等价描述？
2. 为什么加法、减法和乘法可以在每一步取模？
3. C++ 的 `%` 与数学标准非负模在负数上有什么区别？
4. 怎样把一个 64 位整数规范到 `[0,mod-1]`？为什么只需加一次 `mod`？
5. 两个已经规范化的数相减时，为什么可以先加一个 `mod`？
6. 为什么 `a*b%mod` 仍可能在取余以前溢出？
7. 为什么模意义下的除法不能直接使用普通整数 `/`？

同余类的抽象代数结构、一般 64 位模数的无溢出乘法和中国剩余定理不属于本篇基础运算。固定模数下希望把规范化和运算符封装成类型时，可以阅读配套扩展 [模运算：modint](mod-int.md)。

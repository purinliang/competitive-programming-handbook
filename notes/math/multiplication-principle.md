# 计数原理：乘法原理

> 最近修订：2026-08-15 22:18 +10:00（未审阅）

一个完整方案需要依次完成多个步骤。若第一步有 `a` 种选择，并且对第一步的每种选择，第二步都有 `b` 种选择，那么完整方案数是：

$$
a\times b.
$$

例如一套服装由一件上衣和一条裤子组成。有 `3` 件上衣、`4` 条裤子，每件上衣都能与每条裤子搭配，总方案数是：

$$
3\times4=12.
$$

这就是乘法原理。

## 多个连续步骤

若一个完整方案由 $k$ 个步骤共同组成，第 `i` 步有 $c_i$ 种选择，并且无论前面怎样选择，这一步的可选数量始终是 $c_i$，那么：

$$
c_1c_2\cdots c_k
$$

就是完整方案数。

例如用 `4` 个字符组成长度为 `3` 的字符串，每个位置都允许重复使用任意字符：

```text
第 1 位：4 种
第 2 位：4 种
第 3 位：4 种
```

所以共有：

$$
4\times4\times4=4^3=64
$$

个字符串。

乘法原理通常对应自然语言中的：

```text
先完成第一步，再完成第二步，再……
```

每个完整方案必须包含每一步的一次选择。

## 有序选择组

把各步选择分别记为集合：

$$
S_1,S_2,\ldots,S_k.
$$

一个完整方案可以唯一写成有序组：

$$
(s_1,s_2,\ldots,s_k),qquad s_i\in S_i.
$$

第一项有 $|S_1|$ 种可能；固定第一项后，第二项有 $|S_2|$ 种；继续固定前缀后，每个前缀都能与下一步的所有选择组合。

因此所有有序组的数量是：

$$
|S_1|\times|S_2|\times\cdots\times|S_k|.
$$

“唯一写成”很重要：若同一个最终方案能由多组步骤选择产生，直接相乘会重复统计；若某些步骤组合不合法，直接相乘又会把非法组合算入。

## 选择数随前缀变化

简单乘积要求同一步的选择数不依赖前面具体选了什么。

假设先选一个题库，再从其中选一道题：基础题库有 `12` 道，提高题库有 `7` 道，挑战题库有 `5` 道。第二步不是固定的 `12`、`7` 或 `5` 种，而是取决于第一步。

应分别计算三种第一步：

$$
1\times12+1\times7+1\times5=24.
$$

也就是先对每个分支使用乘法原理，再用 [加法原理](addition-principle.md) 合并互斥分支。

更一般地，如果第二步在第一种选择后有 $b_1$ 种、第二种选择后有 $b_2$ 种，就应计算：

$$
b_1+b_2+\cdots+b_a,
$$

不能擅自挑一个 `b` 写成 `a*b`。

## 不允许重复选择

从 `n` 个不同元素中依次选择 `k` 个，并且同一个元素不能重复使用：

```text
第 1 个位置：n 种
第 2 个位置：n-1 种
第 3 个位置：n-2 种
...
第 k 个位置：n-k+1 种
```

虽然选择数会随着步骤编号变化，但对于任何合法前缀，同一步剩余的元素数量都相同，所以仍可直接相乘：

$$
n(n-1)(n-2)\cdots(n-k+1).
$$

这正是下一篇排列数的来源。

## 零种选择

若任何一个必需步骤有 `0` 种合法选择，就无法组成完整方案。乘积中出现因数 `0`，答案自然为 `0`。

反过来，没有任何步骤的空过程有一种完成方式，称为空积：

$$
\prod_{i=1}^{0}c_i=1.
$$

因此代码把答案初始化为乘法单位元 `1`。当 `k=0` 时直接输出 `1`。

## 翻译成代码

若 `choices[i]` 表示第 `i` 个必需步骤的选择数：

```cpp
ll answer = 1;
for (int i = 1; i <= k; i++) {
    answer *= choices[i];
}
```

与加法原理一样，循环本身不是难点。使用乘法以前必须证明：

- 每个完整方案恰好对应一组步骤选择；
- 每组被计算的步骤选择都合法；
- 每一步的选择数在所有合法前缀下符合所写的因数。

## 完整代码

下面的程序读取 `k` 个连续步骤的选择数并求乘积，假设准确答案能够放入 64 位整数。

```cpp
#include <bits/stdc++.h>

using namespace std;

typedef long long ll;

int main() {
    int k;
    scanf("%d", &k);

    vector<ll> choices(k + 5);
    ll answer = 1;
    for (int i = 1; i <= k; i++) {
        scanf("%lld", &choices[i]);
        answer *= choices[i];
    }

    printf("%lld\n", answer);
    return 0;
}
```

输入：

```text
3
4 4 4
```

输出：

```text
64
```

若题目要求答案模 `MOD`，每一步改为：

```cpp
answer = answer * choices[i] % MOD;
```

仍需根据 `MOD` 的范围保证乘法中间值不会溢出。

## 与加法原理的区别

两种原理关心的结构不同：

| 原理 | 完整方案的结构 | 运算 |
| --- | --- | --- |
| 加法原理 | 从若干互斥的完整情形中选择一个 | 相加 |
| 乘法原理 | 依次完成构成同一方案的多个步骤 | 相乘 |

复杂问题常同时使用两者：先固定某个关键选择，把所有方案拆成互斥情形；再在每个情形内部把连续步骤的选择数相乘；最后把各情形结果相加。

## 复杂度

已知 `k` 个步骤的选择数时，求乘积需要 $O(k)$ 时间。示例保存输入数组，使用 $O(k)$ 空间；边读边乘可以降到 $O(1)$ 额外空间。

真实问题的难点仍然是建立步骤与完整方案之间的一一对应，而不是执行乘法循环。

## 常见错误

### 把互斥方法相乘

若方案只需选择方法 A 或方法 B，应使用加法原理。只有一个完整方案同时包含两步选择时才相乘。

### 忽略前面选择对后面的影响

后续选择数随前缀变化时，不能使用一个固定因数。应拆分分支，或建立能够准确统计合法后继的状态。

### 统计了非法组合

并非每个第一步选择都能与每个第二步选择搭配时，笛卡尔积中包含非法方案。必须加入限制或重新分类。

### 同一结果由多条过程得到

若题目只区分最终结果，而多组步骤会得到同一结果，直接相乘会重复。先明确“方案”是否包含选择过程和顺序。

### 忘记空积与零因数

没有步骤时有一个空方案，答案初始化为 `1`；任一步没有合法选择时，完整方案数为 `0`。

### 忽略乘积容量

计数乘积增长很快。根据数据范围使用 64 位整数、指定模数或其他精确表示。

## 基础练习

1. 有 `5` 件上衣、`3` 条裤子和 `2` 双鞋，计算完整搭配数量。
2. 使用 `0,1` 组成长度为 `8` 的字符串，允许重复时有多少种？
3. 从 `10` 个不同元素中依次选出 `3` 个且不重复，写出每一步选择数。
4. 构造一个第二步选择数依赖第一步的例子，说明为什么不能直接写固定乘积。
5. 举出同一最终结果可由多组过程产生、因而直接相乘会重复的例子。
6. 修改完整代码，在固定模数下计算乘积。

## 需要记住什么

1. 乘法原理描述的完整方案由什么组成？
2. 为什么各步选择可以表示成有序组？
3. 直接相乘要求后续选择数满足什么条件？
4. 选择数依赖前缀时怎样结合加法原理？
5. 不允许重复选择为什么得到递减的因数？
6. 空积为什么是 `1`，某一步有零种选择时为什么答案是 `0`？
7. 加法原理与乘法原理最核心的区别是什么？

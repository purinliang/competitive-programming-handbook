# 字符串构造

> 最近修订：2026-08-17 07:33 +10:00（未审阅）

有些字符串问题不需要发明新的匹配算法，只需要先把原字符串按照问题
的结构重新拼接，再使用已经学过的 KMP、Z 函数或字符串哈希。最常见的三种
构造是：

- 用分隔符把两个字符串放进同一个字符串；
- 复制一遍原串，把循环位移变成普通子串；
- 反转原串，把对称关系变成两段字符串的相等关系。

构造只是改变问题的表示。它不会自动完成匹配，也不会让一个原本很慢的
匹配方法自动变快。

## 用分隔符阻断边界

用 Z 函数匹配模式串 `pattern` 和文本串 `text` 时，可以构造：

```text
pattern#text
```

拼接后的字符串只有一个开头，Z 函数因此可以把每个位置与 `pattern`
比较。`#` 的作用是阻止一次匹配穿过两个字符串的边界。

分隔符必须不会出现在输入中。若题目保证字符串只含小写英文字母，`#`
就是可用的选择；若输入可以包含任意字符，就不能不加说明地假定 `#`
安全。

假设 `pattern` 的长度为 $m$，在 0-based 的 `string` 中：

- `pattern` 占据 `[0,m-1]`；
- 分隔符位于 `m`；
- `text[k]` 位于拼接串的 `m+1+k`。

因此，算法在拼接串上得到位置后，必须减去模式串和分隔符占用的
`m+1` 个位置，才能回到文本串中的下标。

## 用倍长串表示循环位移

字符串 `abcd` 向左循环移动一位得到 `bcda`。直接枚举切分位置时，每次
都要把后半段与前半段重新拼接。

把原串复制一遍：

```text
abcdabcd
```

长度为 $4$ 的四种循环位移恰好是其中从位置 `0,1,2,3` 开始的四个长度为
$4$ 的子串：

```text
abcd  bcda  cdab  dabc
```

设原串长度为 $n$。所有不同切分位置只需要考虑倍长串中的起点
`0..n-1`。位置 `n` 开始的长度 $n$ 子串又是原串，只是位置 `0` 的重复。

因此，判断长度相同的 `t` 是否为 `s` 的循环位移，可以转化为：

> `t` 是否在 `s+s` 中出现。

先比较长度很重要。若不限制长度，一个较短字符串也可能在倍长串中出现，
但它不是原串的循环位移。

## 用反转串表示对称

将 `s` 复制后反转：

```cpp
string reversed = s;
reverse(reversed.begin(), reversed.end());
```

设 `s` 长度为 $n$。原串的闭区间 `[l,r]` 在反转串中对应：

$$
[n-1-r,n-1-l].
$$

两段内容的顺序恰好相反。所以，回文判定可以被改写成“原串的一段是否
等于反转串中对应的一段”。后续可以使用字符串哈希、后缀数组等结构
加速大量比较。

反转串也可以与分隔符同时使用。例如构造：

```text
s#reverse(s)
```

对它计算前缀函数，最后一个前缀函数值就是 `s` 的最长回文前缀长度。
这不是因为“反转以后自动得到回文”，而是因为拼接串的一个边界同时是：

- `s` 的前缀；
- `reverse(s)` 的后缀，也就是对应前缀反转后的内容。

两者相等，意味着这段前缀正着读与反着读相同。

## 组合构造

上述构造可以组合。判断 `t` 是否为 `s` 的循环位移时，既要使用
`s+s` 把循环位移变成子串，又要构造：

```text
t#s+s
```

这样就可以用前缀函数查找 `t` 是否在倍长串中出现。每一步都只解决一个
问题：

1. 倍长串消除循环边界；
2. 分隔符阻止模式串与文本串串在一起；
3. 前缀函数完成线性匹配。

看到新构造时，也应该逐步回答“每一段解决了什么问题”，而不是把整个式子
当作需要背诵的结论。

## 完整代码

下面的程序判断 `t` 是否为 `s` 的循环位移。输入只含小写英文字母，
因此可以安全使用 `#` 作为分隔符。

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> build_prefix_function(const string& s) {
    int n = s.size();
    vector<int> prefix(n, 0);

    for (int i = 1; i < n; i++) {
        int length = prefix[i - 1];

        while (length > 0 && s[i] != s[length]) {
            length = prefix[length - 1];
        }
        if (s[i] == s[length]) {
            length++;
        }
        prefix[i] = length;
    }

    return prefix;
}

bool is_cyclic_shift(const string& s, const string& t) {
    if (s.size() != t.size()) {
        return false;
    }
    if (s.empty()) {
        return true;
    }

    string combined = t + "#" + s + s;
    vector<int> prefix = build_prefix_function(combined);
    int pattern_length = t.size();

    for (int i = pattern_length + 1; i < (int)combined.size(); i++) {
        if (prefix[i] == pattern_length) {
            return true;
        }
    }

    return false;
}

int main() {
    string s, t;
    cin >> s >> t;

    if (is_cyclic_shift(s, t)) {
        cout << "Yes\n";
    } else {
        cout << "No\n";
    }

    return 0;
}
```

构造拼接串需要 $O(n)$ 时间和空间，前缀函数也是 $O(n)$，所以整个判定的
时间复杂度和空间复杂度都是 $O(n)$。

## 常见错误

- 不比较两个字符串的长度，只检查 `t` 是否在 `s+s` 中出现；
- 把倍长串中的起点 `n` 当作新的循环位移；
- 使用可能出现在输入中的字符作为分隔符；
- 拼接以后忘记把下标换回原字符串的下标；
- 记住 `s#reverse(s)` 的结论，却说不清前缀与反转串后缀的对应关系；
- 只完成字符串构造，却没有选择能满足复杂度要求的后续算法。

## 需要记住什么

- 分隔符解决了什么边界问题？它必须满足什么条件？
- 为什么所有循环位移都会出现在 `s+s` 中？
- 原串区间 `[l,r]` 在反转串中对应哪个区间？
- 为什么 `s#reverse(s)` 的最长边界对应最长回文前缀？
- 字符串构造与 KMP、Z 函数或字符串哈希分别负责什么？

# 输入输出：标准输出

> 最近修订：2026-08-13 02:26 +10:00（未审阅）

程序计算出答案后，需要按照题目规定的文本格式交给评测系统。C++ 将程序通常写出结果的目标称为**标准输出**。

本地直接运行时，标准输出通常显示在终端；在线评测时，评测系统读取这份文本，并与正确答案比较。程序只负责写入标准输出，不必知道输出最终显示在哪里或保存到什么文件。

## cout 输出

[Hello World!](hello-world.md) 已经使用过 `cout`：

```cpp
cout << "Hello, World!" << '\n';
```

`cout` 是 C++ 标准库提供的标准输出流。运算符 `<<` 把右边的值依次送入输出：

```cpp
int a = 3;
int b = 5;

cout << a << ' ' << b << '\n';
```

程序依次输出 `a`、一个空格、`b` 和一个换行，得到：

```text
3 5
```

`cout` 根据值的类型选择输出方式，因此整数、浮点数、字符和布尔值可以沿同一条 `<<` 链输出：

```cpp
int count = 3;
double ratio = 0.5;
char grade = 'A';

cout << count << ' ' << ratio << ' ' << grade << '\n';
```

空格不会自动产生。需要两个值之间出现空格时，必须明确输出 `' '`；需要换行时，也必须明确输出 `\n`。

## 换行

本书统一使用字符 `\n` 换行：

```cpp
cout << answer << '\n';
```

单引号中的 `'\n'` 是一个换行字符。双引号中的 `"\n"` 是只包含换行的字符串，两者都能换行；只输出一个字符时使用单引号更准确。

`endl` 也会换行：

```cpp
cout << answer << endl;
```

但 `endl` 还会立即刷新输出缓冲区。频繁刷新会降低大量输出时的速度，所以普通竞赛题统一使用 `'\n'`。

缓冲意味着输出可能先积累在内存中，再成批交给终端或评测系统。程序正常结束时会处理剩余输出，普通题目不需要手动刷新。只有交互题需要在每次询问后及时刷新，此时可以使用：

```cpp
cout << query << '\n' << flush;
```

交互题会明确说明交互规则；当前只需记住普通输出使用 `'\n'`。

## printf 输出

本书后续的竞赛代码默认使用 `printf`。它通过**格式字符串**说明后续值应该怎样输出：

```cpp
int a = 3;
int b = 5;

printf("%d %d\n", a, b);
```

格式字符串从左到右处理：

- 第一个 `%d` 使用后面的第一个值 `a`；
- 中间的空格原样输出；
- 第二个 `%d` 使用下一个值 `b`；
- `\n` 输出换行。

每个格式控制符都必须与对应值的真实类型匹配：

| 值的类型 | `printf` 格式 |
| --- | --- |
| `int` | `%d` |
| `unsigned int` | `%u` |
| `long long` | `%lld` |
| `unsigned long long` | `%llu` |
| `double` | `%f` |
| `long double` | `%Lf` |
| `char` | `%c` |

例如：

```cpp
int count = 3;
long long total = 5000000000LL;
double average = 2.5;
char grade = 'A';

printf("%d %lld %f %c\n", count, total, average, grade);
```

格式与类型不匹配会让 `printf` 按错误方式解释实参，属于未定义行为。编译器开启警告后通常能发现直接可见的错误，不要忽略这些警告。

### scanf 与 printf 的浮点格式

输入与输出的格式控制符有一个容易混淆的差别：

| 类型 | `scanf` 读入 | `printf` 输出 |
| --- | --- | --- |
| `float` | `%f` | `%f` |
| `double` | `%lf` | `%f` |
| `long double` | `%Lf` | `%Lf` |

`printf` 接收可变数量的实参时，`float` 会先提升成 `double`，所以二者都使用 `%f` 输出。`scanf` 需要把读到的结果写进真实变量，因此必须用 `%f` 区分 `float*`、用 `%lf` 区分 `double*`。

这组差别需要记住：读入 `double` 用 `%lf`，输出 `double` 用 `%f`。

### 输出百分号

`printf` 格式字符串中的 `%` 用来开始格式控制符。如果需要输出普通百分号，要写两个百分号：

```cpp
printf("100%%\n");
```

输出：

```text
100%
```

`cout` 不把 `%` 视为格式字符，可以直接输出：

```cpp
cout << "100%" << '\n';
```

## 浮点数的小数位数

题目经常要求保留固定的小数位。例如输出 `double average`，保留两位小数。

`printf` 在 `%f` 中加入 `.2`：

```cpp
printf("%.2f\n", average);
```

`.2` 表示小数点后输出两位，程序会为显示结果进行舍入。

`cout` 使用 `fixed` 与 `setprecision(2)`：

```cpp
cout << fixed << setprecision(2) << average << '\n';
```

`fixed` 选择定点形式；在这种形式下，`setprecision(2)` 表示小数点后两位。如果不写 `fixed`，`setprecision` 控制的是有效数字总数，含义不同。

这些格式只改变**输出文本**，不会修改变量中保存的 `average`。后续计算仍然使用原来的浮点值。

> 二进制浮点数只能近似表示许多十进制小数，因此显示舍入也会受到原值近似的影响。题目若接受误差，应按题面要求选择精度；不要把 `2` 当作所有浮点题的固定答案。

## 对齐与补零

少数题目要求固定宽度，例如把小时输出成两位，不足时在左边补 `0`。

`printf` 可以写：

```cpp
printf("%02d\n", hour);
```

`2` 表示最小宽度为两位，`0` 表示用零填充。`hour == 8` 时输出 `08`；`hour == 123` 时仍会完整输出 `123`，最小宽度不会截断更长结果。

`cout` 的对应写法是：

```cpp
cout << setfill('0') << setw(2) << hour << '\n';
```

`setw(2)` 只影响紧跟在它后面的一个输出值，`setfill('0')` 设置的填充字符则会保持，直到再次修改。固定宽度远不如普通输出和浮点精度常用，知道遇到时可以查阅即可。

## 精确匹配题目格式

非交互普通题通常按空白分隔答案，因此行末多一个空格往往不会影响评测；但这不是所有题目的保证。字符串输出、构造题和特殊评测规则可能要求更精确的文本。

最稳定的习惯是按照题面明确构造输出：

- 值之间需要分隔时输出一个空格；
- 每行结束后输出 `\n`；
- 不输出 `answer =`、提示语或调试信息，除非题面明确要求；
- 大小写与固定符号完全遵照题面。

例如题目只要求输出和，就应该写：

```cpp
cout << a + b << '\n';
```

而不是：

```cpp
cout << "The answer is " << a + b << '\n';
```

OJ 比较的是程序真正输出的文本，不会自动忽略自行添加的说明。

## 选择一套输入输出接口

一份正式解题代码应成对选择一套接口：

- `cin` 与 `cout`；
- `scanf` 与 `printf`。

若使用 `cin` 和 `cout`，竞赛代码常在第一次输入输出之前设置：

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

第一行关闭 C++ 流与 C 标准输入输出之间的同步，提高大量输入输出时的速度；关闭后不要再与 `scanf`、`printf` 混用。第二行解除 `cin` 对 `cout` 的自动刷新绑定，普通 OJ 不需要在读入前显示提示，因此通常合适。

如果选择 `scanf` 和 `printf`，不需要这两行。本书的竞赛模板默认采用这套接口；教学正文在更容易说明类型时也会使用 `cin` 和 `cout`。同一份完整程序内保持一致即可。

## 完整代码

输入整数总分 `sum` 和正整数人数 `count`，输出总分与平均分。第一行输出整数总分，第二行输出保留两位小数的平均分。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int sum;
    int count;
    scanf("%d%d", &sum, &count);

    double average = 1.0 * sum / count;

    printf("%d\n", sum);
    printf("%.2f\n", average);
    return 0;
}
```

输入：

```text
5 2
```

输出：

```text
5
2.50
```

`%.2f` 只控制第二行怎样显示；变量 `average` 仍然保存计算得到的浮点值。

## 常见错误

### 忘记输出分隔符

`cout << a << b;` 会直接拼接两个数的文本。题目要求两个数时，明确输出空格或换行。

### printf 格式与类型不匹配

`long long` 使用 `%lld`，`double` 使用 `%f`。格式错误不是普通的显示差异，而可能造成未定义行为。

### 混淆 double 的输入输出格式

`scanf` 读入 `double` 用 `%lf`；`printf` 输出 `double` 用 `%f`。

### 普通输出频繁使用 endl

`endl` 每次都刷新缓冲区，大量输出时可能明显变慢。普通题使用 `'\n'`，只有确实需要立即交互时再刷新。

### 自行添加提示文字

OJ 输入输出不是人机对话。只输出题目要求的内容，不要添加 `Please input` 或 `The answer is`。

## 需要记住什么

1. 本地运行和 OJ 评测时，标准输出分别通常交给谁？
2. `cout` 怎样依次输出多个值？值之间的空格会自动出现吗？
3. 为什么普通竞赛题统一用 `'\n'` 而不是 `endl`？
4. `printf` 输出 `int`、`long long`、`double` 和 `char` 分别使用什么格式？
5. `scanf` 与 `printf` 处理 `double` 时，格式控制符有什么区别？
6. 怎样分别用 `printf` 和 `cout` 将浮点数输出为小数点后两位？
7. `printf` 格式字符串中怎样输出普通 `%`？
8. 为什么关闭流同步后不应再混用 `cin` / `cout` 与 `scanf` / `printf`？

固定宽度与补零只需在题目要求特殊格式时查阅。当前最重要的是类型匹配、明确输出分隔符、统一换行，并且不添加题面之外的文本。

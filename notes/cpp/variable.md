# 变量

> 最近修订：2026-08-16 07:05 +10:00（未审阅）

程序处理的数据不会永远写死在源码中。输入的分数、数组长度、当前答案和是否访问过某个点，都需要在运行期间保存，并在后面的代码中再次使用。

在 C++ 标准术语中，声明一个对象或引用会引入一个**变量**。本篇先讨论最常见的具名对象：类型决定怎样解释其中的数据，名称让后面的代码能够找到它。普通的、没有 `const` 限制的变量还可以随着程序执行获得新值。

这里的**对象**不是专指由 `class` 创建的实例。C++ 把占据一段存储、具有类型和值的数据实体都称为对象，因此一个 `int`、一个数组和一个结构体实例都是对象；类的实例只是对象的一种。日常交流中仍然可以把普通的 `int score` 简称为变量，不必每次都强调“对象”。

## 声明变量

我们已经见过最常见的变量声明：

```cpp
int score;
```

这行代码由三个部分组成：

- `int` 是类型，表示变量保存整数；
- `score` 是变量名；
- 末尾的分号 `;` 表示这条语句结束。

同样的方法可以声明此前学过的其他基本类型：

```cpp
double temperature;
char direction;
bool visited;
```

变量的类型一旦确定就不会改变。`score` 以后可以保存另一个 `int` 值，但不会在运行到一半时变成 `double` 或 `char`。

当前先使用由英文字母、数字和下划线组成、且不以数字开头的变量名。后面的 [标识符](identifiers.md) 会系统整理命名规则；`int`、`return`、`if` 等具有语法作用的 [关键字](keywords.md) 不能用作变量名。

## 初始化

只有类型和名称还不够。程序第一次使用变量的值以前，必须先让它得到一个确定值。

在变量创建时给出第一个值，称为**初始化**：

```cpp
int score = 0;
double temperature = 36.5;
char direction = 'L';
bool visited = false;
```

可以把 `int score = 0;` 从左到右读成：“创建一个名为 `score` 的整数，它最初是 `0`。”

初始值应该反映变量开始时的真实状态：

- 尚未获得任何分数时，`score` 从 `0` 开始；
- 尚未找到答案时，`found` 从 `false` 开始；
- 已知第一个候选答案时，`answer` 可以直接用该候选值初始化。

不要为了形式统一把所有变量都随意初始化为 `0`。例如方向字符的合理初始值取决于题意，写成空字符或 `'0'` 可能反而隐藏错误。

## 赋值

变量创建以后，还可以把新值写进去。这称为**赋值**：

```cpp
int score = 0;
score = 10;
score = 25;
```

第一行的 `= 0` 是初始化的一部分；后两行的 `=` 是赋值运算符。它们都把右边的值放进左边变量，但发生的时机不同：

- 初始化在变量创建时发生一次；
- 赋值发生在变量已经存在以后，可以执行许多次。

每次赋值都会替换原来的值。上面三行执行完后，`score` 保存 `25`；之前的 `0` 和 `10` 不会自动保留。

赋值右边也可以使用变量当前的值：

```cpp
score = score + 5;
```

执行顺序是：先读取右边旧的 `score`，计算加 $5$ 的结果，再把结果写回左边的 `score`。若原来是 `25`，执行后就是 `30`。

## 输入写入变量

输入操作也会把值写入变量：

```cpp
int score;
cin >> score;
```

第一行创建 `score`，第二行从标准输入取得一个整数并存进去。在 OJ 保证输入合法时，只要读取完成以后才使用 `score`，这种写法就是安全的。

这与提前初始化成固定值不同：

```cpp
int score = 0;
```

这里不等待输入，变量一创建就已经是 `0`。选择哪种写法取决于数据从哪里来：已知起始状态直接初始化，必须由题目提供的数据则从输入读取。

## 未初始化变量

函数内部的普通基本类型变量若没有初始化，其中并不会自动出现一个可以依赖的 `0`：

```cpp
int score;
cout << score << '\n';
```

这里在任何写入发生以前就读取 `score`。它的值不确定，读取它会导致未定义行为；程序可能输出看似随机的数，也可能在不同编译方式下表现不同。

正确做法是保证每条执行路径都先写后读：

```cpp
int score = 0;
cout << score << '\n';
```

或者让输入先成功写入：

```cpp
int score;
cin >> score;
cout << score << '\n';
```

“声明后马上初始化”是很好的默认习惯。只有变量必然紧接着由输入或某个函数写入时，才通常省略初始值。

## 一行一个变量

C++ 允许在一行中声明多个同类型变量：

```cpp
int width, height;
```

但在教学代码和变量含义较长时，一行一个变量更容易阅读，也不容易漏掉某个初始值：

```cpp
int width;
int height;
```

竞赛模板中 `int n, m;` 这类短小且关系明确的写法也很常见。两种形式的语义相同；选择标准是能否让含义保持清楚，而不是强行压缩行数。

## 完整代码

现在用变量记录两轮比赛后的总分。玩家开始时分数为 $0$，程序读入两轮各自获得的分数，并依次更新总分。

这需要三个不同含义的变量：

- `total_score` 保存会不断变化的总分，初始值是 `0`；
- `first_round` 和 `second_round` 保存输入的两轮得分；
- 每轮结束后，用一次赋值把旧总分与本轮得分相加，再写回总分。

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int total_score = 0;

    int first_round;
    int second_round;
    cin >> first_round >> second_round;

    total_score = total_score + first_round;
    total_score = total_score + second_round;

    cout << total_score << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
12 8
```

执行过程是：

```text
初始总分：0
加入第一轮：0 + 12 = 12
加入第二轮：12 + 8 = 20
```

输出：

```text
20
```

这份程序当然也可以直接输出 `first_round + second_round`，但保留 `total_score` 展示了“状态从初值开始，经过多次赋值逐步更新”的过程。以后处理更多轮、循环和动态规划时，同一种模式会不断出现。

## 常见错误

### 先读取后赋值

```cpp
int answer;
answer = answer + 1;
```

右边先读取了尚未初始化的 `answer`。若它表示计数，应从有意义的初值开始：

```cpp
int answer = 0;
answer = answer + 1;
```

### 重复声明同一变量

```cpp
int score = 10;
int score = 20;
```

在同一个位置不能用相同名称重新创建另一个变量。若意图是修改已有值，第二行不再写类型：

```cpp
int score = 10;
score = 20;
```

不同代码区域何时允许出现同名变量，会在 [作用域](scope.md) 中解释。

### 用等号表达数学等式

C++ 的赋值 `=` 有明确方向：先计算右边，再写入左边。`score = score + 1` 不是数学方程，而是一条更新指令。

判断左右是否相等要使用 `==`，它会产生一个 `bool`，不会写入左边变量。

## 需要记住什么

1. 一条基本变量声明由类型、名称和什么结束符组成？
2. 初始化与赋值分别发生在什么时候？
3. 连续两次给同一变量赋值后，旧值会怎样？
4. `score = score + 5` 按什么顺序读取、计算和写入？
5. 为什么不能输出一个尚未初始化的函数内局部 `int`？
6. `int score; cin >> score;` 为什么在合法输入下可以安全使用？
7. 什么情况下应该用 `bool` 而不是 `int` 保存状态？
8. 为什么变量名应该长期只承担一种含义？

正式标准中“声明”与“定义”的细分、对象生命周期和不同存储区域的自动初始化规则暂时不要求掌握。本篇只要求能创建含义清楚的变量，给出合理初值，并保证任何读取都发生在写入之后。

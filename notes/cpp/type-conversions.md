# 类型转换

> 最近修订：2026-08-16 07:09 +10:00（未审阅）

C++ 允许不同类型的值共同参与程序。例如，用整数总分除以人数得到小数平均分，把字符转换成编号，或者把计算结果保存进另一种类型的变量。它们背后都需要同一件事：把一个类型的值转换成另一个类型。

**类型转换**根据原值产生一个目标类型的值。它不会凭空提高原有数据的精度，也不会自动修正此前已经发生的整数除法或溢出；除非把转换结果重新赋值给原变量，否则原变量本身也不会改变。

## 转换发生在哪里

基础程序中，类型转换最常出现在三个位置：

1. 初始化或赋值时，右边的值要转换成左边变量的类型；
2. 不同类型共同运算时，操作数要先转换成适合共同计算的类型；
3. 程序员明确写出目标类型，主动要求一次转换。

前两种由语言规则自动完成，称为**隐式转换**；第三种称为**显式转换**。

## 初始化与赋值中的隐式转换

把 `int` 保存进 `double` 时，整数值会转换成浮点数：

```cpp
int score = 73;
double precise_score = score;
```

此时 `precise_score` 保存的是浮点数 `73.0`。在常见数值范围内，较小整数可以被 `double` 精确表示；特别大的 64 位整数则可能在转换时发生舍入。

反过来，把 `double` 保存进整数类型时，小数部分会向 $0$ 的方向截去：

```cpp
double positive = 3.9;
double negative = -3.9;

int a = positive;
int b = negative;
```

`a` 得到 `3`，`b` 得到 `-3`。这不是四舍五入。若需要按照题意向下取整、向上取整或四舍五入，应使用相应的数学函数，而不是依赖整数转换。

> 只有结果能够由目标整数类型表示时，浮点数转整数才安全。超出范围的转换不应尝试；它不会替你自动限制在最大值或最小值。

赋值只转换右边这一次产生的值，不会改变右边变量本身的类型：

```cpp
double x = 2.75;
int y = x;
```

执行后，`y` 是 `2`，`x` 仍然是 `double`，值仍然是 `2.75`。

## 运算先决定结果类型

运算符先查看操作数的类型，再决定使用哪种运算。

两个整数相除，执行整数除法：

```cpp
int a = 5;
int b = 2;
int quotient = a / b;
```

`quotient` 是 `2`。即使最后把结果保存进 `double`，除法本身仍然先由两个 `int` 完成：

```cpp
double wrong_average = a / b;
```

程序先算出整数 `2`，随后才把它转换成 `double`，所以 `wrong_average` 是 `2.0`，丢失的小数部分不会回来。

要执行浮点除法，必须在除法发生之前让至少一个操作数成为浮点数。竞赛代码最常用浮点字面量 `1.0` 引入这次转换：

```cpp
double correct_average = 1.0 * a / b;
```

`1.0` 是 `double`，所以乘法先把 `a` 转换成 `double`，得到的乘积也是 `double`。它再与 `b` 相除时，`b` 也会转换成 `double`，最终得到 `2.5`。

## 混合算术的共同类型

一个常见的简化理解是：

- 两边都是普通整数类型时，进行整数运算；
- 一边是 `double`、另一边是整数时，整数先转换成 `double`，再进行浮点运算；
- 一边是 `float`、另一边是整数时，整数转换成 `float`；
- `char`、`bool` 和 `short` 参与普通整数算术时，通常先提升为 `int`。

例如：

```cpp
double x = 2.5;
int y = 4;
double sum = x + y;
```

`y` 先转换为 `double`，所以结果是 `double` 类型的 `6.5`。

字符也能参加整数运算：

```cpp
char digit = '7';
int value = digit - '0';
```

两个 `char` 都先提升成字符编号对应的 `int`，相减得到整数 `7`。[字符类型](character-types.md) 已经解释了为什么同一份字符数据既能显示为字符，也能参与整数运算。

## bool 与其他类型

整数转换成 `bool` 时，`0` 变成 `false`，其他值都变成 `true`：

```cpp
bool a = 0;
bool b = -7;
```

`a` 是 `false`，`b` 是 `true`。反过来，`false` 转换成整数是 `0`，`true` 转换成整数是 `1`。

在主流竞赛环境中，`sizeof(bool)` 通常是 `1`，也就是一个字节；这不表示它能保存 $256$ 种数值。`bool` 只携带一位真假信息，存储到其中的整数最终仍然只会变成 `false` 或 `true`。

虽然这些规则允许把整数直接写进条件，但表达真正含义的比较通常更清楚：

```cpp
if (count != 0) {
    cout << "nonzero\n";
}
```

这比 `if (count)` 更明确地说明程序关心的是“数量不为零”。对于本身就是 `bool` 的 `visited`，则直接写 `if (visited)` 最自然。

## 显式转换

需要明确指定目标类型时，竞赛代码常把目标类型写在值前面的圆括号中：

```cpp
double x = (double)a;
int y = (int)3.9;
int code = (int)'A';
```

上面三行分别得到浮点数 `a`、整数 `3` 和字符 `'A'` 的编号。这种写法表示“程序员有意在这里改变类型”，不要在没有必要时到处添加。

显式转换也常被称为**强制类型转换**。这个名称不表示转换一定安全：目标类型无法保留全部信息时，显式写出转换仍然会丢失信息。

整数除法也可以这样提前转换一个操作数：

```cpp
double average = (double)sum / count;
```

不过只为了进入浮点运算时，本书优先使用更常见也更直观的 `1.0 * sum / count`。

## 窄化会丢失信息

若目标类型不能保留源值的全部信息，这次转换称为**窄化转换**。常见情况包括：

- `double` 转为整数时丢掉小数部分；
- 较大的整数转为较小整数类型时可能超出范围；
- 很大的整数转为浮点数时可能丢失末尾精度。

下面的写法虽然能编译，但应当先确认丢失小数确实符合题意：

```cpp
double distance = 12.8;
int whole_distance = (int)distance;
```

`whole_distance` 是 `12`。如果题目要的是向上取整到 `13`，这次转换就不是正确算法。

花括号初始化会主动拒绝许多明显的窄化转换：

```cpp
int x{3.9};
```

这段代码无法通过编译。初学阶段若希望编译器帮助发现意外精度损失，可以优先使用花括号初始化；若确实要截去小数，则用 `(int)distance` 明确表达。

## 有符号与无符号混合

有符号整数与无符号整数共同运算或比较时，会按照类型范围和等级选择共同类型，结果可能违背直觉。最典型的同宽例子是：

```cpp
int a = -1;
unsigned int b = 1;
bool smaller = a < b;
```

在常见的 32 位 `int` 环境中，`a` 会转换成很大的 `unsigned int`，所以 `smaller` 是 `false`。

不要为了消除编译警告随意把负数转换成无符号类型。更可靠的办法是从题目范围出发，让需要共同比较的量一开始就采用能够表达全部合法值的统一类型。涉及容器长度的 `size_t` 会在学习相应容器时结合实际代码说明。

不同宽度的有符号与无符号类型还有更细的共同类型规则，本篇不要求背诵。需要记住的是：混用会发生自动转换，负数尤其危险。

## 完整代码

输入整数总分 `sum` 和正整数人数 `count`，输出平均分，保留两位小数。

若直接计算 `sum / count`，小数部分会在赋值给 `double` 之前丢失。因此先让浮点字面量 `1.0` 参与计算：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int sum;
    int count;
    cin >> sum >> count;

    double average = 1.0 * sum / count;
    cout << fixed << setprecision(2) << average << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
5 2
```

输出：

```text
2.50
```

若把核心一行误写为：

```cpp
double average = sum / count;
```

同一组输入会输出 `2.00`。目标变量是 `double` 并不能改变右边已经完成的整数除法。

## 常见错误

### 在整数除法之后才转换

`(double)(a / b)` 会先执行整数除法，再转换已经截断的结果。应让浮点数在除法前参与运算，例如 `1.0 * a / b`。

### 把浮点转整数当成四舍五入

转换只向 $0$ 截去小数部分。需要哪一种取整方式，应根据题意选择对应算法。

### 以为转换会修改原变量

表达式中的转换产生一个供当前运算使用的值。除非随后赋值回原变量，否则原变量的类型和值不会改变。

### 随意混合有符号与无符号整数

自动转换可能把负数变成很大的无符号数。先统一数据的语义和合法范围，再选择类型。

## 需要记住什么

1. 隐式转换与显式转换分别由谁发起？
2. `double x = 5 / 2;` 中，除法按整数还是浮点数计算？最终 `x` 是多少？
3. 怎样在除法发生之前把一个操作数转换成 `double`？
4. `(int)3.9` 和 `(int)-3.9` 分别得到什么？这是四舍五入吗？
5. `char` 和 `short` 参与普通整数算术时通常先提升成什么类型？
6. 整数 `0` 和非零整数转换成 `bool` 时分别得到什么？
7. 什么是窄化转换？花括号初始化怎样帮助发现它？
8. 为什么负数与无符号整数混合比较可能得到反直觉结果？

完整的整数提升等级、所有浮点类型组合和每一种越界转换规则不要求记忆。当前需要做到的是：先判断运算将采用整数还是浮点数，再在丢失信息确实符合题意时明确转换。

# 移位运算

> 最近修订：2026-08-16 20:40 +10:00（未审阅）

二进制数每向左移动一位，各个 `1` 的位权都会乘以 $2$；每向右移动一位，最低位会
被移出，其余位的位权除以 $2$。C++ 使用 `<<` 和 `>>` 表示这两种移位。

移位不只是乘除 $2$ 的缩写。它还能把最低位的 `1` 移到指定位置，从而连接
[按位运算](bitwise-operators.md) 与“查询或修改第 $k$ 位”的实际操作。

## 左移

表达式 `x << k` 把 `x` 的二进制位向左移动 $k$ 位，右侧空出的位置补 `0`：

```text
00001101 << 2
00110100
```

若 `x` 是非负整数，而且数学结果能够由当前类型表示，左移 $k$ 位相当于乘以
$2^k$：

```cpp
unsigned int result = x << k;
```

“能够表示”是必要条件。固定宽度整数左侧移出的高位无法保留；有符号整数左移到
不可表示范围还可能产生未定义行为。因此，普通乘法问题优先写乘法，位模式问题优先
使用无符号整数表达。

## 右移

对无符号整数，`x >> k` 把二进制位向右移动 $k$ 位，左侧补 `0`：

```text
00110101 >> 2
00001101
```

它等价于对非负整数做向下取整的除法：

$$
x\mathbin{\texttt{>>}}k=\left\lfloor\frac{x}{2^k}\right\rfloor.
$$

被移出的是最低的 $k$ 位，它们相当于除法中的余数。

负有符号整数的规则不同。在 C++17 中，负数右移的结果由实现决定；竞赛中要处理
明确位模式时，统一使用无符号整数，不依赖平台怎样补左侧高位。

## 构造单个位掩码

无符号整数 `1u` 只有最低位为 `1`。把它左移 $k$ 位，就能得到只有第 $k$ 位为 `1`
的掩码：

```cpp
unsigned int bit = 1u << k;
```

例如 $k=3$ 时：

```text
00000001 << 3
00001000
```

得到 `bit` 以后，就能把[按位运算](bitwise-operators.md)应用到一个准确位置：

```cpp
bool enabled = (mask & bit) != 0;
mask |= bit;
mask &= ~bit;
mask ^= bit;
```

四行依次表示查询、设为 `1`、清为 `0` 和翻转第 $k$ 位。实际程序通常只选择题目
需要的一项，不会连续修改同一个 `mask` 四次。

## 左操作数决定宽度

移位运算先根据左操作数的类型执行，结果变量的类型不能反过来扩大这次运算：

```cpp
long long bit = 1 << k;
```

右侧的 `1` 是 `int`，所以 `1 << k` 先按常见的 32 位整数计算，完成以后才保存进
`long long`。若 $k$ 较大，问题已经在赋值前发生。

已知只需要 64 位整数的非负数值，而且 $0\leq k<63$ 时，可以写：

```cpp
long long power = 1LL << k;
```

需要把全部 64 位当作位模式时，使用无符号左操作数：

```cpp
unsigned long long bit = 1ULL << k;
```

`LL` 和 `ULL` 的作用发生在移位**以前**。把结果变量改成 64 位整数，却仍写
`1 << k`，不能达到同样效果。

## 移位位数的范围

移动位数必须满足两个条件：

1. `k` 不能是负数；
2. `k` 必须严格小于左操作数类型的位数。

在常见的 32 位 `unsigned int` 中，`1u << k` 要求 $0\leq k<32$；在常见的 64 位
`unsigned long long` 中，`1ULL << k` 要求 $0\leq k<64$。移动恰好等于类型宽度
也不合法。

可以用 `numeric_limits` 查询类型中的二进制数值位数：

```cpp
int width = numeric_limits<unsigned int>::digits;
```

竞赛题通常会直接保证位编号范围，正文和模板仍应在接口说明中写清楚这一前提。

## 无符号整数的成环

假设无符号类型有 $N$ 个二进制位，它的算术结果按 $2^N$ 取模。左移无符号整数时，
超出宽度的高位被丢弃，留下的位模式与乘以 $2^k$ 后按 $2^N$ 取模一致。

这条规则是无符号整数的正式语义，不应推广成“所有整数溢出都会成环”。有符号整数
的算术溢出是未定义行为；有符号左移也需要单独满足标准规定的范围。

## 运算符优先级

加减法的优先级高于移位，所以：

```cpp
1ULL << k + 1
```

会被理解成：

```cpp
1ULL << (k + 1)
```

按位运算与比较混合时也存在不同层级。与其背完整优先级表，不如用括号把位掩码的
生成和查询边界明确写出：

```cpp
bool enabled = (mask & (1u << k)) != 0;
```

输出语句中的 `cout << value` 使用了同一个 `<<` 符号，但这里的左操作数是输出流，
C++ 为它定义的是“把内容送入输出流”，不是整数移位。

## 完整代码

输入非负整数 `mask` 和位编号 `k`，保证 `unsigned int` 在当前环境中为 32 位，并且
$0\leq k<32$。程序分别从原始 `mask` 出发，查询、设置、清除和翻转第 $k$ 位。

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    unsigned int mask;
    int k;
    cin >> mask >> k;

    unsigned int bit = 1u << k;

    bool enabled = (mask & bit) != 0;
    unsigned int set_mask = mask | bit;
    unsigned int cleared_mask = mask & ~bit;
    unsigned int toggled_mask = mask ^ bit;

    cout << enabled << '\n';
    cout << set_mask << '\n';
    cout << cleared_mask << '\n';
    cout << toggled_mask << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
10 2
```

$10=(1010)_2$，第 $2$ 位原来是 `0`。输出：

```text
0
14
10
14
```

把第 $2$ 位设为 `1` 或翻转后，结果都是 $(1110)_2=14$；清除一个原本就是 `0` 的
位置不会改变 `mask`。这些固定宽度整数操作的时间和额外空间都视为 $O(1)$。

## 常见错误

### 先用 int 移位，再保存进 64 位整数

```cpp
long long bit = 1 << k;
```

需要更宽的左操作数时，应从 `1LL` 或 `1ULL` 开始，不能依赖赋值目标补救。

### 移动超过类型宽度

负的移动位数，或大于等于左操作数类型位数的移动，都会产生未定义行为。

### 把左移无条件当成乘法

只有在符号与表示范围满足条件时，左移才对应普通整数乘法。题目只是计算 $x\times
2^k$ 时，直接乘法通常更能表达意图；位掩码才是移位的核心场景。

### 依赖负数右移

C++17 没有统一规定负有符号整数右移怎样补高位。需要确定的位模式时改用无符号
整数，并先明确题目的数学语义。

# 内存：竞赛程序的常见分区

> 最近修订：2026-08-13 04:07 +10:00（未审阅）

竞赛代码中常见一个很直接的现象：同样大的数组，声明在函数内可能导致运行时错误，移到函数外却能正常使用。数组元素没有变，变化的是对象使用了哪类存储。

要理解这个现象，需要把两层规则分开：

- C++ 规定对象何时存在，例如自动存储期、静态存储期和动态存储期；
- 编译器、操作系统和运行环境通常把它们安排到代码区、全局与静态数据区、栈和堆等区域。

第一层才是 C++ 语言保证。第二层是主流竞赛环境中非常稳定的实现模型，能解释常见错误，但不应当被误写成 C++ 对具体地址的承诺。

## 常见区域

竞赛中常用下列模型理解一个正在运行的程序：

| 常见名称 | 主要保存什么 | 典型特点 |
| --- | --- | --- |
| 代码区 | 编译后的机器指令 | 通常不允许程序当作普通数据修改 |
| 全局与静态数据区 | 全局对象、`static` 局部对象等 | 在整个程序运行期间存在 |
| 栈 | 函数参数、普通局部对象和调用状态 | 随函数调用自动建立和撤销，容量通常较小 |
| 堆 | 运行时申请的动态存储 | 容量通常比栈大，存在时间不由当前函数返回直接决定 |

这张表表达用途，不表达固定的地址顺序。有些图把栈画在高地址、堆画在低地址，并用相反箭头表示它们的常见增长方向；这是某些系统的常见布局，不是本篇需要依赖的规则。

## 代码与只读数据

源代码会被编译成机器指令，运行时通常被加载到代码区，也常称为 text segment。函数名称、局部变量名称和注释不会原样变成运行时数据；编译器会把程序的行为翻译成指令。

字符串字面量和部分只读常量通常放在只读数据中。例如：

```cpp
printf("Hello\n");
```

其中 `"Hello\n"` 需要有存储位置，但程序不应当修改字符串字面量。

编译器还可以把某个常量直接合并进指令，甚至完全消除一个没有必要实际存储的对象。因此，“`const` 就一定放在某个只读分区”也不是 C++ 的通用规则。

## 全局与静态对象

函数外声明的全局对象具有静态存储期，从程序开始一直存在到程序结束：

```cpp
int initialized = 3;
int zero_initialized;
```

[变量：static 局部变量](static-local-variables.md) 中的对象也具有静态存储期：

```cpp
void solve() {
    static int remembered = 5;
}
```

`remembered` 的名称只在 `solve()` 内可见，但对象不会在 `solve()` 返回时销毁。因此它通常与全局对象位于同一类静态数据区，而不是调用栈。

常见可执行文件会再把这类数据分成：

- 已经具有非零初值的数据，通常放在已初始化数据段；
- 零初始化或没有显式初值的数据，通常放在 BSS。

BSS 不需要在可执行文件中重复写下每一个零；加载程序时，运行环境为这块存储提供零初值。但它在程序运行后仍然真实占用内存，不是“免费空间”。

竞赛中的大型内置数组若必须使用固定容量，通常声明在全局作用域：

```cpp
const int MAXN = 2e6 + 5;
int a[MAXN];
```

它不会占用某一次函数调用的栈空间，而且程序开始时已经全部零初始化。这解释了为什么传统竞赛模板常把大型静态数组放在全局作用域。

## 调用栈

普通局部对象具有自动存储期：执行进入它所在的代码块时建立，离开代码块时销毁。主流竞赛环境通常用调用栈保存函数参数、返回所需状态和需要实际存储的普通局部对象。

```cpp
void solve() {
    int local = 7;
    int small[100];
}
```

`local` 和 `small` 通常属于本次 `solve()` 调用的栈帧。函数返回后，这次调用的存储也随之撤销。

栈容量通常明显小于程序的总内存限制。若在函数内声明数百万个 `int`，单次调用就可能耗尽栈空间：

```cpp
void solve() {
    int a[2000005]; // 在某些竞赛环境中可能导致栈溢出
}
```

具体上限由操作系统、OJ 和启动方式决定，不要背诵一个固定字节数。看到程序“内存限制还很宽松却立即运行时错误”时，检查大型局部对象和过深递归是很有价值的第一步。

编译器可以把小型局部变量保留在寄存器中，直接把常量结果算出，或完全消除无用对象。因此“普通局部变量通常由栈支持”是实用模型，不是说每个源代码变量都必须占用一个可见的栈地址。

## 动态存储与堆

对象也可以在运行时申请动态存储。在主流环境中，这类存储通常来自堆。

```cpp
int* value = new int(13);
printf("%d\n", *value);
delete value;
```

`new int(13)` 申请能保存一个 `int` 的动态存储，用 `13` 初始化对象，再返回指向它的指针。`value` 这个指针变量自己是普通局部变量，通常由栈支持；它指向的 `int` 对象才使用动态存储。

`delete value` 销毁该对象并释放这段存储。若指针变量离开作用域，它指向的动态对象并不会因此自动释放。手写 `new` / `delete` 不是本书竞赛模板的默认存储方式；这里只用一个对象说清“局部指针”和“动态对象”位于不同类存储中。

后续学习 `vector` 后，竞赛代码通常由容器自动管理动态存储：

```cpp
void solve() {
    vector<int> a(2000005);
}
```

`a` 这个 `vector` 对象是局部对象，但数百万个元素使用容器管理的动态存储，不会把整个元素区域放入当前调用栈。函数结束时，`vector` 会自动释放自己管理的存储。具体接口在 [序列容器：vector（正文待写）](../CATALOG.md#01-c-基础) 中学习；当前只需知道它为什么能避免大型局部内置数组的栈压力。

## 声明与存储的对应

| 源代码形式 | C++ 存储期 | 常见存储区域 | 离开当前函数后 |
| --- | --- | --- | --- |
| 函数外 `int a;` | 静态 | BSS 或静态数据区 | 继续存在 |
| 函数外 `int a = 3;` | 静态 | 已初始化数据段 | 继续存在 |
| 函数内 `static int a;` | 静态 | BSS 或静态数据区 | 继续存在 |
| 函数内 `int a;` | 自动 | 通常是栈或寄存器 | 对象销毁 |
| `new int` 创建的对象 | 动态 | 通常是堆 | 不会仅因函数返回而释放 |
| 局部 `vector` 的元素 | 由容器管理的动态存储 | 通常是堆 | 容器销毁时自动释放 |

一个对象的名称在哪里可见，仍由作用域决定。它使用哪类存储、存在多久，是另一条规则。因此 `static` 局部变量可以同时“名称只在函数内可见”和“对象在整个程序期间存在”，两者并不矛盾。

## 完整代码

下面的程序同时使用全局对象、`static` 局部对象、普通局部对象和动态对象。程序只计算它们的值，不输出具体地址：地址会因编译器、系统和每次运行而改变，也不能证明 C++ 必须采用某一种分区顺序。

```cpp
#include <bits/stdc++.h>
using namespace std;

int initialized = 3;
int zero_initialized;

void solve() {
    static int remembered = 5;
    int local = 7;
    int* dynamic = new int(13);

    int sum = initialized + zero_initialized + remembered + local + *dynamic;
    printf("%d\n", sum);

    delete dynamic;
}

int main() {
    solve();
    return 0;
}
```

输出：

```text
28
```

`zero_initialized` 在程序开始时被零初始化，因此结果是 $3+0+5+7+13=28$。

## 常见错误

### 把所有局部变量都当成栈上的固定地址

编译器可以使用寄存器、常量传播或死代码消除。“局部对象通常由栈支持”用来分析容量和调用关系，不是对每个变量地址的语言承诺。

### 认为全局数组不计入内存

BSS 可以避免在可执行文件里存一大片零，但程序运行时仍需要真实存储。全局数组不占调用栈，不等于不占内存。

### 认为内存限制足够就不会栈溢出

调用栈常有自己的较小上限。大型局部内置数组和过深递归可以在总内存尚未耗尽时先用尽栈。

### 以为指针离开作用域会释放动态对象

指针和它指向的对象是两个不同对象。手写 `new` 时必须与合适的 `delete` 配对；竞赛中优先让 `vector` 等标准库容器管理大块动态存储。

1. C++ 的存储期规则与操作系统的常见内存分区有什么区别？
2. 代码区、全局与静态数据区、栈和堆分别主要保存什么？
3. 全局变量与 `static` 局部变量的名称作用域是否相同？它们的存储期呢？
4. BSS 为什么能减少可执行文件中重复的零？它在运行时是否占用内存？
5. 为什么大型局部内置数组可能在总内存限制仍足够时导致运行时错误？
6. 局部指针变量和它通过 `new` 指向的对象是否使用同一类存储？
7. 为什么局部 `vector` 可以保存大量元素，而不把全部元素放在调用栈？
8. 为什么不应当背诵各区的固定地址顺序、栈的固定容量或每个局部变量的实际位置？

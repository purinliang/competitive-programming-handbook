# 对象生命周期

> 最近修订：2026-08-16 14:54 +10:00（未审阅）

一个名字在当前代码中看不见，不一定表示对应对象已经消失；一个指针仍然保存某个
地址，也不一定表示那个地址中的对象还活着。要判断代码能否安全访问数据，需要
区分三件事：

- **作用域**：一个名称能在源代码的哪些位置被直接查找到；
- **存储期**：保存对象的存储维持多久；
- **生命周期**：某个具体对象从开始存在到结束存在的时间。

三者彼此相关，但不是同一条规则。尤其不能把 `static` 局部对象称为“局部作用域
的全局变量”：它拥有局部名称作用域，却拥有静态存储期。

## 生命周期的开始与结束

对本书常见对象，可以先用下面的直觉理解：

1. 程序为对象取得满足大小和对齐要求的存储；
2. 对象完成规定的初始化，生命周期开始；
3. 程序在生命周期内按照类型规则使用对象；
4. 对象被销毁，或其存储被释放、重新用于其他对象，生命周期结束。

类对象的构造与析构让这两个边界最容易观察。基本类型没有用户可见的构造函数体，
仍然具有自己的生命周期。

存储里存在一些字节，不等于某个类型的对象已经在那里开始生命周期。放置 `new`、
联合体复杂成员切换等底层规则会精确控制这一点，但不属于竞赛主线。

## 自动存储期

普通块作用域局部对象通常拥有**自动存储期**：执行进入声明并完成初始化时建立，
离开所在作用域时自动销毁。

```cpp
void work() {
    int value = 5;
}
```

每次调用 `work` 都建立一个新的 `value` 对象；函数返回后，该次调用的对象生命
周期结束。下一次调用得到的是另一个对象，不会自动保留旧值。

类类型局部对象离开作用域时会运行析构过程。`return`、`break` 或异常等控制流只要
确实离开对象所在作用域，也要处理已经完整构造的自动对象。

## 静态存储期

全局对象、命名空间作用域的静态对象，以及 `static` 局部对象拥有**静态存储期**。
它们的存储贯穿整个程序执行期，只建立一次。

```cpp
int next_id() {
    static int id = 0;
    id++;
    return id;
}
```

名称 `id` 只在 `next_id` 函数块中可见，因此作用域是局部的；对象却不会在函数
返回时销毁，下一次调用继续使用同一个值。具体规则见
[static 局部变量](static-local-variables.md)。

函数内静态对象第一次执行到声明时初始化。程序正常结束时，它会按静态对象规则
销毁。不同翻译单元中的静态对象初始化与销毁顺序可能更复杂，竞赛单文件代码通常
无需依赖这种跨文件顺序。

## 动态存储期

`new` 表达式可以建立动态对象，其存储由对应的 `delete` 释放：

```cpp
int* pointer = new int(5);
cout << *pointer << '\n';
delete pointer;
```

动态对象不会因为保存地址的局部指针离开作用域就自动销毁：

```cpp
int* pointer = new int(5);
```

若函数直接返回，指针名字消失，动态对象却仍然存在，程序也失去了释放它的地址，
形成内存泄漏。

竞赛代码优先使用 `vector`、`string` 和其他自动管理动态存储的对象，不直接维护
`new` 与 `delete`。这些容器把动态资源的生命周期绑定到容器对象，离开作用域时
自动清理。

## 线程存储期

使用 `thread_local` 声明的对象具有**线程存储期**：每个线程拥有独立实例，实例
通常贯穿该线程的执行期。

```cpp
thread_local int counter = 0;
```

普通算法竞赛程序通常只有一个执行线程，不需要这种存储期。本篇列出它是为了说明
C++ 的存储期不只有“局部、全局、动态”三类，不要求掌握线程初始化细节。

## 作用域与生命周期

局部名称在块外不可见，但对象可能仍存在：

```cpp
int* pointer;

{
    static int value = 5;
    pointer = &value;
}

cout << *pointer << '\n';
```

块外不能再直接写名字 `value`，但静态对象仍在，因此这次通过保存的地址访问仍然
有效。

反过来，指针名字仍然可见，对象却可能已经结束：

```cpp
int* pointer;

{
    int value = 5;
    pointer = &value;
}

cout << *pointer << '\n';
```

内层块结束后，自动对象 `value` 的生命周期已经结束。`pointer` 成为悬空指针，
解引用属于未定义行为。地址数值尚未从指针中消失，并不能延长目标对象寿命。

## 引用不会延长普通目标的寿命

引用只是既有对象的别名。若目标先结束，引用同样悬空：

```cpp
int& bad_reference() {
    int value = 5;
    return value;
}
```

函数返回时 `value` 被销毁，返回的引用不能使用。返回局部对象的**值**则通常安全，
因为结果对象通过复制、移动或复制消除建立在调用方：

```cpp
int good_value() {
    int value = 5;
    return value;
}
```

C++ 对某些临时对象绑定到引用的表达式提供专门的生命周期延长规则，但规则依赖
初始化形式，不能概括成“引用总会延长对象寿命”。竞赛代码不要返回局部变量引用，
需要拥有结果时直接返回值。

## 容器与失效

`vector` 扩容时可能在新存储中重新建立元素，并结束旧元素对象的生命周期。因此
原来指向元素的指针、引用和迭代器不能继续使用：

```cpp
vector<int> values;
values.push_back(1);

int* pointer = &values[0];
values.push_back(2);

// pointer 可能已经悬空
```

问题不只是“地址可能改变”，而是原存储中的元素对象已经被搬到新位置并销毁。
需要继续定位元素时，在可能扩容的操作以后重新取得引用或下标；能预知容量时也可
先调用 `reserve` 减少重新分配，但仍要遵守真实失效规则。

## RAII 与拥有关系

对象拥有资源时，构造函数取得资源，析构函数归还资源，可以让资源寿命跟随对象
寿命。这就是 [析构函数](destructors.md) 中介绍的 RAII。

要判断一个地址是否安全，关键问题不是“这个指针变量还在不在”，而是：

1. 谁拥有目标对象？
2. 目标对象的生命周期是否仍在进行？
3. 中间操作是否让容器重新分配或用新对象复用了存储？

明确拥有关系比手动在多个地方猜测何时 `delete` 更可靠。

## 完整代码

下面对比普通局部对象与 `static` 局部对象在两次调用之间的状态：

```cpp
#include <bits/stdc++.h>
using namespace std;

void show() {
    int local = 0;
    static int persistent = 0;

    local++;
    persistent++;

    cout << local << ' ' << persistent << '\n';
}

void solve() {
    show();
    show();
}

int main() {
    solve();
    return 0;
}
```

输出：

```text
1 1
1 2
```

每次调用都建立新的 `local`，所以它总从零开始；`persistent` 只初始化一次，并在
函数返回以后继续存在。

## 常见错误

### 用作用域判断对象是否存在

作用域只决定名称可见性。静态局部对象的名字在函数外不可见，对象仍持续存在。

### 用地址数值判断对象是否仍然有效

生命周期结束后，保存旧地址的指针会悬空。内存尚未被覆盖不代表可以访问。

### 返回局部对象的指针或引用

自动局部对象随函数返回销毁。需要结果时返回值，或让调用者拥有对象。

### 忘记容器操作可能结束旧元素生命周期

`vector` 重新分配后，旧元素的指针、引用和迭代器失效。不要继续使用缓存地址。

### 把 static 局部对象叫作全局变量

它拥有静态存储期，但名称仍在局部作用域。作用域和存储期必须分别描述。

## 需要记住什么

1. 作用域、存储期和生命周期分别回答什么问题？
2. 自动局部对象通常在什么时候开始和结束生命周期？
3. `static` 局部对象为什么能跨函数调用保留状态，却仍不是全局名称？
4. 动态对象为什么不会随保存地址的局部指针一起自动销毁？
5. 指针仍保存地址时，目标对象是否一定还活着？
6. 为什么不能返回自动局部变量的引用？
7. `vector` 重新分配后，旧元素指针为什么失效？
8. RAII 怎样把资源寿命绑定到对象寿命？

# 复合赋值运算符

> 最近修订：2026-08-16 07:51 +10:00（未审阅）

变量经常需要根据自己的旧值更新。例如，把新得分加入总分，可以写成：

```cpp
total = total + score;
```

这行代码先读取 `total` 的旧值，计算它与 `score` 的和，再把结果写回同一个变量。C++ 使用**复合赋值运算符**把这种“运算后写回”的结构直接表达出来。

## 算术复合赋值

五种二元算术运算都提供对应的复合赋值写法：

| 写法 | 对简单变量的含义 |
| --- | --- |
| `x += y` | `x = x + y` |
| `x -= y` | `x = x - y` |
| `x *= y` | `x = x * y` |
| `x /= y` | `x = x / y` |
| `x %= y` | `x = x % y` |

例如：

```cpp
int score = 10;

score += 5; // 15
score -= 3; // 12
score *= 2; // 24
score /= 4; // 6
score %= 4; // 2
```

每一行都会修改左侧变量。右侧可以是字面量、变量或其他表达式：

```cpp
sum += value;
remaining -= used;
answer *= base + 1;
```

## 先读旧值再写回

复合赋值不是变量初始化。左侧变量必须已经存在，而且它的旧值会参与计算：

```cpp
int sum = 0;
sum += 7;
sum += 4;
```

执行过程是：

```text
初值：0
加入 7：0 + 7 = 7
加入 4：7 + 4 = 11
```

如果忘记给局部变量初值：

```cpp
int sum;
sum += 7;
```

`sum += 7` 会先读取尚未初始化的 `sum`，导致未定义行为。求和通常从 `0` 初始化，求积通常从 `1` 初始化：

```cpp
int sum = 0;
int product = 1;
```

初值必须由变量的真实含义决定，不能看见复合赋值就机械地全部写成 `0`。

## 与自增自减的关系

只增加或减少 $1$ 时，可以使用 [自增与自减运算符](increment-decrement-operators.md)：

```cpp
count++;
remaining--;
```

需要改变其他数量时，复合赋值更直接：

```cpp
count += 3;
remaining -= used;
```

`count++` 与 `count += 1` 单独成句时都会让 `count` 加 $1$。本书在普通计数循环中使用 `i++`，在累计任意数值时使用 `sum += value`。

## 运算规则不会改变

复合赋值仍然使用原本的算术运算规则：

- 整数 `x /= y` 仍然执行向 $0$ 截断的整数除法；
- `x /= 0` 和 `x %= 0` 仍然是未定义行为；
- 结果超出整数类型范围时，复合写法不会自动扩大类型；
- 目标类型无法保存全部结果时，仍然可能发生转换和信息丢失。

因此，复合赋值只是更准确地表达“更新同一个变量”，不是另一套更安全的算术。

对简单变量 `x`，可以把 `x += y` 理解为 `x = x + y`。严格来说，复合赋值不是源码的文本替换：左侧表达式只会求值一次。基础代码应让左侧保持简单，不把自增、函数调用或其他副作用藏在其中。

## 完整代码

输入三轮得分，使用复合赋值依次累加并输出总分：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int first;
    int second;
    int third;
    cin >> first >> second >> third;

    int total = 0;
    total += first;
    total += second;
    total += third;

    cout << total << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
12 8 15
```

输出：

```text
35
```

## 常见错误

### 把复合赋值当成初始化

`sum += x` 需要读取 `sum` 的旧值。第一次累计以前，必须先给 `sum` 一个有意义的初值。

### 颠倒左右含义

`x -= y` 表示从 `x` 中减去 `y` 并写回 `x`，不是计算 `y - x`。除法和取余同样有明确方向。

### 以为复合写法会保护范围

`x *= y` 与普通乘法面对相同的溢出风险。应根据题目范围选择类型，而不是依赖运算符写得更短。

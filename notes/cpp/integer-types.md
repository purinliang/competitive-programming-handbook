# 基本类型：整数

> 状态：定稿

[入门：A+B Problem](a-plus-b-problem.md) 第一次使用了 `int`。它是竞赛中最常用的整数类型，也是理解其他整数类型的起点。

## int

### 位与字节

计算机用只有 `0` 和 `1` 的二进制位保存数据。一个这样的 `0` 或 `1` 称为一个**位**，英文是 bit。

现代竞赛环境中，一个**字节**（byte）通常由 8 位组成。`int` 通常占用 4 字节，因此共有

$$
4 \times 8 = 32
$$

位，也称为 **32 位整数**。

`sizeof` 可以查看一个类型占用多少字节，`CHAR_BIT` 表示当前环境中一个字节包含多少位：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    cout << sizeof(int) << '\n';
    cout << sizeof(int) * CHAR_BIT << '\n';
}

int main() {
    solve();
    return 0;
}
```

在常见的 Linux 竞赛环境中，输出为：

```text
4
32
```

> C++17 只保证一个字节由若干连续的位组成，具体位数由实现决定；`int` 也只保证至少能表示 16 位整数。一个字节等于 8 位、`int` 等于 4 字节，是现代桌面、服务器和主流竞赛环境中的事实标准，而不是所有 C++17 实现都必须遵守的规定。可以参见 [C++17 内存模型](https://timsong-cpp.github.io/cppwp/n4659/intro.memory) 与 [C++17 基本类型](https://timsong-cpp.github.io/cppwp/n4659/basic.fundamental)。

位、字节、更大的存储单位以及网络带宽中的 `Mbps` 统一放在 [基础：位、字节与存储单位](bits-bytes-and-storage-units.md) 中。本篇只使用结论：主流竞赛环境中 1 字节等于 8 位。

### 整数字面量

直接写在源代码中的整数称为**整数字面量**。同一个数可以用不同进制书写；前缀告诉编译器应该使用哪一种进制：

| 进制 | 可用数字 | 源码前缀 | 十进制 42 的写法 |
| --- | --- | --- | --- |
| 二进制 | `0`、`1` | `0b` 或 `0B` | `0b101010` |
| 八进制 | `0` 到 `7` | 一个前导 `0` | `052` |
| 十进制 | `0` 到 `9` | 无 | `42` |
| 十六进制 | `0` 到 `9`、`a` 到 `f` | `0x` 或 `0X` | `0x2a` |

下面四个变量保存的值完全相同：

```cpp
int bin_value = 0B101010;
int oct_value = 052;
int dec_value = 42;
int hex_value = 0x2a;

cout << bin_value << ' ' << oct_value << ' ' << dec_value << ' ' << hex_value << '\n';
```

这里没有直接使用 `oct`、`dec` 和 `hex` 作为变量名，因为它们已经是 `cin`、`cout` 的进制控制名称；统一增加 `_value` 可以避免遮蔽和混淆。前缀中的 `B`、`X` 以及十六进制数字 `A` 到 `F` 都可以大写或小写。

输出为：

```text
42 42 42 42
```

进制前缀只决定编译器怎样解释源码中的数字，不会成为变量的一部分。需要特别留意八进制：源码中的 `010` 表示十进制的 `8`，不是十进制的 `10`；八进制中也不能出现 `8` 或 `9`。

以上规则由 [C++17 整数字面量](https://timsong-cpp.github.io/cppwp/n4659/lex.literal) 规定。竞赛中需要记住 `0b` 和 `0x`；前导 `0` 的八进制需要能够辨认，但应尽量避免用它书写普通整数，以免误读。

### 进制输入与输出

写在输入文件里的 `0x10` 只是一串字符，不再是源代码。输入函数是否识别前缀，取决于使用的读取规则：

| 方式 | 默认规则 | 自动识别十、八、十六进制 | 固定进制 |
| --- | --- | --- | --- |
| `cin` | 十进制 | `cin >> setbase(0) >> x` | `dec`、`oct`、`hex` |
| `scanf` | `%d` 读取十进制 | `%i` | `%d`、`%o`、`%x` |

下面的完整程序把两种方式放在一起，只用于比较它们的规则：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int a;
    int b;
    int c;

    cin >> dec >> a;
    cin >> setbase(0) >> b >> c;
    cout << "cin: " << a << ' ' << b << ' ' << c << '\n';

    scanf("%d %i %i", &a, &b, &c);
    printf("scanf: %d %d %d\n", a, b, c);
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
16 020 0x10
16 020 0x10
```

输出：

```text
cin: 16 16 16
scanf: 16 16 16
```

这个对比程序没有关闭 C 与 C++ 标准流之间的同步，所以可以依次使用 `cin` 和 `scanf`。正式解题时应选择其中一套输入方式，不要混用。`scanf` 中的 `&`、格式控制符和输入流同步会在各自的文章中解释，这里只需把程序当作可运行的对照实验。

`cout` 可以用 `dec`、`oct`、`hex` 选择十、八、十六进制输出；`printf` 对应使用 `%d`、`%o`、`%x`。标准 C++17 的这两套接口都没有二进制输入输出格式；标准规定的自动识别方式也不包含 `0b`。如果题目给出二进制文本，通常把它作为字符串读取，再自行转换。

这段输入输出对照只用于辨析“源码字面量”和“输入文本”，不要求理解或记忆其中的控制方式。真正需要掌握的是源码中四种整数字面量的前缀。

### 二进制表示与取值范围

现代竞赛环境采用 32 位二进制补码保存 `int`，因此它的范围是

$$
[-2^{31},\ 2^{31}-1],
$$

也就是

```text
-2147483648 到 2147483647
```

原码、反码、补码的位模式、转换与范围差异放在配套篇 [基本类型：整数的二进制表示](signed-integer-representations.md) 中。它们会在部分基础课程或考试中出现，但不是使用 `int` 解题的前置。

### 有符号整数溢出

如果计算结果超出 `int` 的范围，就发生了**有符号整数溢出**。下面的程序把最大值手动写成十进制，再加 `1`：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int x = 2147483647;
    cout << x << '\n';
    x = x + 1;
    cout << x << '\n';
}

int main() {
    solve();
    return 0;
}
```

在许多主流竞赛环境中，这个简单程序通常表现为：

```text
2147483647
-2147483648
```

看起来就像数值越过最大值后绕回了最小值。

> **未定义行为（Undefined Behavior，UB）** 表示 C++17 标准不再规定程序必须怎样运行。编译器可以输出看似成环的结果，也可以基于“正确程序不会发生有符号溢出”这一假设改写或删除相关计算。因此，上面的程序只用于观察常见现象，正确代码不能依赖这个结果。 [C++17 表达式规则](https://timsong-cpp.github.io/cppwp/n4659/expr) 明确规定：数学结果不在类型可表示范围内时，行为未定义。

> 这里所说的“环境”主要包括目标处理器与 ABI、编译器及其版本、编译选项和优化级别。操作系统通常只是间接决定默认工具链与 ABI。x86-64 等主流处理器的整数加法指令会自然截断高位，但 C++ 编译器仍然按照“有符号溢出不会发生”进行优化，所以不能把硬件现象当成语言保证。

竞赛中不需要担心主流机器是否采用补码；真正需要做的是在计算前选择足够大的类型，避免有符号溢出。后文的 `long long` 就是最常用的选择。

## unsigned int

在 `int` 前加上 `unsigned`，就得到无符号整数类型 `unsigned int`，也可以简写为 `unsigned`。

常见竞赛环境中的 `unsigned int` 同样占 32 位，但没有负数。32 位都用于表示非负数，所以范围是

$$
0 \le x \le 2^{32}-1,
$$

也就是

```text
0 到 4294967295
```

无符号运算严格按照 $2^{32}$ 取模，因此成环是 C++17 明确保证的行为：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    unsigned int x = 0;
    cout << x << '\n';
    x = x - 1;
    cout << x << '\n';
}

int main() {
    solve();
    return 0;
}
```

输出为：

```text
0
4294967295
```

无符号整数的成环虽然确定，但减法和有符号、无符号混合比较很容易产生反直觉结果。竞赛中除非题目确实需要位模式或模 $2^N$ 运算，否则仍然优先使用有符号整数，并通过更大的类型避免溢出。

## long long

主流竞赛环境中的 `long long` 占 8 字节，也就是 64 位，范围为

$$
[-2^{63},\ 2^{63}-1],
$$

大约是 $-9.22 \times 10^{18}$ 到 $9.22 \times 10^{18}$。

普通下标和不超过约 $2 \times 10^9$ 的数通常使用 `int`；乘法、前缀和以及可能达到 $10^{18}$ 的答案通常使用 `long long`。选择足够大的类型，是避免有符号整数溢出的主要方法。

## 其他整数类型

C++ 还提供 `short` 和 `long`，但它们在不同平台上的位宽并不完全相同。竞赛中通常不需要 `short`，需要大范围时则直接使用大小更稳定的 `long long`。各平台的典型大小、完整范围、`int16_t`、`int32_t`、`int64_t` 和 `__int128` 统一放在配套篇 [基本类型：整数的位宽与平台差异](integer-type-widths.md) 中。

## 特殊整数类型

`bool` 和 `char` 在 C++ 的分类中也属于整数类型，但它们各自承担特殊职责，行为与普通整数不完全相同。

- `bool` 只表示 `false` 和 `true`。它没有 `signed bool`、`unsigned bool`、`short bool` 或 `long bool`。
- `char` 主要保存字符，但底层仍使用整数值。它恰好占 1 字节；这个字节有多少位由 `CHAR_BIT` 决定。主流竞赛环境的 `CHAR_BIT` 为 8，所以 `char` 占 8 位。
- `char`、`signed char` 和 `unsigned char` 是三个不同的类型。单独写 `char` 时，它是否能够表示负数由编译器和目标平台决定；程序不能依赖某一种默认结果。需要明确行为时直接写 `signed char` 或 `unsigned char`。

后续的“基本类型：布尔”和“基本类型：字符”会分别解释它们的具体行为；当前只需知道它们属于整数家族，却不应该当作普通 `int` 的缩小版使用。

# 整数类型

> 最近修订：2026-08-16 21:28 +10:00（未审阅）

[A+B Problem](a-plus-b-problem.md) 第一次使用了 `int`：

```cpp
int a = 3;
```

`int` 表示变量保存整数，`a` 是这个变量的名称，`3` 是写在源代码中的整数值。
本篇只解决竞赛中最先遇到的两个问题：一个整数能保存多大的数，以及什么时候应该
从 `int` 换成 `long long`。

## `int`

`int` 是竞赛中最常用的整数类型：

```cpp
int count = 0;
int score = 95;
int temperature = -7;
```

在主流竞赛环境中，`int` 是 32 位整数，取值范围是

$$
-2^{31}\leq x\leq2^{31}-1,
$$

也就是：

```text
-2147483648 到 2147483647
```

因此，题目中的人数、下标和不超过约 $2\times10^9$ 的普通整数通常可以使用
`int`。

> C++17 只保证 `int` 至少能表示 $-32767$ 到 $32767$，没有规定它必须是 32 位。
> 32 位 `int` 是现代桌面、服务器和主流竞赛环境中的事实标准。本书讨论竞赛代码时
> 使用这一常见环境，同时在涉及语言边界时区分标准保证与环境事实。

这里先把“32 位”理解成描述整数容量的常用说法。位、字节以及二进制机器表示会在
[进制表示](base-notation.md) 所在单元系统解释。

## `long long`

两个不超过 $10^9$ 的整数相乘，结果可能达到

$$
10^9\times10^9=10^{18},
$$

已经远远超过 `int` 的范围。这时应使用 `long long`：

```cpp
long long answer = 1000000000LL * 1000000000LL;
```

主流竞赛环境中的 `long long` 是 64 位整数，取值范围是

$$
-2^{63}\leq x\leq2^{63}-1,
$$

大约是 $-9.22\times10^{18}$ 到 $9.22\times10^{18}$。可能达到 $10^{18}$ 的
答案、乘积、前缀和与计数通常使用 `long long`。

后缀 `LL` 让整数字面量本身具有 `long long` 类型。更常见的竞赛场景是变量已经用
`int` 保存，但乘法结果需要 64 位。这时让 `1LL` 先参与运算：

```cpp
int a = 1000000000;
int b = 1000000000;
long long product = 1LL * a * b;
```

如果误写成：

```cpp
long long product = a * b;
```

右侧会先按 `int` 计算乘法，溢出以后才尝试保存进 `long long`；左侧类型更大并不能
挽回右侧已经发生的错误。更完整的运算类型规则会在 [类型转换](type-conversions.md)
中解释。

## `ll` 类型别名

竞赛代码经常把 `long long` 缩写成 `ll`：

```cpp
typedef long long ll;
```

这行代码为已有类型 `long long` 引入了一个较短的名称，没有创建新的整数类型。
声明以后，下面两行含义相同：

```cpp
long long first = 0;
ll second = 0;
```

本书的竞赛代码统一保留 `typedef long long ll;`。类型别名的完整语法和作用域属于
后面的扩展内容；当前只需会使用这个固定别名。

## 有符号整数溢出

如果数学结果超出类型能够表示的范围，就发生溢出。下面的程序让 32 位 `int` 的
最大值加 `1`：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int x = 2147483647;
    cout << x << '\n';
    x = x + 1;
    cout << x << '\n';
}

int main() {
    solve();
    return 0;
}
```

许多主流竞赛环境中，它看起来可能从 `2147483647` 绕到 `-2147483648`。这个现象
不能成为正确代码的一部分。

> **未定义行为（Undefined Behavior，UB）** 表示 C++17 不再规定程序必须怎样
> 运行。编译器可能显示常见的成环结果，也可能利用“正确程序不会发生有符号溢出”
> 这一前提重新组织甚至删除相关计算。处理器、ABI、编译器、编译选项和优化级别都
> 可能影响观察结果；操作系统通常只会间接影响默认工具链。正确程序必须在计算发生
> 以前选好足够大的类型，不能依赖某次实验的输出。

`long long` 只是范围更大，并不是不会溢出。选择类型时必须根据题目给出的最大值
估算整个表达式的最大结果。

## 其他整数类型

C++ 还有 `short`、`long` 和无符号整数类型。它们各有标准规则，但普通竞赛题很少
需要用 `short` 节省空间，`long` 的常见位宽又会随平台变化。需要更大范围时，通常
直接使用含义更稳定的 `long long`。

`unsigned int` 等无符号类型的取值范围和成环规则会在位运算单元结合位模式说明。
`bool` 和 `char` 在 C++ 的分类中也属于整数类型，但它们分别承担真假与字符处理，
后面会独立学习。

完整的平台差异、固定位宽整数与 `__int128` 收录在配套扩展篇
[整数类型的位宽与平台差异](integer-type-widths.md) 中。

## 完整代码

输入两个绝对值不超过 $10^9$ 的整数，输出它们的乘积：

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

void solve() {
    int a;
    int b;
    cin >> a >> b;

    ll product = 1LL * a * b;
    cout << product << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
1000000000 1000000000
```

输出：

```text
1000000000000000000
```

## 需要记住什么

1. 主流竞赛环境中，`int` 和 `long long` 通常分别能保存多大范围的整数？
2. 两个不超过 $10^9$ 的整数相乘时，为什么结果通常要使用 `long long`？
3. 当 `a` 和 `b` 都是 `int` 时，`1LL * a * b` 中的 `1LL` 有什么作用？
4. `typedef long long ll;` 创建了新类型，还是只引入了一个别名？
5. 为什么正确程序不能依赖有符号整数溢出后的常见表现？

`short`、`long`、无符号整数、固定位宽整数和 `__int128` 的完整规则不要求在本篇
记忆。

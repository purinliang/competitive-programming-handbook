# 基本类型：整数

> 状态：草稿
> 直接前置：[0101 入门：Hello World!](hello-world.md)

上一篇 [入门：A+B Problem](a-plus-b-problem.md) 第一次使用了 `int`。它是竞赛中最常用的整数类型，也是理解其他整数类型的起点。

## int

### 位与字节

计算机用只有 `0` 和 `1` 的二进制位保存数据。一个这样的 `0` 或 `1` 称为一个**位**，英文是 bit。

现代竞赛环境中，一个**字节**（byte）通常由 8 位组成。`int` 通常占用 4 字节，因此共有

$$
4 \times 8 = 32
$$

位，也称为 **32 位整数**。

`sizeof` 可以查看一个类型占用多少字节，`CHAR_BIT` 表示当前环境中一个字节包含多少位：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    cout << sizeof(int) << '\n';
    cout << sizeof(int) * CHAR_BIT << '\n';
}

int main() {
    solve();
    return 0;
}
```

在常见的 Linux 竞赛环境中，输出为：

```text
4
32
```

> C++17 只保证一个字节由若干连续的位组成，具体位数由实现决定；`int` 也只保证至少能表示 16 位整数。一个字节等于 8 位、`int` 等于 4 字节，是现代桌面、服务器和主流竞赛环境中的事实标准，而不是所有 C++17 实现都必须遵守的规定。可以参见 [C++17 内存模型](https://timsong-cpp.github.io/cppwp/n4659/intro.memory) 与 [C++17 基本类型](https://timsong-cpp.github.io/cppwp/n4659/basic.fundamental)。

### 二进制表示与取值范围

以下讨论采用现代竞赛环境普遍使用的 **32 位二进制补码**。

32 位 `int` 的最高位可以先理解为符号位：

- 最高位是 `0`，表示 `0` 或正数。
- 最高位是 `1`，表示负数。
- 其余 31 位保存数值的低位部分。

最小值和最大值的二进制形式分别是：

```text
最小值  10000000000000000000000000000000  = -2^31
最大值  01111111111111111111111111111111  =  2^31 - 1
```

所以 32 位 `int` 的范围是

$$
-2^{31} \le x \le 2^{31}-1,
$$

也就是

```text
-2147483648 到 2147483647
```

最高位虽然能够判断正负，但补码并不是“一个符号位加 31 位绝对值”。例如最小值的最高位为 `1`、其余位全为 `0`，表示的是 $-2^{31}$，而不是“负零”。

> C++17 本身没有强制有符号整数使用补码，也允许反码和原码；现代桌面、服务器与主流竞赛环境实际都使用补码。本节解释的是竞赛中真正会遇到的表示方式，同时把标准没有保证的边界明确标出。

### 有符号整数溢出

如果计算结果超出 `int` 的范围，就发生了**有符号整数溢出**。下面的程序把最大值手动写成十进制，再加 `1`：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int x = 2147483647;
    cout << x << '\n';
    x = x + 1;
    cout << x << '\n';
}

int main() {
    solve();
    return 0;
}
```

在许多主流竞赛环境中，这个简单程序通常表现为：

```text
2147483647
-2147483648
```

看起来就像数值越过最大值后绕回了最小值。

> **未定义行为（Undefined Behavior，UB）**表示 C++17 标准不再规定程序必须怎样运行。编译器可以输出看似成环的结果，也可以基于“正确程序不会发生有符号溢出”这一假设改写或删除相关计算。因此，上面的程序只用于观察常见现象，正确代码不能依赖这个结果。[C++17 表达式规则](https://timsong-cpp.github.io/cppwp/n4659/expr)明确规定：数学结果不在类型可表示范围内时，行为未定义。

> 这里所说的“环境”主要包括目标处理器与 ABI、编译器及其版本、编译选项和优化级别。操作系统通常只是间接决定默认工具链与 ABI。x86-64 等主流处理器的整数加法指令会自然截断高位，但 C++ 编译器仍然按照“有符号溢出不会发生”进行优化，所以不能把硬件现象当成语言保证。

竞赛中不需要担心主流机器是否采用补码；真正需要做的是在计算前选择足够大的类型，避免有符号溢出。后文的 `long long` 就是最常用的选择。

## unsigned int

在 `int` 前加上 `unsigned`，就得到无符号整数类型 `unsigned int`，也可以简写为 `unsigned`。

常见竞赛环境中的 `unsigned int` 同样占 32 位，但没有负数。32 位都用于表示非负数，所以范围是

$$
0 \le x \le 2^{32}-1,
$$

也就是

```text
0 到 4294967295
```

无符号运算严格按照 $2^{32}$ 取模，因此成环是 C++17 明确保证的行为：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    unsigned int x = 0;
    cout << x << '\n';
    x = x - 1;
    cout << x << '\n';
}

int main() {
    solve();
    return 0;
}
```

输出为：

```text
0
4294967295
```

无符号整数的成环虽然确定，但减法和有符号、无符号混合比较很容易产生反直觉结果。竞赛中除非题目确实需要位模式或模 $2^N$ 运算，否则仍然优先使用有符号整数，并通过更大的类型避免溢出。

## 其他整数类型

C++ 还提供 `short`、`long` 和 `long long`：

- `short` 是 `short int` 的简写。
- `long` 是 `long int` 的简写。
- `long long` 是 `long long int` 的简写。
- 在前面增加 `unsigned`，就得到对应的无符号类型。

它们的实际大小可以继续用 `sizeof` 检查：

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    cout << "short: " << sizeof(short) << " bytes\n";
    cout << "int: " << sizeof(int) << " bytes\n";
    cout << "long: " << sizeof(long) << " bytes\n";
    cout << "long long: " << sizeof(long long) << " bytes\n";
}

int main() {
    solve();
    return 0;
}
```

当前 Linux x86-64 + GCC 环境中的输出为：

```text
short: 2 bytes
int: 4 bytes
long: 8 bytes
long long: 8 bytes
```

### 有符号整数范围

下表采用当前主流 Linux x86-64 竞赛环境的大小和二进制补码表示。“`1` + 其余全 `0`”与“`0` + 其余全 `1`”分别表示该位数的最小值和最大值。

| 类型 | 占用 | 最小值（二进制） | 最大值（二进制） | 十进制范围 |
| --- | ---: | --- | --- | ---: |
| `short` | 2 字节 / 16 位 | `1` + 15 个 `0` | `0` + 15 个 `1` | -32768 到 32767 |
| `int` | 4 字节 / 32 位 | `1` + 31 个 `0` | `0` + 31 个 `1` | -2147483648 到 2147483647 |
| `long` | 8 字节 / 64 位 | `1` + 63 个 `0` | `0` + 63 个 `1` | -9223372036854775808 到 9223372036854775807 |
| `long long` | 8 字节 / 64 位 | `1` + 63 个 `0` | `0` + 63 个 `1` | -9223372036854775808 到 9223372036854775807 |

### 无符号整数范围

对应的无符号类型使用全部位保存非负数：

| 类型 | 占用 | 最小值（二进制） | 最大值（二进制） | 十进制范围 |
| --- | ---: | --- | --- | ---: |
| `unsigned short` | 2 字节 / 16 位 | 16 个 `0` | 16 个 `1` | 0 到 65535 |
| `unsigned int` | 4 字节 / 32 位 | 32 个 `0` | 32 个 `1` | 0 到 4294967295 |
| `unsigned long` | 8 字节 / 64 位 | 64 个 `0` | 64 个 `1` | 0 到 18446744073709551615 |
| `unsigned long long` | 8 字节 / 64 位 | 64 个 `0` | 64 个 `1` | 0 到 18446744073709551615 |

> C++17 只规定这些类型的顺序和最低要求：`short`、`int`、`long`、`long long` 提供的存储空间不能依次变小；它们至少分别具有 16、16、32、64 位。`long` 的平台差异尤其明显：Linux x86-64 通常是 8 字节，Windows x64 通常仍是 4 字节。`int` 在现代主流平台上已经形成 4 字节、32 位的事实标准，但写程序时仍可以用 `sizeof` 确认当前环境。

竞赛中最常用的是：普通下标和不超过约 $2 \times 10^9$ 的数使用 `int`；乘法、前缀和及可能到 $10^{18}$ 的答案使用 `long long`。由于 `long` 的大小会随平台变化，需要明确的大范围整数时通常直接选择 `long long`。

## 特殊整数类型

`bool` 和 `char` 在 C++ 的分类中也属于整数类型，但它们各自承担特殊职责，行为与普通整数不完全相同。

- `bool` 只表示 `false` 和 `true`。它没有 `signed bool`、`unsigned bool`、`short bool` 或 `long bool`。
- `char` 主要保存字符，但底层仍使用整数值。它恰好占 1 字节；这个字节有多少位由 `CHAR_BIT` 决定。
- `char`、`signed char` 和 `unsigned char` 是三个不同的类型。单独写 `char` 时，它是否能够表示负数由编译器和目标平台决定。

后续的“基本类型：布尔”和“基本类型：字符”会分别解释它们的具体行为；当前只需知道它们属于整数家族，却不应该当作普通 `int` 的缩小版使用。

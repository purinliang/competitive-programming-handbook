# 内存：字节寻址

> 最近修订：2026-08-13 02:35 +10:00（未审阅）

变量名称让源代码能够找到对象，但程序运行时还需要在内存中定位它实际占用的位置。计算机把可访问的内存看成许多按顺序排列的字节，并为每个字节分配一个编号。

这个编号称为**地址**。理解字节与地址后，才能准确解释下一篇中的指针保存了什么。

## 字节是基本寻址单位

[基础：位、字节与存储单位](bits-bytes-and-storage-units.md) 已经区分了 bit 与 byte：位是表示二进制信息的最小单位，字节是 C++ 内存的基本存储与寻址单位。

在主流竞赛环境中，一个字节包含 $8$ 位。内存可以想象成一列格子：

| 地址 | `...1000` | `...1001` | `...1002` | `...1003` | `...1004` |
| --- | --- | --- | --- | --- | --- |
| 一个字节 | 8 位 | 8 位 | 8 位 | 8 位 | 8 位 |

相邻字节的地址相差 $1$。程序通常用十六进制显示地址，例如 `0x7ffc...`；十六进制只是更紧凑的写法，不改变地址本身的含义。

> 这里讨论的是程序能够看到的地址。现代操作系统通常为每个进程提供虚拟地址空间，再由系统映射到实际硬件内存；普通竞赛程序不需要知道最终物理位置。

## 对象占用连续字节

一个 `char` 恰好占一个字节，而 `int`、`double` 等对象通常占多个连续字节。可以用 `sizeof` 查询对象占用多少字节：

```cpp
int x = 42;
double y = 3.5;

cout << sizeof(x) << '\n';
cout << sizeof(y) << '\n';
```

在常见竞赛环境中，`int` 占 $4$ 字节，`double` 占 $8$ 字节。

如果一个 $4$ 字节 `int` 从地址 `1000` 开始，它占用：

| 字节序号 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| 地址 | 1000 | 1001 | 1002 | 1003 |

通常用第一个字节的地址代表整个对象的位置。知道起始地址与 `sizeof`，就知道对象覆盖的字节区间。

对象不能与另一个仍然存在的普通对象随意重叠。`union` 是语言明确提供的共享存储例外；普通独立变量各自拥有自己的存储区域。

## 取地址运算符

在一个对象前写 `&`，可以取得它的地址：

```cpp
int x = 42;
cout << &x << '\n';
```

这里的 `&` 是一元**取地址运算符**，与两个整数之间的按位与不是同一种用法：

```cpp
int bits = a & b; // 按位与
cout << &x;       // 取得 x 的地址
```

运算符由操作数位置决定含义。`a & b` 的 `&` 位于两个表达式中间；`&x` 的 `&` 只作用于右边一个对象。

地址不是对象中保存的普通数值。`x` 表示整数值 `42`，`&x` 表示这个整数对象存放在哪里。下一篇会用专门的指针类型保存地址。

## 低地址与高地址

地址本质上按数值排列：地址较小的一侧称为**低地址**，地址较大的一侧称为**高地址**。

若三个连续字节地址是 `1000`、`1001`、`1002`：

- `1000` 比 `1001` 低；
- `1002` 比 `1001` 高。

有些内存示意图把高地址画在上方，有些画在下方。图的上下方向不是定义；只比较地址数值大小。

程序每次运行时，对象的具体地址可能变化。操作系统、编译器、运行方式和地址随机化都会影响结果，所以不能记住某次输出并把地址硬编码进程序。

## 数组中的连续地址

[数组：一维数组](one-dimensional-arrays.md) 已经说明元素连续存放。现在可以用地址更准确地表示：

```cpp
int a[3] = {10, 20, 30};
```

若 `sizeof(int) == 4`，并且 `a[0]` 从地址 `1000` 开始：

| 元素 | 起始地址 | 占用字节 |
| --- | ---: | --- |
| `a[0]` | 1000 | 1000 到 1003 |
| `a[1]` | 1004 | 1004 到 1007 |
| `a[2]` | 1008 | 1008 到 1011 |

相邻元素的起始地址相差一个元素的字节数，不是永远相差 $1$。对 `char` 数组，元素恰好一个字节，所以相邻字符地址才相差 $1$。

可以直接输出各元素地址观察这个关系：

```cpp
cout << &a[0] << '\n';
cout << &a[1] << '\n';
cout << &a[2] << '\n';
```

具体十六进制数每次可能不同，但后一个 `int` 元素会紧跟前一个元素的完整存储区域。

二维内置数组也按行连续存放。`a[i][j]` 之后先出现同一行的 `a[i][j + 1]`，一行结束后再进入下一行。

## 对齐与空隙

某些类型要求起始地址满足特定倍数，这称为**对齐**。编译器可能在独立对象或结构体成员之间留下没有成员使用的填充字节，让后续对象从合适地址开始。

所以“数组元素连续”不能推广成“程序中的所有变量之间都没有空隙”。数组保证相同类型的元素首尾相接；两个独立局部变量的相对位置和先后顺序则不应依赖。

结构体大小也可能大于成员大小之和。例如一个 `char` 后接一个 `int` 时，中间可能加入填充。对齐的精确规则由类型与平台决定，基础竞赛代码通常只需通过 `sizeof` 观察，不手算布局。

## 字节序

多字节整数自身的各个字节也要按某种顺序存放。低位字节放在低地址称为**小端序**，高位字节放在低地址称为**大端序**。

主流 x86-64 竞赛环境采用小端序，网络协议常规定大端顺序。但正常读写 `int` 时，编译器会按当前平台正确解释整个对象，算法代码不需要手动关心其中每个字节的顺序。

只有在查看原始字节、解析二进制文件或网络数据时，字节序才会直接影响代码。怎样安全访问对象的字节表示，要在学会指针后再讨论；本篇只需要知道“地址连续”并不等于“最低有效位一定画在左边或右边”。

## 地址与对象大小

对于任何普通对象，可以同时询问：

```cpp
cout << &x << '\n';
cout << sizeof(x) << '\n';
```

第一行回答对象从哪里开始，第二行回答它占多少字节。两者共同描述存储位置，但都不告诉你变量名称、题目含义或当前数值。

反过来，只知道一个裸地址也不够安全访问对象。程序还需要知道：

- 这里是否确实存在一个仍然有效的对象；
- 对象是什么类型；
- 它占用多少字节；
- 当前操作是否拥有读写权限。

指针类型会保存“指向哪种对象”的信息，解引用则通过地址访问对象。地址本身只是建立这些规则的基础。

## 完整代码

下面的程序输出一个 `int` 数组的元素字节数、整个数组字节数和三个元素的地址。地址的具体文本无需与任何固定样例相同，只观察它们按元素大小连续排列。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int a[3] = {10, 20, 30};

    cout << sizeof(a[0]) << '\n';
    cout << sizeof(a) << '\n';
    cout << &a[0] << '\n';
    cout << &a[1] << '\n';
    cout << &a[2] << '\n';
    return 0;
}
```

在 `int` 占 $4$ 字节的常见环境中，前两行是：

```text
4
12
```

后三行通常显示三个十六进制地址，数值依次相差 $4$。再次运行时起始地址可以改变，这不影响数组连续存储的关系。

## 常见错误

### 把地址当成对象的值

`x` 是对象保存的值，`&x` 是对象的位置。两者类型、用途和输出都不同。

### 以为相邻元素地址永远相差 1

地址以字节编号。相邻数组元素起始地址相差 `sizeof(element)`；只有单字节元素才相差 $1$。

### 根据声明顺序猜局部变量地址

编译器可以按对齐和优化需要安排独立对象。只有数组等语言明确保证的布局可以依赖。

### 硬编码某次运行输出的地址

地址由本次程序运行环境决定，可能每次变化。程序通过对象和指针取得地址，不把显示值抄回源码。

### 用图的上下方向定义高低地址

高低只由地址数值决定。阅读内存图时先看标注，不假设向上或向下一定是哪一侧。

## 需要记住什么

1. C++ 内存的基本寻址单位是 bit 还是 byte？
2. 地址表示一个字节的什么信息？相邻字节地址相差多少？
3. 一个多字节对象通常用哪一个字节的地址代表位置？
4. `x` 与 `&x` 分别表示什么？
5. 低地址与高地址由图的方向决定，还是由地址数值决定？
6. 为什么相邻 `int` 数组元素的地址通常相差 $4$，而不是 $1$？
7. 数组连续存储是否意味着所有独立变量之间都没有空隙？
8. 具体地址为什么可能在不同运行之间变化？

虚拟内存映射、完整对齐规则、字节序转换和对象表示不要求在本篇理解或记忆。当前重点是把内存看成按字节编号的空间，并用“起始地址加对象大小”理解对象位置。

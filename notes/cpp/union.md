# 联合体

> 最近修订：2026-08-16 14:18 +10:00（未审阅）

一个 [结构体](struct.md) 的每个成员都同时存在：参赛者的编号和分数需要各自的存储空间。但有些数据只会处于若干形态中的一种，例如一个输入值要么是整数，要么是浮点数，从来不需要同时保存两份值。

联合体（`union`）的成员共用同一段存储空间，因此同一时刻通常
只有一个**当前有效成员**（active member）。

## 声明联合体类型

下面的类型可以保存一个 `int` 或一个 `double`：

```cpp
union Number {
    int integer;
    double decimal;
};
```

它的外形与 `struct` 相似：

- `union` 表示声明联合体类型；
- `Number` 是类型名；
- `integer` 与 `decimal` 是成员；
- 右花括号后的分号不能省略。

声明对象后，仍然使用点运算符访问成员：

```cpp
Number number;
number.integer = 42;
```

这次赋值让 `integer` 成为当前保存的成员，可以读取：

```cpp
printf("%d\n", number.integer);
```

## 共用存储空间

`struct` 为所有成员分别保留空间，`union` 则让所有成员从同一位置开始，共用足以容纳最大成员的空间。

假设常见环境中的 `int` 占 $4$ 字节、`double` 占 $8$ 字节：

- `struct` 同时保存两者，还可能为了对齐加入空隙；
- `union Number` 只需容纳两者中更大的 `double`，通常占 $8$ 字节。

可以用 `sizeof` 查看当前环境的实际结果：

```cpp
printf("%zu\n", sizeof(Number));
```

联合体大小至少能容纳最大的成员，并满足最严格成员的对齐要求；不要把某个平台上的具体字节数当作所有环境的固定规则。

节省空间的代价是不能同时保留两个成员。先写入整数，再写入浮点数：

```cpp
number.integer = 42;
number.decimal = 3.5;
```

第二次赋值复用了同一段存储，原来的整数不再是当前有效值。此后应该读取 `number.decimal`，不能期待 `number.integer` 仍然保存 `42`。

## 当前有效成员

对本篇使用的 `int`、`double` 等简单类型，给某个成员赋值后，就把该成员当作
当前有效成员：

```cpp
Number number;

number.integer = 42;
printf("%d\n", number.integer);

number.decimal = 3.5;
printf("%.1f\n", number.decimal);
```

程序必须自己记住最后写入了哪个成员。`union` 对象内部不会自动保存“现在是整数还是浮点数”的标签。

读取并非当前有效的成员，企图借此观察同一组字节的另一种解释，在标准 C++ 中通常是未定义行为：

```cpp
number.integer = 42;
printf("%f\n", number.decimal); // 错误：decimal 不是当前成员
```

这种做法称为类型双关。某些编译器或平台可能给出看似稳定的位模式，但竞赛代码不能依赖它。需要复制或检查对象的原始字节时，应使用专门的安全工具，而不是随意读取另一个联合体成员。

## 需要额外标签

如果一个联合体对象会被保存并在以后读取，程序还需要一个独立标签，记录当前成员是谁：

```cpp
char type;
Number number;
```

约定 `type == 'i'` 表示整数，`type == 'd'` 表示浮点数：

```cpp
if (type == 'i') {
    printf("%d\n", number.integer);
} else if (type == 'd') {
    printf("%f\n", number.decimal);
}
```

标签与写入操作必须同步：

```cpp
type = 'i';
number.integer = 42;
```

如果标签写着 `'i'`，实际最后写入的却是 `decimal`，程序仍然会读错成员。`union` 只共用空间，不负责维护这条不变量。

后面的 `enum` 可以给有限状态起比字符更准确的名称；标准库 `variant` 还能把标签与联合数据包装在一起并进行检查。基础竞赛代码很少需要手写这种通用容器，本篇只要求理解 `union` 的语言语义。

## 初始化

简单联合体可以先声明对象，再明确给需要的成员赋值：

```cpp
Number number;
number.integer = 42;
```

这比依赖默认初始化规则更直观。若普通局部联合体没有初始化，也没有给任何成员赋值，就不能读取其中内容。

使用初始化列表时，C++17 默认初始化第一个成员：

```cpp
Number number = {42};
```

因为 `integer` 是 `Number` 中声明的第一个成员，这相当于用 `42` 初始化 `number.integer`。若希望初始化其他成员，C++17 中仍然优先先声明再赋值，避免引入其他版本的语法。

## 与 struct 的区别

两者解决的问题不同：

| 类型 | 成员关系 | 同时有效的成员 | 典型用途 |
| --- | --- | --- | --- |
| `struct` | 每个成员分别存储 | 所有成员 | 一个对象同时具有多项信息 |
| `union` | 所有成员共用存储 | 一个成员 | 一个对象只处于若干表示之一 |

参赛者同时具有编号和分数，应使用 `struct`。一个值在整数与浮点形式中二选一，才可能考虑 `union`。

不要为了节省几个字节，把本来需要同时存在的数据放进 `union`。如果程序随后还要读取全部字段，它们就必须有各自的存储空间。

## 非简单成员

`string`、`vector` 等类型需要在创建和销毁时运行特殊操作。把它们直接放入 `union` 后，程序必须手动管理哪个对象已被构造、何时销毁，远超基础竞赛用法。

本篇只在 `union` 中使用 `int`、`double`、`char` 等简单类型。需要安全保存复杂的多选一对象时，优先使用标准库 `variant`，不要手写构造与析构管理。

## 完整代码

输入一个类型字符与对应的值：`i` 后跟一个整数，`d` 后跟一个浮点数。程序把值写入联合体的对应成员，再按照标签读取并输出。

```cpp
#include <bits/stdc++.h>
using namespace std;

union Number {
    int integer;
    double decimal;
};

void solve() {
    char type;
    cin >> type;

    Number number;

    if (type == 'i') {
        cin >> number.integer;
        cout << number.integer << '\n';
    } else if (type == 'd') {
        cin >> number.decimal;
        cout << fixed << setprecision(2) << number.decimal << '\n';
    }
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
i 42
```

输出：

```text
42
```

另一组输入：

```text
d 3.5
```

输出：

```text
3.50
```

分支不仅决定怎样读写，也保证程序只读取刚刚写入的当前成员。

## 常见错误

### 以为所有成员同时存在

写入新成员会复用同一段存储。若多项信息都要保留，应该使用 `struct`。

### 读取非当前成员

`union` 不是任意转换位模式的工具。写入哪个成员，就只按那个成员读取，除非后续又明确切换。

### 忘记保存标签

对象以后再读取时，程序必须知道当前成员是谁。标签和值需要同时更新并始终一致。

### 假设 sizeof 等于成员大小之和

联合体只为最大成员准备共享空间，并满足对齐要求。它的大小不是所有成员大小之和。

### 放入需要手动管理的复杂类型

包含 `string`、`vector` 等成员的联合体涉及构造、析构与当前成员切换。基础竞赛代码不这样使用。

## 需要记住什么

1. `union` 的成员是分别存储，还是共用同一段空间？
2. 同一时刻可以把多少个成员当作当前有效值？
3. 写入一个新成员后，旧成员是否仍然可以读取？
4. 为什么联合体通常还需要一个独立标签？
5. `struct` 与 `union` 分别适合怎样的成员关系？
6. `sizeof(union)` 为什么不是所有成员大小之和？
7. 为什么不能通过读取非当前成员进行类型双关？
8. 为什么基础代码不在 `union` 中保存 `string`、`vector` 等复杂对象？

`union` 在普通算法竞赛解题代码中很少直接使用。当前需要能读懂声明、知道成员共用空间，并避免读取错误成员；复杂对象管理与底层字节解释都不要求掌握。

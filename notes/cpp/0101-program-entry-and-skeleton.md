# 程序结构：竞赛代码骨架

> 状态：草稿
> 直接前置：—

## 问题背景

一道题的解法最终要交给评测机运行。评测机需要知道从哪里开始执行，而我们也需要一个固定位置放置真正解决题目的代码。

如果把所有内容都堆在程序入口里，读题、计算和输出很快就会混在一起。以后修改算法时，我们还得绕过启动程序所需的固定结构。因此，本篇先建立一个最小的竞赛代码骨架：程序有唯一入口，解题过程有自己的位置，入口只负责启动解题过程并正常结束。

这篇文章只讨论程序各部分的职责，不提前讲输入输出、变量、循环和算法。那些内容会沿学习路线逐步填进骨架。

## 前置知识

无。

本文是学习路线的起点。代码中会出现函数定义、函数调用和返回值的固定写法；现在只需要先认识它们在骨架中的位置，后续的“函数：定义与调用”会解释完整语法。

## 一步一步解构

### 1. 先给程序一个入口

评测机启动可执行文件后，需要一个约定好的起点。这个起点准确地叫作**程序入口**，C++ 规定它的英文名称是 `main`。

```text
评测机启动程序
      │
      ▼
   程序入口 main
      │
      ▼
   程序正常结束
```

我们的入口骨架显式做两件事：接过执行权，然后报告程序正常结束。`return 0;` 中的 `0` 就是正常结束的状态。

### 2. 给解题过程一个独立位置

真正做题时，入口内部会逐渐出现读入、计算和输出。把这些内容全塞进 `main` 虽然可以运行，却会让固定骨架和题目逻辑混在一起。

我们因此增加一个专门处理题目的函数。它的职责是“解决当前题目”，所以给它一个准确而直接的英文名称 `solve`。入口只调用一次 `solve`，等它完成后再结束程序。

```text
评测机
  │ 启动
  ▼
main（程序入口）
  │ 调用
  ▼
solve（解题过程）
  │ 完成后返回
  ▼
main 报告正常结束
```

这里没有为了代码而凭空创造名称：只有当“固定入口”和“随题目变化的解题过程”需要分开时，`main` 与 `solve` 才分别出现。

### 3. 先保持骨架最小

现在还没有具体题目，因此 `solve` 暂时不需要保存变量，也不需要调用输入输出工具。`#include <bits/stdc++.h>`、`using namespace std;` 和 `typedef long long ll;` 会在实际题目需要标准库名称和整数类型时加入；把它们提前塞进最小程序，反而无法解释它们为什么存在。

这个骨架只增加一次函数调用，所以不会改变任何实际算法的时间复杂度；函数本身也没有申请额外数据结构。对竞赛程序而言，这点固定开销可以视为常数。

## 示例代码

### 1. 翻译“解题过程有独立位置”

目前还没有题目逻辑，所以函数体留空：

```cpp
void solve() {}
```

`solve` 是刚才确定的职责名称。这里的 `void` 表示它完成工作后不需要把一个结果交还给调用者；完整含义会在函数教程中解释。

### 2. 翻译“入口启动解题过程”

```cpp
int main() {
    solve();
    return 0;
}
```

`solve();` 对应流程图中的“调用解题过程”，`return 0;` 对应“报告正常结束”。因为 `main` 要调用 `solve`，所以 `solve` 的定义放在 `main` 前面，让编译器先见到这个名称。

## 完整代码

下面是组合后的最小竞赛代码骨架，可以直接用 C++17 编译运行：

```cpp
void solve() {}

int main() {
    solve();
    return 0;
}
```

它不读取数据也不产生输出，这是当前知识边界内的完整行为，而不是缺失了一部分代码。后续教程会在 `solve` 内逐步加入类型、变量、输入输出、分支和循环。

## 基础练习

1. 不看上文，默写最小骨架，并指出哪一个名称表示程序入口，哪一个名称表示解题过程。
2. 把 `solve` 的定义移到 `main` 后面并尝试编译，观察编译器如何报告“调用时还不认识这个名称”；再恢复原顺序确认能够编译。
3. 暂时删除 `solve();` 并运行程序。比较两次执行流程，解释为什么两份程序都能正常结束，但只有原程序真正把执行权交给了解题位置。

如果编译失败，先按以下顺序检查：花括号是否成对、每条语句末尾是否有分号、`solve` 的拼写在定义和调用处是否完全一致、`solve` 是否出现在调用它的代码之前。

## 扩展阅读

这部分是未来工作，不是当前阶段的下一步：

- 当学过循环后，可以让 `main` 根据测试组数重复调用 `solve`。
- 当代码开始使用标准库时，可以进一步了解 `include`、头文件、命名空间与 `std`；这些属于扩展说明，不需要阻塞主线。
- 更大型的软件会讨论命令行参数、多个源文件和不同退出状态，但它们不是竞赛基础骨架的一部分。

# 比较运算符

> 最近修订：2026-08-16 07:32 +10:00（未审阅）

许多问题并不要求算出一个新的数，而是判断两个值之间的关系：成绩是否达到分数线、两个答案是否相同、当前值是否小于上限。

C++ 使用**比较运算符**回答这些问题。一次比较只产生一个 [布尔类型](boolean-type.md) 结果：关系成立时是 `true`，不成立时是 `false`。

## 六种比较

常用比较运算符共有六种：

| 运算符 | 含义 | 示例 | 结果 |
| --- | --- | --- | --- |
| `==` | 等于 | `5 == 5` | `true` |
| `!=` | 不等于 | `5 != 3` | `true` |
| `<` | 小于 | `3 < 5` | `true` |
| `<=` | 小于等于 | `5 <= 5` | `true` |
| `>` | 大于 | `3 > 5` | `false` |
| `>=` | 大于等于 | `5 >= 5` | `true` |

“小于等于”和“大于等于”都要把等号写在右边：`<=`、`>=`。C++ 中不存在 `=<` 或 `=>`。

比较式本身就是一个表达式，可以把结果保存到 `bool`：

```cpp
int score = 73;
int passing_score = 60;

bool passed = score >= passing_score;
```

这里先读取 `score` 和 `passing_score`，再判断 $73\ge60$，最终把 `true` 保存进 `passed`。

## 等于与赋值

比较相等使用两个等号 `==`：

```cpp
bool same = a == b;
```

单个等号 `=` 已经用于赋值：

```cpp
a = b;
```

两者的作用完全不同：

- `a == b` 读取两边并产生 `bool`，不会修改 `a` 或 `b`；
- `a = b` 把 `b` 的值写入 `a`，会修改 `a`。

在条件中误写单等号是常见错误：

```cpp
if (a = b) {
    cout << "same\n";
}
```

这段代码不是判断相等，而是先赋值，再把赋值后的数转换成 `bool`。编译器通常会给出警告，但代码可能仍能编译。正确写法是：

```cpp
if (a == b) {
    cout << "same\n";
}
```

## 严格与非严格关系

`<` 和 `>` 不包含相等的情况，称为严格比较；`<=` 和 `>=` 包含边界上的相等。

假设比赛要求分数至少为 $60$ 才通过：

```cpp
bool passed = score >= 60;
```

这里必须使用 `>=`，因为恰好 $60$ 分也应该通过。若误写成 `score > 60`，边界值 $60$ 会得到错误结果。

反过来，规则要求年龄“未满 $18$ 岁”时，应使用严格比较：

```cpp
bool eligible = age < 18;
```

年龄恰好为 $18$ 时已经不满足“未满”，因此不能写成 `<= 18`。比较题意时，最值得单独测试的通常就是等号对应的边界。

## 算术结果的比较

[算术表达式](arithmetic-expressions.md) 产生数值，比较运算符可以继续判断这个数值：

```cpp
bool enough = a + b >= target;
```

算术运算的优先级高于比较，所以它等价于：

```cpp
bool enough = (a + b) >= target;
```

程序先计算 `a + b`，再与 `target` 比较。主动加括号可以让阅读顺序更明确，尤其不要依靠记忆优先级理解很长的表达式。

## 字符比较

`char` 内部保存字符编号，因此也可以比较：

```cpp
bool earlier = 'a' < 'c';
```

在主流竞赛环境的 ASCII 兼容编码中：

- `'0'` 到 `'9'` 按数字顺序递增；
- `'A'` 到 `'Z'` 按字母顺序递增；
- `'a'` 到 `'z'` 按字母顺序递增。

所以同一类字符可以直接比较先后。大写字母与小写字母的编号区间不同，不能只凭日常字母顺序猜测 `'Z' < 'a'` 等跨区间比较；题目需要忽略大小写时，应先按照题意统一大小写。

字符串的字典序比较会在 [string](string.md) 中单独解释，不属于单个 `char` 的比较规则。

## 浮点数比较

浮点数只能近似保存许多十进制小数，因此计算结果不一定适合直接用 `==` 判断：

```cpp
double x = 0.1 + 0.2;
bool exactly_equal = x == 0.3;
```

在主流竞赛环境中，`exactly_equal` 通常是 `false`。若题目允许绝对误差，可以检查两数之差是否足够小：

```cpp
double difference = abs(x - 0.3);
bool close_enough = difference < 1e-9;
```

`1e-9` 只是常见示例，不是所有题目的固定答案。容许误差应根据题目范围和误差要求选择。[浮点类型](floating-point-types.md) 已经解释了误差从哪里来。

整数和字符没有这种舍入误差；判断两个 `int` 是否完全相等时可以直接使用 `==`。

## 不能连续书写范围比较

数学中可以写：

$$
0\le x\le10.
$$

但 C++ 不能直接照抄成：

```cpp
bool inside = 0 <= x <= 10;
```

C++ 会从左到右先计算：

```cpp
bool first = 0 <= x;
```

`first` 只可能是 `false` 或 `true`，在整数环境中分别相当于 `0` 或 `1`。程序随后比较的是：

```cpp
first <= 10
```

无论 `first` 是 `0` 还是 `1`，这个比较几乎总是成立，因此它没有正确检查上界。

一个数同时满足下界和上界，需要把两个完整比较组合起来：

```cpp
bool inside = 0 <= x && x <= 10;
```

其中 `&&` 表示“并且”，属于 [逻辑运算符](logical-operators.md)。本篇先记住：每个比较运算符只比较左右两个值，数学中的连续不等式必须拆开。

## 完整代码

现在解决达标判断问题：输入实际分数 `score` 和及格线 `passing_score`，若实际分数大于等于及格线，输出 `true`；否则输出 `false`。

程序只需要：

1. 读入两个整数；
2. 使用 `>=` 比较；
3. 把比较结果保存为 `bool` 并输出。

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int score;
    int passing_score;
    cin >> score >> passing_score;

    bool passed = score >= passing_score;
    cout << boolalpha << passed << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
73 60
```

输出：

```text
true
```

边界输入：

```text
60 60
```

仍然输出：

```text
true
```

若把输入改成 `59 60`，比较不成立，输出 `false`。

## 常见错误

### 把 == 写成 =

赋值会修改左操作数；相等比较只产生真假结果。编译时不要忽略“条件中的赋值”一类警告。

### 漏掉边界上的等号

看到“至少”“不小于”“不超过”“至多”等题面词语时，先明确边界是否包含，再选择 `<`、`<=`、`>` 或 `>=`。

### 照抄数学连续不等式

`l <= x <= r` 不能正确表达闭区间。必须写成两个比较，再用逻辑运算符组合。

### 直接比较浮点计算结果

整数相等与浮点近似相等是两个问题。浮点题允许误差时，依据题意检查差值，不要机械使用 `==`。

## 需要记住什么

1. 六种比较运算符分别表达什么关系？
2. 比较表达式的结果是什么类型？
3. `=` 和 `==` 分别做什么，会不会修改左边变量？
4. “至少 $60$”应该写成 `score > 60` 还是 `score >= 60`？
5. 为什么边界值需要单独测试？
6. `a + b >= target` 先计算哪一部分？
7. 为什么 `0 <= x <= 10` 在 C++ 中不能正确检查区间？
8. 浮点计算结果为什么不一定适合直接用 `==` 判断？

混合整数类型比较时的自动转换不在本篇展开，会在 [类型转换](type-conversions.md) 中统一解释。当前重点是准确选择关系、理解结果为 `bool`，并认真处理等号对应的边界。

# 变量：static 局部变量

> 最近修订：2026-08-13 03:24 +10:00（未审阅）

[名称：作用域](scope.md) 已经说明：函数中的局部变量名只能在对应代码块内使用。普通局部变量还有另一个特点——每次进入代码块都会创建新的对象，离开时对象被销毁。因此，函数通常不会记住上一次调用留下的局部状态。

有时我们恰好需要一个只属于某个函数、却能在多次调用之间保留的变量。`static` 局部变量解决的就是这个问题。

## 普通局部变量

下面的函数想在每次调用时生成一个递增编号：

```cpp
int next_id() {
    int id = 0;
    id++;
    return id;
}
```

但每次调用 `next_id()` 都会重新创建一个 `id`，并再次把它初始化为 `0`：

```cpp
int first = next_id();
int second = next_id();
printf("%d %d\n", first, second);
```

输出是：

```text
1 1
```

第一次调用结束时，函数内的 `id` 已经销毁。第二次调用创建的是另一个新的 `id`，它与第一次调用中的对象没有关系。

## 全局变量

把 `id` 移到所有函数外面，可以让两次调用读写同一个对象：

```cpp
int id = 0;

int next_id() {
    id++;
    return id;
}
```

这次连续调用会得到 `1, 2, 3, ...`。代价是名称 `id` 进入了全局作用域，后面的其他函数也能直接读取和修改它：

```cpp
void reset() {
    id = 0;
}
```

如果这个计数器只属于 `next_id()`，扩大名称的可见范围没有必要。我们真正想要的是：名称仍然留在函数内，但对象不要在每次调用结束时消失。

## static 局部变量

在局部变量声明前加入 `static`：

```cpp
int next_id() {
    static int id = 0;
    id++;
    return id;
}
```

`id` 的两个性质现在需要分开理解：

- 它的名称仍然只在 `next_id()` 的函数体内可见；
- 整个程序运行期间，这条声明只对应同一个对象，多次调用会继续使用它上一次留下的值。

因此，第一次调用把 `id` 从 `0` 改成 `1`，第二次调用从已有的 `1` 继续改成 `2`，第三次调用再得到 `3`。

`static` 在这里改变的是对象的**存储期**，没有把名称移到全局作用域。把它叫作“局部作用域的全局变量”会混淆两条独立规则；准确说法是“具有局部作用域和静态存储期的变量”，通常简称 **`static` 局部变量**。

## 初始化一次

`static` 局部变量的初始化只发生一次。若初始化式需要运行时的值，第一次执行到这条声明时使用当时的值；以后再次执行到这里，不会重新初始化：

```cpp
int remember_first(int x) {
    static int first = x;
    return first;
}
```

依次调用：

```cpp
int a = remember_first(3);
int b = remember_first(5);
printf("%d %d\n", a, b);
```

输出：

```text
3 3
```

第一次调用用 `3` 初始化 `first`。第二次调用虽然传入了 `5`，但初始化已经完成，函数直接读取原来的 `3`。

整数类型的 `static` 局部变量即使省略初始化式也会从 `0` 开始：

```cpp
static int count;
```

不过，本书仍然优先写出明确的 `= 0`，让初值不必依赖读者回忆默认初始化规则：

```cpp
static int count = 0;
```

## 三种变量的区别

| 声明位置与写法 | 名称在哪里可见 | 多次调用是否使用同一对象 | 初始化次数 |
| --- | --- | --- | --- |
| 函数内 `int value` | 当前代码块 | 否 | 每次执行声明时 |
| 函数内 `static int value` | 当前代码块 | 是 | 一次 |
| 函数外 `int value` | 全局声明之后 | 是 | 一次 |

`static` 局部变量与全局变量都能跨越多次函数调用保留状态，但名称的可见范围不同。这正是作用域与存储期必须分开讨论的原因。

## 使用边界

只有当一份状态在整个程序中都应该归属于同一个函数，并且确实需要跨调用保留时，才适合使用 `static` 局部变量，例如函数内部独占的调用次数或编号生成器。

竞赛程序尤其要注意多组测试数据。`static` 局部变量不会在下一组测试开始时自动恢复初值：

```cpp
void solve() {
    static int count = 0;
    // count 会保留上一组测试留下的值
}
```

如果状态属于单组测试，就应把普通局部变量声明在 `solve()` 中，或者把状态作为参数和对象成员显式传递。不要用隐藏的持久状态代替本来应该清楚表达的数据关系。

`static` 写在函数外的变量或函数上时会涉及内部链接；写在结构体或类的成员上时表示成员属于类型本身，而不是某个对象。这两种含义与局部变量的存储期不是同一个主题，已经分别登记为扩展阅读，本篇不混在一起。

## 完整代码

下面的程序读入需要生成的编号数量。题目保证 `n >= 1`；`next_id()` 内的 `static` 局部变量记录上一次已经生成到哪里：

```cpp
#include <bits/stdc++.h>
using namespace std;

int next_id() {
    static int id = 0;
    id++;
    return id;
}

void solve() {
    int n;
    scanf("%d", &n);

    for (int i = 1; i <= n; i++) {
        printf("%d", next_id());
        if (i == n) {
            printf("\n");
        } else {
            printf(" ");
        }
    }
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
5
```

输出：

```text
1 2 3 4 5
```

每次调用 `next_id()` 的时间复杂度为 $O(1)$，只保存一个整数，额外空间为 $O(1)$。

## 基础练习

1. 删除 `next_id()` 中的 `static`，预测并验证完整程序的输出怎样变化。
2. 把 `id` 的初值改成 `100`，生成三个编号并观察第一次返回的值。
3. 分成两个循环分别调用 `next_id()` 三次，确认第二个循环是否会从 `1` 重新开始。
4. 编写两个不同的函数，让它们各自声明 `static int count = 0`；验证两个计数器是否互相影响。
5. 模拟两组测试数据，观察把组内计数器误写成 `static` 后为什么不会自动清零。

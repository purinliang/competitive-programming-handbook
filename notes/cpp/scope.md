# 名称：作用域

> 最近修订：2026-08-13 02:13 +10:00（未审阅）

函数、变量和参数都需要名称。随着程序变长，同一个简单名称可能在不同地方反复出现：两个函数都想把结果叫作 `result`，两段循环都习惯用 `i`，函数形参也可能与调用处的变量同名。

C++ 使用**作用域**规定一个名称可以在哪一段源代码中被找到。作用域关心的是“这里写下这个名称时，它表示谁”，不是对象占用内存多久；对象的生命周期是后面的独立主题。

## 代码块作用域

一对花括号 `{}` 包围一个**代码块**。在代码块中声明的局部变量，从声明位置开始可见，到这个代码块结束：

```cpp
if (score >= 60) {
    int bonus = 5;
    cout << score + bonus << '\n';
}
```

`bonus` 只能在这对花括号内使用。离开代码块后再写它，编译器无法找到这个名称：

```cpp
if (score >= 60) {
    int bonus = 5;
}

cout << bonus << '\n';
```

这段代码不能通过编译。如果分支之后仍然需要 `bonus`，就应在更外层先声明它：

```cpp
int bonus = 0;

if (score >= 60) {
    bonus = 5;
}

cout << bonus << '\n';
```

变量应放在能够覆盖所有使用位置的**最小合理作用域**。过小会导致需要它的位置不可见；毫无必要地放到很外层，则会让更多代码都能修改它。

## 声明位置之前不可见

作用域通常从声明位置开始，不会向前延伸：

```cpp
cout << answer << '\n';
int answer = 42;
```

上面的输出位置还不知道 `answer` 是什么，因此不能编译。正确顺序是先声明并初始化，再使用：

```cpp
int answer = 42;
cout << answer << '\n';
```

C++ 从上到下处理名称。函数也遵循相同原则：调用之前，至少要出现函数声明或完整定义。

## 函数的局部作用域

每次进入函数，形参和函数体中声明的变量都属于这个函数调用的局部环境：

```cpp
int add(int a, int b) {
    int result = a + b;
    return result;
}
```

形参 `a`、`b` 和局部变量 `result` 都只能在 `add` 的函数体中使用。另一个函数可以使用相同名称，而不会访问 `add` 中的变量：

```cpp
int multiply(int a, int b) {
    int result = a * b;
    return result;
}
```

两个 `result` 是不同变量。两个函数的 `a` 和 `b` 也各自独立；形参名称只在对应函数内部代表本次调用收到的值。

调用处的实参与函数中的形参即使名称相同，也不是同一个局部变量：

```cpp
int x = 2;
int result = add(x, 3);
```

调用时，`x` 的值提供给形参 `a`。函数体使用自己的 `a`，而调用处仍然使用自己的 `x`。参数传递究竟复制值还是建立别名，会在“函数：参数传递”中单独说明。

## 控制结构产生的作用域

`if`、`while` 和 `for` 后的代码块都会产生新的作用域。`for` 初始化部分声明的计数变量还属于整个循环本身：

```cpp
for (int i = 0; i < n; i++) {
    cout << i << '\n';
}
```

`i` 可以出现在循环条件、更新和循环体中，但循环结束后不可见：

```cpp
for (int i = 0; i < n; i++) {
    cout << i << '\n';
}

cout << i << '\n';
```

最后一行不能编译。因为第一段循环的 `i` 已经离开作用域，后面可以重新声明另一个 `i`：

```cpp
for (int i = 0; i < n; i++) {
    cout << i << '\n';
}

for (int i = 0; i < m; i++) {
    cout << i << '\n';
}
```

两个循环变量互不影响。这比把一个 `i` 声明在两个循环外面更准确地限制了它的用途。

## 嵌套作用域与名称查找

代码块可以嵌套。使用一个名称时，编译器先在当前位置所在的最内层作用域查找，再逐层向外：

```cpp
int x = 10;

if (condition) {
    cout << x << '\n';
}
```

内层没有声明 `x`，于是找到外层的 `x`，输出 `10`。

内层也允许重新声明同名变量：

```cpp
int x = 10;

if (condition) {
    int x = 20;
    cout << x << '\n';
}

cout << x << '\n';
```

内层 `x` 会暂时遮住外层 `x`，这种现象称为**名称遮蔽**。分支内输出 `20`，离开分支后重新看到外层 `x`，输出 `10`。

名称遮蔽虽然合法，却很容易让人误判某一行正在读写哪个变量。本书的竞赛代码避免主动使用遮蔽：同一条逻辑中的不同对象采用不同名称，而不是依赖作用域区分两个 `x`。

## 全局作用域

在所有函数之外声明的名称位于全局作用域：

```cpp
int answer;

void solve() {
    answer = 42;
}
```

从全局声明之后开始，后面的函数都可以使用 `answer`。竞赛程序常把规模很大的数据和需要由多个函数共享的状态放在全局作用域，避免在函数内部的调用栈中分配过大对象，也避免把同一份数据层层传参。

全局可见不等于所有数据都应该全局化。若变量只属于一个函数，把它留在局部作用域可以减少意外修改，也能直接说明它的用途范围。通常只有以下数据适合放到全局：

- 规模很大的固定数组；
- 确实需要由多个辅助函数共同维护的题目状态；
- 表示题目固定上限或常量的名称。

全局对象和局部对象存放在哪片内存、何时创建和销毁，不由“作用域”这一个概念解释，会在内存分区与生命周期文章中展开。

## 作用域不等于生命周期

作用域是源代码中的名称可见范围；生命周期是运行时对象从创建到销毁的时间。两者经常相关，但不是同一个概念。

例如，普通局部变量的名称离开代码块后不可见，对象通常也在此时销毁。以后学习 `static` 时会看到：一个局部名称仍然只在函数内可见，但它对应的对象可以在多次函数调用之间持续存在。

当前只需用作用域回答名称查找问题：

1. 这个名称是否已经声明？
2. 当前代码是否仍在它的作用域内？
3. 若内外层存在同名声明，最内层找到的是哪一个？

不要用作用域提前推断所有内存与生命周期行为。

## 完整代码

输入两个整数，分别调用加法函数和乘法函数。两个函数都使用形参 `a`、`b` 和局部变量 `result`，但它们处于不同函数作用域，互不冲突：

```cpp
#include <bits/stdc++.h>
using namespace std;

int add(int a, int b) {
    int result = a + b;
    return result;
}

int multiply(int a, int b) {
    int result = a * b;
    return result;
}

int main() {
    int a;
    int b;
    cin >> a >> b;

    int sum = add(a, b);
    int product = multiply(a, b);

    cout << sum << '\n';
    cout << product << '\n';
    return 0;
}
```

输入：

```text
3 5
```

输出：

```text
8
15
```

`main` 中的 `a` 和 `b` 是调用处的局部变量；进入 `add` 或 `multiply` 后，对应函数的形参获得输入值。三个函数中的名称相同不代表它们是同一个变量。

## 常见错误

### 在作用域之外使用局部变量

如果分支或循环结束后仍然需要某个结果，应在包含所有使用位置的外层声明变量，再在内层更新它。

### 在声明之前使用名称

变量作用域不会向声明位置之前延伸。按“声明和初始化在前，读取在后”的顺序组织代码。

### 误以为同名形参与实参是同一变量

形参是函数内部使用的名称，实参是调用时提供的表达式。名称碰巧相同不会改变参数传递方式。

### 主动制造名称遮蔽

内层同名变量会隐藏外层变量，代码仍可能编译，却容易修改错对象。给不同含义使用不同名称。

### 把所有变量都放到全局

全局数据适合共享的大型题目状态，局部数据适合只服务当前函数的临时结果。作用域越小，能够意外修改它的代码越少。

## 需要记住什么

1. 作用域回答的是名称可见范围，还是对象存在时间？
2. 代码块中声明的局部变量从哪里开始可见，到哪里结束？
3. 为什么两个函数都可以声明名为 `result` 的局部变量？
4. `for` 初始化部分声明的 `i` 在循环结束后还能使用吗？
5. 编译器在嵌套作用域中按什么顺序查找名称？
6. 什么是名称遮蔽？为什么本书避免主动使用它？
7. 哪些竞赛数据适合放在全局作用域，哪些更适合留在局部？
8. 为什么作用域与生命周期不能视为同一个概念？

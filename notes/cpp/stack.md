# 容器适配器：stack

> 最近修订：2026-08-13 21:34 +10:00（未审阅）

[栈](../algorithm-basics/stack.md) 已经解释后进先出（LIFO）、数组实现和 `push`、`top`、`pop`、`empty` 四个抽象操作。实际比赛通常不需要重新实现普通栈，标准库 `stack` 已经提供了完全对应的受限接口。

本篇只学习怎样可靠地使用这个接口。括号匹配、出栈序列、表达式求值和单调栈分别有自己的问题模型，不在标准库文章中重新展开。

## 声明一个 stack

`stack` 是类模板，尖括号中填写元素类型：

```cpp
stack<int> st;
```

此时建立了一个保存 `int` 的空栈。变量名 `st` 是竞赛代码中常用的 stack 缩写；语境复杂时也可以使用更明确的名称，例如 `operators`、`values` 或 `history`。

保存其他类型时只需替换模板参数：

```cpp
stack<char> brackets;
stack<pair<int, int>> positions;
```

标准头文件是 `<stack>`。本仓库完整竞赛代码统一使用：

```cpp
#include <bits/stdc++.h>
using namespace std;
```

因此不需要另外列出 `<stack>`。

## 压入栈顶

`push(value)` 把一个新元素放到栈顶：

```cpp
st.push(3);
st.push(5);
st.push(8);
```

此时从栈底到栈顶依次是：

```text
3 5 8 <- top
```

最后压入的 `8` 成为最先能够访问和删除的元素。

## 读取栈顶

`top()` 返回当前栈顶元素：

```cpp
int value = st.top();
```

这一步只读取 `8`，不会删除它。再次调用 `st.top()` 仍然得到 `8`。

`top()` 实际返回栈顶对象的引用，因此也可以直接修改：

```cpp
st.top() = 10;
```

此后栈顶从 `8` 变成 `10`。普通算法更常把它当作读取接口；只有题意确实要修改最上层状态时才直接赋值。

## 删除栈顶

`pop()` 删除栈顶：

```cpp
st.pop();
```

标准库 `pop()` 的返回类型是 `void`，它不会返回被删除的元素。需要“取出并删除”时必须先保存 `top()`，再调用 `pop()`：

```cpp
int value = st.top();
st.pop();
```

顺序不能交换。先 `pop()` 会删除原栈顶，随后 `top()` 读取到的是下一个元素；若原来只有一个元素，删除后再访问还会落到空栈。

不要保留即将删除元素的引用：

```cpp
int& value = st.top();
st.pop();
```

`pop()` 已经销毁原栈顶，`value` 此后失效，不能继续使用。需要保留数值时像前一个例子一样复制到普通变量。

## 判断是否为空

`empty()` 返回栈是否没有元素：

```cpp
if (st.empty()) {
    printf("empty\n");
}
```

`top()` 和 `pop()` 都要求栈非空。在输入操作不保证合法时，必须先判断：

```cpp
if (!st.empty()) {
    int value = st.top();
    st.pop();
}
```

空栈上调用 `top()` 或 `pop()` 是未定义行为，不会自动返回 `0`、`-1` 或抛出一个可以依赖的竞赛结果。

若题面已经明确保证每次查询和删除前栈非空，代码可以直接调用，但应当能指出这个前置条件来自哪里。

## 查询元素数量

`size()` 返回当前栈中的元素数量：

```cpp
int count = st.size();
```

标准库实际返回无符号的 `size_type`。竞赛题已经保证数量能放进 `int` 时，本书按照统一风格直接保存为 `int`。

以下关系始终成立：

```cpp
st.empty() == (st.size() == 0)
```

只判断有没有元素时使用 `empty()` 更直接；真正需要数量时使用 `size()`。

## 接口对应关系

标准库接口与抽象栈完全对应：

| 抽象操作 | `stack` 接口 | 作用 |
| --- | --- | --- |
| 压栈 | `st.push(value)` | 在栈顶加入元素 |
| 查看栈顶 | `st.top()` | 返回栈顶引用，不删除 |
| 弹栈 | `st.pop()` | 删除栈顶，不返回元素 |
| 判空 | `st.empty()` | 判断是否没有元素 |
| 查询数量 | `st.size()` | 返回当前元素数 |

在默认底层容器下，这五个操作都是 $O(1)$。保存 $n$ 个元素需要 $O(n)$ 空间。

## 为什么叫容器适配器

`stack` 本身不规定一套新的底层存储。它把一个已有序列容器限制成只允许访问末端，并把末端操作重新命名为栈接口：

```text
底层末端加入     -> push
底层末端元素     -> top
底层末端删除     -> pop
```

这种把已有容器接口改造成另一种受限行为的类型称为容器适配器（container adaptor）。`stack<int>` 默认使用 `deque<int>` 作为底层容器。

也可以显式指定 `vector`：

```cpp
stack<int, vector<int>> st;
```

普通竞赛代码没有明确原因时保留默认写法 `stack<int>`。算法依赖的是后进先出接口，不应依赖底层恰好使用哪一种容器。

## 受限接口的意义

`stack` 不提供 `operator[]`，不能写：

```cpp
// st[0]  // 不存在这个接口
```

它也不提供 `begin()`、`end()`，不能直接使用范围 `for` 遍历。只能反复读取并弹出栈顶，才能按照从顶到底的顺序访问全部元素，而这会清空原栈。

受限不是缺陷。选择 `stack` 正是在代码中声明：这个算法只应该看到最近压入且尚未删除的元素。若需要随机访问、遍历或保留全部元素后反复查看，应使用 `vector`、`deque` 或其他真正符合操作需求的容器。

## 操作序列程序

为了集中验证全部接口，定义五类操作：

| 类型 | 输入 | 行为 |
| ---: | --- | --- |
| 1 | `1 value` | 把 `value` 压栈 |
| 2 | `2` | 输出并删除栈顶 |
| 3 | `3` | 输出栈顶但不删除 |
| 4 | `4` | 输出元素数量 |
| 5 | `5` | 空栈输出 `1`，否则输出 `0` |

输入保证类型 `2`、`3` 出现时栈非空。

类型 `1` 直接调用 `push`：

```cpp
int value;
scanf("%d", &value);
st.push(value);
```

类型 `2` 必须先复制栈顶再删除：

```cpp
int value = st.top();
st.pop();
printf("%d\n", value);
```

其余查询不会修改栈：

```cpp
printf("%d\n", st.top());
printf("%d\n", (int)st.size());
printf("%d\n", st.empty());
```

`bool` 传给 `printf` 时会提升为 `int`，因此用 `%d` 输出 `empty()` 会得到 `0` 或 `1`。

## 完整代码

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int q;
    scanf("%d", &q);

    stack<int> st;

    for (int i = 1; i <= q; i++) {
        int type;
        scanf("%d", &type);

        if (type == 1) {
            int value;
            scanf("%d", &value);
            st.push(value);
        } else if (type == 2) {
            int value = st.top();
            st.pop();
            printf("%d\n", value);
        } else if (type == 3) {
            printf("%d\n", st.top());
        } else if (type == 4) {
            printf("%d\n", (int)st.size());
        } else if (type == 5) {
            printf("%d\n", st.empty());
        }
    }

    return 0;
}
```

输入：

```text
9
1 3
1 5
3
4
2
3
5
2
5
```

输出：

```text
5
2
5
3
0
3
1
```

执行结束时栈为空。

## 常见错误

### 认为 pop 会返回元素

不能写 `int value = st.pop()`。标准库把读取与删除分成 `top()` 和 `pop()` 两个操作，需要值时先读取再删除。

### 空栈访问 top 或 pop

`empty()` 不是只用于输出的附加接口。题面没有保证操作合法时，必须在读取或删除以前判空。

### 删除后继续使用栈顶引用

`top()` 返回引用，但 `pop()` 会销毁它所指向的对象。需要在弹栈后使用原值时保存一份副本。

### 试图使用下标或迭代器

`stack` 故意不暴露中间元素，也不能直接遍历。若算法需要这些操作，容器选择已经不符合问题语义。

### 为普通用法指定底层容器

`stack<int, vector<int>>` 是合法接口，但不应把它当成每道题都要填写的固定模板。默认 `stack<int>` 更短，也不让算法代码依赖无关实现选择。

### 用 size 反复模拟栈顶下标

标准库已经维护元素数量和栈顶。不要另建一个可能与真实容器不同步的 `top_index`；只有自己实现数组栈时才需要它。

## 基础练习

1. 手动模拟完整代码样例，写出每一步栈中从底到顶的元素。
2. 测试只压入一个元素后分别调用 `top()`、`size()`、`empty()`，确认查询不改变栈。
3. 增加操作类型 `6`，在栈非空时清空全部元素并输出删除数量。
4. 用 `stack<char>` 把一段不含空格的字符串逆序输出。
5. 把抽象栈文章中的括号匹配实现改成 `stack<char>`，保持算法判断逻辑不变。
6. 对随机合法操作序列，用 `vector<int>` 的 `push_back`、`back`、`pop_back` 建立独立模型，与 `stack<int>` 输出对拍。

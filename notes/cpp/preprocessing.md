# 预处理

> 最近修订：2026-08-16 16:10 +10:00（未审阅）

C++ 编译器真正分析类型、表达式和函数以前，源文件会先经过**预处理**。以 `#`
开头的预处理指令能够包含头文件、定义宏或根据条件保留一部分代码；处理结果再
进入后续编译。

预处理器主要处理记号和文件内容，不理解 `int` 是否适合某个表达式，也不会执行
程序的运行时控制流。把这一阶段与普通 C++ 分开，才能理解为什么 `#include` 不写
分号、宏没有类型，以及条件编译为什么不能替代 `if`。

## 从源文件到翻译单元

对日常竞赛代码，可以把前半段构建过程简化为：

```text
源文件
  ↓ 预处理：处理 include、宏和条件编译
预处理后的翻译单元
  ↓ 编译与生成目标代码
目标文件
  ↓ 链接
可执行文件
```

一个 `.cpp` 连同它通过 `#include` 引入的内容，经预处理后形成供编译器处理的
翻译单元。头文件不是预先独立“自动加入项目”的；源文件通过包含指令建立依赖。

真实 C++ 标准规定了更细的翻译阶段，编译器也可能把多个步骤合并实现。本篇模型
用于理解代码和错误出现在哪一层，不代替完整编译原理。

## 预处理指令

指令通常从逻辑行开头的 `#` 开始：

```cpp
#include <iostream>
#define LIMIT 100
#if LIMIT > 50
#endif
```

它们不是普通 C++ 语句，因此末尾不写分号。预处理器先识别指令并产生新的记号
序列；被条件排除的代码不会进入后续语法和类型检查。

反斜杠可以让一条预处理指令延续到下一物理行：

```cpp
#define ADD(a, b) ((a) + (b))
```

这在多行宏中常见，也增加了维护风险。反斜杠后出现空格以外的意外字符，或漏写
某一行的反斜杠，都可能提前结束宏定义。

## include

`#include` 让指定头提供的内容在当前位置参与翻译：

```cpp
#include <vector>
#include "point.h"
```

标准头通常使用尖括号，项目头通常使用双引号；搜索位置与具体实现和编译选项有关。
完整规则见 [#include](include.md)。

一个头可能被多条路径重复包含。传统头文件使用 include guard 防止内容在同一
翻译单元中重复展开；它怎样通过 `#ifndef` 与 `#define` 配合工作，见
[条件编译](conditional-compilation.md#include-guard)。

## 宏定义

`#define` 建立对象式宏或函数式宏，`#undef` 取消定义：

```cpp
#define LIMIT 100
#undef LIMIT
```

宏按预处理规则替换记号，没有 C++ 类型。参数括号、重复求值与名称污染等问题见
[#define 宏](define.md)。本仓库不用宏压缩常量、类型、循环或树节点公式。

## 条件编译

预处理器可以根据宏是否存在或整数条件选择哪些代码进入本次编译：

```cpp
#ifdef LOCAL
cerr << "debug\n";
#endif
```

只有定义了 `LOCAL`，中间代码才进入编译。`#if`、`#ifdef`、`#ifndef`、
`#elif`、`#else`、`#endif`、`defined(...)`、命令行 `-D`、include guard 和
预定义宏统一在 [条件编译](conditional-compilation.md) 中解释。

## pragma

`#pragma` 为实现提供额外控制入口：

```cpp
#pragma once
```

具体 pragma 的含义通常由编译器规定。未知 pragma 的处理也遵循实现规则，因此
不要把某个编译器的优化、打包或警告 pragma 当成跨平台 C++ 语义。

算法竞赛中偶尔能见到用 pragma 强制目标指令集或优化级别的代码。它可能使程序
无法在评测机器运行，也不能修复复杂度不足；本仓库模板不依赖这些指令。

## 查看预处理结果

编译器通常提供只运行预处理的选项。GNU C++ 可以使用：

```text
g++ -std=c++17 -E main.cpp
```

输出可能非常长，因为标准头的内容也被展开。它适合检查宏最终变成了什么、某个
条件分支是否保留，以及头文件从哪里进入翻译单元。

这是 GNU 工具接口，不是程序需要提交给评测机的代码。

## 完整代码

下面用对象式宏展示预处理结果怎样进入后续编译；实际竞赛代码应当使用有类型的
`const` 常量：

```cpp
#include <bits/stdc++.h>
using namespace std;

#define ANSWER 42

void solve() {
    cout << ANSWER << '\n';
}

int main() {
    solve();
    return 0;
}
```

输出：

```text
42
```

使用 `g++ -E` 查看时，程序中的 `ANSWER` 已经被替换为 `42`。宏的类型和求值
陷阱由 [预处理：`#define`](define.md) 继续解释。

## 常见错误

### 把预处理指令当成普通语句

指令不写分号，也不遵循函数块中的运行时执行顺序。

### 依赖非标准 pragma 修复算法

实现专属优化可能不被评测环境支持，也不会改变错误的渐进复杂度。

# 函数：参数传递

> 最近修订：2026-08-13 02:43 +10:00（未审阅）

[函数：定义与调用](function-definition-and-calls.md) 已经说明实参按位置提供给形参，但“提供”并不只有一种方式。函数有时只需要获得一个值的副本，有时必须修改调用处的对象，有时则希望只读一个大型对象而不复制。

**参数传递方式**决定形参与实参之间的关系。基础竞赛代码最常用值参数、引用参数、`const` 引用参数和指针参数。

## 值传递

普通形参声明会从实参初始化一个新的局部对象：

```cpp
void add_one(int x) {
    x++;
}
```

调用：

```cpp
int value = 10;
add_one(value);
```

进入函数时，形参 `x` 得到整数 `10` 的副本。`x++` 只把副本改成 `11`；调用结束后，原变量 `value` 仍然是 `10`。

可以把关系画成：

```text
调用处 value：10
             │ 复制值
             ▼
函数内     x：10 → 11
```

值传递适合两类情况：

- 函数只需要读取小型值，例如 `int`、`char`、`bool`；
- 函数本来就需要一份可以独立修改的副本。

形参是独立对象，因此函数内对它的赋值、递增和交换都不会修改实参。

## 引用传递

在形参类型中加入 `&`，形参会成为实参对象的引用：

```cpp
void add_one(int& x) {
    x++;
}
```

调用方式不变：

```cpp
int value = 10;
add_one(value);
```

但这次 `x` 是 `value` 的别名，没有整数副本：

```text
函数内 x ──别名──> 调用处 value：10 → 11
```

函数返回后，`value` 是 `11`。

非 `const` 引用参数明确表示函数可能修改实参。调用它时，实参必须是能够被修改并且类型匹配的对象：

```cpp
add_one(10);
```

普通字面量 `10` 没有可供函数长期修改的调用处变量，不能绑定到 `int&`。

## const 引用传递

有时函数不应修改实参，却又不希望复制整个对象。`const` 引用把形参绑定到原对象，但只允许读取：

```cpp
struct Contestant {
    int id;
    int score;
};

void print_contestant(const Contestant& contestant) {
    printf("%d %d\n", contestant.id, contestant.score);
}
```

这里没有复制 `Contestant`，函数也不能通过 `contestant` 修改成员。`const T&` 适合只读的大型结构体、`string`、`vector` 等对象。

对 `int`、`char` 等小型基础类型，值传递通常更简单：

```cpp
int square(int x) {
    return x * x;
}
```

不要机械地把所有参数都写成引用。先问两个问题：函数是否需要修改调用处对象？复制这个类型是否值得避免？

`const` 的系统规则会在 [修饰符：const](const.md) 中单独整理；当前把 `const T&` 理解为“不复制、只读取原对象”的参数即可。

## 指针参数

指针参数本身仍然按值传递：函数得到一份地址副本。但这个地址仍然指向调用处对象，所以解引用后可以修改原对象：

```cpp
void add_one(int* p) {
    (*p)++;
}
```

调用时明确传入地址：

```cpp
int value = 10;
add_one(&value);
```

`p` 是 `&value` 的副本，`*p` 是原对象 `value`。因此函数返回后 `value` 变成 `11`。

引用与指针都能修改原对象，但调用语义不同：

```cpp
add_one_by_reference(value);
add_one_by_pointer(&value);
```

引用参数表示目标必须存在；指针参数还可以用 `nullptr` 表示没有目标：

```cpp
void print_if_present(const int* p) {
    if (p != nullptr) {
        printf("%d\n", *p);
    }
}
```

函数若接受空指针，就必须在解引用前检查。目标始终存在且不需要改变指向时，引用参数通常更直接；“可能没有对象”是选择指针参数的真实理由。

给指针形参本身重新赋值，不会改变调用处的指针，因为地址也被复制了一份：

```cpp
void clear_pointer(int* p) {
    p = nullptr;
}
```

它只把函数内的 `p` 改为空，不会修改调用处指针保存的地址。要修改指针变量本身，需要更进一步的指针引用或多级指针，不属于本篇基础。

## 数组参数

把内置数组写在函数参数中时，它会调整为指向首元素的指针：

```cpp
void clear(int a[], int n) {
    for (int i = 1; i <= n; i++) {
        a[i] = 0;
    }
}
```

调用：

```cpp
int value[4] = {0, 10, 20, 30};
clear(value, 3);
```

函数中的 `a[i]` 访问原数组元素，所以修改会保留在调用处。参数写作 `int a[]` 不会复制整个数组，也不会自动知道长度。

因此数组参数通常还要单独传递实际长度 `n`。在函数内部，`sizeof(a)` 得到的是指针大小，不是原数组容量：

```cpp
void inspect(int a[]) {
    printf("%zu\n", sizeof(a));
}
```

编译器通常会警告这里的 `sizeof` 作用于数组形参。数组长度必须由调用者明确传入，不能在被调函数中用 `sizeof(a) / sizeof(a[0])` 恢复。

`int a[]` 与 `int* a` 在函数参数位置表达同一种调整后的类型。本书在算法函数中常写 `int a[]`，提醒读者它按数组下标使用；理解底层关系时则明确它实际是指针参数。

如果选择内置定长数组，最大容量在编译前已经确定的大型数组通常声明为全局变量，让 `solve` 和辅助函数直接使用。这样既避免把大型局部数组放进调用栈，也避开多维数组冗长的参数类型。这是传统一次性竞赛代码的简单方案，不表示可复用模板都应暴露全局静态数组。

学习 `vector` 后，可复用的数据结构通常可以用 `struct` 封装，并在内部按实际规模分配 `vector`。需要把动态数组交给普通函数修改时，一般传递 `vector<int>&`；只读取时传递 `const vector<int>&`。非 `const` 引用允许函数修改元素，也允许它改变 `vector` 的长度，因此函数是否只改元素仍要由接口约定和实现保证。

`array` 适合长度在编译期确定、希望像普通对象一样复制或使用 STL 接口的小型定长序列。它的长度是类型的一部分，传引用时不会退化成指针；但嵌套多维 `array` 的类型很长，也不能解决大型局部对象占用调用栈的问题，所以它通常不会取代竞赛中的全局静态数组。

多维内置数组只能退化最外面一维、为什么必须保留后续维度，以及 `int**` 为什么不能接收普通二维数组，集中写在扩展篇 [数组：多维数组的布局与参数传递](multidimensional-array-layout-and-parameters.md) 中。

## 返回值与输出参数

函数只产生一个自然结果时，优先使用返回值：

```cpp
int maximum(int a, int b) {
    if (a > b) {
        return a;
    }
    return b;
}
```

调用表达式 `maximum(a, b)` 可以直接用于初始化、比较或更大表达式，含义清楚。

函数需要同时产生多个结果时，引用参数可以充当输出位置。例如同时计算整数除法的商和余数：

```cpp
void divide(int a, int b, int& quotient, int& remainder) {
    quotient = a / b;
    remainder = a % b;
}
```

调用处准备两个变量：

```cpp
int quotient;
int remainder;
divide(a, b, quotient, remainder);
```

看到非 `const` 引用参数时，要检查它是输入、输出还是读写两者。准确的函数名与形参名应让这种关系尽量明确。

若多个结果天然属于一个整体，也可以定义 `struct` 并按值返回。现代编译器通常能高效处理这种返回；不要只为了避免一个简单结构体返回值而制造许多输出参数。

## 选择方式

| 需求 | 常用形参 |
| --- | --- |
| 读取小型值 | `int x` 等值参数 |
| 需要独立副本 | `T value` |
| 修改必须存在的实参 | `T& value` |
| 只读且避免复制大型对象 | `const T& value` |
| 目标可能不存在 | `T* p` 或 `const T* p` |
| 内置数组及其长度 | `T a[]` 与 `int n` |

选择参数方式是接口语义，不是固定的性能口诀。小型整数按值传递最自然；大型只读对象才有必要用 `const` 引用避免复制。

## 完整代码

输入两个整数，通过引用参数交换它们，再输出结果。先保存 `a` 的旧值，随后依次覆盖两个原对象：

```cpp
#include <bits/stdc++.h>
using namespace std;

void swap_values(int& a, int& b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int a;
    int b;
    scanf("%d%d", &a, &b);

    swap_values(a, b);
    printf("%d %d\n", a, b);
    return 0;
}
```

输入：

```text
3 5
```

输出：

```text
5 3
```

如果把函数头部误写成 `void swap_values(int a, int b)`，函数只会交换两个副本，调用处仍然输出 `3 5`。

标准库已经提供 `swap(a, b)`；这里手写函数是为了观察引用参数怎样把修改带回调用处，不是要求以后重复实现交换。

## 常见错误

### 以为值参数会修改实参

普通形参是独立副本。需要修改调用处对象时，接口必须明确使用引用或指针。

### 为所有小型参数使用 const 引用

`const int&` 通常不比 `int` 更清楚或更快。基础数值按值传递，大型只读对象再使用 `const` 引用。

### 解引用可能为空的指针

指针参数若允许 `nullptr`，函数必须先检查。引用参数则表达目标必定存在。

### 试图在数组参数中用 sizeof 求长度

内置数组传参后调整为指针，函数不再拥有原数组容量信息。显式传递 `n`。

### 输出参数没有在所有路径赋值

函数承诺通过非 `const` 引用写出结果时，每条合法执行路径都要完成赋值，避免调用处读取未初始化变量。

## 需要记住什么

1. 值参数与实参是同一对象，还是由实参初始化的副本？
2. 为什么修改 `T&` 形参会修改调用处对象？
3. 哪些对象适合按值传递，哪些只读对象适合 `const T&`？
4. 指针形参本身是按值还是按引用传递？为什么 `*p` 仍能修改原对象？
5. 引用参数与指针参数怎样表达“目标是否可能不存在”？
6. 内置数组作为参数时会调整成什么？为什么还要传递长度？
7. 一个自然结果为什么优先使用返回值？多个结果可以怎样返回？
8. 若 `swap_values` 使用两个 `int` 值参数，为什么交换不会保留到调用处？

多级指针、转发引用、完美转发、移动语义和 ABI 层面的传参方式都不属于基础竞赛用法，不要求理解或记忆。

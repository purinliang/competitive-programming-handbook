# 预处理：`#define`

> 最近修订：2026-08-16 16:10 +10:00（未审阅）

竞赛代码里经常能见到这样的写法：

```cpp
#define MAXN 200005
#define FOR(i, l, r) for (int i = l; i <= r; i++)
```

它们看起来像常量或函数，却没有声明 C++ 对象。`#define` 是预处理指令：在
C++ 编译器分析类型和表达式以前，预处理器先按照规则替换源代码中的记号。

宏可以缩短代码，也很容易隐藏类型、优先级和求值次数。本书需要能够读懂常见宏，
但竞赛模板不会用它压缩常量、类型、循环或树的左右儿子。

## 不带参数的宏

最简单的宏为一个名字规定替换内容：

```cpp
#define MAXN 200005
```

后续代码中的 `MAXN` 会在预处理阶段被替换成 `200005`。末尾不写分号，因为这
不是普通 C++ 语句。

宏只是文本层面的名字，没有 C++ 类型，也不服从普通变量的块作用域。表示有类型
的常量时，本书使用 `const`：

```cpp
const int MAXN = 200005;
```

这样编译器知道 `MAXN` 是 `int`，报错和调试信息也仍然保留这个名字。

## 带参数的宏

宏也可以接收参数：

```cpp
#define SQUARE(x) ((x) * (x))
```

预处理器遇到：

```cpp
int answer = SQUARE(a + 1);
```

会得到近似下面的代码，再交给编译器：

```cpp
int answer = ((a + 1) * (a + 1));
```

宏定义中的 `SQUARE` 与左括号之间不能留空格，否则它会变成不带参数的宏，替换
内容从 `(x)` 开始。

## 括号与运算符优先级

如果宏没有为参数和整个结果加括号：

```cpp
#define BAD_SQUARE(x) x* x
```

那么 `BAD_SQUARE(a + 1)` 会展开为：

```cpp
a + 1 * a + 1
```

乘法先于加法，结果不再是 $(a+1)^2$。即使写成 `((x) * (x))`，也只是修复了
这类优先级问题，并没有让宏真正变成函数。

## 重复求值

参数在替换内容中出现几次，传入的表达式就可能被求值几次：

```cpp
SQUARE(get_value())
```

会调用两次 `get_value()`。传入 `x++`、输入操作或会修改状态的函数时，结果可能
错误，甚至触发未定义行为。

普通函数会先求出每个实参，再把结果传给形参：

```cpp
int square(int x) {
    return x * x;
}
```

因此，只要普通函数足够表达目的，本书就使用函数，不使用带参数的运算宏。

## 多条语句的宏

有些旧代码把多条语句包装成宏。直接使用花括号仍可能与外层 `if` 和 `else` 的
分号结合出错，因此常见写法是：

```cpp
#define UPDATE(a, b)                                                           \
    do {                                                                       \
        (a) += (b);                                                            \
        (b) = 0;                                                               \
    } while (0)
```

`do { ... } while (0)` 只执行一次，却让整个展开结果在语法上表现得像一条语句。
这里的目的只是帮助读者识别已有代码；本书不会为了这种宏提前学习或推广
`do while`。

多行宏末尾的反斜杠表示定义在下一行继续。反斜杠后不能再放普通字符；维护这种
代码比维护函数更容易出错。

## 常见竞赛缩写

下面的宏在旧竞赛代码中很常见：

```cpp
#define FOR(i, l, r) for (int i = (l); i <= (r); i++)
#define REP(i, n) for (int i = 0; i < (n); i++)
#define ls (u * 2)
#define rs (u * 2 + 1)
```

它们节省的字符很少，却把变量范围、区间端点和树节点公式藏在自定义缩写里。
本仓库显式书写 `for`、`u * 2` 和 `u * 2 + 1`，让代码能够从语义直接阅读。

## 取消宏定义

宏从定义位置开始影响后续预处理，不服从函数或代码块的花括号作用域。如果没有
主动取消，它会持续到当前预处理输入结束；可以使用 `#undef` 提前取消定义：

```cpp
#define SQUARE(x) ((x) * (x))

int answer = SQUARE(5);

#undef SQUARE
```

这能限制宏继续污染后面的代码，但不能消除定义区间内的类型和求值陷阱。

`#ifdef`、`#ifndef`、`#if`、`#elif`、`#else` 和 `#endif` 等指令统一在
[条件编译](conditional-compilation.md) 中解释；它们根据宏和预处理整数条件决定
哪些代码会进入编译，不是 `#define` 本身的另一种类型。

## 完整代码

下面的程序先用一个带足括号的宏演示预处理替换，再用普通函数完成同一任务。
传给宏的参数没有副作用，因此两者结果相同：

```cpp
#include <bits/stdc++.h>
using namespace std;

#define SQUARE(x) ((x) * (x))

int square(int x) {
    return x * x;
}

void solve() {
    int x;
    cin >> x;

    cout << SQUARE(x + 1) << '\n';
    cout << square(x + 1) << '\n';
}

int main() {
    solve();
    return 0;
}

#undef SQUARE
```

输入：

```text
4
```

输出：

```text
25
25
```

实际竞赛代码应直接保留 `square` 函数；宏只为了展示本篇讨论的替换行为。

## 常见错误

### 把宏当成有类型的常量

`#define MAXN 200005` 只替换记号。需要整数常量时使用
`const int MAXN = 200005;`。

### 只给整个宏加括号

参数本身和整个结果都可能与外层运算符结合。即使括号完整，重复求值仍然存在。

### 向参数宏传入有副作用的表达式

宏不会保证一个参数只求值一次。不要把 `x++` 或修改状态的函数调用传给重复使用
参数的宏。

### 用宏代替类型别名

`#define ll long long` 仍然是文本替换。类型别名应使用 `typedef` 或 `using`；
后续 [`typedef` 类型别名](typedef-type-alias.md) 与
[`using` 类型别名](using-type-aliases.md) 会分别解释两种写法。

3. 参数宏为什么需要为每个参数和整个结果加括号？

# 一维数组

> 最近修订：2026-08-16 10:24 +10:00（未审阅）

只需要保存一个整数时，可以声明一个 `int`。如果题目给出 $n$ 个整数，并且后面还要根据位置反复查询它们，给每个数手动起一个变量名既不现实，也无法用循环处理。

**数组**用一个名字保存固定数量、类型相同的元素，再用下标区分每个元素。

## 声明数组

下面的语句声明一个能保存 $5$ 个 `int` 的数组：

```cpp
int a[5];
```

- `int` 是每个元素的类型；
- `a` 是数组名；
- `[5]` 表示数组容纳 $5$ 个元素。

C++ 数组的第一个下标是 `0`，因此这 $5$ 个元素依次是：

| 下标 | `0` | `1` | `2` | `3` | `4` |
| --- | --- | --- | --- | --- | --- |
| 元素 | `a[0]` | `a[1]` | `a[2]` | `a[3]` | `a[4]` |

容量是 $5$ 时，最后一个合法下标是 $4$，不是 $5$。

## 访问元素

数组名后的方括号表示要访问的下标。可以像普通变量一样读取或修改某个元素：

```cpp
a[0] = 10;
a[1] = 20;

int x = a[0];
a[1] = a[0] + 5;
```

下标不必是直接写出的数字，也可以是整数变量或表达式：

```cpp
int i = 2;
a[i] = 30;
a[i + 1] = 40;
```

这正是数组可以配合循环的原因。对于任意合法下标 `i`，读取或修改 `a[i]` 都只需要 $O(1)$ 时间。

## 容量与实际长度

竞赛题目通常在运行时读入实际长度 `n`，但会在题面中给出它的最大范围。先根据最大范围定义容量，再将 `n` 保存为当前真正使用的元素数量：

```cpp
const int MAXN = 2e5 + 5;

int n;
int a[MAXN];
```

- `MAXN` 是编译时已知的**数组容量**，并且额外留出几个位置；
- `n` 是运行时读入的**实际长度**。

不要用同一个名字混淆容量与实际长度。本书统一用 `MAXN`、`MAXM` 等大写名称表示预留容量，用 `n`、`m` 等小写名称表示实际规模。

```cpp
int a[n];
```

有些编译器将上述变长数组当作扩展接受，但它不是标准 C++17。竞赛代码不使用这种写法；大小需要随运行时数据变化时，后续使用 `vector`。

## 0-based 与 1-based

C++ 数组本身从 `0` 开始。当题目也将元素编号为 $0,1,\ldots,n-1$ 时，可以直接使用 **0-based** 下标：

```cpp
for (int i = 0; i < n; i++) {
    scanf("%d", &a[i]);
}
```

竞赛中许多题目却把第一个元素编号为 $1$。此时常常放弃 `a[0]`，使用 **1-based** 下标：

```cpp
for (int i = 1; i <= n; i++) {
    scanf("%d", &a[i]);
}
```

对于一个长度为 $5$ 的逻辑数组，1-based 存储可以表示为：

| 下标 | `0` | `1` | `2` | `3` | `4` | `5` |
| --- | --- | --- | --- | --- | --- | --- |
| 用途 | 不使用 | 第 1 个 | 第 2 个 | 第 3 个 | 第 4 个 | 第 5 个 |

因为需要访问 `a[n]`，1-based 数组的容量至少是 `n + 1`。`MAXN = limit + 5` 的习惯会同时留出 `a[0]` 和少量安全余量。

0-based 和 1-based 都是正常写法。选择与题面和公式更自然的一种，然后在同一段代码中保持一致。

## 连续存放

数组的元素按下标顺序连续存放在内存中。如果一个 `int` 占 $4$ 字节，那么 `int a[5]` 的 $5$ 个元素总共占 $20$ 字节，中间不会插入其他对象。

连续存放是 C++ 数组的基本性质。数组名与地址、指针之间的具体关系放在后续指针文章中解释。

## 初始化

在函数外声明的全局数组会在程序开始时自动初始化为 $0$：

```cpp
const int MAXN = 2e5 + 5;
int a[MAXN];
```

函数中的普通局部数组不会自动清零：

```cpp
void solve() {
    int a[5];
}
```

在给某个元素赋值前读取它，会使用不确定的内容，属于未定义行为。需要将局部数组全部初始化为 $0$ 时，可以写：

```cpp
int a[5] = {};
```

也可以依次提供初值：

```cpp
int a[5] = {10, 20, 30, 40, 50};
```

初值数量少于数组容量时，未明确列出的后续元素都会初始化为 $0$：

```cpp
int a[5] = {10, 20}; // 10, 20, 0, 0, 0
```

竞赛中的大数组通常声明在函数外。这样它们会自动清零，也避免占用有限的函数调用栈空间。全局名称的可见范围和对象存放时间属于作用域与存储期，本篇只记住这个数组写法。

## 数组越界

C++ 不会在每次数组访问时自动检查下标。对于 `int a[5]`，只有 `a[0]` 到 `a[4]` 是该数组内的元素：

```cpp
int a[5] = {};
a[5] = 10;  // 越界
a[-1] = 20; // 越界
```

越界读写都是未定义行为。程序可能立即崩溃，也可能看似正常却悄悄改坏其他数据。“这次没有报错”不能证明下标合法。

检查循环边界时，同时写出逻辑下标范围：

- 0-based 长度 `n`：`0 <= i && i < n`；
- 1-based 长度 `n`：`1 <= i && i <= n`。

还要确认最大逻辑下标没有超过实际声明的数组容量。

## sizeof 与元素数量

`sizeof` 可以得到对象占用的字节数。对当前作用域中的完整数组使用 `sizeof`，得到整个数组的字节数：

```cpp
int a[10];

printf("%zu\n", sizeof(a));
printf("%zu\n", sizeof(a[0]));
printf("%zu\n", sizeof(a) / sizeof(a[0]));
```

在 `int` 占 $4$ 字节的常见竞赛环境中，三行依次输出 $40$、$4$ 和 $10$。
“整个数组的字节数除以一个元素的字节数”，得到声明时的数组容量。

这个公式只能对当前仍然是完整数组的名称使用。将数组作为函数参数后，它的类型会发生调整，不能在被调函数内用同一公式求原数组长度。该规则需要指针和函数参数知识，目前只要不在函数参数上套用此公式。

## 完整代码

下面的程序读入 $n$ 个整数并按 1-based 下标保存。随后每次读入一个下标 `x`，输出原序列第 `x` 个整数：

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 2e5 + 5;

int n;
int a[MAXN];

void solve() {
    scanf("%d", &n);
    for (int i = 1; i <= n; i++) {
        scanf("%d", &a[i]);
    }

    int q;
    scanf("%d", &q);
    while (q--) {
        int x;
        scanf("%d", &x);
        printf("%d\n", a[x]);
    }
}

int main() {
    solve();
    return 0;
}
```

例如，输入：

```text
5
8 3 6 1 9
3
1
4
5
```

输出：

```text
8
1
9
```

读入整个数组需要 $O(n)$ 时间。每次通过下标查询一个元素需要 $O(1)$ 时间，$q$ 次查询总共需要 $O(q)$ 时间。数组保存 $n$ 个有效整数，空间复杂度为 $O(n)$。

## 常见错误

### 把容量当成实际长度

`MAXN` 只说明数组最多能容纳多少位置；真正参与输入和计算的元素数量仍由 `n`
决定。遍历到 `MAXN` 会读到题目没有提供的区域。

### 混用两套下标

若逻辑序列使用 1-based 下标，就从 `1` 遍历到 `n`；若直接使用 C++ 原生的
0-based 下标，就从 `0` 遍历到 `n - 1`。不要在一个循环中混合两组边界。

### 读取未初始化的局部数组

函数内的普通数组不会自动清零。必须先通过初始化式、输入或赋值写入元素，再
读取它。

### 只检查循环次数，不检查最大下标

执行恰好 `n` 次不代表下标一定合法。还要写出第一项和最后一项分别访问哪里，
确认最大下标小于声明容量。

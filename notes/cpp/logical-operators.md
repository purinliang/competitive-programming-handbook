# 逻辑运算符

> 最近修订：2026-08-17 10:05 +10:00（未审阅）

一次 [比较](comparison-operators.md) 只能回答一个关系是否成立，但题目经常同时提出多个要求：一个数既要不小于下界，又要不大于上界；选手满足年龄条件或持有特别许可即可报名；某个位置没有被禁止时才能使用。

C++ 使用**逻辑运算符**组合这些布尔条件。最常用的三个逻辑运算符是：

| 运算符 | 读法 | 结果为 `true` 的条件 |
| --- | --- | --- |
| `&&` | 并且 | 左右条件都为 `true` |
| `||` | 或者 | 左右条件至少一个为 `true` |
| `!` | 不是 | 后面的条件为 `false` |

它们的操作数会被当作 `bool`，结果也仍然是 `bool`。

## 并且

判断整数 `x` 是否属于闭区间 $[l,r]$，需要同时检查下界和上界：

```cpp
bool above_lower_bound = l <= x;
bool below_upper_bound = x <= r;
bool inside = above_lower_bound && below_upper_bound;
```

只有前两个条件都成立，`inside` 才是 `true`。通常可以直接写成：

```cpp
bool inside = l <= x && x <= r;
```

这正是数学连续不等式在 C++ 中的写法。每个比较各自产生一个 `bool`，`&&` 再要求两个结果同时成立。

`&&` 的真值表如下：

| `a` | `b` | `a && b` |
| --- | --- | --- |
| `false` | `false` | `false` |
| `false` | `true` | `false` |
| `true` | `false` | `false` |
| `true` | `true` | `true` |

## 或者

假设分数位于 $[0,10]$ 或 $[90,100]$ 时都属于特殊区间：

```cpp
bool in_lower_interval = 0 <= score && score <= 10;
bool in_upper_interval = 90 <= score && score <= 100;
bool special = in_lower_interval || in_upper_interval;
```

`||` 表示至少一个条件成立。左右都成立时，结果仍然是 `true`；它不是“恰好一个成立”。

| `a` | `b` | `a || b` |
| --- | --- | --- |
| `false` | `false` | `false` |
| `false` | `true` | `true` |
| `true` | `false` | `true` |
| `true` | `true` | `true` |

题面中的“或者”有时表示至少一个，有时要求恰好一个。必须从题意判断，不能看见“或”字就机械使用 `||`。若要求两个条件恰好一个成立，可以在条件已经是 `bool` 时比较它们是否不同：

```cpp
bool exactly_one = a != b;
```

## 不是

`!` 把真假结果反转：

```cpp
bool blocked = x == 5;
bool available = !blocked;
```

| `a` | `!a` |
| --- | --- |
| `false` | `true` |
| `true` | `false` |

如果已经能直接写出肯定形式，通常不必额外取反。例如下面两种写法含义相同：

```cpp
bool available = !(x == 5);
bool available = x != 5;
```

第二种更直接。但当变量本身表示一种状态时，`!visited`、`!blocked` 和 `!finished` 都很自然。

连续写两次逻辑非可以把整数规范成 `bool`：

```cpp
bool flag = !!x;
```

整数 `0` 得到 `false`，任何非零整数得到 `true`。这种写法偶尔用于强调“只保留
真假”，但直接写 `x != 0` 通常更容易读。

## 从题意拆出条件

不要一开始就把所有内容挤进一行。先给每个题意条件一个准确名称，再按“并且”“或者”“不是”组合。

例如，整数 `x` 合法需要满足：

1. `x` 位于 $[0,10]$ 或 $[90,100]$；
2. `x` 不能等于 $5$。

先分别定义两个区间：

```cpp
bool in_lower_interval = 0 <= x && x <= 10;
bool in_upper_interval = 90 <= x && x <= 100;
```

再把两个区间合并为候选范围：

```cpp
bool in_allowed_interval = in_lower_interval || in_upper_interval;
```

最后定义禁止状态并排除它：

```cpp
bool blocked = x == 5;
bool accepted = in_allowed_interval && !blocked;
```

这种分解让变量名称直接对应题面。确认逻辑后，可以按可读性需要保留这些中间变量；不必为了追求短而强行压成一个难以检查的表达式。

## 短路求值

逻辑与和逻辑或从左到右计算，并且可能跳过右边：

- `a && b` 中，若 `a` 已经是 `false`，整体不可能成立，因此不再计算 `b`；
- `a || b` 中，若 `a` 已经是 `true`，整体已经成立，因此不再计算 `b`。

这种规则称为**短路求值**。它不只是优化，还可以保护只有满足前提时才安全的操作。判断 `a / b` 是否大于 $2$ 之前，必须先排除除数为 $0$：

```cpp
bool valid = b != 0 && a / b > 2;
```

当 `b == 0` 时，左边是 `false`，右边的除法不会执行。顺序不能随意交换：

```cpp
bool valid = a / b > 2 && b != 0;
```

这段代码会先计算除法；若 `b == 0`，后面的检查已经来不及了。

短路规则要求左边先写便宜且必要的前提，右边再写依赖这个前提的操作。

## 优先级与括号

在本阶段常见表达式中，可以先按下面的顺序理解：

1. 圆括号 `()`；
2. 逻辑非 `!`；
3. 算术与比较表达式；
4. 逻辑与 `&&`；
5. 逻辑或 `||`。

因此：

```cpp
bool accepted = 0 <= x && x <= 10 || 90 <= x && x <= 100;
```

会先完成比较，再分别完成两个 `&&`，最后计算 `||`。不过混合使用 `&&` 和 `||` 时，主动用括号展示题意更容易检查：

```cpp
bool accepted = (0 <= x && x <= 10) || (90 <= x && x <= 100);
```

括号不改变这里的结果，却明确表示“属于第一个区间，或者属于第二个区间”。不要依靠读者背诵优先级来理解复杂条件。

## 德摩根律

有时需要否定一整个组合条件。下面两组关系很常用：

$$
\neg(a\land b)=(\neg a)\lor(\neg b),
$$

$$
\neg(a\lor b)=(\neg a)\land(\neg b).
$$

翻译成 C++：

```cpp
bool not_both = !(a && b);
bool at_least_one_false = !a || !b;
```

上面两个变量始终相等。另一组可以写成：

```cpp
bool neither = !(a || b);
bool both_false = !a && !b;
```

例如，“`x` 不在闭区间 $[l,r]$ 内”可以写成：

```cpp
bool outside = !(l <= x && x <= r);
```

把否定分配进去后是：

```cpp
bool outside = x < l || r < x;
```

第二种直接描述“低于下界或高于上界”，通常更容易读。德摩根律不要求死记符号；先用普通语言说清楚被否定后的条件，再翻译成代码即可。

## 完整代码

现在实现前面的合法值判断：输入一个整数 `x`。若 `x` 位于 $[0,10]$ 或 $[90,100]$，并且不等于被禁止的值 $5$，输出 `true`；否则输出 `false`。

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int x;
    cin >> x;

    bool in_lower_interval = 0 <= x && x <= 10;
    bool in_upper_interval = 90 <= x && x <= 100;
    bool in_allowed_interval = in_lower_interval || in_upper_interval;
    bool blocked = x == 5;
    bool accepted = in_allowed_interval && !blocked;

    cout << boolalpha << accepted << '\n';
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
7
```

输出：

```text
true
```

边界输入 `0`、`10`、`90` 和 `100` 都输出 `true`。输入 `50` 不在任何一个允许区间，输出 `false`；输入 `5` 虽然在第一个区间，却被第二条规则排除，也输出 `false`。

## 常见错误

### 混淆 &&、|| 与 !

先把题意写成“同时满足”“至少一个满足”或“条件不成立”，再选择运算符。不要只看一句话中出现“和”或“或”字，因为自然语言可能省略逻辑关系。

### 把 && 和 || 写成 & 和 |

`&`、`|` 是位运算符，不是本篇的逻辑运算符。虽然某些布尔表达式碰巧能得到相同结果，但它们没有相同的短路行为，也表达了不同的操作。

### 把短路保护写在危险操作之后

`b != 0 && a / b > 2` 会先检查除数；反过来写就失去了保护作用。所有依赖某个前提才能安全执行的操作，都必须放在对应检查之后。

### 省略混合逻辑中的说明性括号

编译器知道 `&&` 比 `||` 优先，但人很容易看错。括号应当展示题目的分组，而不只是满足语法。

## 需要记住什么

1. `&&`、`||`、`!` 分别表示什么？结果是什么类型？
2. `a || b` 是“至少一个成立”还是“恰好一个成立”？
3. 怎样判断 `x` 属于闭区间 $[l,r]$？
4. `a && b` 在什么情况下不会计算 `b`？`a || b` 呢？
5. 为什么 `b != 0 && a / b > 2` 的左右顺序不能交换？
6. 混合使用 `&&` 和 `||` 时，谁的优先级更高？为什么仍建议加括号？
7. “不在 $[l,r]$ 内”怎样写成两个比较与一个逻辑或？
8. 为什么不能用 `&` 和 `|` 代替 `&&` 和 `||`？

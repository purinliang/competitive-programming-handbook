# 析构函数

> 最近修订：2026-08-16 13:37 +10:00（未审阅）

[构造函数](constructors.md) 在对象开始存在时建立有效状态。对象的生命周期结束
时，有些类型还要释放自己取得的资源，例如关闭文件、归还动态内存或释放系统
句柄。**析构函数**在对象销毁时执行这项清理。

大多数竞赛类型只包含 `int`、`vector` 等会自行清理的成员，不需要手写析构函数。
理解它仍然有助于判断局部对象何时消失、容器为什么会自动释放内存，以及多态删除
为什么需要虚析构函数。

## 析构函数的形式

析构函数的名字是波浪号 `~` 加类名，没有返回类型，也不接收参数：

```cpp
class Trace {
public:
    ~Trace() {
        cout << "destroy\n";
    }
};
```

一个类只有一个析构函数，不能像构造函数那样按照不同参数重载。不能给它写
`void`，也不能从调用位置传入实参。

如果类没有声明析构函数，编译器通常会隐式声明一个。它会让对象的成员按照规则
完成销毁；只使用标准容器和普通数值成员时，这往往正是需要的行为。

## 自动对象的销毁

在普通代码块中声明的自动存储期对象，会在执行离开其作用域时自动销毁：

```cpp
void work() {
    Trace trace;
}
```

`work` 正常执行到末尾时调用 `trace` 的析构函数。提前 `return`，或用 `break`、
`continue` 离开包含对象的作用域时，已经完整构造的自动对象也会按规则销毁。

同一作用域中的局部对象通常按照构造完成的相反顺序销毁：

```cpp
Trace first{1};
Trace second{2};
```

`second` 先销毁，`first` 后销毁。这使后建立、可能依赖先建立对象的资源先被归还。

## 成员的销毁顺序

执行一个对象的销毁过程时，先运行它自己的析构函数体，然后非静态数据成员按照
声明顺序的相反顺序销毁。若以后涉及继承，基类部分在派生类部分之后销毁。

成员析构不需要手写调用：

```cpp
class Data {
private:
    vector<int> values;
    string name;
};
```

`Data` 销毁时，`name` 与 `values` 会自动执行各自的析构过程。给 `Data` 写一个
空析构函数不会让这种清理更完整。

## 动态对象与 delete

使用 `new` 建立的动态对象不会因为建立它的局部指针离开作用域而自动销毁：

```cpp
Trace* trace = new Trace{1};
delete trace;
```

`delete trace` 先调用目标对象的析构函数，再释放这次 `new` 取得的存储。数组形式
必须与数组删除匹配：

```cpp
Trace* traces = new Trace[3];
delete[] traces;
```

竞赛代码优先使用普通局部对象、`vector`、`string` 和其他能自动管理资源的标准
类型，尽量不直接配对 `new` 与 `delete`。这既更短，也能避免提前返回时忘记释放。

## RAII

把资源的取得绑定到对象构造，把归还绑定到析构，称为
**资源获取即初始化**（Resource Acquisition Is Initialization，RAII）。名称强调
“资源由对象生命周期管理”，不表示所有资源都必须是初始化表达式中的普通数值。

例如 `vector` 对象建立后管理自己的动态存储；离开作用域时，它的析构函数自动
释放存储。调用者不需要在每个返回分支手动清理：

```cpp
void work(int n) {
    vector<int> values(n);
    if (n == 0) {
        return;
    }
}
```

提前返回仍会销毁 `values`。这是“使用标准容器通常不需要自己写析构函数”的根本
原因之一。

## 不要手动调用析构函数

普通对象的析构由作用域或拥有它的资源管理对象负责。直接写：

```cpp
trace.~Trace();
```

会提前结束对象的生命周期；如果稍后作用域又按照普通规则尝试销毁同一对象，程序
很容易发生未定义行为。显式析构只用于配合放置 `new` 等底层内存管理技术，不是
竞赛中释放局部对象的日常写法。

## 虚析构函数

若通过基类指针执行 `delete`，而指针实际指向派生类对象，基类析构函数通常需要
声明为 `virtual`，才能让完整派生对象按正确层次销毁：

```cpp
virtual ~Base() = default;
```

这不是“所有析构函数都必须是虚函数”。只有类型被设计为通过基类指针多态删除时
才需要这个保证；完整原因在“多态”中结合虚函数解释。

## 完整代码

下面用输出观察嵌套作用域和反向销毁顺序：

```cpp
#include <bits/stdc++.h>
using namespace std;

class Trace {
private:
    int id;

public:
    explicit Trace(int id)
        : id(id) {
        cout << "construct " << id << '\n';
    }

    ~Trace() {
        cout << "destroy " << id << '\n';
    }
};

void solve() {
    Trace first{1};

    {
        Trace second{2};
        cout << "inside\n";
    }

    cout << "outside\n";
}

int main() {
    solve();
    return 0;
}
```

输出：

```text
construct 1
construct 2
inside
destroy 2
outside
destroy 1
```

`second` 在内层作用域结束时先销毁；`first` 一直存在到 `solve` 返回。

## 常见错误

### 为普通容器成员重复释放内存

`vector`、`string` 等成员会自行析构。不要取得它们内部存储后再手动 `delete`。

### new 与 delete 不匹配

单个对象使用 `delete`，数组使用 `delete[]`。更好的竞赛写法通常是避免直接管理
这对操作。

### 手动析构自动对象

普通局部对象会在离开作用域时自动销毁。提前显式调用析构函数会让后续生命周期
极难正确维护。

### 认为所有析构函数都应 virtual

虚函数有其用途与实现成本。只有需要通过基类接口多态销毁的类型才要求虚析构。

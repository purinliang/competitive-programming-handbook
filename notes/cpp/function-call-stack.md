# 调用栈

> 最近修订：2026-08-17 10:10 +10:00（未审阅）

[函数的定义与调用](function-definition-and-calls.md) 已经说明了如何把一段计算拆成函数。但当 `solve()` 调用 `add()` 时，程序还需要解决三个运行时问题：

- `add()` 从哪里得到本次调用的参数？
- `solve()` 暂停时，它已经读入的局部变量保存在哪里？
- `add()` 执行 `return` 后，程序怎样知道应当回到 `solve()` 的哪一行继续？

调用栈用“后进先出”的方式记录尚未结束的函数调用，使这些信息可以层层嵌套，再按相反顺序恢复。

## 一层调用状态

先看一个最小的函数：

```cpp
int add(int a, int b) {
    int result = a + b;
    return result;
}
```

某一次调用 `add(3, 5)` 时，这次调用至少需要保留以下语义信息：

| 信息 | 本次调用中的含义 |
| --- | --- |
| 参数 | `a = 3`、`b = 5` |
| 局部状态 | `result = 8` |
| 返回位置 | `add()` 结束后，回到调用它的位置之后 |

主流运行环境会为一次未完成的函数调用维护一层状态，通常称为栈帧（stack frame）。参数、局部变量、临时结果、保存的寄存器和返回位置中的哪些实际放在栈帧内，由编译器、优化和平台调用约定决定。

本篇把栈帧当作“恢复这次调用所需的一层状态”。这个模型足以解释函数嵌套、局部变量隔离和栈溢出，不要求背诵具体机器的字节布局。

## 嵌套调用

考虑下面的调用关系：

```cpp
int add(int a, int b) {
    int result = a + b;
    return result;
}

void solve() {
    int x = 3;
    int y = 5;
    int answer = add(x, y);
    printf("%d\n", answer);
}

int main() {
    solve();
    return 0;
}
```

程序从 `main()` 开始后，未完成调用的变化过程如下。

### 进入 main

`main()` 开始执行，调用栈中有一层 `main()` 的状态：

| 栈顶 | 函数 | 当前状态 |
| --- | --- | --- |
| ← | `main()` | 即将调用 `solve()` |

栈顶表示当前正在执行的那层调用。

### main 调用 solve

`main()` 需要在 `solve()` 结束后继续执行 `return 0;`，因此它的调用还不能撤销。程序在上方新增一层 `solve()` 状态：

| 栈顶 | 函数 | 当前状态 |
| --- | --- | --- |
| ← | `solve()` | 建立 `x = 3`、`y = 5` |
| | `main()` | 暂停，等待 `solve()` 返回 |

此时 `main()` 仍在调用栈里，但只有栈顶的 `solve()` 继续执行。

### solve 调用 add

`solve()` 执行到 `add(x, y)`，再建立一层 `add()` 调用。`solve()` 自己的 `x,y` 和“返回后要给 `answer` 初始化”的状态仍然需要保留：

| 栈顶 | 函数 | 当前状态 |
| --- | --- | --- |
| ← | `add()` | `a = 3`、`b = 5`，正在计算 `result` |
| | `solve()` | `x = 3`、`y = 5`，等待 `add()` 的结果 |
| | `main()` | 等待 `solve()` 返回 |

最后进入调用栈的 `add()` 位于栈顶，因此会最先结束。这就是后进先出。

## 逐层返回

`add()` 计算出 `result = 8`，再执行：

```cpp
return result;
```

返回值被交给调用者，`add()` 这层调用结束。它的参数 `a,b` 和局部变量 `result` 随之销毁，程序恢复到 `solve()` 的调用位置之后：

```cpp
int answer = 8;
```

调用栈又只剩两层：

| 栈顶 | 函数 | 当前状态 |
| --- | --- | --- |
| ← | `solve()` | `answer = 8`，即将输出 |
| | `main()` | 等待 `solve()` 返回 |

`solve()` 输出后执行到函数末尾。`void` 函数在这里结束，`x,y,answer` 销毁，程序回到 `main()` 中的 `solve();` 之后。

最后 `main()` 执行 `return 0;`，它的调用也结束。整个过程的入栈顺序是

```text
main -> solve -> add
```

出栈顺序则完全相反：

```text
add -> solve -> main
```

## 每次调用都独立

函数中的普通局部变量属于某一次具体调用，而不是永久属于函数名。

```cpp
int add_one(int x) {
    int result = x + 1;
    return result;
}
```

调用 `add_one(3)` 和 `add_one(10)` 时，两次调用分别拥有自己的 `x` 和 `result`。第一次调用中的 `x = 3` 不会被第二次的 `x = 10` 覆盖。

普通局部变量也不会自动保留上一次调用的数值。如果需要跨调用共享同一个对象，
必须通过参数、返回值、对象成员、全局对象或
[`static` 局部变量](static-local-variables.md) 等方式明确表达。

## 返回时局部状态结束

普通局部对象只属于当前这次函数调用。函数计算返回值以后，这一层调用结束，参数和局部状态也随之结束。

直接按值返回局部变量是正常用法：

```cpp
int good() {
    int value = 7;
    return value;
}
```

函数先用 `value` 确定返回结果，再结束当前调用。调用处得到返回的数值，不需要让局部变量本身继续存在。指针如何与对象的存在时间相互影响，会在 [指针](pointers.md) 中单独解释。

## 栈溢出

调用栈容量有限。每多一层尚未结束的函数调用，通常就需要多保留一层调用状态。两类常见原因会用尽栈空间：

- 某一层调用声明了过大的局部对象；
- 函数调用嵌套过深，大量栈帧同时没有返回。

大型局部数组可能让单层调用占用过多空间；[竞赛程序的常见内存分区](competitive-program-memory-layout.md#调用栈)
会在扩展阅读中进一步解释。过深调用则常出现在递归中：函数在本次调用还没结束时
再次调用自己，每一次都必须保留独立的参数、局部状态和返回位置。

具体能容纳多少层不是 C++ 的固定常量。它取决于运行环境的栈上限与每层实际使用的空间，因此不要把某次测试能运行的递归深度当成所有 OJ 的保证。

## 完整代码

下面的程序从输入读取两个整数，完整经过 `main()`、`solve()` 和 `add()` 三层调用。

```cpp
#include <bits/stdc++.h>
using namespace std;

int add(int a, int b) {
    int result = a + b;
    return result;
}

void solve() {
    int x;
    int y;
    scanf("%d%d", &x, &y);

    int answer = add(x, y);
    printf("%d\n", answer);
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
3 5
```

输出：

```text
8
```

`add()` 本身执行常数次运算，时间复杂度为 $O(1)$。这个程序同时存在的调用最多只有 `main()`、`solve()` 和 `add()` 三层，因此调用栈额外空间是 $O(1)$。

## 常见错误

### 把函数名当成唯一一份局部状态

同一个函数可以被调用许多次，每次未结束的调用都有自己的参数、局部变量和返回
位置。函数代码共享，不代表调用状态共享。

### 以为普通局部变量会保留到下次调用

本次函数返回后，它的普通局部状态就已经结束。再次调用同一个函数时会建立一份新的状态；需要保留结果时，应当使用返回值或由调用者保存。

### 把抽象栈帧当成固定字节表

栈帧用于理解调用需要保存一层状态。具体哪些值位于栈、寄存器或被优化掉，由
平台和编译器决定。

### 只用总内存限制估计递归安全性

调用栈通常有自己的上限。每层局部对象大小和最大嵌套深度共同决定实际栈空间，
不能只看题目的总内存限制。

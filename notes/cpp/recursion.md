# 函数：递归

> 最近修订：2026-08-13 04:18 +10:00（未审阅）

[函数：调用栈](function-call-stack.md) 已经说明：函数调用另一个函数时，调用者的状态可以保留在下方，被调用者在新的一层中执行。被调用者返回后，调用者再从原来的位置继续。

如果一个问题在删去一小部分后，剩下的仍然是同一类更小问题，就可以让函数在本次调用尚未结束时再次调用自己。这种写法称为递归（recursion）。

递归不是让同一份参数和局部变量覆盖自己。每次调用都是独立的一层，只是这些调用执行的函数代码恰好相同。

## 从原问题取出一项

考虑计算

$$
1+2+\cdots+n.
$$

如果暂时取出最后一项 $n$，剩下的部分是

$$
1+2+\cdots+(n-1).
$$

它与原问题完全同类，只是规模从 $n$ 变成了 $n-1$。把“从 $1$ 加到 $n$”命名为 $S(n)$，就得到

$$
S(n)=S(n-1)+n.
$$

这个等式告诉我们怎样用更小的同类问题计算原问题，但还不是完整算法。若一直把 $n$ 变成 $n-1$，必须有一个不再继续调用的终点。

## 终止条件

当 $n=0$ 时，没有任何需要相加的整数，所以

$$
S(0)=0.
$$

这是可以直接返回答案的最小问题，称为递归的终止条件（base case）：

```cpp
if (n == 0) {
    return 0;
}
```

其余 $n>0$ 的情况使用 $S(n)=S(n-1)+n$：

```cpp
return recursive_sum(n - 1) + n;
```

这一部分通常称为递归情况（recursive case）。

完整函数是：

```cpp
ll recursive_sum(int n) {
    if (n == 0) {
        return 0;
    }
    return recursive_sum(n - 1) + n;
}
```

这里假设 $n\ge0$。当 $n>0$ 时，下一次调用的参数严格变小；经过有限次减一后一定会到达 $0$。终止条件不仅要被写出，还必须能被所有合法输入真正到达。

## 递归的三个部分

对一个基础递归，可以逐项检查：

1. 原问题能否转化成一个或多个同类子问题？
2. 是否有一个可比较的量在每层严格缩小？
3. 是否存在能够直接返回的终止条件？

对 `recursive_sum(n)`：

| 部分 | 具体内容 |
| --- | --- |
| 同类子问题 | `recursive_sum(n - 1)` |
| 严格缩小的量 | 非负整数 `n` 每次减 $1$ |
| 终止条件 | `n == 0` 时返回 $0$ |
| 由子问题还原原问题 | 子问题答案再加 `n` |

“调用自己”只是代码外形。真正保证算法有限结束的是后两项：某个量严格缩小，并且必然到达可直接返回的终点。

## 向下进入子问题

调用 `recursive_sum(4)` 时，每一层都需要等待更小子问题的答案：

| 当前调用 | 暂时不能完成的计算 |
| --- | --- |
| `recursive_sum(4)` | 等待 `recursive_sum(3)`，再加 $4$ |
| `recursive_sum(3)` | 等待 `recursive_sum(2)`，再加 $3$ |
| `recursive_sum(2)` | 等待 `recursive_sum(1)`，再加 $2$ |
| `recursive_sum(1)` | 等待 `recursive_sum(0)`，再加 $1$ |
| `recursive_sum(0)` | 命中终止条件，直接返回 $0$ |

当最底层还没有返回时，调用栈中同时存在 `n = 4,3,2,1,0` 的五次独立调用。每一层都保留自己的 `n` 和“子问题返回后还要加上该层 `n`”的状态。

## 向上恢复答案

`recursive_sum(0)` 返回 $0$ 后，调用按照后进先出的顺序逐层结束：

| 返回的层 | 恢复本层计算 | 返回值 |
| --- | --- | ---: |
| `recursive_sum(0)` | 直接返回 | $0$ |
| `recursive_sum(1)` | $0+1$ | $1$ |
| `recursive_sum(2)` | $1+2$ | $3$ |
| `recursive_sum(3)` | $3+3$ | $6$ |
| `recursive_sum(4)` | $6+4$ | $10$ |

递归的执行因此可以分成两个方向：

- 向下调用：不断进入规模更小的子问题；
- 向上返回：从终止条件开始，用子问题答案恢复每层原问题。

后续树的深度优先遍历会先沿一条路径向下访问子节点，然后向上返回父节点；分治会先解决多个更小子问题，再合并它们的答案。它们都使用同一个调用栈模型。

## 与循环的对比

从 $1$ 加到 $n$ 也可以直接使用循环：

```cpp
ll iterative_sum(int n) {
    ll result = 0;
    for (int i = 1; i <= n; i++) {
        result += i;
    }
    return result;
}
```

两种写法都执行 $O(n)$ 次基本操作。循环只保留一份 `result` 和 `i`，额外空间是 $O(1)$；递归在最深时同时保留 $n+1$ 层调用，调用栈空间是 $O(n)$。

这个线性求和问题的循环写法更简单、更节省空间，实战中应当使用循环。本篇选它作为例子，是因为所有算式都很熟悉，可以把注意力集中在递归结构和调用栈上。

递归不会自动降低时间复杂度。当问题本身具有树形、分治或回溯结构时，递归通常能直接对应问题的层级关系；当状态只是简单线性推进时，循环通常更合适。

## 常见错误

### 没有终止条件

函数不断调用自己，调用栈持续增长，最终导致栈溢出。

### 参数没有向终止条件靠近

仅仅写出 `if (n == 0)` 不能保证结束。若递归调用使用 `n + 1`，从正整数开始就会越来越远离 $0$。

### 终止条件与合法输入不匹配

本篇函数假设 $n\ge0$。如果错误传入负数，`n - 1` 同样不会到达 $0$。函数的输入约束必须与证明终止的过程一致。

### 忽略递归深度

算法逻辑正确不代表调用栈一定足够。若最深调用层数与输入规模同阶且可能很大，应当考虑循环或显式数据结构。C++ 标准不保证把尾递归优化成循环，不能依赖这种优化规避栈溢出。

## 完整代码

下面的程序读入非负整数 $n$，递归计算从 $1$ 到 $n$ 的和。为了让教学示例不依赖具体环境能够承受多深的调用，输入限制为 $0\le n\le10000$。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

ll recursive_sum(int n) {
    if (n == 0) {
        return 0;
    }
    return recursive_sum(n - 1) + n;
}

int main() {
    int n;
    scanf("%d", &n);
    printf("%lld\n", recursive_sum(n));
    return 0;
}
```

输入：

```text
5
```

输出：

```text
15
```

函数一共执行 `n + 1` 次调用，时间复杂度为 $O(n)$，调用栈空间为 $O(n)$。

## 基础练习

1. 手动写出 `recursive_sum(3)` 的向下调用顺序和向上返回顺序。
2. 把终止条件改成 `n == 1`，分析合法输入中的哪个边界会出错。
3. 递归计算 $1\times2\times\cdots\times n$，明确写出终止条件和每层缩小的量。
4. 分别用循环和递归计算从 $1$ 到 $n$ 的和，对比它们的时间与额外空间。
5. 阅读一个没有终止条件的递归函数，解释为什么它会持续增加调用栈深度。

## 需要记住什么

1. 什么是递归？同一函数的多次递归调用是否共享同一份普通局部变量？
2. 写一个递归时，为什么要同时检查同类子问题、严格缩小的量和终止条件？
3. `recursive_sum(n)` 中哪一行是终止条件，哪一行是递归情况？
4. `recursive_sum(4)` 向下调用时每层在等待什么？向上返回时每层又做了什么？
5. 为什么一个写出终止条件的递归仍然可能永不终止？
6. 为什么递归不会自动降低时间复杂度？本篇求和问题为什么更适合循环？
7. 怎样从最深调用层数推导递归的调用栈空间？

间接递归、尾调用优化的平台实现和把任意递归机械改写为状态机都不属于本篇的竞赛基础内容，不要求理解或记忆。

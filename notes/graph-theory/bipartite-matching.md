# 二分图：最大匹配

> 最近修订：2026-08-17 09:42 +10:00（未审阅）

有一组学生和一组项目。每名学生只愿意参加其中一些项目，每个项目最多接收一名
学生，每名学生也最多参加一个项目。怎样安排，才能让尽可能多的学生获得项目？

把学生作为二分图左部点，项目作为右部点；一名学生愿意参加某个项目，就在两点
之间连边。选择若干条没有公共端点的边，称为一个**匹配**。边数最大的匹配称为
**最大匹配**。

直接让每名学生选择第一个空项目会失败：当前项目虽然已经有人，但原来的学生
也许还能换到另一个项目。最大匹配的关键正是允许沿一串已有安排重新分配。

## 从一个未匹配点出发

设左部学生 `u` 尚未匹配。依次查看它愿意参加的项目 `v`：

- 若 `v` 当前无人参加，直接把 `u` 匹配给 `v`；
- 若 `v` 已匹配给学生 `old_u`，尝试为 `old_u` 另找项目；
- 若 `old_u` 成功换走，`v` 就可以交给 `u`。

例如已有匹配：

```text
学生 1 -> 项目 A
学生 2 -> 项目 B
```

学生 3 只愿意参加 A，而学生 1 还愿意参加 C。沿着：

```text
学生 3 -> 项目 A -> 学生 1 -> 项目 C
```

重新安排后，匹配数从 2 增加到 3。

这条路径从未匹配的左部点出发，在“未选边、已选边、未选边”之间交替，最终
到达未匹配的右部点，称为**增广路**。把路径上未选边改为已选、已选边改为未选，
匹配边数恰好增加 1。

## 递归寻找增广路

用 `match_right[v]` 表示右部项目 `v` 当前匹配的左部学生；值为 0 表示未匹配。

```cpp
bool find_augmenting_path(int u) {
    for (int v : g[u]) {
        if (vis[v]) {
            continue;
        }
        vis[v] = 1;

        if (match_right[v] == 0 || find_augmenting_path(match_right[v])) {
            match_right[v] = u;
            return true;
        }
    }
    return false;
}
```

递归的含义是：

> 能否为学生 `u` 找到一个项目，并把途中已经占用项目的学生依次安置到别处？

一旦递归成功，返回路径上的每一层都把当前项目改配给当前学生，正好完成整条
增广路的翻转。

## 为什么一次搜索不能重复访问右部点

一轮搜索中，若项目 `v` 已经访问过，再次到达它时，后续能尝试的原匹配学生与
出边都完全相同，不会产生新结果。重复访问还可能让递归在交替关系中来回绕圈。

因此，每次从一个新的左部点开始寻找增广路前，将 `vis` 清空；同一次搜索
内，每个右部点最多访问一次。

`vis` 不能在全部搜索间永久保留。前一轮修改匹配以后，同一个项目可能通过
新的交替路径帮助后面的学生完成增广。

## 为什么找不到增广路就是最优

增广路算法依赖一个重要结论：

> 一个匹配是最大匹配，当且仅当图中不存在相对于它的增广路。

若存在增广路，翻转以后显然能多匹配一条边，所以当前匹配不可能最大。

反过来，设当前匹配为 $M$，另有一个更大的匹配 $M'$。只保留恰好属于两者之一
的边，每个点的度数最多为 2，因此这些边会分成若干交替路径和交替环。因为
$M'$ 的边更多，至少有一条交替路径中 $M'$ 比 $M$ 多一条边；它的两个端点在
$M$ 中未匹配，正是一条相对于 $M$ 的增广路。这与“不存在增广路”矛盾。

程序不断寻找增广路，直到所有左部点都尝试过，得到最大匹配。

## 完整代码

输入左部点数 `n`、右部点数 `m` 和边数 `e`，随后给出每条允许匹配的边
`u v`。程序输出最大匹配大小，以及每个已经匹配的右部点对应的左右端点。

```cpp
#include <bits/stdc++.h>
using namespace std;

int n, m, e;
vector<vector<int>> g;
vector<int> match_right;
vector<int> vis;

bool find_augmenting_path(int u) {
    for (int v : g[u]) {
        if (vis[v]) {
            continue;
        }
        vis[v] = 1;

        if (match_right[v] == 0 || find_augmenting_path(match_right[v])) {
            match_right[v] = u;
            return true;
        }
    }

    return false;
}

int maximum_matching() {
    match_right.assign(m + 5, 0);
    int matching_size = 0;

    for (int u = 1; u <= n; u++) {
        vis.assign(m + 5, 0);
        if (find_augmenting_path(u)) {
            matching_size++;
        }
    }

    return matching_size;
}

void solve() {
    cin >> n >> m >> e;

    g.assign(n + 5, {});
    for (int i = 1; i <= e; i++) {
        int u, v;
        cin >> u >> v;
        g[u].push_back(v);
    }

    cout << maximum_matching() << '\n';
    for (int v = 1; v <= m; v++) {
        if (match_right[v] != 0) {
            cout << match_right[v] << ' ' << v << '\n';
        }
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    solve();
    return 0;
}
```

## 复杂度

一次增广路搜索中，每个右部点至多访问一次，每条相关边至多检查一次，时间为
$O(e)$。最多从每个左部点发起一次搜索，因此总时间为 $O(ne)$，空间为
$O(n+m+e)$。

这个基础算法代码短，足以处理许多中等规模的匹配问题。图很大时，可以让多条
最短增广路分层一起推进，把复杂度改进为 $O(e\sqrt{n+m})$；那是
Hopcroft–Karp 算法。只有基础增广路成为真正瓶颈时，才值得承担额外实现成本。

## 怎样识别二分图匹配问题

最自然的信号是：对象明确分成两类，只允许跨类别配对，每个对象最多使用一次，
目标是让配对数量最大。例如人员与任务、机器与作业、课程与教室等。

若一个对象可以同时接收多个匹配，需要加入容量，问题会走向网络流；若边有收益
并要求最大总收益，则是带权匹配。不要仅因为题目出现“两组对象”就立即套模板，
先确认“一点至多匹配一次”是否正是题目的约束。

## 常见错误

- 使用贪心占据第一个空右部点，却不允许原匹配重新安排；
- 把 `match_right[v]` 误写成布尔值，丢失需要递归换位的原学生编号；
- 一轮搜索中不记录访问点，造成重复搜索或递归环；
- 全部左部点共用一份永久的 `vis`，错过匹配改变后的新增广路；
- 递归成功后忘记执行 `match_right[v] = u`；
- 已经找到一条增广路后仍继续修改其他项目；
- 混淆最大匹配与极大匹配：无法直接再加一条边的匹配未必拥有最大边数；
- 一侧节点具有容量时仍使用“一点最多匹配一次”的数组表示。

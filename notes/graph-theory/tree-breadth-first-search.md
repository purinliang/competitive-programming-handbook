# 树的遍历：广度优先搜索（BFS）

> 最近修订：2026-08-16 18:00 +10:00（未审阅）

[树的深度优先搜索（DFS）](tree-depth-first-search.md) 会先处理完整棵子树，再返回
父节点。如果问题更关心“离根有几条边”或者需要按照深度逐层处理节点，继续沿一条
分支深入就不够直观。

广度优先搜索（breadth-first search，BFS）使用队列保存已经发现、但还没有展开
的节点。它先处理离根近的节点，再处理离根远的节点，因此能在一次遍历中确定每个
节点的父节点和深度。

## 按深度逐层访问

下面把节点 $1$ 选作根。每个圆中的 `u · #k` 表示节点编号为 `u`，并且它是 BFS
第 $k$ 个访问到的节点。

![树的广度优先搜索顺序](../assets/graph-theory/tree-breadth-first-search.svg)

如果相邻节点按照图中从左到右的顺序存储，BFS 的访问顺序是：

```text
1 2 3 4 5 6 7 8
```

节点 $1$ 的深度为 $0$；节点 $2,3,4$ 的深度为 $1$；节点 $5,6,7,8$ 的深度为
$2$。BFS 会先访问完深度 $1$ 的全部节点，再处理深度 $2$，不会像 DFS 那样先从
节点 $2$ 深入到节点 $5$。

同一层内部的先后顺序取决于邻接表顺序，但深度较小的节点一定先于深度较大的节点
出队。

## 用队列保存等待处理的节点

首先把根节点 `s` 放入先进先出的队列：

```cpp
queue<int> q;
q.push(s);
```

只要队列不为空，就取出最早加入的节点：

```cpp
while (!q.empty()) {
    int u = q.front();
    q.pop();

    order.push_back(u);
}
```

处理 `u` 时，它的子节点会依次加入队尾。队列中原本等待的同层节点仍在前面，
所以当前层会先处理完，新发现的下一层节点随后才会出队。

## 跳过父节点

输入是一棵无向树，每条边在邻接表中保存两个方向。从父节点进入 `u` 后，`g[u]`
会再次看见来时的节点。令 `par[u]` 表示 `u` 的父节点，枚举邻居 `v` 时跳过它：

```cpp
for (int v : g[u]) {
    if (v == par[u]) {
        continue;
    }

    par[v] = u;
    q.push(v);
}
```

真实节点使用从 $1$ 开始的编号，根节点没有父节点，因此令 `par[s] = 0`。

树中两点之间的简单路径唯一。除父节点以外，`u` 的每个邻居都位于一棵尚未访问
的子树中，不可能通过另一条边提前进入同一个节点；否则这些边会形成环。因此树的
BFS 只跳过父节点就足够，不需要额外的 `vis`。

如果输入只是一般图，这个结论不成立。一般图必须像
[图的广度优先搜索](graph-breadth-first-search.md) 一样，在节点入队时使用 `dist`
或 `vis` 标记它已经被发现。

## 入队时确定深度

根节点的深度为 $0$：

```cpp
par[s] = 0;
dep[s] = 0;
q.push(s);
```

从 `u` 第一次发现子节点 `v` 时，根到 `v` 的唯一路径比根到 `u` 多一条边：

```cpp
par[v] = u;
dep[v] = dep[u] + 1;
q.push(v);
```

父节点和深度必须在入队时确定。“发现节点”“写入层级关系”和“安排以后处理”在
同一步完成；等 `v` 出队时，这些信息已经可以直接使用。

## 为什么队列得到正确层次

开始时，队列中只有深度为 $0$ 的根。假设队列正在处理深度为 $d$ 的节点 `u`，
它新发现的子节点深度都是 $d+1$，并被放到队尾。所有更早发现的深度为 $d$ 的
节点仍排在这些子节点之前。

因此队列中的深度从队首到队尾不会下降：深度为 $d$ 的节点全部处理完以后，才会
轮到深度为 $d+1$ 的节点。由归纳可知，BFS 按照深度逐层处理整棵树。

## 可以重复调用的 BFS

`g` 和 `n` 描述当前题目的树；`par`、`dep` 和 `order` 是一次 BFS 产生的结果。
它们都是题目级共享状态，但每次更换根调用 `bfs(s)` 时，旧结果都必须清除：

```cpp
void bfs(int s) {
    par.assign(n + 5, 0);
    dep.assign(n + 5, 0);
    order.clear();

    queue<int> q;
    par[s] = 0;
    dep[s] = 0;
    q.push(s);

    // 继续逐层遍历
}
```

`assign` 同时保证数组长度正确并重置全部元素；`clear` 让访问顺序重新变为空序列。
初始化由 `bfs` 自己完成，所以调用者可以对同一棵树连续执行 `bfs(1)`、`bfs(5)`，
不需要记住额外的清理步骤。

## 完整代码

下面的程序读取一棵树，以节点 $1$ 为根执行 BFS，输出访问顺序，再输出每个节点的
父节点和深度。

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
vector<vector<int>> g;
vector<int> par;
vector<int> dep;
vector<int> order;

void bfs(int s) {
    par.assign(n + 5, 0);
    dep.assign(n + 5, 0);
    order.clear();

    queue<int> q;
    par[s] = 0;
    dep[s] = 0;
    q.push(s);

    while (!q.empty()) {
        int u = q.front();
        q.pop();
        order.push_back(u);

        for (int v : g[u]) {
            if (v == par[u]) {
                continue;
            }

            par[v] = u;
            dep[v] = dep[u] + 1;
            q.push(v);
        }
    }
}

void solve() {
    scanf("%d", &n);

    g.assign(n + 5, {});
    for (int i = 1; i < n; i++) {
        int u, v;
        scanf("%d%d", &u, &v);
        g[u].push_back(v);
        g[v].push_back(u);
    }

    bfs(1);

    for (int i = 0; i < n; i++) {
        printf("%d%c", order[i], i + 1 == n ? '\n' : ' ');
    }

    for (int u = 1; u <= n; u++) {
        printf("%d %d %d\n", u, par[u], dep[u]);
    }
}

int main() {
    solve();
    return 0;
}
```

输入：

```text
8
1 2
1 3
1 4
2 5
2 6
3 7
4 8
```

输出：

```text
1 2 3 4 5 6 7 8
1 0 0
2 1 1
3 1 1
4 1 1
5 2 2
6 2 2
7 3 2
8 4 2
```

后八行依次表示节点编号、父节点和深度。若把 `bfs(1)` 改成 `bfs(5)`，同一棵无根
树会按照节点 $5$ 重新建立父子关系和深度。

## BFS 与子树信息

BFS 很自然地得到从浅到深的顺序，但 `siz[u]` 依赖全部子节点先计算完成，不能在
第一次从队列取出 `u` 时直接得到。

如果只需要子树大小，递归 DFS 的返回过程更直接。如果题目必须使用迭代写法，可以
先保存 BFS 或栈遍历顺序，再按相反顺序累加：越深的节点会先贡献给父节点。这里先
建立这个方向感，具体写法在需要迭代树形 DP 时再展开。

## 复杂度

每个节点恰好入队、出队一次，每条无向边对应的两个邻接项各查看一次，因此时间
复杂度是 $O(n)$。邻接表使用 $O(n)$ 空间，队列、父节点数组、深度数组和访问顺序
也各使用 $O(n)$ 空间。

与递归 DFS 不同，BFS 不使用递归调用栈；队列最多可能同时保存一整层的节点，最坏
仍需 $O(n)$ 空间。

## 常见错误

### 把栈当成等待队列

后进先出的栈会优先深入最近发现的节点，得到的是迭代 DFS，不再保证逐层出队。

### 不跳过父节点

无向边保存两个方向。不跳过 `par[u]` 会立即把父节点重新加入队列，并沿原边不断
重复。

### 把树的写法用于一般图

一般图可能通过另一条边再次到达已发现节点。只有输入保证为树时，跳过父节点才
足够。

### 在出队时才设置父节点

节点入队时就已经确定由谁发现。延后赋值会让队列中的节点缺少层级信息，也破坏
“发现与标记同时发生”的统一结构。

### 重复调用前不重置结果

换根以后，旧 `par`、`dep` 和 `order` 都已经失去含义。让 `bfs` 自己初始化结果，
不要要求每个调用者分别清理。

## 基础练习

1. 把根改成节点 $5$，手算并验证每个节点新的 `par` 和 `dep`。
2. 给定节点 `u`，沿 `par[u]` 不断向上直到根，恢复根到 `u` 的唯一路径。
3. 使用 `dep` 统计每一层包含多少节点。
4. 连续调用 `bfs(1)` 和 `bfs(5)`，确认第二次结果中没有残留第一次的父节点、
   深度和访问顺序。

## 需要记住什么

- BFS 为什么使用先进先出的队列？
- 队列为什么保证节点按照深度从小到大处理？
- `par[v]` 和 `dep[v]` 为什么要在 `v` 入队时确定？
- 为什么树中只跳过父节点就足够，而一般图还需要 `dist` 或 `vis`？
- 同一棵无根树更换根以后，哪些结果必须重新计算？
- 为什么 `bfs(s)` 应当自己重置 `par`、`dep` 和 `order`？
- BFS 为什么不能在第一次处理节点时直接得到子树大小？
- 树上 BFS 的时间和空间复杂度为什么都是 $O(n)$？

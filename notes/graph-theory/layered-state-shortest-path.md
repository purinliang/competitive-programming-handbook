# 最短路：分层图与状态图

> 最近修订：2026-08-17 07:02 +10:00（未审阅）

普通最短路只需要知道“当前在哪个点”。若题目增加一次性能力，例如：

- 至多一次免费经过一条边；
- 已经拿到或尚未拿到钥匙；
- 已使用多少次加速；
- 当前燃料、方向或剩余资源；

同一个图上点在不同状态下，未来可用操作不同。只保存 `dist[u]` 会把这些情况
错误合并。

状态图把“图上的点”和“影响未来决策的状态”一起视为新节点，再在新图上运行
普通最短路。

## 问题：一条边可以免费

给定一张非负权无向图，从点 `1` 到点 `n`。整个行程中至多选择一条经过的边，
令它的费用变成 `0`，求最小总费用。

到达点 `u` 时必须区分：

```text
(u, 0)：还没有使用免费机会
(u, 1)：已经使用免费机会
```

这两个状态虽然位于同一个原图点，但未来选择不同：

- 状态 `0` 仍可免费经过一条边；
- 状态 `1` 以后只能支付正常边权。

因此定义：

$$
dist[u][used]
$$

为到达点 `u`，且免费机会使用状态为 `used` 的最短距离。

## 两层图

把原图复制成两层：

```text
第 0 层：尚未使用免费机会
第 1 层：已经使用免费机会
```

对原图每条边 `u-v`、权值 `w`，建立三类状态转移。

### 不使用机会

在任意一层都可以正常付费：

```text
(u, 0) -> (v, 0)，费用 w
(u, 1) -> (v, 1)，费用 w
```

无向边还要有 `v` 到 `u` 的对应转移。

### 在当前边使用机会

只有尚未使用时可以跨到已使用层：

```text
(u, 0) -> (v, 1)，费用 0
```

这个转移一旦发生，状态就从 `0` 变成 `1`，以后不能返回第 `0` 层，因此免费
机会最多使用一次。

## 状态必须足以决定未来

建立状态时要满足：

> 只要当前“点与状态”相同，过去怎样到达这里就不再影响后续合法操作与费用。

本题只关心免费机会是否用过，因此一个布尔状态足够。无需记录免费用在哪条边、
已经走了多少条边或此前完整路径。

如果压缩掉一个会影响未来的信息，不同情况会被错误合并；如果保存大量不会影响
未来的信息，状态数会无谓膨胀。

这与动态规划中的状态设计完全相同：状态要包含所有影响后续决策的信息，同时
尽量删除无关历史。

## 不必真的复制图

可以显式建立 `2n` 个新点，但代码会重复存储边。更自然的做法是在 Dijkstra
枚举原图边时，现场生成状态转移。

从状态 `(u, used)` 沿边 `u-v,w`：

```cpp
relax(v, used, current_distance + w);
```

若 `used == 0`，还可以：

```cpp
relax(v, 1, current_distance);
```

原图仍只保存一份，状态图是**隐式图**：节点和边没有全部提前建出，但邻接关系
能根据当前状态即时生成。

## 为什么仍能使用 Dijkstra

状态图中的边权只有：

- 原图非负边权 `w`；
- 使用机会时的 `0`。

它们都非负，因此 Dijkstra 的正确性条件仍然成立。状态改变不会破坏算法；真正
决定能否使用 Dijkstra 的是展开后每条状态转移边是否非负。

若某种能力产生负费用，就需要重新判断是否存在负边或负环，并选择对应最短路
算法。

## 起点和终点

起点尚未使用免费机会：

```cpp
dist[1][0] = 0;
```

“至多使用一次”允许完全不用，所以答案是：

```cpp
min(dist[n][0], dist[n][1])
```

若题目要求“恰好使用一次”，答案只能取 `dist[n][1]`。一个词的差异会改变
终点状态集合。

## 完整代码

下面处理非负权无向图，求从 `1` 到 `n`、至多免费经过一条边的最短距离。若
无法到达，输出 `-1`。

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

const ll INF = 1LL << 62;

struct Edge {
    int v;
    ll w;
};

int n, m;
vector<vector<Edge>> g;
vector<array<ll, 2>> dist;

void dijkstra() {
    dist.assign(n + 5, {INF, INF});

    using State = tuple<ll, int, int>;
    priority_queue<
        State,
        vector<State>,
        greater<State>> que;

    dist[1][0] = 0;
    que.push({0, 1, 0});

    while (!que.empty()) {
        auto [current_distance, u, used] = que.top();
        que.pop();

        if (current_distance != dist[u][used]) {
            continue;
        }

        for (const Edge& edge : g[u]) {
            int v = edge.v;
            ll w = edge.w;

            if (dist[v][used] >
                current_distance + w) {
                dist[v][used] =
                    current_distance + w;
                que.push({dist[v][used], v, used});
            }

            if (used == 0 &&
                dist[v][1] > current_distance) {
                dist[v][1] = current_distance;
                que.push({dist[v][1], v, 1});
            }
        }
    }
}

void solve() {
    cin >> n >> m;

    g.assign(n + 5, {});

    for (int i = 1; i <= m; i++) {
        int u, v;
        ll w;
        cin >> u >> v >> w;
        g[u].push_back({v, w});
        g[v].push_back({u, w});
    }

    dijkstra();

    ll answer = min(dist[n][0], dist[n][1]);

    if (answer == INF) {
        cout << -1 << '\n';
    } else {
        cout << answer << '\n';
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    solve();
    return 0;
}
```

## 推广到多次机会

若最多免费使用 $k$ 次，状态可以改成：

```text
dist[u][used]，0 <= used <= k
```

正常经过边保持 `used`，免费经过边从 `used` 转到 `used+1`。状态图有
$(k+1)n$ 个节点和约 $(2k+1)m$ 级别的转移。

状态数与资源上限相乘。若 $k$ 很大，直接分层可能无法承受，需要寻找其他性质；
“可以定义状态”不等于“状态数量一定可行”。

## 复杂度

本题有 $2n$ 个状态节点，每条原图边产生常数个状态转移：

- 时间复杂度：$O((n+m)\log n)$；
- 空间复杂度：$O(n+m)$。

一般 $k+1$ 层时，应写成状态图规模对应的复杂度，不能仍然忽略 $k$。

## 常见错误

- 只维护 `dist[u]`，把免费机会已用和未用状态混在一起；
- 从已使用层又转回未使用层，使机会可以重复使用；
- 免费转移以后仍保持 `used = 0`；
- “至多一次”只取 `dist[n][1]`，强迫使用机会；
- 状态转移中出现负权却仍直接使用 Dijkstra；
- 显式复制图时漏掉某一层的正常边；
- 状态保存了完整历史，导致状态数指数膨胀。

- 为什么本题展开以后仍满足 Dijkstra 的条件？

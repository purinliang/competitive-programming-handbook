# 图的存储：边的记录

> 状态：草稿
> 直接前置：[0121 复合类型：struct](../cpp/0121-struct.md)、[0401 图：点与边](vertices-and-edges.md)

数学定义中的图由点和边组成。程序要保存一条边，至少需要知道它从哪里出发、到哪里结束；带权边还要保存边权。本篇只确定一条边在代码中表示什么，下一篇再决定如何组织许多条边。

## 有向边记录

程序中最基础的边记录表示一条有向边：

```cpp
struct Edge {
    int from;
    int to;
    int weight;
};
```

例如：

```cpp
Edge edge = {2, 5, 7};
```

它表示一条从点 $2$ 指向点 $5$、边权为 $7$ 的有向边。完整名称 `from`、`to` 和 `weight` 直接说明三个字段的含义，适合第一次认识边记录。

如果图没有边权，就不需要保存一个没有意义的 `weight`：

```cpp
struct Edge {
    int from;
    int to;
};
```

竞赛代码通常把一条输入边的两个端点和边权暂存在变量 `u`、`v`、`w` 中。这些是 `from`、`to`、`weight` 的惯用缩写；只有在上下文已经明确时才使用：

```cpp
int u, v, w;
scanf("%d%d%d", &u, &v, &w);
```

## 无向边的两个方向

无向边 $(u,v)$ 本身没有方向，但从点 $u$ 可以沿它到达点 $v$，从点 $v$ 也可以沿它到达点 $u$。为了让后续算法统一枚举“从当前点出发的边”，程序通常把一条无向边展开成两条有向边记录：

```cpp
Edge forward = {u, v, w};
Edge backward = {v, u, w};
```

这只是存储方式。数学意义上仍然只有一条无向边，不能因为代码中出现两条记录，就把题目的边数从 $m$ 改成 $2m$。

无权无向边同样展开为 `(u, v)` 和 `(v, u)` 两条记录，只是不保存 `weight`。

如果无向边是自环 $(u,u)$，两个方向的起点和终点看起来相同，通用的“双向加入”仍会产生两条记录。这与无向自环的两个端点都落在同一点上相符；具体算法是否需要保留两份，要看题目如何使用自环。

## 原始边与边记录

需要区分两种数量：

- 原始边是题目给出的数学对象；
- 边记录是为了从某个方向遍历而保存的代码对象。

有向图的一条原始边通常对应一条边记录。无向图的一条普通原始边通常对应两条方向相反的边记录。

普通 DFS、BFS 和最短路只需从当前点枚举可以走向哪里的记录，不一定关心两条记录来自同一条无向边。但有些算法需要高频访问这种关系：

- 欧拉路径和欧拉回路必须保证每条原始边只使用一次；
- 网络流会为一条有向边建立残量意义下的反向边，并不断在两者之间切换。

本书在这些算法中统一使用链式前向星：把相互关联的两条记录连续存入同一个全局边数组，以相邻编号互相定位。普通图算法则使用代码更短的 `vector` 邻接表。

> 哈密顿路径和哈密顿回路限制的是每个点只出现一次，不是每条边只使用一次，因此不会仅仅因为哈密顿问题就要求配对两条反向边。

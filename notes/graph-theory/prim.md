# 最小生成树：Prim

> 最近修订：2026-08-17 05:39 +10:00（未审阅）

Kruskal 从“边”出发，把所有边排序后不断合并连通分量。Prim 从“当前已经连通的
点集”出发，每次选择一条最轻的边，把点集外的一个新点接进来。

两种算法都依据最小生成树的割性质，但组织候选边的方式不同。Prim 使用邻接表和
小根优先队列，不必预先排序整个边集。

## 维护一个不断扩大的连通点集

任意选择一个起点，例如点 `1`。初始生成树只包含这个点，还没有边。

令 `vis[u]` 表示点 `u` 是否已经加入生成树。每一步都在所有满足下列条件的边中
选择权值最小的一条：

- 一个端点已经在生成树内；
- 另一个端点仍在生成树外。

选中这条边后，把树外端点和这条边一起加入。由于每次只接入一个新点，已选边不会
形成环；重复 `n-1` 次后便得到一棵生成树。

## 每个树外点只关心最轻接入边

对尚未加入的点 `v`，不需要保存所有从当前点集连接到它的边。只维护：

```cpp
best[v]
```

表示把点 `v` 接入当前生成树的最小边权。

处理刚加入的点 `u` 时，枚举每条无向邻接边 $(u,v,w)$：

```cpp
if (!vis[v] && w < best[v]) {
    best[v] = w;
}
```

这不是起点到 `v` 的最短路径长度。`best[v]` 只是一条边的权值，表示当前生成树
通过哪条最便宜的边可以直接接入 `v`。

例如，生成树内已经有点 `1` 和 `2`：

```text
1 -- 3 (8)
2 -- 3 (4)
```

则 `best[3]=4`。即使从起点走到点 `2` 已经花费其他权值，也不加到 `4` 上；
生成树目标是所选边权总和，不是某条根到点路径的长度。

## 用优先队列选择全局最轻接入边

若每轮扫描全部树外点寻找最小 `best`，时间复杂度为 $O(n^2)$。邻接表版本把
候选状态保存为：

```cpp
pair<ll, int>{edge_weight, v}
```

并使用小根优先队列：

```cpp
priority_queue<pair<ll, int>,
               vector<pair<ll, int>>,
               greater<pair<ll, int>>> q;
```

起点不需要接入边，把它的代价设为零：

```cpp
best[1] = 0;
q.push({0, 1});
```

每次弹出的最小有效状态，就是当前跨越“树内点集与树外点集”这个割的最轻边。

## 更新会留下过期状态

点 `v` 可能先通过权值 `10` 的边成为候选，后来又发现权值 `6` 的接入边。优先
队列中会同时保留 `(10,v)` 与 `(6,v)`。

弹出时检查：

```cpp
if (vis[u] || edge_weight != best[u]) {
    continue;
}
```

- `vis[u]` 为真，说明点已经通过更早的状态加入；
- 快照不等于 `best[u]`，说明候选边已经被更轻边替代。

有效状态弹出后，点 `u` 第一次加入生成树，这时才把 `edge_weight` 加入答案。
不能在更新 `best[v]` 时立即加边权，因为那个候选以后还可能被替换。

## 为什么每次选择都是安全的

当前已加入的点形成集合 `S`，其余点形成集合 $V\setminus S$。算法选择跨越这个割
的最小权边 `e`。

假设一棵最小生成树 `T` 不含 `e`。把 `e` 加入 `T` 会形成一个环；该环必须还有
另一条跨越同一个割的边 `f`。由于 `e` 是最轻跨割边：

$$
w(e)\le w(f).
$$

删除 `f` 并加入 `e` 后，仍是一棵生成树，总权值不会增加。因此总存在一棵最小
生成树包含当前已经选择的全部边。

这和 Kruskal 使用的是同一个交换论证。差别只在于：

- Kruskal 的割来自当前多个连通分量；
- Prim 的割始终是一个已连通点集与其余点。

## 图不连通时会发生什么

若当前点集与外部没有任何边，优先队列会提前变空。此时仍有点未加入，说明起点
所在连通分量无法到达它们，原图不存在生成树。

程序维护：

```cpp
int vertex_count = 0;
```

每加入一个点就增加 `1`。算法结束后只有 `vertex_count == n` 才成功。

如果题目要求最小生成森林，可以从每个未访问点重新开始 Prim；本篇目标是覆盖全部
点的一棵最小生成树，因此不自动重启。

## 负边、重边与自环

Prim 可以处理负边。跨割最小边可以是负数，交换论证仍然成立。

平行边会通过 `w < best[v]` 自动保留更轻候选。自环的另一个端点仍是当前点本身，
而它已经满足 `vis[u]`，所以不会成为接入新点的边。

无向图邻接表需要保存两个方向：

```cpp
g[u].push_back({v, w});
g[v].push_back({u, w});
```

这与 Kruskal 的单份原始边集不同，因为 Prim 要从刚加入的点出发访问全部邻边。

## 正确性

算法始终保持：

1. 已选点和已选边构成一棵连通树；
2. 当前选择可以扩充成某棵最小生成树。

初始单点树满足两个条件。每次选择跨越当前割的最轻边，它连接一个树外新点，所以
保持连通且不成环；根据割性质，又总有一棵最小生成树包含这条边。

若最终加入全部 `n` 个点，算法恰好选择 `n-1` 条边，得到一棵生成树；它能扩充成
某棵最小生成树，而边数已经相同，所以自身就是最小生成树。

若优先队列提前为空，则当前点集与其他点之间不存在边，原图不连通。

## 复杂度

每条无向边的两个邻接项各检查一次，每次成功改善 `best` 会进行一次优先队列
插入。总时间复杂度为：

$$
O((n+m)\log n),
$$

通常简写为 $O(m\log n)$。邻接表、候选数组和优先队列共占 $O(n+m)$ 空间。

## 完整代码

程序读取一张带权无向图。存在最小生成树时输出总权值；图不连通时输出 `-1`。

```cpp
#include <bits/stdc++.h>

using namespace std;

typedef long long ll;

const ll INF = 1LL << 62;

int n, m;
vector<vector<pair<int, ll>>> g;
vector<ll> best;
vector<bool> vis;

pair<bool, ll> prim() {
    best.assign(n + 5, INF);
    vis.assign(n + 5, false);

    priority_queue<pair<ll, int>,
                   vector<pair<ll, int>>,
                   greater<pair<ll, int>>> q;
    best[1] = 0;
    q.push({0, 1});

    ll answer = 0;
    int vertex_count = 0;

    while (!q.empty()) {
        auto [edge_weight, u] = q.top();
        q.pop();

        if (vis[u] || edge_weight != best[u]) {
            continue;
        }

        vis[u] = true;
        answer += edge_weight;
        vertex_count++;

        for (auto& [v, w] : g[u]) {
            if (vis[v] || w >= best[v]) {
                continue;
            }

            best[v] = w;
            q.push({best[v], v});
        }
    }

    return {vertex_count == n, answer};
}

int main() {
    scanf("%d%d", &n, &m);

    g.assign(n + 5, {});
    for (int i = 1; i <= m; i++) {
        int u, v;
        ll w;
        scanf("%d%d%lld", &u, &v, &w);
        g[u].push_back({v, w});
        g[v].push_back({u, w});
    }

    auto [exists, answer] = prim();
    if (!exists) {
        printf("-1\n");
    } else {
        printf("%lld\n", answer);
    }
    return 0;
}
```

输入：

```text
5 7
1 2 3
1 3 4
2 3 1
2 4 6
3 4 5
3 5 2
4 5 7
```

输出：

```text
11
```

## 常见错误

### 把 `best[v]` 当成起点最短路

它只保存连接当前生成树与点 `v` 的最小单边权值，不累加根到当前点的路径。

### 更新候选时立即累计答案

候选边可能被更轻边替换。只有点通过有效最小状态正式加入时，才能累计边权。

### 忘记把无向边存成两个邻接项

Prim 需要从每个新点访问所有邻边。只存一个输入方向可能让无向图看起来不可达。

### 不检查加入点数

优先队列为空不一定表示已经覆盖全部点，也可能是原图不连通。

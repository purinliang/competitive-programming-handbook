# YAML Schema v2 草案

`cp-diagram/v2` 在 v1 单行数组的基础上试验三类新图形：上下对齐的多行数组、普通图和树。v1 继续负责已经稳定的单行数组 annotation；v2 暂时集中审核节点、边和多行布局，不修改 v1 的输入或输出。

## 共同字段

```yaml
schema: cp-diagram/v2
type: graph
background: white
```

| 字段 | 必需 | 说明 |
| ---- | ---- | ---- |
| `schema` | 是 | 固定为 `cp-diagram/v2` |
| `type` | 是 | `array`、`graph` 或 `tree` |
| `background` | 否 | `transparent` 或 `white`，默认 `transparent` |

v2 沿用 v1 的黑色基础几何、透明节点内部和手写印刷体文字。几何扰动全部为 `0`，圆、正方形、矩形和直线都保持精确。YAML 仍不能指定坐标、尺寸、字体、线宽、随机种子或 CSS 颜色。

## 编号、标签和值

图和树的节点统一使用以下内容字段：

```yaml
- id: 3
  label: u
  index: "[1, 4]"
  value: 17
  fields:
    sum: 42
    lazy: 0
```

| 字段 | 必需 | 说明 |
| ---- | ---- | ---- |
| `id` | 是 | 节点的唯一身份，边通过它引用节点；字符串或整数 |
| `label` | 否 | 覆盖默认显示的 `id`，但不改变引用身份 |
| `index` | 否 | 使用 index 字号显示在节点外部正下方，例如线段树区间 |
| `interval` | 否 | 区间宽度树用于校验和布局的语义区间 `[l, r]`；不直接渲染成文字 |
| `value` | 否 | 节点存储的一个主要值，例如点权 |
| `fields` | 否 | 多项具名信息组成的映射，例如 `sum` 和 `lazy` |

普通图的点编号仍叫 `id`，因为它是身份，不要求连续，也不要求是整数。`index` 专门表示需要像数组下标一样放在节点外部的辅助信息；内部引用始终使用 `id`，不会受显示文字影响。

`interval` 只参与区间宽度树的校验和几何布局，因此不能与 `index` 同时提供。普通图、普通有根树和统一宽度树不接受 `interval`。区间宽度线段树用节点跨度直接表达覆盖范围，不再重复显示 `[l,r]`；Fenwick 区间由 `lowbit` 自动推导，不在节点中手写。

圆形或正方形节点只有 `id` 或 `label` 时，这段文字在节点中央显示。节点同时具有 `value` 时，value 使用与数组格 value 相同的字号在节点中央显示，编号或 label 使用与数组 index 相同的字号放在节点外部下方。因此，点编号和点权不会被合并成一个含义不清的字符串。

矩形数据结构节点默认在内部显示全部信息：编号或 label 是较小的辅助行，value 是主要行，`fields` 按 YAML 顺序显示成 `name = value`。指定 `index` 后，index 移到节点外部正下方；节点内部只保留显式 label、value 和 fields。`fields` 只允许用于矩形节点。

普通图默认使用圆形节点，也可以使用与圆形同尺寸规则的正方形节点。需要保存区间、聚合值、懒标记等多项信息的数据结构树使用可扩展宽高的矩形节点：

```yaml
node-shape: rectangle
```

同一张图中的节点使用统一形状和统一尺寸。圆形与正方形复用数组的 value 字号、index 字号、文字内边距和最小格宽；圆形直径与正方形边长始终相等。矩形复用数组的 value 字号、最小格高和内边距，再按多行内容扩展。最长内容决定全部节点的尺寸，使层内间距和树的对称性保持稳定。

## 边和值

图和普通树显式列出边：

```yaml
edges:
  - from: 2
    to: 5
    value: 7
```

`from` 和 `to` 引用节点 `id`。可选 `value` 表示边权、容量或其他边上的值。边 value 与数组格 value、节点主 value 使用完全相同的字号和正常字重；它保持为水平文字，不随斜边旋转。

渲染器从边的中点沿法向偏移 `0.7` 个 value 字号，并在两个法向中选择屏幕坐标更靠上的一侧。因此水平边的 value 位于正上方，斜边的 value 贴近斜边上侧。竖直边没有几何上的“上侧”，统一放在边的右侧。边线从节点外边框开始并在目标节点外边框结束，不穿过节点内容。

普通图带外部编号时，布局器会对指向正下方扇区的邻边施加额外角度排斥，尽量把该位置留给编号。普通图的直边始终沿两个圆心的连线，并只在圆周处截断，不会为了避让把端点改接圆的侧面。这个要求在稠密图中仍是软约束。二叉树另有明确的结构语义：左右孩子边分别从矩形父节点底部左角和右角出发，再接到孩子上边框中点，使父节点下方居中的区间 index 与两条分叉线互不重叠。

v2 支持单个节点上的自环。在角度模型中，自环按图论定义贡献两个 incident half-edge；距离弹簧忽略自环，因为自身到自身没有可优化的边长。渲染器寻找普通邻边之间最大的空夹角，把自环的两个连接端口放在该夹角的两个三等分点，角度力也把这两个端口计入节点总度数。若移除自环节点后各个分支互不连通，渲染器会把每个分支作为整体旋转，使普通边和自环的两个端口严格等角；一般稠密图则保留软约束近似。接近相同大小的空夹角优先选择上方，避免压住圆外编号。边 value 放在环的外侧；有向自环在重新接触节点外框前绘制箭头。v2 仍拒绝同向重复边；多重边需要曲线顺序和独立的标签避让，后续单独设计。

## 多行数组

```yaml
schema: cp-diagram/v2
type: array
background: white
index: 1-based
layout: stacked
rows:
  - id: a
    cells: [3, 1, 4, 1, 5, 9]
  - id: prefix
    cells: [3, 4, 8, 9, 14, 23]
```

顶层字段：

| 字段 | 必需 | 说明 |
| ---- | ---- | ---- |
| `index` | 否 | `0-based`、`1-based` 或 `none`，默认 `1-based` |
| `layout` | 否 | `stacked` 或 `projection`，默认 `stacked` |
| `rows` | 是 | 至少一行数组 |

每一行包含：

| 字段 | 必需 | 说明 |
| ---- | ---- | ---- |
| `id` | 是 | 行的唯一身份，也是默认显示的数组名 |
| `label` | 否 | 覆盖左侧显示的数组名 |
| `cells` | 是 | 非空的字符串或数字列表 |

所有行必须具有相同数量的格子。渲染器根据所有行中的最长 value 只计算一次统一格宽，所有行复用完全相同的列坐标。行距固定且相等；数组名与各自行的 value 共用水平中心线；index 只在最下面一行之后显示一次。

handbook 正文仍统一使用 `1-based`。`0-based` 只是绘图器保留的接口。

v2 多行数组暂不接受 annotation。需要单行箭头、范围和格子强调时继续使用 v1；等多行基础布局稳定后，再设计 annotation 应该引用哪一行以及如何分配行间轨道。

### projection 布局

`projection` 必须恰好包含两行：第一行是上层派生数组，第二行是原数组。上层使用实线格，下层使用虚线格，每一列用同主题虚线向下连接。相邻格之间留出 `0.25` 格宽，实线格与虚线格共享同一列距；这个间距接近一组 `7px + 5px` 的虚线节奏，避免相邻虚线边框视觉粘连。上下两层之间使用与树层相同的 `54px` 标准净空。两行的 `id` 和 `label` 都不显示；如果启用 index，只在下层原数组之后显示一次。这个布局适合前缀和等下标与原数组一一对应的派生数组：投影已经表达对应关系，不在上层重复数组名或下标。

## 普通图

```yaml
schema: cp-diagram/v2
type: graph
background: white
directed: false
layout: balanced
node-shape: circle
nodes:
  - {id: 1, value: 8}
  - {id: 2, value: 3}
edges:
  - {from: 1, to: 2, value: 4}
```

| 字段 | 必需 | 说明 |
| ---- | ---- | ---- |
| `directed` | 否 | 是否绘制有向边，默认 `false` |
| `layout` | 否 | 当前固定为 `balanced` |
| `node-shape` | 否 | `circle`、`square` 或 `rectangle`，默认 `circle` |
| `nodes` | 是 | 非空节点列表 |
| `edges` | 是 | 边列表，可以为空 |
| `annotations` | 否 | 加粗路径或回路 |

有向边的箭头接触目标节点的外边框。`from` 和 `to` 只决定方向，不暗含树中的父子关系。

### path annotation

```yaml
annotations:
  - type: path
    nodes: [1, 2, 3]
    closed: true
    color: red
```

`nodes` 按路径经过顺序至少列出两个节点。`closed: true` 会额外连接最后一个节点和第一个节点，此时起点不在列表末尾重复书写。渲染器校验每一对相邻节点之间确实存在边；有向图还必须沿边方向前进。

path annotation 用基础线宽的 1.25 倍覆盖路径边和相关节点外框，节点内部 value 与外部编号仍保持黑色。`color` 默认 `red`，也可以显式使用 `blue` 或 `green`。同图需要表示主回路和第二条路径时，先用红色，再用蓝色。

### balanced 布局

普通图很难像树一样同时满足固定边长、无交叉和局部等角。v2 把这些目标作为软约束，按以下固定流程求近似布局：

1. 按规范化后的节点 `id` 排序，避免 YAML 节点顺序影响初始编号。
2. 在圆周附近生成初始位置，并使用固定种子 `20260811` 产生小范围角度和半径扰动。
3. 运行 420 轮确定性的力导向迭代：所有节点互相排斥，相连节点由目标边长弹簧吸引，整体受到轻微向心力。
4. 对同一节点的相邻边增加较弱的角度均衡力，让局部过小的夹角展开。它是软约束，不会为了等角完全破坏边长。
5. 有外部编号时，在不改变边长和夹角的前提下枚举整图旋转角度，选择最能避开竖直边的位置；含自环时同时约束自环留在上方。
6. 按边长中位数统一缩放到主题目标边长，并在必要时整体放大，保证圆形或矩形节点不相撞。
7. 根据最终包围盒生成画布，不把计算坐标暴露给 YAML。

算法不调用全局随机状态，也不提供单图 `seed` 字段。相同输入、相同渲染器版本必须逐字节生成相同 SVG。对于高度对称或很稠密的图，布局仍可能存在边交叉；这不是第一版的硬性失败条件。

## 普通树

```yaml
schema: cp-diagram/v2
type: tree
layout: rooted
root: 1
nodes:
  - {id: 1}
  - {id: 2}
edges:
  - {from: 1, to: 2}
```

`rooted` 布局要求：

- `root` 必须存在。
- `edges` 必须恰好有 `n - 1` 条。
- 每条边按父节点到子节点书写。
- 每个非根节点恰好有一个父节点，且所有节点从 root 可达。
- `node-shape` 默认是 `circle`。

布局先计算每棵子树需要的叶槽宽度，再给兄弟子树分配连续且不重叠的水平区间，父节点放在自己的区间中央。所有深度使用相同的竖直间距，同一父节点的孩子按 YAML 边顺序从左到右排列。叶槽使用统一宽度，因此同层节点会尽量均匀，同时不会相撞。

可选 `directed: true` 会给父子边添加向下箭头；默认只利用 root 确定布局，不绘制方向。

## 二叉树与线段树

```yaml
schema: cp-diagram/v2
type: tree
layout: binary
node-shape: square
node-width: uniform
root: n1_2
nodes:
  - id: n1_2
    index: "[1, 2]"
    value: 4
  - id: n1
    index: "[1, 1]"
    value: 3
  - id: n2
    index: "[2, 2]"
    value: 1
edges:
  - {from: n1_2, to: n1, side: left}
  - {from: n1_2, to: n2, side: right}
```

`binary` 具有和 `rooted` 相同的树结构校验，但每条边必须额外指定 `side: left` 或 `side: right`，同一个父节点的两侧不能重复。显式 side 可以正确表达只有一个孩子的树，避免渲染器猜测它是左孩子还是右孩子。

布局为完整二叉树的每一层保留规则槽位：左右孩子相对父节点使用相反且相同的水平偏移，所有层使用相同竖直间距。完整层中的节点等距；缺失节点只留下对应空槽，不会把另一侧拉到中央。因此线段树在叶子数量为二的幂时严格左右对称，同一父节点的两条边也严格等角。

基础线段树把区间写成节点外部较小的 index，把区间和直接写成节点内部的主要 value，不重复添加 `sum =`。只有一个 value 时使用与数组格尺寸规则一致的正方形；父节点的两条边从底部两角岔开，不经过位于正下方的区间。只有节点确实同时保存 `sum`、`lazy` 等多项信息时才改用 rectangle 和 fields。整张图始终使用最长内部内容计算出的统一节点尺寸，避免某个 value 变长后单独改变一条边的角度。

`node-width` 的 schema 默认值仍是 `uniform`，用于普通二叉树和旧图兼容；正式线段树示例采用区间宽度布局：

```yaml
layout: binary
node-shape: rectangle
node-width: interval
root: n1_11
source-array: [3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5]
nodes:
  - {id: n1_11, interval: [1, 11], value: 44}
  - {id: n1_6, interval: [1, 6], value: 23}
  # ...
```

此时每个节点必须提供 `interval`，并且必须同时提供从 1 开始的 `source-array`。根区间覆盖整个原数组；每个非叶节点的左右区间必须连续且无重叠地划分父区间；叶节点必须是单点。相邻原数组格留出 `0.25` 格宽，原数组统一使用虚线框；节点从首格左边界延伸到末格右边界并覆盖内部间距，横向中心与整个覆盖跨度对齐。节点只显示 value，覆盖范围完全由长度和列边界表达，不重复显示 `[l,r]`。父子边的理论直线连接父区间中心与子区间中心，节点内部的线段被裁掉，只显示两个矩形边框之间的部分；因此锚点保持在区间中心，又不会穿过文字。各层不再追求完整二叉树的等距槽位，长度 11 会保留真实的不对称结构。叶节点与原数组之间使用标准 `54px` 净空，并通过虚线向下投影；原数组保留唯一一套位置下标。

## 树状数组

```yaml
schema: cp-diagram/v2
type: tree
layout: fenwick
node-shape: rectangle
node-width: uniform
source-array: [3, 1, 4, 1]
nodes:
  - {id: 1, value: 3}
  - {id: 2, value: 4}
  - {id: 3, value: 4}
  - {id: 4, value: 9}
```

Fenwick 布局要求节点 `id` 恰好是连续整数 `1..n`，不接受 `root`、`edges`、节点 `label` 或节点 `index`。它本质上仍是数组，所以渲染器直接把连续 id 自动显示成节点外部的数组下标 `1, 2, 3, ...`，不显示 `tree[1]` 之类的重复名称。可选 `source-array` 直接写成恰好含 n 个值的列表。渲染器按以下规则自动生成结构：

```text
parent(i) = i + lowbit(i)
```

当 parent 不超过 n 时，绘制 `i` 到 parent 的边。节点的横坐标按数组下标使用统一槽位；纵坐标由 `log2(lowbit(i))` 决定，管辖区间越长的节点越靠上。相同 lowbit 的节点位于同一行，行间距固定，同一行内的节点也落在等距下标网格上。最终效果自然向右上方倾斜，而不是强行伪装成完整二叉树。

指定 `source-array` 后，各槽位收紧为连续数组格宽，原数组在整棵 Fenwick 结构下方另画成完整的全虚线行。每个实线 Fenwick 节点都向同一列的虚线原数组格投影，包括 `lowbit(i) = 1` 的叶节点；因此 `tree` 与原数组不会共用同一个方框。节点自己的 index 仍在节点正下方，投影线要等 index 文字结束并再留出固定间隙后才开始，不穿过下标。虚线样式已经足以表达这行是映射出的原数组，所以不再显示数组 label。渲染器仍要求奇数叶节点 value 与对应 source value 完全一致。

节点内部的 value 是 Fenwick 数组真正存储的区间和：

```text
tree[i] = sum(a[i - lowbit(i) + 1 ... i])
```

完整示例使用 `a = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5]`，因此 11 个节点的 value 依次为 `3, 4, 4, 9, 5, 14, 2, 31, 5, 8, 5`。这里的边表示 `i -> i + lowbit(i)` 的更新传播关系，不表示线段树式的互不相交区间合并，所以父节点 value 不一定等于所有入边孩子 value 之和。

默认边没有箭头。需要讲更新方向时可以写 `directed: true`，箭头会从 `i` 指向 `i + lowbit(i)`。

正式树状数组示例使用 `node-width: interval`，并同时提供 `source-array`。渲染器自动推导节点覆盖区间 `[i - lowbit(i) + 1, i]`，节点框从首格左边界延伸到第 `i` 格右边界，覆盖格间的 `0.25` 格宽间距。框的几何中心负责放置 value，但结构锚点始终是最右侧第 `i` 格的中心；到 `parent(i)` 的实线边和到原数组第 `i` 格的虚线都从这个锚点出发。最底层节点与原数组之间使用标准 `54px` 净空。原数组使用互相分离的虚线格并独占一套 `1..n` 下标，Fenwick 节点下方不再重复显示 `i`。这使节点宽度负责表达“覆盖谁”，右端锚点与虚线负责表达“这是 `tree[i]`”。

当前区间宽度示例使用长度 11，而不是补齐到 16。非二次幂边界会直接显示 Fenwick 结构的尾部和线段树的不对称性；SVG 宽度随内容自然增长，不压缩字号、格宽或间距。

## 确定性与严格校验

- `yaml.safe_load` 不执行自定义对象或表达式。
- 未知字段、错误类型、重复 id、悬空边和非法树结构直接报错。
- 所有文字按纯文本写入原生 SVG `<text>`，不解释 HTML。
- rough-py 的每个几何图元继续使用确定性 seed；普通图布局使用独立的固定 seed。
- 同一输入连续渲染必须产生完全相同的 SVG。

# 第 01、02 章逐篇重写目标

## 启动条件

本目标承接 [学习路线重组计划](CURRICULUM-PLAN.md)。当第 01、02 章的文章边界、学习单元和大致顺序已经完成一轮目录审查，并且当前协作学习系统的活动目标已经结束或由用户明确切换后，创建并执行对应的长期 goal。

目录不需要成为永远不变的最终版本。逐篇写作中发现遗漏、重复、错误依赖或不自然的单元边界时，可以先用一个独立小提交修订目录，再继续正文；不得为了等待“完美大纲”停止内容推进。

## 总目标

按照 `notes/learning-path.md` 中的学习单元，逐篇重写和细化：

- `01 C++ 基础`；
- `02 算法基础`。

每篇学习正文只解决一个足够小且明确的问题，从真实用途或问题背景出发，把关键结论和代码逐步推导出来，并配套真正能够检验理解的单项选择题。完成后，两章应当能够按顺序连续学习，也能让模块正文独立查阅；不能只完成目录、空骨架或术语清单。

## 出版边界

- `notes/learning-path.md` 决定课程顺序和学习单元。
- `notes/catalog.md` 决定模块归属和完整知识登记。
- 课程需要不同引入、取舍或练习时，在 `notes/learning-path/<module>/` 保存学习正文；模块正文不为了复用而被迫承担两种不同叙事。
- 真正共享的事实、SVG 和竞赛模板继续复用，不复制两套会独立漂移的资产。
- 学习路线专属选择题保存在正文旁的 `<filename>.quiz.json`；模块正文不自动获得同一套学习状态。
- 文件名使用稳定的语义 `article_key`。已有文章拆分时，优先把原文件收窄为最接近的主题；确需改名或替换时，同时处理旧链接、内容清单和用户状态迁移。

## 学习单元

以正式学习路线中的单元为准，不根据文件夹或模块机械分组。当前规划至少包括：

### 01 C++ 基础

1. 第一个竞赛程序；
2. 值、类型、字面量、变量与常量；
3. 表达式与控制流；
4. 函数、作用域与程序交互；
5. 数组、C 字符串与结构体；
6. 地址、指针、引用与参数传递；
7. 存储期、调用栈与递归；
8. 不阻塞竞赛主线的 C++ 扩展单元。

正式目录在执行前还可以按 `CURRICULUM-PLAN.md` 中已经确认的细分进一步调整。关键字与标识符放在读者已经见过函数和主要控制语句以后归纳；`static`、内存、类与面向对象机制不得为了形式完整而提前阻塞主线。

### 02 算法基础

1. 复杂度；
2. 数组与 `vector`；
3. `pair`、排序接口与去重；
4. 递归与递推；
5. 排序；
6. 分治；
7. 二分；
8. 前缀和、差分、双指针与滑动窗口等序列技巧；
9. 枚举与模拟。

`string` 跟在 C 字符串以后留在第 01 章；`vector` 紧随抽象数组留在第 02 章。`pair` 在自定义排序以前进入主线，`tuple` 与 `array` 保留为模块扩展。链表、栈、队列、双端队列和对应标准库接口从第 02 章移到初中基础，使概念与接口相邻。

二叉堆和 `priority_queue` 不塞入第 02 章最早的算法基础，也不属于某一篇贪心文章。它们组成 `04 初中进阶` 开头的独立学习单元，紧邻贪心以前：先用完全二叉树的局部形状和 1-based 数组编号推导二叉堆，再学习 `priority_queue` 接口，随后在反悔贪心等算法中直接使用。

`set`、`multiset`、`map` 与 `multimap` 组成有序关联容器单元；`unordered_set` 与 `unordered_map` 组成哈希容器单元。两组不为表面整齐合并，也不要求先学平衡树实现；它们暂留 `04 初中进阶`，不属于本目标的逐篇正文范围。

## 单篇完成标准

每篇文章遵守 `AGENTS.md` 与 `notes/AGENTS.md`，并按主题判断是否需要以下内容，而不是机械套用固定七段式：

- 读者为什么需要这个知识，它解决什么真实问题；
- 当前真正需要的前置，只用自然语言链接；
- 从已有做法逐步引出概念、变量、性质和算法步骤；
- 能显著降低理解成本的手算、流程或 SVG；
- 与推导顺序一致的分块代码；
- 适用时提供可直接运行或提交的完整 C++17 代码；
- 正确性直觉、复杂度、边界与常见错误；
- 只依赖本文及其前置的基础练习；
- 需要记住什么，以及哪些内容只需理解或查阅；
- 自然延伸但不属于本篇的扩展阅读。

C++ 与 STL 短文可以比算法文章短，但必须给出准确语义、最小完整示例、常用复杂度和真正会遇到的陷阱。算法文章必须让关键函数和状态能够从正文重新推导，不能先给模板再倒着解释。

新写或发生实质变化的正文统一标为“待审阅”，写入当次 Australia/Sydney 时间的最近修订信息。只有用户明确完整审阅当前版本，才能改成“已审阅”。

## 选择题标准

- 默认单项选择题，每题四个选项。
- 以“每个具有独立检验价值的二级标题约一道题”作为审查尺度，不作为硬性配额。
- 不考正文没有教过的术语，不用语法陷阱冒充理解，不为短文章强行凑题。
- 优先检查概念边界、代码执行、复杂度、关键不变量、边界条件和常见误解。
- 答错时不立即暴露正确选项；解析由读者主动查看，并说明错误选项为什么错。
- `question_id` 使用稳定的语义名称；题意变化更新 `question_revision`，完全替换题目才更换 ID。
- 新增或修改一道题不能让同文其他题的作答状态失效。
- 题目中的标识符、表达式和代码片段使用正确的 Markdown 代码格式。

## 逐篇执行流程

1. 按学习单元选择下一篇，不同时主动重写多篇正文。
2. 检查当前目录、同名单元、已有模块正文、下游引用、模板和图片资产。
3. 必要时先提交文章边界或目录顺序修正。
4. 重写正文并同步状态、最近修订时间、链接和稳定内容身份。
5. 新建或修订该文自己的 `.quiz.json`。
6. 运行 `make notes-check`、内容身份检查、题库校验和正文中代码的相关编译测试。
7. 只提交当前文章、直接题库、直接资产及不可分割的导航变化，使用中文提交说明。
8. 用户提出批注后继续按同一粒度修订；未被用户完整审阅时保持“待审阅”。
9. 一个学习单元完成后，检查单元内部顺序、前向依赖、术语统一、网站导航、小测验状态和主要桌面阅读体验，再进入下一单元。

已有工作区中的其他正文草稿属于独立任务。不得将它们顺手混入当前文章提交，也不得用破坏性 Git 操作清理。

## 完成标准

- 第 01、02 章正式目录中的每篇核心文章都有聚焦、可连续阅读的学习正文。
- 每篇正文的标题、路径、状态、最近修订时间和稳定内容身份一致。
- 所有真正值得检验的知识都配有选择题；题目、答案和解析通过构建校验。
- 拆分后的文章不存在失效链接、错误串接的用户状态或重复承担同一主题的正文。
- 学习单元内部基本只依赖此前内容；必要的螺旋回访在正文中明确说明。
- C++ 示例和竞赛模板遵守仓库命名、1-based、闭区间、`+5` 容量和代码格式约定。
- `make notes-check`、网站内容构建、类型检查和相关测试全部通过。
- 每篇文章保持独立小提交，用户能够逐篇审阅、批注和继续修订。
- 只有达到上述条件并完成一次全章审计，才能把该长期 goal 标记完成；“文章已经起草”不等于完成。

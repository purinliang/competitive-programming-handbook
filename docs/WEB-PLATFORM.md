# 在线学习平台规划

本项目将在现有 handbook 的基础上建设一个公开、免费的算法竞赛学习平台。网站首先服务于阅读和教学，随后逐步加入知识检查、CSP 模拟、学习记录与内容讨论。平台用于传播课程和沉淀学习过程，不设计付费墙、会员等级或付费解锁。

## 产品目标

- 将 `notes/` 中的 Markdown 与 SVG 发布为适合长期阅读的网页。
- 同时提供按学习路线和按知识模块两种导航，两者指向同一份正文。
- 在文章末尾提供少量 takeaway 选择题，检查读者是否掌握本文最重要的内容。
- 提供 CSP 初赛、复赛相关的模拟、作答记录和逐题讲解。
- 用户系统建立后，保存阅读进度、作答历史以及文章和段落下的讨论。
- 匿名读者始终可以阅读公开内容；用户身份只用于同步状态和参与讨论。

## 平台边界

网站统一部署在 Cloudflare：

- 第一阶段使用 Next.js App Router 静态导出；Cloudflare Workers Static Assets 直接分发 HTML、RSC 数据、CSS、JavaScript、SVG 和搜索索引，不部署 Next.js 运行时 Worker。
- Markdown、目录与 Shiki 只在构建期运行。正文增长只增加静态资源，不占用 Worker 脚本大小额度。
- 需要用户数据后再增加只处理 `/api/*` 的 Worker；公开正文仍保持静态，不随请求重新渲染。
- D1 保存用户、进度、作答和讨论等结构化数据。
- R2 只在出现用户上传图片或附件时启用。
- Turnstile 用于保护注册、登录、留言和试卷提交等公开入口。
- Queues、Cron Triggers、KV 和 Durable Objects 只在出现相应需求时启用，不为了凑齐产品而提前引入。

网站不部署到 Cloudflare Pages。第一阶段虽然是纯静态站，但仍使用 Workers Static Assets，使以后可以在同一个 Cloudflare Worker 项目中为 `/api/*` 增加动态逻辑；静态资源默认不会触发 Worker。动态功能上线前不为了未来需求提前携带 OpenNext 或完整 Next.js 服务端运行时。

## 内容与数据的边界

Git 是出版内容的唯一事实来源：

```text
notes/                         教程正文、目录、学习路线和 SVG
assessments/takeaways/         文章 takeaway 题目、答案与讲解
assessments/csp/               CSP 试卷、答案与讲解
```

D1 只保存用户产生的状态：

```text
用户身份与会话
文章和段落阅读进度
练习及模拟考试作答记录
文章或段落的留言、回复、举报与审核状态
```

文章正文、题目、标准答案和讲解不以 D1 为主存储。它们需要接受与代码相同的审查、版本控制和构建检查，也必须能够在没有数据库的情况下完整生成网站。

## 文章身份

四位编号只用于当前目录编排，不作为网站、API 或数据库中的文章 ID。

正文文件名去掉 `.md` 后得到 `article_slug`，例如 `hello-world.md` 对应 `hello-world`。由于不同模块中已经存在 `array.md`、`queue.md`、`sorting.md` 和 `stack.md` 等重名文件，运行时使用模块相对路径作为唯一的 `article_key`：

```text
cpp/hello-world
data-structures/array
stl/stack
```

文章公开地址与该身份保持一致，例如 `/cpp/hello-world/`。重命名或移动正文会改变 `article_key`，因此必须同时登记旧地址别名并迁移关联的用户数据。构建检查必须拒绝重复的 `article_key`、失效的目录路径和未处理的别名冲突。

每次构建还应为正文计算 `content_revision`。阅读进度、题目和讨论可以借此判断自己引用的是当前版本还是旧版本。

## 段落身份与讨论

网站将标题、普通段落、代码块、表格和图片等 Markdown 块视为可定位的内容块。构建结果至少包含：

```text
article_key
content_revision
block_key
block_kind
quoted_text
```

默认 `block_key` 根据所在标题路径与规范化内容生成。确实需要长期稳定引用的段落允许在 Markdown 中显式指定锚点。讨论串同时保存 `block_key` 和当时的引用文本：文章修改后如果无法可靠地重新定位，讨论仍显示原引用，并明确标记为对应旧版本，不把留言猜测性地挂到另一段正文。

讨论数据采用“讨论串 + 留言”的模型。留言可以通过 `parent_comment_id` 回复另一条留言；数据允许多级关系，界面初期只展示顶层留言和回复两级。模型从开始就保留软删除、锁定、举报和审核状态，避免公开讨论上线后再破坏性迁移。

## 练习与模拟考试

文章 takeaway 与正式模拟承担不同任务：

- takeaway 紧邻文章，题量少，提交后立即展示答案与解释，不承担防作弊职责。
- CSP 模拟是独立试卷，支持计时、统一提交、评分和逐题讲解。标准答案不进入发送给浏览器的试卷数据，由 Worker 在服务端判定。

题目使用稳定的语义键，不使用展示顺序作为身份。试卷和题目都保存修订版本；数据库记录用户回答的是哪个版本。初期可以匿名完成练习而不保存云端记录，用户系统完成后再绑定 `user_id`。

文章中的练习在阅读体验上属于正文末尾的一部分，但题目源文件仍保存在 `assessments/takeaways/`，通过 `article_key` 绑定正文。这样可以单独校验选项、答案、解析和题目修订，而不把交互数据混进 Markdown 结构。

第一版 takeaway 完全在浏览器中运行：

- 练习区位于正文结束以后、上一篇与下一篇导航以前，不使用弹窗。
- 一次只展示一道题；小型题号导航始终显示，包括只有一两道题的文章。
- 每道题独立选择和提交，未提交以前不显示正确性。
- 提交后同时标出正确选项和读者选择；成功与错误状态除绿、红语义色以外，还必须使用图标或文字，不允许只靠颜色传达。
- “查看解析”在本题提交后可用，由读者主动展开；上一题、下一题与提交保持固定操作位置。
- 匿名作答状态可以保存在浏览器本地，并以 `article_key`、题目语义键和题目修订共同区分；清除浏览器数据后可以丢失，不承诺跨设备同步。

takeaway 是低压力的理解检查，答案随静态资源发送到浏览器没有防作弊意义。CSP 模拟仍由服务端判定，两者不能复用同一套答案暴露策略。

## 内容推进顺序

知识库采用“先覆盖，再练习，再反复审阅”的推进方式：

1. 先维护模块目录和学习路线，允许在写作中继续拆分、合并、移动或补登记知识点。
2. 按学习路线依次起草全部核心教程，再按模块目录顺序起草全部扩展专题；每篇正文聚焦一个主题，完成检查后单独提交并标为“待审阅”。触及一篇文章时同时检查其标题和学习单元，必要时随该篇逐步重命名或调整分组，不等待一次全库迁移。
3. 全部已登记知识点至少拥有一版正文以后，再为各篇文章编写 takeaway 选择题并实现上述静态交互；补题时仍可根据正文的真实边界修订标题和学习单元。
4. 作者逐篇阅读、提问和修订；只有经过完整人工审阅的当前版本才标为“已审阅”。正文后续发生实质变化时，相关题目也必须检查是否仍然成立。

这一顺序不要求大纲先成为不可修改的最终拓扑。正文起草暴露出的主题边界、真实前置和难度问题，应立即反向修订目录；但不得同时大批起草正文和题目，使同一处知识变化需要维护两套尚未稳定的内容。

## 第一阶段交付

第一阶段只建设无需用户数据也能完整工作的阅读站：

1. Next.js App Router 静态导出与 Workers Static Assets 部署骨架。
2. 从 `CATALOG.md` 和 `LEARNING-PATH.md` 构建统一内容索引。
3. 渲染 Markdown、GFM 表格、LaTeX、代码块、相对链接和 SVG。
4. 学习路线、模块目录、文章页、文章目录和上一篇/下一篇导航。
5. 全文搜索、响应式布局和深色模式。
6. 显著展示计划、待审阅、已审阅及旧状态；计划文章不可点击。
7. 构建时检查文章身份、链接、资源、路由和内容元数据。

第一阶段不创建假的用户表、空讨论接口或无法使用的题库后台，但其路由、内容身份和数据边界不得妨碍后续阶段。

## 界面设计

网站沿用同一作者项目 Arctic Aria 的基础设计语言，但不复制其复杂业务界面：

- 使用同源的蓝色与中性灰视觉方向，以及页面、面板、面板标题三层表面角色。
- 颜色通过全局语义变量引用，普通页面和组件不自行创建局部色板。
- 主间距以 `16px` 为基本节奏，小间距从 `4px`、`8px`、`12px` 中选择。
- 中文界面使用适合简体中文的系统无衬线字体栈和更宽松的多行行高。
- 普通界面字重只使用正常、中等和半粗，不用大量粗体制造层级。
- 桌面阅读页采用模块导航、正文、本文目录三栏；窄屏时收起两侧导航，优先保证正文宽度。
- 交互状态复用主按钮与次按钮的颜色角色；文章审阅状态使用安静的文字说明，不堆叠彩色标签。
- 浅色、深色使用同一组语义角色，组件不分别维护两套颜色判断。

handbook 可以针对长文阅读提高正文行高、代码块密度和内容最大宽度；这些是阅读场景对同一设计语言的适配，不另立一套视觉系统。

完整的组件范围、阅读站新增组件和移植规则见 [在线学习平台界面规范](UI-DESIGN.md)。

## 后续阶段

### 第二阶段：知识检查

- 定义并校验题目文件格式。
- 为文章加入 takeaway 选择题。
- 实现固定题号导航、逐题提交、提交后正误标记、按需展开解析和上一篇/下一题操作。
- 匿名作答进度先保存在浏览器本地，不提前依赖账户或 D1。
- 建立 CSP 试卷页面、服务端判题和讲解页面。
- 在没有账户时允许匿名练习，不承诺跨设备保存。

### 第三阶段：用户状态

- 建立适合公开学生使用的登录与会话系统。
- 使用 D1 保存学习进度、作答历史和模拟考试结果。
- 匿名浏览保持可用，不增加付费权限层。

### 第四阶段：内容讨论

- 开放文章级和内容块级讨论。
- 支持回复、引用旧版本、举报、软删除和审核。
- 使用 Turnstile、限流和必要的异步审核控制滥用。

## 工程原则

- 先保持内容系统简单，再为已经出现的用户行为增加服务。
- 优先使用 Cloudflare 原生能力，但不让产品设计依赖某个不必要的专有服务。
- 本地构建和测试不得依赖线上 D1；动态能力使用 Wrangler 提供的本地绑定验证。
- `next dev` 只能用于界面开发；提交前必须运行静态导出，并使用 Wrangler 本地预览或部署 dry-run 检查实际 Workers Static Assets 环境。
- 每一阶段都必须可以独立部署、使用和回退，不能提交只有未来功能完成后才成立的中间态。

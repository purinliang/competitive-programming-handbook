## 推进方式

1. 选择当前学习单元中的一篇文章。
2. 核对标准术语、竞赛圈常用说法和真实使用场景，避免用跨语言上位概念替代 C++ 中的自然名称。
3. 修订或新建正文，并检查它没有提前依赖后面的知识。
4. 同步学习路线、模块目录、引用、稳定文章身份和审阅状态。
5. 运行内容检查；一次提交只固化一个主题或一个不可分割的小组。
6. 用户阅读并提出修改后继续修订；只有用户完整审阅当前版本才标记“已审阅”。

已有文章的语义文件名是协作系统中的稳定 `article_key`。拆分时优先把原文件收窄为最接近的核心主题，新主题使用新文件；确需改名时必须同时设计旧地址和用户数据迁移，不能只修改路径。

## C++ 基础的已确认结构

### 第一个竞赛程序

1. Hello World!
2. A+B Problem

### 基本类型

1. 整数类型
2. 浮点类型
3. 字符类型
4. 布尔类型
5. 类型转换。

类型转换区分隐式转换与显式转换，并说明截断和精度丢失。转换为 `bool` 时，零变成 `false`，所有非零值包括负数都变成 `true`；`bool` 的对象大小不表示它能保存同样数量的独立数值。

### 变量、常量与字面量

1. 变量
2. 常量
3. 字面量

每种类型在自己的文章中解释对应字面量的具体写法；“字面量”只统一名称、类型关系以及它与变量、`const` 对象的区别，不重复机器表示。

C++ 标准术语中，由声明引入的对象或引用是变量，因此 `const int MOD` 仍然是变量，同时也是 `const` 对象。文章标题和日常正文使用竞赛圈更自然的“常量”；首次定义时再说明标准分类，并区分字面量、常量和常量表达式。

C++ 中的对象不限于类实例；普通整数、数组和结构体实例都可以是对象。正文第一次使用“对象”时说明这个范围，后续日常表达仍可直接说变量。

`constexpr` 与 `volatile` 是本单元中的独立扩展。前者在普通常量以后区分“值不可修改”和“可在编译期求值”，后者只准确解释访问语义及其不能替代线程同步的边界；二者都可跳过，不作为后续核心文章的前置。

### 表达式

1. 算术运算符
2. 比较运算符
3. 逻辑运算符
4. 自增、自减运算符
5. 复合赋值运算符
6. 位运算符

位运算符文章覆盖 `&`、`|`、`^`、`~`、`<<` 和 `>>`；逻辑运算符文章覆盖 `&&`、`||` 和 `!`。不建立一篇要求背诵完整表格的运算符优先级文章：每篇只解释当前必须知道的局部关系，混合不同运算符时优先用括号直接表达结构。

### 控制流

1. `if` 与 `else`
2. `switch`
3. `while`
4. `for`
5. `do while`

`switch` 不与 `if` 合篇；`while`、`for` 和 `do while` 也各自成篇。`break` 在 `switch` 和循环的实际语境中解释，`continue` 在循环中解释，不单独成篇。`do while` 使用频率低，但语义独立，因此放在本单元最后，目标只是会读、会在“至少执行一次”时使用。

### 函数、作用域与程序交互

函数不是为了凑“控制流”分类而并入条件和循环。函数定义、调用与返回先形成独立主题；随后再用一篇“关键字与标识符”归纳此前已经反复出现的语言保留词和程序名称。它不是声明变量以前必须先学的抽象前置。

函数部分需要逐篇回答：

1. 函数的定义与调用；
2. 返回值与 `return`；
3. 形参、实参与参数传递；
4. 递归函数留到调用栈以后回访，不在函数基础中提前倾倒。

“关键字与标识符”在这里回顾此前见过的 `int`、`return`、`if`、`else`、`for`、`while` 等关键字，再总结变量名、函数名和类型名都是标识符。它只列当前已经出现且值得辨认的关键字，不要求背诵完整关键字表。

作用域在读者已经见过函数和代码块后学习。这里区分局部名称、全局名称以及遮蔽关系；局部、全局与 `static` 局部变量还要区分名称可见范围和对象存储期，不能把 `static` 局部变量叫作“局部作用域的全局变量”。`static` 的初始化时机、跨调用保留状态以及与普通局部变量的区别单独成篇。

标准输入、标准输出、格式控制和文件重定向根据实际主题分别成篇。

### 数组

1. 一维数组
2. 多维数组

一维数组先讲容量、下标和遍历；多维数组再讲行列下标。数组与字符串不共用学习单元：数组解决一组同类型对象怎样连续存放，字符串还要建立终止标记、文本输入和字符串操作等独立语义。

### 字符串

1. C 字符串；
2. `string`；
3. 整行输入。

C 字符串建立在字符数组之上，先说明末尾空字符。随后从手工维护长度和容量的困难引入标准库类型 `string`，明确它虽然属于 C++ 标准库，但在这里按“怎样表示文本”的问题进入主线，不需要先学完其他 STL 接口。整行输入最后统一比较 `fgets`、`cin.getline` 和 `getline`，不能误写成只有 `string` 才能读整行。

正文需要区分头文件 `<cstring>` 与 `<string>`：前者提供处理 C 字符串的函数，后者声明标准库字符串类型。

多维数组的连续布局、行优先顺序、作为函数参数时后续维度为什么必须已知，以及结构体内存对齐都属于明确的配套扩展。正文要解释：大型内置数组常放在全局作用域是一种避免调用栈大对象和复杂参数类型的竞赛实现选择；需要传递并修改动态序列时，通常传 `vector` 的引用。这不是宣称所有代码都应使用全局静态数组。

### 地址、指针与引用

建议逐篇组织：

1. 地址与字节寻址；
2. 指针；
3. 引用；
4. 参数传递；
5. 指针与引用中的 `const`。

地址先说明变量占据内存、地址用来定位它，不需要一开始讲完整计算机体系结构。指针保存地址，引用提供别名；二者有联系但不能合成一个主题。参数传递在读者已经理解值、地址和引用以后，区分按值复制、指针参数和引用参数。

早期“常量”文章只讲普通 `const` 对象。`const int*`、`int* const`、`const int* const` 和 `const T&` 等读者理解指针与引用后再系统比较；不能让早期常量文章同时承担对象、指针和引用三套声明语义。

### 结构体、联合体与枚举

建议逐篇组织：

1. `struct`；
2. 结构体成员与点运算符；
3. 指向结构体的指针与箭头运算符；
4. `union`（扩展）；
5. `enum`（扩展）。

把这一单元放在指针以后，`.` 与 `->` 都能从对象和地址的区别自然解释。中文正文使用“结构体”或“结构体类型”，不把 `struct` 固定称为“记录类型”。严格分类上，C++ 的 `struct` 与 `class` 都能声明类类型；主线先学习竞赛中把若干相关字段组织在一起的结构体用法。`union` 与 `enum` 在当前阶段适合了解但不会阻塞后续，因此与结构体同单元并标星；成员函数、继承和多态进入独立的“类与对象”单元。

结构体内存布局使用 `0121e1*` 作为 `struct` 的附属扩展，不进入学习路线或扩展阅读索引；模块目录仍完整收录，并从结构体正文提供直接链接。

内存布局扩展说明字段声明顺序、对齐、填充、`sizeof` 和二维数组嵌入结构体时的布局。它帮助解释观察到的大小，不能把某个编译器的具体填充结果写成所有平台唯一可能的标准布局。

### 内存、调用栈与递归

这一单元在变量、函数、地址和数组都出现以后再学习：

1. 竞赛程序常见的内存区域；
2. 调用栈；
3. 递归；
4. `static` 局部变量可根据真实依赖放在作用域之后或在这里回访。

“内存区域”只从 C++ 竞赛程序解释全局或静态存储、调用栈和动态分配等常见现象，高地址低地址只作为实现示意，不宣称标准规定了唯一布局。对象生命周期、存储期和作用域是相互关联但不同的概念；需要分别命名，不能用一张“四区图”替代全部语言规则。

调用栈先解释一次普通函数调用保存什么，再解释嵌套调用，最后才引出递归。递归是函数调用自己的特殊情况，不把它提前放进与函数无关的章节。

### 输入输出

基本 `cin`、`cout` 已在 Hello World! 和 A+B Problem 中先作为格式代码使用。后期再分别系统整理：

1. 标准输入；
2. 标准输出；
3. 浮点精度和其他格式控制；
4. 整行输入；
5. 文件重定向。

这一安排允许读者先写程序，再理解 `scanf` / `printf`、流状态和格式接口，不为了介绍完整 I/O 提前阻塞语言主线。文件重定向介绍 `freopen` 和 OI 赛制中按题目要求读写文件的标准写法。

### C++ 扩展阅读

扩展内容也必须保留明确文章边界和教学问题，不能只留一串名词。

#### 从源码到程序

建议逐篇组织：

1. 编译：C++ 源码怎样翻译成机器可以执行的内容；
2. 链接：多个翻译单元以及库中的名称怎样组成最终程序；
3. 预处理；
4. 预处理：`#include`；
5. 预处理：`#define`。

预处理正文先给出从源文件到可执行程序的阶段关系，再解释预处理命令发生在哪里。`#include` 单独比较尖括号与双引号的查找语义。宏覆盖对象式宏、带参数宏、括号与作用域污染等问题，并简短解释多语句宏为什么常由 `do while` 包裹；正文可以展示 `FOR`、`REP` 等竞赛代码中可能遇到的缩写，但明确本书不采用这种风格。

这里只建立读代码和理解错误信息所需的直觉，不扩展成完整编译原理课程。`#include` 与 `#define` 都由预处理器处理，但用途不同，因此分别成篇。宏需要说明文本替换、参数括号和污染范围等陷阱，同时明确本书模板不用宏压缩类型、常量、左右儿子或递归参数。

#### 命名空间与别名

建议顺序：

1. 命名空间与作用域解析运算符 `::`；
2. `using namespace std;` 与 using 声明；
3. `typedef`；注意提一下这个是安全的，比define好，不过define顺序是反过来的。
4. using 类型别名。

命名空间先解释它怎样解决不同库或区域中的同名问题，以及 `std::vector` 中 `::` 的作用。随后才能准确解释 `using namespace std;` 为什么让代码省略 `std::`，以及只引入一个名称的 using 声明。

`typedef` 和 `using` 类型别名解决相似问题，但语法与现代模板能力不同，因此分别成篇。先用 `typedef long long ll;` 解释本仓库实际采用的别名，再让 `using` 文章比较等号两侧的顺序、using 声明、using 指令和别名模板；不能只写一个泛化的“类型别名”条目后遗忘差别。

#### union 与 enum

`union` 和 `enum` 分别成篇，不把枚举错误地归为“结构体的一种”。`union` 解释多个成员共享存储以及当前有效成员的约束；`enum` 解释一组具名整数值和作用域枚举。二者在竞赛中都低频，进入扩展阅读，但初赛或阅读代码可能遇到，因此需要准确的最小正文。

#### 类与对象

建议形成一个独立扩展单元：

1. `class` 与对象；
2. 类的成员；
3. 访问权限，其中介绍友元（`friend`）；
4. 构造函数；
5. 析构函数；
6. 函数重载与运算符重载；
7. 继承；
8. 多态。

`class` 首先与已经学过的 `struct` 比较：两者都能声明类类型，关键的语言差别包括默认成员访问权限和默认继承权限，而不是“`struct` 只能保存数据、`class` 才能有函数”。随后定义对象是类类型的实例之一，同时提醒 C++ 标准中的“对象”范围更广，普通整数同样是对象。

“类的成员”区分成员变量与成员函数，并说明日常所说的方法对应成员函数。还需要区分属于每个对象的非静态成员与属于类本身的静态成员；常量成员仍然是成员变量，只是具有 `const` 限制，不能另造“成员常量不是变量”的错误分类。

访问权限至少覆盖 `public`、`private` 和 `protected`，不能因为竞赛中前两者更常见就漏掉第三种。`friend` 允许指定函数或类访问非公开成员，是访问控制的例外机制，不把它描述成一种访问权限关键字。

构造函数解释对象建立时的初始化；析构函数解释对象结束时的清理。虚析构函数放在多态语境中说明：通过基类指针删除派生对象时为什么基类析构函数需要是虚函数，而不是把“析构函数一定要 virtual”写成普遍规则。

继承说明派生类复用和扩展基类接口，并覆盖单继承、多继承以及公开、保护、私有继承的名称可访问关系。竞赛主线不依赖这些机制，但正文不能只列名词。

多态重点区分：

- 同名函数或运算符根据静态参数选择属于重载；
- 派生类重新定义基类虚函数属于覆盖；
- 通过基类指针或引用调用虚函数，运行时选择实际派生对象的实现，才是这里重点解释的运行时多态。

正文可用最小示例辅助理解虚函数、对象中的实现开销以及常见的虚函数表模型，但必须注明虚函数表和虚表指针是主流实现技术，不是标准强制规定的对象布局。按值把派生对象复制到基类对象会发生对象切片，不能借此展示运行时多态。

这些机制竞赛中收益很低，扩展单元只要求理解名词、基本行为和阅读能力，不扩张到工程设计模式、模板元编程或完整现代 C++ 工程实践。

#### 其他语言机制

`inline`、`volatile`、对象生命周期、`constexpr` 等按独立问题标星，并放入语义最接近的学习单元和扩展阅读索引。每篇必须说明真实语义以及为什么不阻塞竞赛主线；不能因为作者当前很少使用就写成“没有作用”，也不能为了显得完整把它变成后续核心文章的前置。

## 算法基础的已确认结构

### 学习单元一：复杂度

1. 复杂度
2. 从代码分析复杂度
3. 渐近记号（配套扩展）

“复杂度”建立输入规模、时间与空间复杂度、大 $O$、最坏情况、常见增长数量级、总空间与额外空间。“从代码分析复杂度”逐步分析：

- `i++`、`i += c` 等线性变化；
- `i *= c`、`n /= c` 等对数变化；
- 顺序代码相加；
- 独立嵌套循环相乘；
- 内层边界依赖外层时求总次数；
- 多个下标互相影响时统计整个程序中的总移动次数；
- 数组、容器和递归调用栈的空间。

复杂度示例优先写能直接体现规模变化的 `n /= 2`，不为了炫示位运算改成把移位赋值塞进条件。渐近记号扩展完整区分 $O$、$\Omega$、$\Theta$、$o$ 和 $\omega$；核心路线不要求记忆大 $O$ 以外的形式化定义。

这个单元虽然位于第 02 章开头，但不是一篇短导论。“复杂度”负责尺度、记号和空间口径，“从代码分析复杂度”负责把代码翻译成执行次数；二者共同完成一次完整学习任务。递归式、均摊分析等需要后续结构的内容不为追求一次讲完而提前加入。

### 高中阶段的复杂度进阶

高中基础再次设置独立学习单元：

1. 均摊复杂度；
2. 均摊复杂度：势能法。

第一篇从一串操作的总成本出发，使用动态数组扩容、栈的连续操作等例子说明：某一次操作可以很贵，但任意操作序列的总成本仍然受到更紧的限制。正文依次介绍聚合法和记账法，并严格区分：

- 最坏复杂度研究最坏的一次或最坏输入；
- 平均复杂度依赖输入分布；
- 期望复杂度依赖随机变量；
- 均摊复杂度不需要概率，它对操作序列的总成本作保证。

势能法独立成篇。先为数据结构状态定义非负势能，再把一次操作的实际代价与势能变化相加得到均摊代价；最后对整个操作序列求和，解释中间势能怎样抵消。正文必须从聚合分析已经得到的总成本反推一个自然势能，不能一上来凭空给出公式要求背诵。

均摊复杂度不是“把最坏时间除以操作次数”，势能也不是程序中实际存储的能量。两篇都要通过同一个操作序列逐步计算实际代价、账户余额或势能变化，让三种证明方式得到一致结论。

### 标准库基础

不再设置一章按标准库名字平铺的“STL 工具大全”。当前马上需要的类型和算法组成“标准库基础”，其余接口在对应实际问题出现时学习：

1. `vector`；
2. `fill`；
3. `pair`；
4. `tuple`；
5. `sort`；
6. `unique`。

复杂度独立组成第一个学习单元，不属于标准库基础。读者理解操作次数以后，再把以上六项作为后续代码马上需要的标准库工具学习；这一单元不提前罗列全部容器。数组作为数据结构的访问、插入删除和复杂度放到初中基础，与链表连续比较，不在复杂度和标准库基础中间突然插入一个“抽象数组”单元。

`string` 跟在 C 字符串以后留在 C++ 基础。它在那里解释字符串值、`getline`、`substr`、查找和修改；字符串算法以后复用这些接口，不在排序前把 `string` 当作一个无动机的 STL 名称重新学习。

`pair` 与 `tuple` 在 `sort` 以前学习。两篇分别保持聚焦：`pair` 处理两个值，`tuple` 推广到数量固定的多个值；它们都说明默认字典序、结构化绑定以及字段缺少业务名称的代价。这样排序、去重、二分和带权图可以复用同一种复合值表示，不必在存图时临时插入标准库接口。`array` 是固定长度序列容器，却通常既不如内置数组直接，也不如 `vector` 灵活，因此继续留在模块目录供查阅，不阻塞核心学习路线。

`unique` 必须说明它只整理相邻等价元素并返回新的逻辑结尾，不会自行缩短容器；排序去重再组合 `sort`、`unique` 和 `erase`。

`fill` 是文章的唯一主题。`memset` 不是 STL，而是按字节写内存的 C 标准库函数；它只在 `fill` 正文的下属二级标题中用于辨析。普通数值数组优先使用 `fill`。必须展示 `memset(a, 1, sizeof a)` 不会把每个 `int` 赋成 `1`，并且不能把主流竞赛环境中常见的字节模式行为误写成适用于任意类型和平台的通用赋值规则。

`min`、`max`、`swap`、`reverse` 等接口在第一次真实使用时解释，不为追求形式对称全部独立成篇。

`sort` 是一篇完整文章。它先解释迭代器范围、默认升序、原地修改和简单类型，再用“自定义排序”二级标题逐步覆盖降序、多关键字、具名比较函数、lambda、函数对象、类型自己的 `operator<`、`stable_sort` 以及比较规则一致性。比较器离开排序没有独立学习目标，因此不另建目录节点；正文仍可用多个二级标题控制篇幅。

### sort 的默认顺序与自定义排序

C++ 已经为许多标准类型提供自然的默认顺序：

- `pair` 先比较 `first`，相等时比较 `second`；
- `tuple` 按元素位置从前到后比较；
- `array`、`vector` 和 `string` 按元素字典序比较；变长序列的共同前缀完全相同时，较短者更小；
- 对一个 `string` 自身调用范围排序，是重新排列其中的字符；把若干 `string` 作为元素排序，才使用字符串之间的字典序。

短小记录若所有字段都按同一方向组成完整字典序，优先复用 `pair`、`tuple` 或 `array` 的默认比较，排序、相等判断和二分更容易保持一致。例如把 `(value, id)` 作为整体按值、再按编号排序时，`pair` 比额外定义比较器更短。

这不是要求把所有记录压成匿名元组。字段具有明确含义、字段类型不同且数量较多、排序方向混合，或者同一种记录需要多套顺序时，具名 `struct` 更可读：

- 类型只有一种真正自然、会被排序和二分反复使用的顺序时，可以为类型定义严格的 `operator<`；
- 某次操作需要临时顺序时，向 `sort`、`lower_bound` 等算法显式传入同一个比较器，避免把临时规则伪装成类型的天然含义；
- 教学代码先使用命名比较函数；lambda 适合只在调用点使用的短规则；重载 `operator()` 的函数对象用于需要携带配置或复用的比较器，并在正文说明 `greater<T>` 本身就是这种对象。

多关键字比较必须逐层处理：主关键字不同就立即决定顺序，主关键字相等才看次关键字。比较器返回“左侧是否严格在右侧以前”，相等时必须为 `false`，不能使用 `<=` 或 `>=`。

降序需要比较三种写法：

1. 简单类型使用 `greater<T>()`；
2. 复杂或混合方向使用自定义比较器；
3. 先升序 `sort` 再调用 `reverse` 可以得到整体逆序，但 `reverse` 只是翻转已有顺序，还会同时反转所有关键字方向，并额外线性扫描一次。

这里的方法名是 `reverse`，不是只预留容量的 `reserve`。若要求“分数降序、编号升序”，不能把默认升序整体 `reverse`，必须明确写出混合方向的比较规则。

排序、去重和二分必须共享同一套“先后”与“等价”语义。若 `comp(a,b)` 是严格比较，则排序意义下等价表示：

```text
!comp(a, b) && !comp(b, a)
```

但 `unique` 默认调用 `==`，并不会自动从 `comp` 推导等价关系。自定义类型按部分字段排序、却按全部字段判断 `==` 时，排序去重可能不符合题意；应当定义相符的 `operator==`，或显式传入等价判断。使用默认 `pair`、`tuple`、`array` 的优势之一，就是完整字典序和完整相等关系已经配套；若题目只按其中部分字段分组，仍需单独定义等价条件。

### 初中基础的数据结构

最初接触的数据结构不再挤进一个大单元，而是按真实关系拆成三个学习单元。

“数组与链表”比较线性表的两种典型存储思路：

1. 数组；
2. 链表。

数组文章复用已经学过的 `vector`，重点讨论随机访问、插入删除和连续存储的复杂度。链表文章依次解释结构与遍历、插入删除、头指针与虚拟头节点、双向链表和环形链表。低频的标准库 `list` 留在模块目录，不作为主线默认选择。

“栈”单元包含：

1. 栈；
2. `stack`；
3. 出栈序列判定；
4. 表达式求值。

中缀、后缀表达式和表达式树都服务于表达式求值。正文只借树形结构说明运算符与操作数的从属关系，不提前要求读者掌握一般树算法。

“队列”单元包含：

1. 队列；
2. `queue`；
3. 双端队列；
4. `deque`。

双端队列是把普通队列允许操作的端点扩展到两端，不与队列并列为单元主题。`deque` 是具体序列容器，`queue` 是默认可由 `deque` 承载的容器适配器；两篇必须分别解释。两个栈实现队列可以作为队列文章的练习或应用，不为它单独建立路线节点。

单调栈和单调队列需要读者理解栈、队列、双指针式的单调移动和更完整的复杂度分析，继续放在高中基础。

链表统一使用以下名称，避免“头节点”一词在不同资料中的歧义：

- `head` 是指向或记录第一个真实节点的头指针、头下标；
- 第一个真实节点仍然保存题目数据；
- 虚拟头节点（dummy head 或 sentinel）是不保存题目数据的额外节点，位于第一个真实节点以前；
- 使用虚拟头节点可以让在链表开头插入、删除与其他位置共用相同操作，但不是链表定义所必需。

链表正文需要对比数组：数组能按下标 $O(1)$ 随机访问，但在中间移动大量元素代价较高；链表只有在已经找到相关节点时，修改链接才是 $O(1)$。不能只写“链表插入删除是 $O(1)$”而漏掉定位节点可能需要 $O(n)$。

栈、队列和双端队列是抽象数据结构；`stack` 与 `queue` 是容器适配器，`deque` 是具体序列容器。文章必须在概念与标准库实现之间维持这一边界。

`priority_queue` 不进入本单元。它在理解二叉堆以后进入初中进阶路线。递推也不再作为算法基础的第二篇；等到递归、数列关系或动态规划真正需要时再安排。

### 排序

主线建议顺序：

1. 冒泡排序；
2. 选择排序；
3. 插入排序；
4. 计数排序；
5. 快速排序；
6. 归并排序；
7. 排序方法比较；
8. 排序的应用：离散化。

前三种都是 $O(n^2)$ 的比较排序，但必须分开推导：冒泡排序不断消除相邻逆序，选择排序每轮找出剩余部分的最小值，插入排序把新元素插进已经有序的前缀。现有“基础排序”正文可以作为共同引言，但正式重组时应根据篇幅拆成聚焦的小文章，不能因为复杂度相同就混成一种方法。

计数排序与桶排序不是同一个算法。本书统一采用严格区分：

- 计数排序为每个离散整数值统计出现次数，再根据次数恢复顺序；
- 桶排序先把一个值域划分为若干桶，还需要处理每个桶内部的顺序；
- 有些 OI 资料口语上会把计数排序称为“桶排序”，正文首次出现时说明这种叫法，但后续不混用。

快速排序和归并排序各自独立成篇。它们不仅要给最终模板，还要逐步解释划分或合并操作、递归区间为什么缩小、终止条件和复杂度来源。归并排序需要说明它为什么天然适合链表；快速排序和堆排序依赖随机访问，在链表上不自然。这里只建立数组与链表排序方式的比较，不要求主线实现完整的链表归并排序。

`sort` 与 `unique` 在前面的标准库基础单元首次学习。离散化不是学习这两个接口的地方，而是第一次把“排序、去重、二分定位”组合成完整算法，因此放在排序单元末尾作为排序的典型应用。正文保留本书自定义数据从 $1$ 开始和闭区间的约定，并明确传给 STL 时怎样转换为左闭右开迭代器范围。

“排序方法比较”独立总结时间、额外空间、原地性、稳定性、是否依赖值域以及适合的存储结构。稳定性必须绑定到具体实现，不能写成“除选择、快速和堆排序以外都稳定”：

- 本书采用严格比较的冒泡排序和插入排序，它们稳定；
- 朴素选择排序、通常的原地快速排序、堆排序、希尔排序以及 `std::sort` 不稳定；
- 归并时相等元素先取左半边，归并排序才稳定；
- 计数排序若只按频次重建整数序列，不保存相同键对象的原顺序；使用前缀位置和额外输出数组才能实现稳定版本；
- 基数排序要求每一趟按位排序稳定，整个算法才能正确保持前面各位建立的次序；
- 桶排序是否稳定取决于元素入桶、桶内排序和拼接方式。

堆排序与基数排序各写一篇扩展阅读：它们确实有方法价值，但不阻塞主学习路线。希尔排序只在“其他排序”中给出名称、基本思想和复杂度难以统一表达的原因，不投入一篇主线教程。桶排序先在计数排序中辨析概念；以后只有在确实需要展示值域分桶方法时再扩成独立文章。

### 二分

建议顺序：

1. 二分查找；
2. 二分边界；
3. 标准库二分查找；
4. 整数答案二分；
5. 浮点数答案二分。

二分查找先手写“是否存在并返回任意一个位置”，建立闭区间候选与每轮排除一半的循环不变量。二分边界再分别推导第一个不小于目标、第一个大于目标以及由二者得到的最后一个不大于目标，不能在第一次遇到相等值时提前返回。

自定义代码统一使用从 $1$ 开始的下标和闭区间 $[l,r]$。标准库二分查找单独整理左闭右开迭代器接口：

- `binary_search` 只回答目标是否存在，不返回位置；
- `lower_bound` 返回第一个不小于目标的位置；
- `upper_bound` 返回第一个大于目标的位置；
- `equal_range` 同时返回上下界，二者之差就是等价元素数量。

两套区间约定都要会，但同一个手写循环中不能来回切换。普通竞赛代码优先调用标准库边界接口；手写版本的价值是建立不变量，并为后面的答案二分服务。

对同一有序范围，`upper_bound` 与 `lower_bound` 返回位置之差就是等价元素数量。普通二分查找、边界查找和答案二分各自有独立目标，因此分别成篇但共用一个学习单元；整体二分、并行二分与三分不进入这个基础单元。

所有 STL 二分接口都要求范围已经按照与查询一致的顺序排列。默认 `pair`、`tuple`、`array`、`vector` 和 `string` 可以直接复用自然字典序；自定义 `struct` 若定义了自然 `operator<`，可以构造同类型查询值。若排序时显式传入了比较器，二分时也必须传入兼容的比较器，不能先按一种顺序排序再按另一种顺序查找。

边界文章必须让每一行来自循环不变量，而不是要求背诵互相矛盾的模板。至少解释：答案仍在哪个区间、`mid` 满足条件后保留哪一半、区间怎样严格缩小、循环结束时哪个变量才是答案，以及不存在答案时怎样表示。

中点计算与 C++ 整数规则需要集中辨析：

- `l + (r - l) / 2` 避免直接计算 `l + r` 可能产生的溢出；
- C++ 有符号整数除法向 $0$ 截断，并不总是数学上的下取整；二分中 `r - l` 非负，因此除以 `2` 才与下取整相同；
- 非负整数右移一位等价于除以 `2` 后下取整，但 C++17 中负有符号整数右移的结果由实现决定；
- `+` 的优先级高于移位运算符，所以 `l + r >> 1` 会被解析为 `(l + r) >> 1`，但它仍然可能溢出且可读性差，本书不采用这种写法；
- 当更新形式为 `l = mid` 时需要使用上中点 `l + (r - l + 1) / 2`，否则两个相邻整数可能使循环不再缩小。

整数答案二分围绕“答案是否可行”具有单调性展开：先写判定函数，再决定要找第一个可行还是最后一个可行，最后把边界模板翻译出来。它不是在数组中找元素，因此与普通二分查找分篇。

浮点数答案二分单独成篇。它没有整数区间相邻时的自然终止点，竞赛模板优先采用固定次数迭代；若使用误差阈值，则必须结合题目要求解释绝对误差、相对误差以及循环条件。不能把整数模板简单换成 `double` 后继续依赖 `l + 1 < r`。

### 前缀和

主线只包含两篇：

1. 前缀和；
2. 差分。

差分是前缀和的逆过程，因此单元以“前缀和”为主题，差分作为掌握累计与恢复关系以后自然得到的第二篇。它们依赖数组，但不属于线性数据结构。数组文章回答元素怎样连续保存、怎样访问以及各种操作的复杂度；本单元回答怎样利用相邻位置的累计关系，把一批区间查询或修改预先合并。因此不把它们塞进“线性结构”单元，也不为了凑篇数与排序或二分合并。

两篇文章组成一对相反过程：

- 前缀和从原数组累计得到前缀数组，并用两个前缀的差回答静态闭区间和；
- 差分保存相邻元素的变化，在两个区间边界记录增量，再用一次前缀和恢复最终数组。

正文需要把这种对应关系画出来，但教学顺序仍然先前缀和、后差分。差分文章可以直接引用读者已经理解的前缀恢复，不重新发明一套不相干的记号。

主线边界是“一维数组、静态区间和”和“一维数组、离线区间加”。以下内容作为本单元的配套扩展分别登记，不塞回两篇基础正文：

- 二维前缀和；
- 二维差分；
- 前缀异或等把加减换成其他可逆运算的变化；
- 高阶差分；
- 树上差分，它依赖树的遍历与最近公共祖先，应留在图论路线；
- 差分约束，它是图上的不等式系统，与差分数组只有名称相似，不属于本单元。

前缀和与差分都使用从 $1$ 开始的下标和闭区间。`prefix[0] = 0` 与 `difference[n + 1]` 都是有明确语义的边界位置，正好体现本书愿意多留少量空间来消除特判的代码风格。

工具选择必须在本单元末尾说清：普通前缀和适合不修改的数组；普通差分适合全部修改完成后再统一恢复。若修改和查询必须在线交错处理，才进入后面的树状数组或线段树，而不是继续硬套这两个静态技巧。

### 双指针

主线包含两篇：

1. 双指针；
2. 滑动窗口。
它们操作数组或字符串中的下标，但仍然不是线性数据结构。线性结构说明数据怎样保存；双指针说明怎样让多个下标单调移动，从而一次排除一批候选。这个区别与前缀和、差分相同，因此单独组成一个短学习单元。

“双指针”先使用有序数组两数之和建立最基础的相向模型：左、右指针分别从两端开始，根据当前和的大小证明可以排除哪个端点。文章必须强调，关键不是代码中恰好有两个下标，而是每次移动都能证明被跳过的状态不会再成为答案。

同篇可以简短指出另外两种形态，但不展开成模板合集：

- 归并两个有序序列时，两个指针分别在各自序列中同向移动；
- 链表的快慢指针用于找中点或判环，依赖链表及环的具体性质，应当在对应问题中重新推导。

“滑动窗口”是同向双指针中专门维护连续区间的一类方法，因此它与双指针同单元但独立成篇。正文同时讲固定长度窗口和由条件决定长度的可变窗口，并让窗口状态只在端点进入或离开时增量更新。

基础示例使用非负或正数数组，使“扩展右端时窗口和不减、收缩左端时窗口和不增”的单调性成立。文章必须给出含负数的反例，说明滑动窗口不是看到连续子数组就能套用的语法模板；需要先证明左右端都不会回退。

复杂度统一从总移动次数推导。即使实现为外层 `for`、内层 `while`，只要左右端各自最多移动 $n$ 次，总时间仍然是 $O(n)$，不能只按循环嵌套层数误判为 $O(n^2)$。

三数之和、去重计数、多序列指针、回文扩展、链表判环以及带单调队列的窗口分别留在具体题型或后续数据结构中。基础单元只建立“单调移动并安全排除”与“维护连续窗口”两种可复用思想。

### 枚举与模拟

主线包含：

1. 枚举；
2. 子集与位掩码枚举；
3. 模拟。

枚举与模拟确实属于算法基础。枚举先确定候选对象、唯一表示、生成顺序和检查成本；模拟先确定状态、每种操作的唯一效果以及执行顺序。它们不依赖某个高级数据结构，也是推导和验证后续算法时最可靠的朴素基准，因此可以组成一个相邻的基础单元。

二者仍然是独立文章。枚举解决“怎样不重不漏地遍历候选”，模拟解决“怎样逐条复现题目过程”，不能因为都常被称为暴力方法就混成一篇。子集枚举依赖已经学过的位运算，并作为普通循环枚举之后的第二种候选表示。

分治不继续与枚举、模拟和贪心共同放在“基本算法设计方法”大表中。它依赖递归，并且已经通过快速排序和归并排序获得具体经验，应独立形成后续的“分治”单元。

## 贪心的基础与进阶应用

贪心是一种基础算法设计思想，不能因为某一种贪心依赖堆，就把整个主题推迟到初中进阶。算法基础中的“贪心”单元放在排序之后，包含：

1. 贪心选择与正确性证明；
2. 邻项交换证明；
3. 反悔贪心。

反悔贪心本身不依赖二叉堆或 `priority_queue`：基础版本可以在线性扫描中找出当前方案里最应撤销的一项。它因此留在第 02 章的贪心单元，与选择规则和证明方法连续学习；以后学过 `priority_queue`，再回看怎样加速反复取最大值或最小值。哈夫曼编码还依赖前缀编码和二叉树，放在初中进阶的“编码”单元，并回链到基础贪心的证明方法。

现有“选择与证明”使用最多不重叠区间，讲清一般交换论证：把某组最优答案中的第一项换成当前贪心选择，并证明合法性与答案质量不变。它保留为单元入口。

“邻项交换”是更专门的排序型证明，不能与一般交换论证只写成一个名词。若一个排列中相邻两项违背目标比较规则，就证明交换这两项不会让答案变差；反复交换可以消除全部逆序，从而得到按该规则排序的最优解。正文必须从两项对总目标的局部贡献推导比较式，而不是先猜一个 `sort` 比较器再补故事。

完整证明还必须补上从局部交换到全局顺序的桥梁：只要序列没有按照目标次序排列，就至少存在一对相邻逆序；交换它们以后答案不变差，并且逆序对数量严格减少。因此这一过程会在有限次交换后终止于目标全序。比较关系还必须具有一致、可传递的顺序语义；若局部比较会形成循环，就不能由相邻交换推出统一的全局排序。

文章名保留“邻项交换证明”和中文竞赛圈通行的“反悔贪心”，不为了标题表面对仗改成“邻项交换策略”和“后悔策略”。前者是证明与比较规则的推导方法，后者是维护、撤销或替换当前方案的构造方法；共同所属的“贪心”学习单元负责表达它们的上位关系。

“反悔贪心”处理当前选择将来可能需要撤销的情形。扫描到每个候选时先把它加入当前方案；若约束被破坏，就找出当前方案中最应撤销的一项并删除。它的正确性不能写成“发现选错了就反悔”，而应证明处理完每个前缀后，当前保留的是这个前缀内满足约束且评价最优的方案之一。

反悔贪心的基础例子使用按截止时间扫描课程或任务：暂时接受当前项目；若总耗时超过截止时间，就线性扫描当前方案并删除耗时最长的一项。这样撤销能给后续释放最多时间，同时保持当前可完成项目数量。学过 `priority_queue` 后，可以用最大堆加速“找出耗时最长项目”这一步；其他题目的撤销规则仍须重新证明，不能把“超限就弹堆顶”当成通用模板。

哈夫曼编码同样是使用小根堆的贪心算法，但它还需要前缀编码与二叉树背景，继续留在编码单元；这里只在贪心总结中建立交叉引用，不把全文搬入基础贪心单元。

## 二叉堆、priority_queue 与关联容器的定位

### 二叉树、二叉堆与优先队列的顺序

初中进阶先完成“数据结构：二叉树”单元：

1. 二叉树的结构与存储；
2. 二叉树的前序、中序与后序遍历。

随后进入独立的“数据结构：二叉堆”单元：

1. 二叉堆；
2. 堆排序（扩展）。

二叉堆与哈希表原理完成以后，进入“标准库进阶”。这一单元集中学习 `priority_queue`、四种有序关联容器和两种无序关联容器：它们不共享一种底层结构，但共同回答“怎样从标准库选择一个较复杂的现成容器”。其中 `priority_queue` 回链第 02 章的反悔贪心，说明它怎样加速反复取最值；结构原理、接口选择和算法应用仍然分篇、分单元。

二叉堆与 `priority_queue` 不并入最早的算法基础，也不塞进某一篇贪心文章。反悔贪心先建立算法思想，`priority_queue` 后来提供更高效的实现；两者仍保持独立正文和独立单元。`priority_queue` 以后还会服务哈夫曼编码、最短路、多个有序来源的合并和其他动态维护最值问题，不能把接口本身误写成反悔贪心的专用部件。

二叉树单元先区分任意二叉树与完全二叉树，再建立堆实际使用的两项性质：

- 完全二叉树除最后一层外全部填满，最后一层从左到右连续；
- 1-based 数组中，节点 `u` 的父节点是 `u / 2`，左右子节点是 `2 * u` 与 `2 * u + 1`。

二叉堆正文从这些已经理解的形状和数组编号继续推导上浮、下沉与建堆，不必临时压缩讲解一遍树。二叉树文章同时比较：完全形状允许隐式数组存储，任意形状通常需要显式保存左右孩子关系。

手写二叉堆的主要作用是理解复杂度、局部不变量和初赛知识，并为特殊堆操作打基础。普通比赛代码不要求背一份自定义堆模板；只需取最大值或最小值、加入和弹出时，最终模板优先使用 `priority_queue`。

`priority_queue` 是容器适配器，因为它在一个符合要求的底层序列容器之上只暴露 `top`、`push`、`pop` 等受限接口，并维护优先队列语义。默认底层容器是 `vector`，通常通过堆算法组织元素；“使用数组保存完全二叉树”解释默认实现为什么自然，却不是“容器适配器”这个类别名称的原因。

二叉堆单元需要读者此前已经掌握 `vector`、数组下标、复杂度、自定义比较和完全二叉树。随后标准库进阶单元把结构操作映射到标准库接口，并回访如何把反悔贪心中的线性最值查找换成最大堆或最小堆。

### 有序关联容器与哈希容器分别成组

`set`、`multiset`、`map` 和 `multimap` 是标准库进阶单元中的有序关联容器部分。它们的接口依赖键的严格顺序，天然接续排序中的比较规则与二分：

- `set` 保存互不等价的键；
- `multiset` 允许等价键重复；
- `map` 为每个互不等价的键关联一个值；
- `multimap` 允许一个等价键对应多条记录，但竞赛中频率明显较低。

核心路线要求会选择容器、插入、查找、删除、遍历、`lower_bound` 和 `upper_bound`，并理解这些操作通常是 $O(\log n)$。不要求先学习红黑树或平衡树旋转；标准只规定接口和复杂度要求，具体库实现不是使用这些容器的前置知识。

这个单元的教学价值是比较工具怎样替代前面已经理解的代码，而不是把接口变成前置捷径：

- 数据一次给完、以后只查询时，通常先排序再二分，连续存储的常数和局部性也更好；
- 数据在线插入、删除，同时还要保持顺序或反复查询边界时，有序关联容器省去手工移动元素和重新排序；
- `set` 不能按下标随机访问，重复元素、键值映射和迭代器失效规则也必须按容器语义处理；
- 学会接口不等于已经学会平衡树。以后学习平衡树时再解释旋转、维护信息和顺序统计等标准容器没有直接提供的能力。

因此有序关联容器位于初中进阶而不是算法基础。它们使用方便，但作为排序、二分或平衡树的前置知识很差；读者先拥有手写基线，才能判断什么时候值得用这个额外工具。

哈希表原理单独组成“数据结构：哈希表”单元。`unordered_set` 与 `unordered_map` 随后作为标准库进阶单元中的无序关联容器部分。它们不维护键的有序关系，平均查找、插入和删除通常是 $O(1)$，最坏情况可以退化；需要顺序、边界查询或稳定复杂度保证时不能用它们替代有序容器。

默认整数、字符串、`pair` 等类型是否已经提供哈希支持必须按 C++17 标准库实际接口说明，不能由“它能够比较”推出“它一定能够哈希”。自定义键还要保证相等判断与哈希一致：两个相等键必须产生相同哈希值。

学习路线中先保留抽象哈希表，再在同一个标准库单元中横向比较优先队列、有序关联容器和无序关联容器。这个合并只发生在课程组织层，不能把三类接口写进同一篇文章，也不能抹掉容器适配器、关联容器和哈希表之间的概念区别。

## 递归、递推、分治与动态规划的定位

这些概念共享“由较小问题得到较大问题”的外观，但处在不同层次。需要分别解释程序怎样执行、问题怎样分解、数值怎样按依赖产生，以及重复子问题怎样合并。

### 同一个递归的两种教学重点

递归仍然只有一个定义：函数直接或间接调用自身。C++ 基础中的“递归”先解释函数调用、终止条件和调用栈，这是程序能够正确执行的语言与运行机制。

算法基础再安排一篇“递归与问题分解”，不把它冒充第二种递归。它重点解释：

1. 先准确规定递归函数接收什么问题、返回什么答案；
2. 确定不再缩小也能直接回答的基本情况；
3. 把当前问题变成参数严格更小的同类问题；
4. 假设较小调用已经按函数定义返回正确结果，再组合当前答案；
5. 证明每条调用链都会到达基本情况。

这一篇位于 C++ 递归和标准库基础以后、快速排序和归并排序以前。它可以使用阶乘和朴素斐波那契递归等极小例子，但不在这里加入记忆化；朴素斐波那契产生的大量重复调用正好为以后理解动态规划留下问题。

### 递归与递推组成独立基础单元

递推关系用已经确定的较早项表示较晚项，并由初始值和依赖顺序产生整个序列。例如：

$$
f[i]=f[i-1]+f[i-2].
$$

按照下标从小到大计算斐波那契数列，只需要初始值、递推关系和计算顺序。教学上把它称为普通递推，不必为了使用了数组就提前称为动态规划。

正式学习单元安排为：

1. 递归与问题分解；
2. 递推。

二者用相同的小数列比较自顶向下调用与自底向上计算，但不重新讲一遍 C++ 调用栈，也不提前讲 DP 状态设计。一个递推关系可以用递归函数求值，也可以用循环递推；递推描述数学依赖，递归描述求值时使用的程序结构。

### 分治放在快速排序和归并排序之后

分治不是递归的同义词。它把原问题分成若干规模更小、通常彼此独立的子问题，分别求解后再合并结果；递归只是实现这些重复子问题结构的自然方式。

学习路线先具体推导快速排序和归并排序，再独立归纳“分、治、合”三步：快速排序先划分再递归，合并工作很轻；归并排序先递归再线性合并。这样读者已经看过两种不同形态，不需要在抽象定义上空转。分治单元因此紧跟排序，位于二分、序列技巧和后续搜索以前。

枚举、模拟、排序、分治、二分、前缀和、双指针和基础贪心先于第 03 章的数据结构。这样后续比较结构操作、分析复杂度和设计基线解法时，读者已经具备共同语言。

### 动态规划另设入门单元

动态规划不与递归、递推合成同一篇或同一基础单元。它建立在递推关系之上，还需要识别重复子问题，并设计足以代表子问题的信息。记忆化搜索和自底向上填表只是同一状态依赖的两种求值顺序。

动态规划中常见的“阶段、状态、决策”应当准确解释：

- 阶段表示问题向前推进的层次或顺序，例如处理到第 `i` 个元素、走到第 `i` 个位置；
- 状态是在某个阶段足以唯一描述当前子问题、并决定后续结果所需的信息；阶段编号经常就是状态的一个维度，甚至是唯一维度，不能把阶段强行排除在状态之外；
- 决策是当前状态允许采取的选择，例如选或不选、最后一步走 $1$ 级还是 $2$ 级；
- 状态转移描述一个状态经过某个决策会依赖或到达哪个状态，转移方程再对全部合法决策对应的结果进行求和、取最值或逻辑合并。决策本身不等于状态转移方程。

`dp[i]` 的含义必须按问题精确定义。它可以表示“只考虑前 `i` 个元素的答案”“恰好以 `i` 结尾的答案”或“规模恰好为 `i` 的子问题答案”，不能一律写成含糊的“规模不超过 `i` 的问题”。

动态规划也不只处理最优化决策。计数、可行性和概率问题同样可以形成 DP；在爬楼梯计数中，把所有走法按最后走 $1$ 级或 $2$ 级分类，就是两种决策对应的前驱状态。

入门单元建议保留：

1. 动态规划：阶段、状态、决策与转移；
2. 动态规划：线性 DP。

现有 `dp-state-transition.md` 保持稳定文件身份，但下一次修订需要补齐上述四个概念，并从暴力递归的重复子问题推导记忆化与递推。难度继续分层：

1. 动态规划入门：阶段、状态、决策、转移和基础线性 DP；
2. 初中阶段主干：最长上升子序列、0-1 背包、完全背包和多重背包；
3. 后续类型：区间 DP、DAG 上的 DP、树形 DP、状态压缩 DP、数位 DP；
4. 扩展与优化：单调队列、斜率、分治、四边形不等式等优化方法。
